# 回流收件箱（host/reflow/）

**子仓 → 本仓**这一向的落点：子仓在它自己的 PR 正文里写 `## 回流` 段（规矩见
`scripts/lib/harvest-check.mjs`），本仓把产物接住——**有人提就得有人接**，不然好东西烂在单里。

## 三个盒子

| 盒子 | 放什么 | 规矩 |
|---|---|---|
| `inbox/` | 子仓提的「可上收产物」，**一条一个文件** | 提出后 7 天内必须有处置 |
| `accepted/` | 已上收 | 文件里写清**上收到哪、谁接的** |
| `rejected/` | 判定不收 | **必须写理由**——没理由算红（不可协商层 C2：抑制必须带理由） |

## 一条怎么投（子仓侧）

在本仓开一个文件 `host/reflow/inbox/<日期>-<短名>.md`，frontmatter 四行：

```md
---
来源仓: ags-orgswitch
产物: reclaude 换号后的探活脚本
为什么通用: ≥2 个场景说得出才写（例：另一台 VPS 也用同一条链路 / 以后新仓接 reclaude 直接用）
落点: scripts/lib/xxx.mjs（建议）
提出: 2026-09-19
---
```

## 本仓怎么处置

**接住** = 把文件移进 `accepted/`，并在文件里补一行：

```
处置：accepted → scripts/lib/xxx.mjs（谁接的）
```

**不收** = 移进 `rejected/`，补一行 `理由：<为什么不上收>`。

**最省事的写法也算**：留在 `inbox/` 里但补一行 `处置：<结论>` 同样算处置过——
约定要容得下最省事的写法，否则没人会遵守。

## 怎么验（三态，退出码分得开）

```bash
node scripts/reflow.mjs          # 0=绿 / 1=红 / 2=没查成
node scripts/reflow.mjs --json
```

红的三条牙（都是确定性的量，不拿墙钟当闸）：

1. `inbox/` 里的条目**超时未处置**（默认 7 天）；
2. `inbox/` 堆积到上限（默认 5 条）；
3. `rejected/` 里**没写理由**；
4. 还有一条更早的病：文件**没提交进 git**——别的机器看不到，等于没写。

**「没查成」不是绿**：目录读不了、git 查未跟踪没成，都落没查成（退出码 2），不许折算成「收件箱是空的」。
