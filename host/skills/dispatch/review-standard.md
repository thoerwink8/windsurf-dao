# 审官质量标准（审读规矩）

> 这是 reviewer-book / soldier-book 里「审读规矩」指针的落点（8-24 审计第五条：此前指针指向空气）。
> reviewer-book 管闭环协议（收信/判定行/合并/结算），本页只管**审查本身的质量**。
> 写法面向最低档模型：每条都是可打勾的动作，不是原则口号。

## 判绿前必核清单（逐条打勾，缺一不许绿）

1. **审的就是这份代码**：`gh pr view <PR号> --json headRefOid` 取 A，树里 `git rev-parse HEAD` 取 B，
   A==B 才开审；对不上先停手报。判绿只对这个 commit 有效——合并前再比一次，变了重审。
2. **被审文件真在树里**：`git show HEAD --stat` 里能看到 PR 改的文件。看不到 = 你的树建错了，
   报出去，**禁止凭 diff 想象内容**（#541 假审：树里没代码，审官编了行号和执行结果）。
3. **检查真跑过**：目标仓有检查命令（本仓 `node scripts/dao-check.mjs`）就在被审 commit 上跑，
   判定正文贴**命令 + 输出末行**。没贴输出 = 没跑。
4. **判别性实验跑过**：任务书点名的那个「目标没达成就会失败」的实验（没点名就自己按验收标准设计一个），
   真跑并贴证据。**测试全绿 ≠ 目标达成**——只跑 lint/单测就判绿是本清单要拦的头号放水。
5. **回归基线取在改动之外**：判「这个红是不是本 PR 引入」，基线必须是 master/merge-base 上的表现；
   拿 PR 自己的前一个 commit 当基线必然得出「不是我引入的」。
6. **通过记录与代码同基线**：PR 里声称「X 修好/测验通过」的，被测代码必须就在本 PR 里（#766）。
7. **新增自动检查须有拦截证据**：本 PR 新建/修改了 hook、CI、检查脚本的，正文必须有
   「故意构造违规样本被当场拦下」的记录；只有「已安装」不算生效。

## 红项怎么写（工人是低档模型也能照改）

- 每条：`文件:行号` + 现象 + 期望改法。给不出位置的疑虑写「疑问」，疑问不计入红项数。
- 超出本单 spec 的问题标「另单」，不阻塞本单——**三个例外必须当场红**：
  密钥/凭据进 git、破坏性动作（删数据、force push）、用假证据冒充通过（贴的输出与命令对不上）。

## 硬边界（协议层，reviewer-book 已写，这里只列不重复）

- 拿不到就报，禁止编造；工人与审官不得同厂（#679）；一 PR 一审官；乒乓两轮仍红才上帅。

## 帅侧抽查（怎么抓假审）

给审官声称做过的**最贵那件事计时**：判定发出时间 − 开审时间 < 跑一遍该实验的最短耗时 ⇒ 假审。
抽查不用读它的论证，先核清单第 1/3/4 条的证据是不是真的（headRefOid 能对上、输出末行能复现）。
