## 干完活之后（顺序执行，缺一不可）

1. 确认全部职责完成：跑测试、开 PR（分支 push 到远端）、PR 正文带 `Closes` 关键词与验收记录。
2. **通知审官开工审查**，不要发给帅。发信只走这一个口子：

   ```bash
   node scripts/dao.mjs notify --hop "士兵→审官" --to {{REVIEWER_HANDLE}} \
     --subject "完工：<PR号> <摘要>" --body "<改了什么、测试结果、PR 号>"
   ```

   审官是你的**直接接手人**（handle: `{{REVIEWER_HANDLE}}`）。收件人是审官不是帅——
   发给帅的消息元帅不会优先看还会漏；**只有审官判绿合并后帅才会出现**。

   **不许改用裸 `orca orchestration send`**：它对不存在的 handle 也返回 exit 0 / `ok:true`，
   链断和链走完在帅眼里长得一模一样。`notify` 先证收件人在、再发、再核回执与落库，四关缺一即非零。
3. **确认送达才算发完**：`notify` 退出码非零 = 没送到，**不许往下走**——
   先照报错修（handle 过期就重新取当时的审官 handle），修不好就升级给帅。
   退出码 0 才进下一步（输出里的 `deliveredAt` 只是参考，判据是退出码）。
4. 发完不撤：继续等审官回信（用 `orca orchestration check` 或当时编排文档的收信方式）：
   - 审官回「红项」→ 逐条修 → 改完 commit/push → **回到第 2 步再发一轮「完工」**（带新 PR head）。
   - 审官回「绿/已合并」→ 收工，本单结束。

## 边界

- **你不做审查、不做合并、不删任何 worktree**——审查是审官，合并与归档收尾是帅（审官不能 rm 自己所在的树，归档是帅的机械动作）。
- 审官是谁、判定怎么落：以**当时的审官任务书/审读规矩**为准，本框架不复制会过时的清单。
- 消息发失败（报错/超时/`The caller is not the Dispatch pane`/收件人 handle 已失效）必须**报出来并重试**，
  不许当发成功（拿不到就报出来，`#532`）。`notify` 已经把这几种情况统一成非零退出，你只要不吞它的退出码。
