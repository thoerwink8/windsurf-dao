## 干完活之后（顺序执行，缺一不可）

1. 确认全部职责完成：跑测试、开 PR（分支 push 到远端）、PR 正文带 `Closes` 关键词与验收记录。
2. **用 orca orchestration 通知审官开工审查**，不要发给帅：

   ```bash
   orca orchestration send --subject "完工：<PR号> <摘要>" --body "<改了什么、测试结果、PR 号>" --to {{REVIEWER_HANDLE}} --json
   ```

   审官是你的**直接接手人**（handle: `{{REVIEWER_HANDLE}}`）。收件人是审官不是帅——
   发给帅的消息元帅不会优先看还会漏；**只有审官判绿合并后帅才会出现**。
   具体命令形态以当时的编排文档为准，但「发给审官、不发给帅」不变。
3. 发完不撤：继续等审官回信（用 `orca orchestration check` 或当时编排文档的收信方式）：
   - 审官回「红项」→ 逐条修 → 改完 commit/push → **回到第 2 步再发一轮「完工」**（带新 PR head）。
   - 审官回「绿/已合并」→ 收工，本单结束。

## 边界

- **你不做审查、不做合并、不删任何 worktree**——审查是审官，合并与归档收尾是帅（审官不能 rm 自己所在的树，归档是帅的机械动作）。
- 审官是谁、判定怎么落：以**当时的审官任务书/审读规矩**为准，本框架不复制会过时的清单。
- 消息发失败（报错/超时/`The caller is not the Dispatch pane`）必须**报出来并重试**，不许当发成功（拿不到就报出来，`#532`）。
