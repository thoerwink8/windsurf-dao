# 项化派工

一块活 → 单卡（`dispatch` skill）。**多块活 → 本页。**

底层命令一律走 `node scripts/dao.mjs`，参数细节见 `dispatch` skill，本页不重复。

## 一、先判要不要开项

```
这批活能拆成几块（几个人能同时干）？
  1 块           → 不开项，走 dispatch 单卡
  ≥2 块，但都很小 → 不开项，打包给一个工人（dispatch skill「小活打包」）
  ≥2 块，各够一个工人干一阵 → 开项
```

两条判据缺一不可：

- **能不能同时干**，不是主题像不像。按主题打包只买到耦合，买不到一致性。
- **值不值得拆**。开项的固定开销是 1 项卡 + N 个 worker + N 个审官 + 1 收口官；块太小时这套开销远大于活本身。

（本 skill 自己的落地就是反例：它拆得出「写 skill」和「改 dao.mjs」两块，但两块都是编辑级，判定走单卡。）

## 二、消歧门（派工前的硬门控）

**待拍板不是停车场，是所有项都要过的一道门。** 过不了不许派。

门的产出 = issue 上一条**消歧记录**：

| 岔路 | 结论 | 依据 |
|---|---|---|
| 这里有几种做法都说得通的地方 | 定成哪个 | 用户拍的 / 有既有拍板可依 / 确无岔路 |

**「接口怎么定」是最典型的岔路**——多个 worker 并行时，接口必须在派工前定死，否则 B 要等 A 才能开工，并行就是假的。

三条硬规矩：

- **帅自己推导出的结论不算消歧**。列岔路是帅的活，选哪个必须用户拍或有旧拍板可依。（2026-08-16 实咬：帅自填八条消歧记录当门过了，用户根本没确认过。）
- 写完打 `已消歧` label，`dao.mjs dispatch` 读不到它**拒绝派工**。正向 label 是 fail-close——忘打标是拦住，不是放行。
- 工人 escalation 类型为「需用户拍板」= 这项消歧门失效，当场记一笔。

值守态（`dao-mode` = `standby`）下，消歧没过的项**攒队列不派**。

## 三、建结构

```
项·<项名>                       ← 顶层，--no-parent
  ├── #565 <动宾> · <模型>       ← worker，--parent-worktree 项卡
  │     └── #565 审 · <模型>     ← 审官，--parent-worktree 该 worker
  ├── #566 <动宾> · <模型>
  │     └── #566 审 · <模型>
  └── 收口 · <模型>              ← 常设，见第四节
```

### 命名

| 卡 | 名字 | 转成的分支 |
|---|---|---|
| 项卡 | `项·调度自动化` | `项-调度自动化` |
| worker | `#565 造 next 函数 · ds` | `565-造-next-函数-ds` |
| 审官 | `#565 审 · gpt` | `565-审-gpt` |
| 收口官 | `收口 · gpt` | `收口-gpt` |

- **用 issue 号，不用 PR 号**。开卡时 PR 还不存在，用 PR 号就必须事后改名——这件事 2026-08-16 一天漏做三次。issue 号开卡时就有，永不改名。
- **`项·` 前缀**让项卡在顶层一眼可辨。
- **模型放末尾**，转成分支后是 `-ds` / `-gpt` 后缀，扫分支列表也认得出。
- **身份必须写在名字里**：面板顺序不是建卡顺序（实测），**不能靠位置传信息**。
- 换人（`--retry-of`）后**卡名要跟着改**，否则名字撒谎。

### 分支

默认全部 `--base-branch master`，各自开 PR 到 master。

**项卡的分支是预留的集成分支**——扁平模式下闲置。真碰上「某一块单独合进 master 会破坏 master」（删了旧接口而别人才是新接口的使用者）时，把那批 worker 的 `--base-branch` 改指向项卡分支即可，**卡结构一个字不用动**。切之前先 rebase 项卡分支到 master（它切出后就不动，会漂）。

不要为了「怕冲突」提前建集成层——git 本来就为并发编辑设计，冲突打回冲突方自己解。

## 四、收口官（常设，挂项卡下）

卡名 `收口 · <模型>`。它**不审代码**——审是各 worker 自己的审官的活。它接的是**原本归帅的收尾动作**：

| 职责 | 说明 |
|---|---|
| 解冲突 | worker PR 之间撞了，由它处理（不是打回给 worker 各自解——它有全局视野，知道谁该让谁） |
| 合并 | 审官判绿的 PR 进入它的队列，由它执行合并 |
| 定顺序 | 谁先合谁后合它统筹；单个审官看不到全局 |
| 关单 | 关 PR、关对应 issue，引用落点 |
| 打标签 | `model/*` `type/*` 从 issue 同步到 PR（`calibrate` 的数据源） |

**输入 = 判绿了的 PR 队列**，所以只要有 PR 判绿它就有活，不会像"审整体"那样大半时间空转。

**边界**：合并前仍要核对四条（审官 APPROVED / CI 全绿 / merge-policy / `review.commit_id == headRefOid`）。四条任一不过就打回，不自行放行。

## 五、归档

归档跑 `node scripts/dao.mjs worktree-rm --worktree <项卡>`（#588：一条命令后序整树收口，人不排叶子→根）。删项卡本身**不级联**，所以不要再手敲 `orca worktree rm`。

收口官**不能删自己所在的树**，所以这一条归帅。读返回的 `ok` 字段，**不看输出形状**——orca 的错误体和成功体尾巴长得一样。占用中会整树拒删并报是哪棵，不会半删。

## 六、没有头工人

分解与定接口在**消歧门**完成（接口本来就是最典型的岔路），不设头工人工位。worker 各做各的，各自的审官把关，收口官统筹合并。

`dispatch` skill 里「改文件的手 ≥2 必须指定头工人」那条对项化路径不适用。

## 实测记录（2026-08-16，本页每条结构性断言的来源）

| 断言 | 怎么验的 |
|---|---|
| 三层嵌套 orca 支持 | 建了 项卡→worker→审官 三层，`parentWorktreeId` 链完整 |
| 不存在纯分组卡 | 项卡也有自己的分支和 git worktree |
| 删项卡不级联 | 删项卡后 7 张子卡全变孤儿 |
| 面板顺序 ≠ 建卡顺序 | 按 1→2→3 建，面板显示 3→2→1 |
| 卡名转分支名的规则 | `#` 去掉、空格与 `·` 转 `-`，中文保留 |
| 每张卡磁盘约 4.4M | 8 张卡共 35M（git worktree 共享 `.git`） |
