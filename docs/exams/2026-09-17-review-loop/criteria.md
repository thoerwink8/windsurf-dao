# 盲设计题判定标准（预注册于起灶之前，2026-09-17）

题目：工人→审官→返工永不收敛（53 轮 0 绿）。

三臂：grok-4.6（xAI）/ gpt-6-astra（OpenAI）/ composer-2.5（Cursor）。均不读仓内约定文件，中性目录起灶。
Claude 族全部排除——我自己是 claude，同源等于破盲。

## 我起灶前的自有结论（封存，用于事后比对是否被独立命中）

1. 根因是**单太大**，不是审官太严。依据：手上 10 张 PR 的行数与轮次近乎单调相关（≤202 行全 1 轮；3161 行 9 轮）。
2. 修法是把拆单判据从主观题（「能不能按文件切开」）换成**客观量（改动行数）**，且落在**交卷闸**而非派工闸（派工时只能估）。
3. 我此前提的「P1/P2/P3 分级放行」是治标；若单足够小，分级可以整个撤掉。

## 判定表（每臂逐项记 命中 / 未命中 / 反对）

| # | 判据 | 怎么算命中 |
|---|---|---|
| ① | 独立发现「改动规模 ↔ 轮次」相关 | 答案里明确把轮次多归因到改动大小/范围，且引用了题面表格的数据 |
| ② | 提出「限制单大小 / 拆单」类机制 | 方案含「把一个改动拆小」或「超过某规模就拒收/拆分」 |
| ③ | 提出「分级放行部分问题」类机制 | 方案含「区分必须修的和可以另记的」 |
| ④ | 提出上面三类之外的机制 | 出现我在封存结论里没写的第四条路 —— **这是本次考试最想要的产出** |
| ⑤ | 「只能改一处」的回答 | 逐臂记录原话，看三臂是否收敛到同一处 |
| ⑥ | 指出自己方案的失效场景 | 有具体的失效条件，不是「可能不适用」这种空话 |

## 判定纪律

- 一致点（≥2 臂独立命中同一条）→ 直接采纳，不再问用户。
- 分歧点 → 整理成选项交用户拍板。
- 若 ④ 出现且言之成理 → 优先于我的封存结论，我的方案让位。
- 单臂阵亡（限流/破盲/跑飞）记档不重跑，≥2 臂有效即成立。
- 破盲判据：答案里出现仓内专有名词（dao-check、worker-done、mirasim、P1/P2/P3、split 等）即判该臂破盲，该臂作废。
