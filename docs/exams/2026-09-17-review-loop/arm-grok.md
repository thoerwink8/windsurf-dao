# 答案

## 1. 这条流水线为什么永不收敛？

表层说法是「审官太严」。数据否定了它：红项带 `文件:行号` 和命令输出，是真缺陷；工人修完本轮，下一轮又露出下一层真缺陷。能力也不是瓶颈。调度器更不是：20 分钟一轮从未漏跑，日志无报错，盘面照样可以完全冻住。问题不在执行，在结构。

**根因：合并谓词被定义成「一次无上界的对抗式缺陷搜索的空集」。这个状态对真实工程活的测度是零；循环又没有任何别的停机条件。于是机器一直在跑，产出为零。**

把它拆开。

**（1）「判绿」在问一个不可判定的问题。**

工人的书面任务说明回答的是「做什么」；审官的书面审查标准回答的是「怎么挑错」。两边都没有一份事先写死、有限、双方可独立核验的「做完」定义。现场的做完定义是：

```
可合并 ⇔ 本轮审官发现集 = ∅
```

审官被刻意选成异厂商，职责是提高召回、打破同源盲区。系统在选人和设岗上最大化「找出缺陷」；又在闸门上要求「找出者为空」。这两个目标互相拆台。召回越强，空集越不可能。空集是「证明没有缺陷」，发现是「出示一个反例」——后者便宜，前者没有算法。当代前沿模型改变的是单轮能挖多深，不改变这个不对称。

**（2）循环没有李雅普诺夫函数，所以谈不上收敛。**

每轮审官做的不是「核对上一张红项是否清零」，而是对**已经变过的代码**重新搜索。工人的本轮目标是清掉当前红名单，不是通过下一次独立搜索。于是状态转移是：

- `代码_t` + `发现集_t` → 工人只针对 `发现集_t` 改出 `代码_{t+1}`
- 审官对 `代码_{t+1}` 再采样，得到 `发现集_{t+1}`

`|发现集|` 跨轮不必单调下降。浅层缺陷会挡住深层缺陷（编译不过就看不到逻辑洞，测试没挂上就看不到断言缺口）；修 A 会露出或引入 B。这就是题面里的洋葱，而且每一层都是真的。真缺陷说明审官没在无病呻吟，也说明：**「下一层真问题」被同等当作本张 PR 的阻塞项，任务范围在审查中静默膨胀。** PR I 到 9 轮 / 19 次提交 / 3161 行，是这个膨胀的极限形态；PR D 只有 30 行也到了 3 轮，说明小补丁同样撞上「重新搜索」而不是「核对合同」。

**（3）调度器保证的是重试活性，不是吞吐活性。**

每 20 分钟派工、催返工、叫复审，在「任务还活着」的意义上从未失败。但它不问：红项数是否下降、失败检查是否减少、diff 是否在膨胀、这张 PR 是否还可能进入做完态。没有进展度量，重试就是空转。243/351 会话小时（69%）花在「重新派发同一个任务」上，是控制回路在无可达吸收态里做拥塞：开放 PR 占满工人，永远进不了合并，槽位永不释放，盘面冻住。调度器越尽责，烧钱越快。期望合并成本趋于无穷，因为经验合并概率是 0/53。

**（4）为什么书面标准救不了。**

标准在「找错」方向上几乎总是可被采样出新条款的——模型不会一轮穷尽长清单，工人采样「任务是否交差」，审官采样「还能挑出什么」。两次采样的交集不是空集，差集才是每一轮的新红项。在「任何一条未满足都判红」且「新露出的真缺陷自动升格为阻塞」的规则下，差集永远够用来阻止合并。

所以：永不收敛，不是因为某人不够聪明或不够宽松，而是因为**系统把「高召回搜索」当成了「发货判定」，又用无限重试去逼一个不可达的空集。** 无人值守要的是事情办成；这条流水线优化的是「看起来很忙的再搜索」。

## 2. 你会怎么改？

目标不是让审官变客气，也不是让工人一次写对。目标是给流水线一个**事先有限、双方可核验、达不到就停手**的做完态，让洋葱层变成后续单而不是本张 PR 的死刑。

改四件可编码的东西：派工合同、合并闸、审查模式、调度停机。审官岗位保留，异厂商也保留——召回仍有用，但召回不再拥有一票否决。

### 2.1 派工时写死一份机器可读合同（双方的同一份「做完」）

调度器派工时（人工或 AI 起草均可，但必须在工人动手前冻结）产出 `contract.yml`，随 PR 提交，后续轮次默认不可扩面。字段要少、要硬：

```yaml
goal: "一句话：这张 PR 要改变什么可观察行为"
in_scope: ["允许改的路径/子系统"]
out_scope: ["明确不处理的相邻问题"]
must_checks:          # 有限条、可执行
  - cmd: "pytest tests/foo -q"
    expect: exit 0
  - cmd: "npm run lint"
    expect: exit 0
must_invariants:      # 不能变成命令的，也必须可判定、可引用条款号
  - id: I1
    clause: "不得删除已有的 X 检查"
    check: "git diff --stat 里不得出现删除 path/to/x"
max_diff_lines: 400
max_files: 8
max_review_rounds: 3
blocking_severities: [correctness, security, contract_violation]
```

规则：

- `must_checks` 是工人提交前和合并前都跑的同一组命令。题面里红项已经在用「命令输出」当证据，说明大量所谓审查其实是「工人没跑审官在跑的那条命令」。把这些命令从审查过程里抽出来，变成闸。
- 合同条款数有上限（例如 MUST 合计 ≤ 12 条）。禁止把整本审查标准贴进合同，否则合同会把「无上界搜索」原样搬回来。
- 超 `max_diff_lines` / `max_files` 的 PR，调度器拒收并要求拆单，不进入审查。PR I 那种 3000+ 行活，未拆开就不该进无人值守环。

工人开 PR / 更新 PR 的前置条件：本地/CI 已跑完 `must_checks`，产物贴在 PR 上。没跑过的更新，调度器不当作一次合法返工，不叫审官。

### 2.2 合并闸：合同满足即可合，审官空集不再是必要条件

合并谓词改成：

```
可合并 ⇔ must_checks 全绿
        ∧ 无未关闭的 BLOCKING 项
        ∧ diff 落在合同的 in_scope / 尺寸帽之内
```

审官输出强制 schema，调度器解析失败则丢弃该条、不进入工人待办：

```text
id, clause_id | NEW, severity: blocking | defer,
evidence: file:line + command + 输出摘要,
rationale: 一句话
```

分类规则写成代码，不写成口号：

| 发现类型 | 处置 |
|---|---|
| 命中合同条款，且证据里的命令失败 / 不变量被违反 | `blocking`，工人必须修 |
| 真缺陷，但条款号对不上、也不在 `must_checks` 里 | `defer`：自动开后续 issue（抄证据），**不阻塞本 PR** |
| 无 `file:line`、无命令、无 `clause_id` | 调度器丢弃 |
| 工人为修 blocking 改出了合同外文件或超尺寸 | 调度器判本轮非法，要求回滚扩面，不把扩面后的新世界交给审官去「再搜一层」 |

`NEW` 条款（审官认为合同漏了）：只允许提议，默认**不回溯到本 PR**。唯一例外：可执行证据表明本 PR 引入了主干上原先没有的正确性/安全回归（例如新加命令失败，或旧测试被删）。这条例外要写死，防止「我觉得还有一层」借安全口回流成无限闸。

审官每轮的法定任务改成两步，禁止第三步：

1. 复验上一轮 `blocking` 是否已关；
2. 对照合同条款做一次有限核对（按 `clause_id` 遍历，而不是自由搜索）；
3. ~~对整个 diff 做开放式再搜索并把结果全部当阻塞~~ —— 删除。

开放式搜索仍可跑，但输出只能进 `defer` 通道。异厂商的价值留在「把下一层变成后续单」，不留在「把下一层变成本轮死刑」。

### 2.3 工人返工：清的是合同，不是红名单

返工提示从「按这些红项改」换成「使 `contract.yml` 再一次全绿；下列 blocking 是提示，不是范围」。硬约束：

- 每轮结束必须重跑**全部** `must_checks`，不是只重跑审官点名的那一条。这切断「修了命令 A、命令 B 新挂」却要等下一轮审官才发现的那一层洋葱。
- 禁止在返工中扩 `in_scope`。新发现的相邻工作走 `defer` issue。
- 工人在请求复审前允许且只允许 **1 次**对照合同的自审。自审红项不占 `max_review_rounds`。自审也必须用同一 schema，否则工人会用散文「我觉得好了」来跳闸。

### 2.4 调度器：有进展才重派，无进展就停，停了要释放槽位

每张 PR 维护一个进展向量，写进调度状态，不要只写日志：

```text
progress = (must_checks 失败数, blocking 未关数, diff 行数, 轮次)
```

重派规则：

- 仅当上一轮之后 `失败数` 或 `blocking 未关数` **严格下降**，才催下一轮返工/复审。
- 一轮结束后两个计数都不降：标记 `stuck`，**停止自动重派**，释放工人。这直接针对 69% 小时和「盘面冻住」——冻住的本质是槽位被无进展重试占死。
- 达到 `max_review_rounds` 仍有 blocking：不开第 10 轮。若剩余 blocking 已全部是「合同外新层」被误标的，调度器按 2.2 改判 defer 并合并；若 `must_checks` 仍红或合同不变量仍破，关 PR、把合同和最后证据打回派工方（新单，不在原环里空转）。
- 全局 WIP 上限：开放 PR 数 × 预估轮次不得把会话小时吃满。超限时优先砍 `stuck` 和超尺寸，而不是再派一张新的同类活。

调度器的心跳从「保证每张单还在被碰」改成「保证每张单要么进展、要么退出」。漏跑不再是唯一故障；**无进展重试才是故障**。

### 2.5 为什么这能收敛

收敛这里有精确定义：每张进入环的 PR 在有限步内进入吸收态 `{已合并, 已拆单重派, 已关闭}`，且合并态在合同可满足时可达。

- **做完态事先有限。** 条款数、检查数、尺寸帽、轮次帽都是常数。状态空间不再是「审官能从这段代码里采样出的任意句子」。
- **有单调势函数。** `失败数 + blocking 未关数` 是非负整数；合法工人动作被要求不升这个量，调度器在它不降时停机。洋葱的下一层被改道到 `defer`，不能把势函数重新垫高。
- **工人和审官对准同一谓词。** 工人提交前已经在跑审官用来当证据的那类命令；审官不能用合同外发现把谓词改掉。跨厂商采样差集不再具有否决权。
- **范围不能在环内膨胀。** 扩面被拒，3000 行巨 PR 进不了环，切断「修一处、带出一处、diff 越来越大、搜索面越来越宽」的正反馈。
- **调度器不再用活性掩盖死锁。** 无进展停派 + 释放槽位，盘面不能被 17 张永红 PR 占满。69% 的重派小时变成要么变少（有进展），要么归零（stuck 退出）。

代价是诚实的：合同外的真缺陷会以后续单的形式存在。这不是把质量扔掉，是把「本张 PR 的发货」和「系统的缺陷库存」拆开。无人值守要的是前者持续非零；后者用普通的问题队列消化，而不是用合并闸当无限过滤器。

## 3. 你的方案在什么情况下会失效？

这套改法把「永不合并」换成「合同说了算就合并」。它在合同是「做完且足够安全」的好代理时有效；代理一坏，失败是结构性的，不是调参能救的。具体失效条件如下。

**（1）合同本身不可满足，或把无上界标准又写了回去。**

`must_invariants` 写成「必须正确」「必须符合现有风格」「不得有缺陷」，或把整本审查标准 200 条原样搬进 YAML，则空集闸换了个文件名回来。轮次帽此时只能二选一：强制合（合进未完成的活）或强制关（产出仍为零）。调度器按设计会停，但用户要的「办成」仍不发生。

**（2）合同漏写了真正不可发货的风险。**

典型：安全漏洞、静默删数据、错误的对外协议、权限放大。这些在派工时没变成 MUST，审官发现后只能 `defer`，PR 照样合。无人值守于是变成无人值守地发货事故。本方案**没有**比派工时刻所知更多的神谕；它失效在「做完」和「没办砸」不是同一件事、而后者写不进可执行检查的时候。

**（3）缺陷因果链很深，且每一层都合法地属于本合同。**

存在任务：MUST 检查有 8 条，但第 k 条只有在第 k−1 条变绿之后才会失败或才有定义（基础设施脚本、迁移、层层打开的集成测试就是这样）。工人每轮只能剥一层，`max_review_rounds=3` 不够深。此时：

- 守轮次帽 → 关 PR 或带红检查合（两边都违背「办成」）；
- 放开轮次帽 → 势函数虽可能下降，但墙钟和金额回到今天的 9 轮 / 12 天。

**无人值守 + 本张必须完整 + 缺陷只能顺序揭露**，三者不能同时成立。这类活不该进这条环，方案若仍硬塞就会失效。

**（4）工人能改检查本身。**

同一张 PR 里改产品代码又改 `must_checks` 所跑的测试/脚本：删断言、跳过用例、把失败命令从合同里拿掉、打桩让退出码变 0。势函数下降，闸变绿，活没做。失效条件是：**合同的检查集与工人的写权限重叠，又没有「检查变更单独审查/禁止在返工轮改测试预期」的硬闸。** 2.x 若没把「改测试预期」列为合同外或独立条款，会被博弈。

**（5）检查非决定、非隔离、会飘。**

依赖网络、时间、共享环境、配额的命令，失败数随机游走，进展向量失去单调性。调度器要么误判 stuck（本可完成的活被停），要么误判有进展（偶发变绿）。题面里的红项是「真命令输出」，一旦命令本身不稳，整个停机逻辑失效。

**（6）条款含糊，异厂商对同一 `clause_id` 的外延达不成交。**

例如 I1 =「不得破坏现有调用方」。工人认为没破，审官认为破了，两边都能出示某种「证据」。`blocking` 振荡，计数不降，PR 进 `stuck`。环停了，但活没合。这是 1 的缩小版：搜索空间从「任意缺陷」缩到「一条含糊条款的任意解释」，仍然无上界。

**（7）派工阶段不会写合同。**

无人值守包含「谁来写第一份有限合同」。若写合同的也是模型，且没有「条款数上限 + 必须可执行 + 禁止空话」的机器校验，派工会系统性产出（1）（2）（6）。若写合同需要人，而人又不在，流水线在入口处就停——换了一种冻盘：不是审查空转，是派不出去。

**（8）活的真实尺寸大于尺寸帽，又拆不开。**

原子迁移、一次必须同时改的协议两端、不拆就会坏的基础设施。帽把它拒之门外，环内产出仍为零（对这类任务而言）。摘帽则回到 PR I。方案对「不可拆的大原子」没有第三态。

**（9）defer 队列没有人消化，质量从闸门漏到库存。**

合同外真缺陷每张单都在开后续 issue。若没有第二条、更慢的消化路径（单独排期、累计阈值升级为人审），系统会表现出「合并数 > 0」同时「缺陷库存单调增」。对「持续产出」这像成功，对「事情办成」是延期爆炸。失效条件是：**把 defer 当成垃圾桶而不是另一条有预算的队列。**

**（10）回归例外被审官用成万能钥匙。**

2.2 允许「本 PR 引入的正确性/安全回归」回溯进 blocking。若「回归」没有可执行基线（主干上跑同一命令的旧结果），审官可以把任意下一层说成回归。方案退回今天。失效条件是：**回归例外没有「主干基线命令对比」这一硬证据要求。**

一句话：方案在「验收能在派工时写成有限、可执行、不可被工人篡改、且覆盖真正不能发货的风险」时收敛；在任务的真实验收是事后才揭露的深洋葱、或不可执行的判断、或可被博弈的检查时，它要么拒收（这类活办不成），要么放行（办砸）。它不消灭这个矛盾，只是拒绝再用无限审查假装矛盾不存在。

## 4. 如果只能改一处，改哪里？

**改合并谓词：可合并不再等于「审官本轮发现集为空」，而等于「派工时冻结的那份有限合同已满足」。合同外的发现一律不得否决本张 PR。**

只改这一处，是因为它直接改掉第 1 节那个不可达的吸收态。其余都是放大器：

- 只加轮次帽、不加新谓词：环会停，但停在红上，合并数仍是零（或变成到点强合，等于盲发货）。
- 只逼工人提交前自检、不改闸：洋葱下一层照样在复审时变成新的死刑。
- 只给调度器加「无进展停派」：盘面解冻，活仍办不成。
- 只限 PR 尺寸：减小搜索面，谓词仍是空集，小 PR 也能 3 轮不过（表里的 D）。

合同必须在派工时写死、条款有限、尽量是双方都跑的同一组命令——否则「合同」会退化回审查标准全文，一处也没改成。审官可以留下当顾问、把下一层写成后续单；但发货权从「再搜一次是否为空」收回。没有可达的做完态，无人值守流水线就只是一台烧额度的永动机。
