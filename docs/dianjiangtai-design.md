# 点将台设计综合稿

> 本稿是「点将台」（多模型派单的记账与选型算法）的五方盲答合成稿。四份盲答（DS / Claude / GPT / Grok）与既有方案对照后，由用户在 issue #438 逐项拍板；本稿只做合成，不改取舍。合成口径与「和既有拍板有什么不同」见文末两张表。

## 总纲

点将台 = 一个「仓库内一事件一文件的 git 真相账 + 门闩先于评分的确定性选型纯函数 + 层级收缩打分 + 确定性配额探索 + 规则前置/换厂商单判官升级/人终裁的归因 + 决策票审计的轻量防绕过」系统：在线派单只做查表与四则运算、毫秒级零 LLM，LLM 只出现在每单结束后的离线归因点。

## A. 存储形态：混合账本

真相源是仓库内**一事件一文件**的 append-only 事件账；draft PR 正文只做人读镜子；物化层可丢可重算；三者靠每日对账互验。

### A.1 三层结构（政策 / 事件 / 物化）+ 脚本

| 层 | 目录 | 格式 | 谁写 | 性质 |
|---|---|---|---|---|
| 政策层 | `policy/` | YAML | 人类独占写 | 门闩与初值：禁令、预算、权重、探索配额、套餐合同、模型目录 |
| 事件账 | `ledger/` | JSON，一事件一文件 | 脚本按类型追加 | 唯一真相源，只增不改 |
| 物化层 | `derived/` | JSON | 脚本整文件重写 | 事件账的纯函数，可丢可重建 |

规范路径（下文 B–E 只引用这套清单，不再出现别名）：

- `policy/models.yml`：模型目录、计价（含峰谷阶梯）、订阅套餐、退役标记、版本串。
- `policy/bans.yml`：硬禁令 `(模型, 身份?, 工种?) → 禁`，命中即拒、不进打分，仅用户可写。
- `policy/weights.yml`：权重初值、探索保底单数、冷却时长。
- `ledger/events/<ulid>-<machine>.json`：一事件一文件，事件类型闭集（见下）。
- `derived/features.json` / `quotes.json` / `scores.json`：物化产物，选型只读这些，不扫全账。
- `schemas/events.schema.json`：事件类型 schema 唯一权威——每个事件类型的必填字段与 `schema_version` 落这里；加类型先改它、只加字段不改语义翻转、读端容忍未知字段。由 `audit.mjs` 在写入时与每日对账时校验（schema 是校验器的唯一输入，闭集是它的派生枚举）。
- `scripts/select.mjs`（在线选型纯函数）、`ingest.mjs`（收终端计量写事件）、`close.mjs`（关单 + L0 归因）、`recompute.mjs`（重放事件重生物化）、`audit.mjs`（对账 + 绕过检查 + schema 校验）、`watchdog.mjs`（看门狗，见 E.4）。

**事件类型闭集（下为派生枚举，唯一权威在 `schemas/events.schema.json`；加类型先改 schema 文件、只加字段不改语义翻转）**：

`job.opened`（任务卡快照 + 候选 + 选中 + 解释串）、`job.dispatch`（实际启动模型 + 终端 + 价目快照 + `decision_id`）、`job.meter`（token 进/出/缓存命中 + 金额）、`job.handoff`（A→B 接手及原因）、`job.closed`（终态 + 总金额 + 是否返工）、`job.override`（用户自选）、`job.explore`（用户尝鲜）、`attr.rule`（L0 规则归因）、`attr.llm`（单判官归因）、`attr.human`（人类终裁）、`attr.retract`（纠错，指向被撤事件）、`policy.patch`（政策变更摘要）、`sub.usage`（套餐剩余配额快照）、`incident`（事故账，见 E.4）、`audit.bypass` / `audit.stale`（审计发现）。

### A.2 三铁律（多机零冲突）+ 全序可重放

1. **一写一文件、文件名唯一**：`events/<ulid>-<machine>.json`，ULID 时间序 + 机器名，全局唯一。两台机器同时干活写的是不同文件，git merge 等于求并集，永不冲突。
2. **写一次即不可变**：事件落盘后永不编辑；纠错另立新文件（`attr.retract`），不覆盖历史。
3. **派生产物可重算**：`derived/` 是事件的纯函数。两台机器各自编译出不同版本若冲突，解决方式 = 删掉重跑（结果确定性相同），永不手工 merge。

**全序排序键**：每事件带 `ts`（时间戳）+ `machine`（机器名）+ `seq`（本机单调计数器）+ `event_id`（内容哈希）。重放统一按 `(ts, machine, seq, event_id)` 字典序折叠——无需全局 seq 协调，本机 seq 单调 + 机器名唯一即可钉死所有机器的重放顺序一致。

### A.3 写权矩阵

| 文件 | 人类 | 协调者 LLM | 在线选型脚本 | 采集/关单脚本 | 归因 LLM |
|---|---|---|---|---|---|
| `policy/*` | 独占写 | 禁止 | 只读 | 只读 | 禁止 |
| `ledger/*` | 只追加纠错/终裁 | 禁止 | 只追加 `job.opened/dispatch/handoff/override/explore` | 只追加 `meter/closed/attr.rule/sub.usage` | 只追加 `attr.llm` |
| `derived/*` | 禁止手改 | 禁止 | 只读 | 整文件重写 | 禁止 |
| draft PR 正文 | 可改任务卡 | 可改任务卡 | 写「选型块」 | 写「计量块」 | 写「复盘块」 |

协调者 LLM **没有**政策写权、事件账改写权、物化写权。它只能：填任务卡、调用选型脚本并执行其输出、把脚本输出原文贴进 PR。

### A.4 draft PR 正文 = 人读镜子（围栏块契约）

PR 正文承载任务叙事（目标/验收/进展），任何模型读它就能接手。账不在 PR 里——账在 `ledger/`。PR 里嵌三段机器可解析围栏块，作为「镜子」：

```markdown
<!-- ledger:job v1 --> ... 任务卡（job_id / task_class / 规模 / 风险） ... <!-- /ledger:job -->
<!-- ledger:select v1 --> ... select.mjs 完整 stdout（含 decision_id） ... <!-- /ledger:select -->
<!-- ledger:meter v1 --> ... 终端采集的最新一行 ... <!-- /ledger:meter -->
```

### A.5 每日对账互验

夜间 `audit.mjs`（零 LLM）：① 重放 `ledger/` 重生成 `derived/`，与提交版本 diff，不一致即红；② 扫 PR 围栏块，与事件账里的 job_id / 选中模型 / 累计金额比对，对不上则认定「镜子破了」，只信账、补写围栏块。选型脚本启动前若发现 `derived/` 比账旧超过 6 小时且中间有关单/归因事件，先强制 `recompute`（确定性、便宜）再给结果。

**被弃盲答方案（一句话理由）**：单一 SQLite / 中心库弃——违反「进版本管理、换机不丢」且要运维中心服务；一个大 `state.json` 原地改弃——并发必然丢更新、merge conflict；账本全写 PR 正文弃——自由文本无类型、可被 force-push 改写，做不了确定性算术；单一 JSONL 追加弃——追加同一文件天然有并发冲突；评分快照 commit 弃——派生物可重算，两机重算即冲突属冗余。

## B. 特征函数清单

评分对象是三元组 `(m, i, w)` = 模型 × 身份（帅/协调者/工人/审官）× 工种（写码/判断/查证/审查/UI/…，`work_types` 可增枚举）。所有特征只允许**数值或枚举**，算法不读任何自然语言——「为什么」只进事件的 `why` 字段和 PR 正文。

主干沿用 DS 臂的 F1–F15，两处按拍板改造：F8 探索由「UCB 加分」改为「配额缺口」（探索移出打分，见 C.3）；F10 成本并入 GPT 臂的订阅摊销公式与 Grok 臂的套餐配额/浪费风险。新增 F16–F18 承载套餐特征。

|---|---|---|---|---|---|

### B.1 门闩特征（结构过滤，先于评分）

F1（硬禁令）、F14（上下文放不下）、F15（离线/忙/厂商故障）是**门闩**，不进加权：命中即剔除，被剔模型仍在输出里标注拒因。**成本/预算不做任何门闩**——成本作为 F10 进打分影响排序、超支只呈现不拦截（见 C.1）；预算只做展示与告警，不因价格剔除候选。

### B.2 成本特征与订阅摊销

本单预估经济成本 `c` = 按量部分 + 订阅摊销部分，全部折算美元，峰谷**现算**：

```
metered = T_in·r_in(t)·(1−h) + T_in·r_cache(t)·h + T_out·r_out(t) + 固定费 + 预估溢出
r(t) = 基础价 × 峰谷乘数（policy/models.yml 阶梯表，派单发生在几点就用几点的价）
```

订阅摊销沿用 GPT 臂公式，不把订阅当「边际成本为零」：

```
usage_unit = T_in(未缓存)·ref_in + T_in(缓存)·ref_cache + T_out·ref_out
在线预测摊销  alloc_hat = 月费 × usage_unit / forecast_total_usage_units_month
月底实际摊销  alloc     = 月费 × usage_unit / Σ(实际 usage_units_month)
无任何用量时，整笔月费记 unallocated_subscription_cost（不进任何单）
```

有硬配额的套餐用 Grok 臂的简化口径：配额内 `amortized_per_mtok = 月费 / included_tokens × 1e6`，配额外走 PAYG 溢出价；畅用包月用 `amortized_per_job = 月费 / fair_share_jobs`。`c = metered + alloc_hat`，预估配比用历史中位数、不用均值，抗单次爆量带偏。

`quota_left`（F16）供「配额耗尽可接手」：耗尽时写 `sub.usage` 并触发 `job.handoff`，源模型本段不记能力失败（见 D）。`waste`（F17）在**质量不低于该类中位数**的前提下，把该订阅模型的 cost_util 上调至 `max(cost_util, 0.7)`（鼓励用完已付月费，边际现金成本≈0），不打破禁令、不改门闩。

**被弃盲答方案（一句话理由）**：embedding/LLM 抽「任务相似度」当特征弃——违反在线零 token、贵、不可解释；上千维自动特征弃——样本太少必过拟合；只用「均价 + 成功率」两个数弃——峰谷、摊销、配额中断、归因错误全会进错账；`cache_hit_rate` 单独再加分弃——它已进成本预测，再加是重复奖励；任务类自由文本弃——类一散，所有 (m,w) 统计作废。

## C. 评分与权重

评分分四段：门闩过滤 → 层级收缩打分 → 确定性配额覆盖 → 输出三选项。

### C.1 层级收缩打分（小样本抗噪核心）

先算 Beta 后验（DS 臂），再套 Claude 臂的收缩形态（k=4）。

**版本先验 base_p**（F7 的归宿）：

```
base_p(m) = 该模型旧版本样本（version ≠ 当前版本）的衰减加权成功率
          = Σ_{旧版本样本} w_time·y / Σ_{旧版本样本} w_time   （y=1 成功，0 失败）
当前版本格的先验中心 p0 = base_p(m)；旧版本样本为空时回退 p0 = 0.5（中立）。
```

**样本权与后验**：

```
w_sample = w_version · w_time · w_conf
  w_version: 同版本=1；异版本样本不进当前格、只进 base_p（F7）
  w_time    = 0.5^(Δt/30天)（F6，base_p 与当前格同一衰减律）
  w_conf    = 归因置信度 0..1（来自 D）
α_eff = α0 + Σ w_sample(正样本)       β_eff = β0 + Σ w_sample(负样本)
α0 = p0·k0，β0 = (1−p0)·k0；k0 = 2（先验强度固定：继承家底只改中心、不改强度）
μ_raw = α_eff / (α_eff + β_eff)                                      (F2)
σ_raw² = α_eff·β_eff / ((α_eff+β_eff)²·(α_eff+β_eff+1))              (F4)
n_eff = α_eff + β_eff − (α0 + β0)                                    (F3)
```

**父级聚合（收缩锚点）**——一律**排除当前格 (m,i,w)**，避免当前格样本在 μ_raw 与父级重复计权；每条样本只属一个格、不重复计数；父级样本权同用完整 `w_sample`（= w_version·w_time·w_conf，见上）：

```
μ_model(m) = Σ_{样本∈该模型当前版本, 除当前格} w_sample·y / Σ w_sample
n_model(m) = 该模型当前版本、除当前格外所有格的有效样本量之和 Σ n_eff
μ_global   = Σ_{全部样本, 除当前格} w_sample·y / Σ w_sample
σ_parent   = 该模型当前版本、除当前格外各格 σ_raw 按 n_eff 加权平均
```

**空父级退化规则（冷启动必须写死，否则新模型/新工种第一单出 NaN）**：

```
μ_global 样本集合为空 → 取 0.5
n_model = 0 → Q_parent = μ_global（公式 (0·μ_model+k·μ_global)/(0+k) 自然给出）
σ_parent 加权集合为空 → 取当前格先验 σ = √(α0·β0/((α0+β0)²·(α0+β0+1)))
                        （α0=β0=k0/2=1 时 = √(1/12) ≈ 0.289）
```

**层级收缩（Claude 臂形态，k=4）**：

```
Q_parent = (n_model·μ_model + k·μ_global) / (n_model + k)   # 模型全工种 → 全局均值
μ_shrunk = (n_eff·μ_raw + k·Q_parent) / (n_eff + k)          # 本格 → 模型全工种，k=4
σ_shrunk = (n_eff·σ_raw + k·σ_parent) / (n_eff + k)          # σ 同式收缩
```

**三个代入例**（设无旧版本 → p0=0.5、k0=2 → α0=β0=1；父级 Q_parent=μ_global=0.5；样本权全为 1）：

| 情形 | α_eff/β_eff | μ_raw | n_eff | μ_shrunk | 结论 |
|---|---|---|---|---|---|
| 零样本 | 1/1 | 0.500 | 0 | (0+4·0.5)/4 = **0.500** | 直接落在父级 Q_parent |
| 1 单成功 | 2/1 | 0.667 | 1 | (1·0.667+4·0.5)/5 = **0.533** | 单样本只抬约 3 分，掀不翻 |
| 5 单全成功 | 6/1 | 0.857 | 5 | (5·0.857+4·0.5)/9 = **0.698** | 自身权重 5/9≈56%，本格接管 |

最终分（在线纯算术，每项可单独打印解释）：

```
Score(m,i,w) = μ_shrunk − λ_risk·σ_shrunk + λ_p·P + λ_c·cost_util
cost_util = 1 − (log1p(c) − min_log) / (max_log − min_log)   # 候选集内 min-max，有界 [0,1]
min_log = min(log1p(c))，max_log = max(log1p(c))；max_log == min_log 时 cost_util = 0.5
默认权重（人可调）：λ_risk=1.0, λ_p=0.2, λ_c=0.15
```

**成本是选型特征（约 0.15 小权重进打分影响排序），永不做闸门**：`cost_util` 有界 [0,1]，成本项最多 ±0.15、不可能压倒质量项（0–1）；超支只呈现不拦截；真正「通道不可用」是 F15 门闩的事实问题，不是「太贵」的评分问题。

### C.2 权重只人改

权重初值写进 `policy/weights.yml`，由人签字确认。`λ` 们**只由人改**，每次改动带 reason；离线 LLM 每月可**提议**改 `λ`（附证据），但必须走人合并才生效——在线路径始终确定、可复现、可追责。凑满「每类每模型约 30 单」之前不许自动改权重；禁令、预算、探索保底、门闩永远不在演化范围。

### C.3 确定性配额探索（替换 epsilon-greedy）

**常规打分之后执行配额覆盖**：门闩通过集合里，若存在 `shortfall>0`（F8）且本单 eligible（低风险、可逆/可沙箱），本单**默认项强制**从缺口集合轮转出，不按分数：

1. 先选缺口最大的；
2. 同缺口选 `c` 最低的；
3. 仍并列用稳定哈希 `hash(job_id ‖ model_id)` 定序——**确定性、可复现，无任何随机数**，记 `reason=quota_explore`。

探索让路（不触发覆盖）的条件只有：**高风险单、禁令命中、上下文放不下、真实通道不可用**——预算/价格不让路。缺口记下来，下一单低风险再补。新模型/低分模型因此永远有翻身样本，不存在饿死或死刑。

### C.4 三选项输出（对接 AskUserQuestion）

选型脚本输出三个选项供用户点选：

- **A 默认推荐**：配额覆盖触发时 = 确定性轮转出的缺口模型（`reason=quota_explore`）；否则 = Score 最高者（`reason=highest_score`）。附各项得分明细与 reject 原因。
- **B 自选**：用户自己挑一个 → 记 `job.override` 事件，喂 F9 用户偏好 `P`。
- **C 尝鲜**：用户主动试新/低分模型（额外探索意愿）→ 记 `job.explore` 事件，**不进 `P`**（选择不算偏好），但其**结局**照常进 `Q`（结果仍是能力证据）。C 是用户可选通道，**不替代也不抵消 A 的强制配额覆盖**。

**特征归宿总表**（F1–F18 各自去哪，实现据此唯一重放）：

| 特征 | 归宿 |
|---|---|
| F1 禁令 | 门闩（剔除，不进分） |
| F2 μ | 进 `μ_raw` → `μ_shrunk` → Score |
| F3 n_eff | 进收缩权重与 σ，间接进 Score |
| F4 σ | 进 `σ_shrunk` → Score（风险折扣） |
| F5 分组先验 | 进 `Q_parent`/`σ_parent`（收缩锚点），间接进 Score |
| F6 新鲜度 | 进 `w_time` 样本权 → α_eff/β_eff |
| F7 版本折扣 | 进 `w_version` 样本权 / base_p |
| F8 缺口 | 进 C.3 配额覆盖，不进 Score |
| F9 偏好 | 进 Score（+λ_p·P） |
| F10 成本 | 进 `cost_util` → Score（+λ_c） |
| F11 缓存命中率 | 进 `c` 的 metered 预估，不进单独分项 |
| F12 token 画像 | 进 `c` 预估，不进单独分项 |
| F13 速度 | **仅进月报呈现，不进选型分**（DS 原卷最终 Q 亦不含速度项）；日后要入分须补有界效用+权重走人改 |
| F14 上下文适配 | 门闩（放不下剔除） |
| F15 可用性 | 门闩（离线/忙/故障剔除） |
| F16 配额剩余 | 进 `c` 预估 + 触发 `job.handoff`，不进 Score |
| F17 浪费风险 | 修正 `cost_util`（有界，`max(cost_util, 0.7)`） |
| F18 摊销 | 进 `c` 的 alloc 部分 |

**被弃盲答方案（一句话理由）**：Thompson 采样弃——随机抽样破坏确定性与可复现；epsilon-greedy 随机探索弃——随机、难复现，改为确定性配额（用户拍板）；在线逻辑回归/学习权重弃——每格 1–5 样本远不够且黑盒不可解释；Elo/TrueSkill 弃——任务不是两两对决、配对稀疏无法收敛；纯频率均值/点估计弃——1 样本即 0/1 或 100% 垄断该类；字典序「先最便宜」弃——忽略返工其实更贵、摊销会被账面价骗；探索做成 `S += bonus/√n` 弃——与成本项缠一起看不懂、权重一演化探索会被学没；自动演化权重直接写回弃——数据侵蚀政策。

## D. 归因机制

回答的问题只有一个：这单的失败/超支成本，有多少该记到模型头上。**钱立刻记，能力债等归因**——成本本身永远入现金账，归因只决定「算不算模型的能力账」。

### D.1 三本账分离 + 责任分解

| 账本 | 记什么 | 是否等归因 |
|---|---|---|
| 现金/经济账 | 所有 `usd_cash` / `usd_economic` | 否，立记。钱花了就是花了 |
| 模型能力账 | 净成功 / 净失败 / 冷却 | 是，用最终归因 |
| 系统质量账 | `brief` 率 / `coord` 率 / `env` 率 | 是。给人类看协调者与任务书，不进模型 Score |

归因主类四枚举（拍板不变）：**模型能力 `model` / 任务书缺陷 `brief` / 协调失误 `coord` / 环境中断 `env`**。混合责任用**责任向量**无损入两本账（Grok 原卷 mixed + share_model 的语义）：

```
attribution = {
  model_share, brief_share, coord_share, env_share: 0..1,
      不变量：四份额和为 1；四份额全 0 是唯一合法例外（= 待定 unknown，须 confidence=low）,
  overrun_attr: model | brief | coord | env | null,   # 超支归因，独立于失败责任向量
  confidence: 0..1,
  evidence: [event_id...],
  why: 人读
}
```

- 纯 `model` 失败 → `(1,0,0,0)`；纯 `brief` → `(0,1,0,0)`；混合 → `model 0.3 + brief 0.7` = `(0.3,0.7,0,0)`。
- `overrun_attr` 独立：失败责任向量 `(0,0,0,1)`（env）+ `overrun_attr=model` = 「失败是 env、超支是 model」。
- **待定 `unknown`**（判不出）不是第五个落地类：四份额全 0 + `confidence=low` 标记待定，**不进净指标、只进生指标**，宁可少学不可乱罚。

| 份额 | 入账 |
|---|---|
| `model_share` | 能力账负样本 × 份额，记该 `(m,i,w)` |
| `brief_share` / `coord_share` | 系统质量账，不罚工人模型 |
| `env_share` | 整单不入能力账（钱仍入现金账） |
| 待定 `unknown`（四份额全 0） | 不进净指标，只进生指标 |

成功合并 → 能力账正样本，记给最终合并作者；中途接手且成果被保留者按贡献份额记正样本。

**事件例（L0/L1/L2/attr.* 同一 schema）**：

```
# 例 1：换模型同时改任务书才通过（L0 规则 7）
{ "type": "attr.rule", "model_share": 0.3, "brief_share": 0.7, "coord_share": 0, "env_share": 0,
  "overrun_attr": null, "confidence": 0.9, "evidence": ["<handoff>", "<job.closed>"] }

# 例 2：失败是环境中断、超支是模型空转（L1 判出）
{ "type": "attr.llm", "model_share": 0, "brief_share": 0, "coord_share": 0, "env_share": 1,
  "overrun_attr": "model", "confidence": 0.85, "evidence": ["<厂商状态页失败>", "<meter 异常>"] }
```

### D.2 判官结构：L0 规则打底 → 换厂商单判官 → 定罪/低置信升级 → 人终裁

```
L0  规则归因（close.mjs，零 LLM，每单必跑）
L1  单判官（换厂商，仅 L0 判不出时出动）
L2  第二判官（定罪 或 低置信 时升级）
L3  人类终裁（两判官冲突 / 高利害 / 用户主动改判）
```

**L0 规则清单（可解释、写死在 `close.mjs`，按第一条命中即停）**：

1. `handoff.reason=quota` 且后继同类一次通过 → `env`（配额耗尽不是能力）。
2. 连续启动失败 / 无任何 meter / 厂商状态页失败 → `env`。
3. 任务卡 `task_class` 关单时被人类改过，且改前模型本就禁入新类 → `coord`。
4. 开单后短时间内人类大幅改需求（新增验收项 ≥3 或改 class）→ `brief`。
5. 工人产出通过了任务卡验收清单、人类仍要求返工 → `brief`（验收没写全）；验收清单为空 → `brief`（任务书不合格，模型不被罚）。
6. 换模型、未改任务书即一次通过 → 对源模型标 `model`（换人就好 = 能力/适配）。
7. 换模型、同时改了任务书才通过 → 混合责任向量 `(model 0.3, brief 0.7, coord 0, env 0)`。
8. 超支且 cache 命中率异常低（低于该模型历史 p20）且是长上下文续作 → `coord`/`brief`，标低置信、留 L1。
9. 其余返工或超支 → 待定 `unknown`（`confidence=low`），升级 L1。

L0 输出必须引用它用过的事件 id，不允许写「感觉是模型不行」。

**L1 单判官（换厂商）**：只对 L0 判不出的失败单出动。判官**必须是与工人不同厂商**的判断类模型（判官选型本身也走点将台，工种=判断）。**无跨厂商判官可用时不降级调用同厂商**，直接标待定 `unknown` 或升级人类终裁 L3。输入=冻结证据包（任务书终稿、L0 结论、事件时间线、验收清单 vs PR 变更摘要——脚本先 diff，不让 LLM 自己翻仓库）。输出=`责任向量(model/brief/coord/env 四份额) + overrun_attr + confidence + 引用证据 + 人读 why`（L0/L1/L2/attr.* 用同一 schema）。一次调用，禁止多模型投票。

**L2 第二判官（升级条件）**：以下任一触发——① L1 的 `model_share > 0`（准备给模型记负样本，定罪必须复核）；② `confidence < 0.8`（低置信）；③ 用户/协调者争议。第二判官换**另一家**厂商独立复核：一致则采纳，不一致升级人终裁。

**L3 人类终裁**：两判官冲突、金额超阈值且 `model_share>0`、同一模型 7 天内将吃第 2 个 `model_share>0` 失败（冷却将触发）、用户在 PR 里直接改判。人写 `attr.human`，最高优先级。

### D.3 判错怎么纠

纠错是**追加，不改历史**：`attr.retract` 指向被撤事件 + 新的 `attr.human` 标签。重放时被 retract 的归因当作没发生，净特征从零算，冷却若仍生效立即解除。已用错误归因做出的历史选型不改写（当时解释仍真实）。每月抽少量未争议归因给人盲审，判官的被推翻率入它自己的「判断」工种 Q——判官自己也在被点将台打分。

### D.4 成本怎么控

只对**走到结论**的单归因；环境中断单直接跳过（连包都不组）。成功合并靠 L0 直记正样本、不花 LLM。归因包 token 封顶（约 2–4k/单），默认用便宜判官，升级才用贵的；夜间批量共享上下文。每月报告列出归因总 token/成本，让人看见这块开销。

**被弃盲答方案（一句话理由）**：全记模型头上弃——任务书/环境/协调失误会污染能力账、选型冤案；全不记模型头上弃——能力差无法显现、系统退化成纯比价；每单都 LLM 复盘弃——违反便宜约束、判官有厂商偏见、不可复现；三家投票归因弃——成本乘三、出现 A 评 B/B 评 A 循环背书；协调者自己写归因弃——既当运动员又当裁判、coord 类错误系统性消失；只规则或只人弃——规则覆盖不了语义失败、只人则用户天天被问。

## E. 防过期与防绕过（轻量版）+ 事故账

两件事：记录与现实脱节怎么发现、协调者拍脑袋派单怎么拦。都用「门闩 + 告警 + 拒绝入账」，不靠道德劝说，也不上重型中心服务。

### E.1 决策票（防绕过的主闸）

选型脚本每次输出附 `decision_id = hash(全部输入特征快照 + 选中项)`，任务卡/PR 正文**必须贴票**。审计作业扫描所有任务 PR：

- 无票、或票不可复算（任何人可重跑同一确定性函数核对）→ 开「规则违例」issue；
- 同一条规二犯 → 升级为模板必填项 + 自动检查（沿用本仓既有升级规矩）。

派单事件存完整特征快照，任何人任何机器可重跑验证「当时的推荐确实是这个输出」——绕过在技术上做得到，也能被当场识破。拍脑袋的正当出口本来就在系统里（B 自选 / C 尝鲜位），绕过没有任何收益只剩成本。

### E.2 价目探针（终端金额当外部探针）

工人终端已经在实时显示金额，拿它当价目保鲜的探针：`ingest.mjs` 解析终端的 `(token_in, token_out, cache_hit, usd_shown)`，用当前价目重算 `usd_expected`，偏差 >15% 连续两次 → 写 `audit.stale`、该模型价目标 `suspect`。`suspect` 期间选型取 `max(政策价, 终端换算价)`——**宁可高估不可低估**。发现涨价最便宜的办法，不必爬厂商官网。

### E.3 每日审计（零 LLM）

重放 `ledger/` 重生成 `derived/` 并与提交版本 diff；扫描 PR 围栏块与事件账对账（A.5）；退役模型仍被新派单 → `audit.bypass`；某 `(m,w)` 证据老化超阈值仍靠历史高分赢单 → 质量效用打回先验；悬单（派单后 N 天无关单事件）→ 报警补结论或判环境出账。

### E.4 事故账：incident 事件类型 + 看门狗

`incident` 事件类型承载事故账，三字段（issue #443 拍板：machine 场 = 指纹 + 处置枚举，人场 = why 一句）：

- **machine 字段**：工位/终端标识。
- **错误指纹**：来自实时探针的当前状态，不是对历史叙述的关键字匹配（后者已被实战证假阳性）。
- **处置枚举**：交卷收卷 / 报错续命一次 / 连续同指纹换人 / 升级协调者 / 升级用户 / 挂账待补。
- **why**：一句人读说明。

**因果顺序是「先探测、后入账」**：实时探针发现状态迁移 → 追加 `incident` → 处置与报表作为 incident 账的纯函数。看门狗不是从 incident 反向推导事故，否则首例事故会漏记、形成循环依赖。

实时探针的输入（issue #442 后续拍板，全部写进 `scripts/watchdog.mjs`）：

1. `orca worktree ps --json` 的 `agents[].state`（working/done/interrupted + lastAssistantMessage）——工人实时状态**真相源**；`waiting` 态即报警（有弹窗/等输入的官方信号），协调者第一动作是发一记回车放行或读屏辨弹窗。
2. **整屏内容哈希三轮不变**判停摆（全屏 TUI 通吃；禁用 cursor 停滞作唯一信号——对 alt-screen 天然失效）。
3. `exited` 且非完工态**独立报警**（与交卷/报错分开）。
4. **错误指纹清单即时报警**（与「活动消失」分开）：`Error:` / `Retry failed` / `terminated` / `login rejected` / `stream disconnected` / `no serving account` / `Reconnecting.*5/5` / `Selected model is at capacity` / `try a different model` 等，append 一行即生效。

**分诊三分支（写死）**：交卷 → 收卷；报错 → 原地续命一次（注入续命指令/输入框补回车）；**同一已知错误在原地续命一次后再次出现** → 换人不救。

**两个阈值各管一件事，互不降格**：「整屏哈希三轮不变」只负责**无已知错误指纹的静默停摆**（全屏 TUI 干活时状态栏 token/费用/计时在变、哈希必变）；「指纹两连同换人」指**同一已知错误续命一次后再现**才换人——不是把三轮哈希降回两轮。对应 issue #442（看门狗：沉默被当「还在跑」）与 #443（教训落库机制：错误指纹进看门狗清单、静态判据进 dao-check、感知判断进常驻注入面）的拍板。

### E.5 唯一合法绕行口

只有用户点「自选/尝鲜」能偏离默认项，且必须记录为事件。任何不能回溯到「默认项 | 用户覆盖 | 合法探索槽」的派单都是违规。禁令、预算、权重只有人能改；协调者无权自改规则。

**被弃盲答方案（一句话理由）**：中心服务器发令牌 / 重型 credential broker 弃——换机、离线、git 原则全破，本规模不需要（用户拍板轻量版）；每次派单让 LLM 自检「我有没有违规」弃——自己审自己、贵、会被提示词绕过；爬厂商定价页做权威弃——页面不稳、要解析、有时登录墙，终端金额已是更近的探针；发现脱节就自动改 `policy/models.yml` 弃——政策是人的，自动改价等于把数据写进门闩；区块链/签名链弃——git 追加事件 + CI 重放已够，再加共识是演戏。

## 与既有拍板的差异清单

三处由盲考四臂一致推翻既有方案，用户 2026-08-14 逐项采纳：

| 既有拍板 | 本稿 | 依据 |
|---|---|---|
| epsilon-greedy 随机探索 | 确定性配额探索（缺口强制覆盖 A 默认项 + 任务 ID 哈希轮序） | 盲考四臂一致 + 用户 2026-08-14 拍板 |
| Laplace 简式评分 | 层级收缩（k=4，本格 → 模型全工种 → 全局均值） | 同上 |
| GitHub-as-ledger（账本全写 PR 正文） | 混合账本（一事件一文件真相源 + PR 人读镜子 + 每日对账） | 同上 |

连带一处：Grok 臂的「预算硬顶」按既有拍板弃——成本只做约 0.15 小权重有界特征进打分，超支只呈现、永不做闸门（正文 B.1/C.1/C.3 已同步：预算/价格不剔除候选、不让路探索）。

全票一致、直接进稿的六条（issue #438）：事件溯源纯函数重算；硬禁令 = 门闩先于评分且仅用户可写；权重仅人改、LLM 只提议；归因分层（规则前置零成本 → 单判官换厂商 → 定罪/冲突才升级）；模型升级旧账降格为先验；机器数值与人话分仓。

一处按 Grok 原卷补全（非改拍板）：归因主类仍是拍板四枚举，但恢复 Grok 原卷的混合责任语义——以责任向量 `(model_share, brief_share, coord_share, env_share)` 无损入两本账、`overrun_attr`（超支独立归因）、`unknown`（待定不进净指标）——四枚举只说「责任主类」，不说「份额」与「失败/超支分离」，不补全会把混合责任硬掰成四选一、记错净账。
