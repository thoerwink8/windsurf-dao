# 点将台设计综合稿

> 本稿是「点将台」（多模型派单的记账与选型算法）的五方盲答合成稿。四份盲答（DS / Claude / GPT / Grok）与既有方案对照后，由用户在 issue #438 逐项拍板；本稿只做合成，不改取舍。合成口径与「和既有拍板有什么不同」见文末两张表。

## 总纲

点将台 = 一个「仓库内一事件一文件的 git 真相账 + 门闩先于评分的确定性选型纯函数 + 层级收缩打分 + 确定性配额探索 + 规则前置/换厂商单判官升级/人终裁的归因 + 决策票审计的轻量防绕过」系统：在线派单只做查表与四则运算、毫秒级零 LLM，LLM 只出现在每单结束后的离线归因点。

## A. 存储形态：混合账本

真相源是仓库内**一事件一文件**的 append-only 事件账；draft PR 正文只做人读镜子；物化层可丢可重算；三者靠每日对账互验。

### A.1 三层结构（政策 / 事件 / 物化三分）

| 层 | 目录 | 格式 | 谁写 | 性质 |
|---|---|---|---|---|
| 政策层 | `policy/` | YAML | 人类独占写 | 门闩与初值：禁令、预算、权重、探索配额、套餐合同、模型目录 |
| 事件账 | `ledger/` | JSON，一事件一文件 | 脚本按类型追加 | 唯一真相源，只增不改 |
| 物化层 | `derived/` | JSON | 脚本整文件重写 | 事件账的纯函数，可丢可重建 |

- `policy/models.yml`：模型目录、计价（含峰谷阶梯）、订阅套餐、退役标记。
- `policy/bans.yml`：硬禁令 `(模型, 身份?, 工种?) → 禁`，命中即拒、不进打分，仅用户可写。
- `policy/weights.yml`：权重初值、探索保底单数、冷却时长。
- `ledger/events/<seq>-<uuid>.json`：一事件一文件，事件类型闭集（见下）。
- `derived/features.json` / `quotes.json` / `scores.json`：物化产物，选型只读这些，不扫全账。

**事件类型（闭集，加类型先改 schema）**：`job.opened`（任务卡快照 + 候选 + 选中 + 解释串）、`job.dispatch`（实际启动的模型 + 终端 + 价目快照）、`job.meter`（token 进/出/缓存命中 + 金额）、`job.handoff`（A→B 接手及原因）、`job.closed`（终态 + 总金额 + 是否返工）、`attr.rule`（L0 规则归因）、`attr.llm`（单判官归因）、`attr.human`（人类终裁）、`attr.retract`（纠错，指向被撤事件）、`policy.patch`（政策变更摘要）、`sub.usage`（套餐剩余配额快照）、`incident`（事故账，见 E）、`audit.bypass` / `audit.stale`（审计发现）。

### A.2 三铁律（多机零冲突）

1. **一写一文件、文件名唯一**：`events/<seq>-<uuid>.json`，seq 单调、uuid 全球唯一。两台机器同时干活写的是不同文件，git merge 等于求并集，永不冲突。
2. **写一次即不可变**：spec / verdict / trace 都是「临时文件 + 原子 rename」一次性落盘，之后永不编辑；纠错另立新文件（`attr.retract` / `verdict.correction-N.json`），不覆盖历史。
3. **派生产物可重算**：`derived/` 是事件的纯函数。两台机器各自编译出不同版本若冲突，解决方式 = 删掉重跑（结果确定性相同），永不手工 merge。

### A.3 写权矩阵

| 文件 | 人类 | 协调者 LLM | 在线选型脚本 | 采集/关单脚本 | 归因 LLM |
|---|---|---|---|---|---|
| `policy/*` | 独占写 | 禁止 | 只读 | 只读 | 禁止 |
| `ledger/*` | 只追加纠错/终裁 | 禁止 | 只追加 `job.opened/dispatch/handoff` | 只追加 `meter/closed/attr.rule/sub.usage` | 只追加 `attr.llm` |
| `derived/*` | 禁止手改 | 禁止 | 只读 | 整文件重写 | 禁止 |
| draft PR 正文 | 可改任务卡 | 可改任务卡 | 写「选型块」 | 写「计量块」 | 写「复盘块」 |

协调者 LLM **没有**政策写权、事件账改写权、物化写权。它只能：填任务卡、调用选型脚本并执行其输出、把脚本输出原文贴进 PR。

### A.4 draft PR 正文 = 人读镜子（围栏块契约）

PR 正文承载任务叙事（目标/验收/进展），任何模型读它就能接手。账不在 PR 里——账在 `ledger/`。PR 里嵌三段机器可解析围栏块，作为「镜子」：

```markdown
<!-- ledger:job v1 --> ... 任务卡（job_id / task_class / 规模 / 风险） ... <!-- /ledger:job -->
<!-- ledger:select v1 --> ... 选型脚本完整 stdout ... <!-- /ledger:select -->
<!-- ledger:meter v1 --> ... 终端采集的最新一行 ... <!-- /ledger:meter -->
```

### A.5 每日对账互验

夜间 CI（零 LLM）：① 重放 `ledger/` 重生成 `derived/`，与提交版本 diff，不一致即红；② 扫 PR 围栏块，与事件账里的 job_id / 选中模型 / 累计金额比对，对不上则认定「镜子破了」，只信账、补写围栏块。选型脚本启动前若发现 `derived/` 比账旧超过 6 小时且中间有关单/归因事件，先强制 `recompute`（确定性、便宜）再给结果。

**被弃盲答方案（一句话理由）**：单一 SQLite / 中心库弃——违反「进版本管理、换机不丢」且要运维中心服务；一个大 `state.json` 原地改弃——并发必然丢更新、merge conflict；账本全写 PR 正文弃——自由文本无类型、可被 force-push 改写，做不了确定性算术；单一 JSONL 追加弃——追加同一文件天然有并发冲突；评分快照 commit 弃——派生物可重算，两机重算即冲突属冗余。

## B. 特征函数清单

评分对象是三元组 `(m, i, w)` = 模型 × 身份（帅/协调者/工人/审官）× 工种（写码/判断/查证/审查/UI/…，`work_types` 可增枚举）。所有特征只允许**数值或枚举**，算法不读任何自然语言——「为什么」只进 `why` 字段和 PR 正文。

主干沿用 DS 臂的 F1–F15，两处按拍板改造：F8 探索由「UCB 加分」改为「配额缺口」（探索移出打分，见 C）；F10 成本并入 GPT 臂的订阅摊销公式与 Grok 臂的套餐配额/浪费风险。新增 F16–F18 承载套餐特征。

| # | 特征 | 定义 | 公式/取值 | 数据来源 | 更新时机 |
|---|---|---|---|---|---|
| F1 | 硬禁令 `B` | 枚举{放行/禁} | 查 `bans.yaml`，命中 `(m,w)` 或 `(m,*)` 即禁 | bans.yaml | 人改策略时（门闩，先于一切评分，数据不可侵蚀） |
| F2 | 技能均值 `μ` | 预期成功率 | Beta 后验均值，见 C | verdict 样本 | 离线归因后 |
| F3 | 有效样本量 `n_eff` | 证据强度 | 衰减后有效样本和 | verdict | 离线归因后 |
| F4 | 不确定性 `σ` | 后验标准差 | `σ² = α_eff·β_eff / ((α_eff+β_eff)²(α_eff+β_eff+1))` | verdict | 离线归因后 |
| F5 | 分组先验 `g` | 收缩锚点 | 本格向「模型全工种均值」收缩，再向「全局均值」收缩，见 C | scorebook | 编译时 |
| F6 | 新鲜度 `r` | 距最近样本的时间衰减 | `r = 0.5^(Δt/30天)` | verdict 时间戳 | 派单时现算 |

| F11 | 缓存命中率 `h` | 输入缓存占比 | EWMA：`h ← 0.9·h + 0.1·(cache/(prompt+cache))` | 工人终端上报 | 实时/收单后 |

| F15 | 可用性 `a` | 枚举{空闲/忙/离线} | 心跳超时判定 | 工人终端心跳 | 实时（门闩） |

### B.1 门闩特征（结构过滤，先于评分）

F1（硬禁令）、F14（上下文放不下）、F15（离线/忙）是**门闩**，不进加权：命中即剔除，被剔模型仍在输出里标注拒因。成本可做预算门闩（超硬顶）但**不做质量闸门**——成本作为 F10 进打分影响排序，超支只呈现不拦截（见 C、差异清单）。

### B.2 成本特征与订阅摊销

本单预估经济成本 `c` = 按量部分 + 订阅摊销部分，全部折算美元，峰谷**现算**：

```
metered = T_in·r_in(t)·(1−h) + T_in·r_cache(t)·h + T_out·r_out(t) + 固定费 + 预估溢出
r(t) = 基础价 × 峰谷乘数（registry 阶梯表，派单发生在几点就用几点的价）
```

订阅摊销沿用 GPT 臂公式，不把订阅当「边际成本为零」：

```
usage_unit = T_in(未缓存)·ref_in + T_in(缓存)·ref_cache + T_out·ref_out
在线预测摊销  alloc_hat = 月费 × usage_unit / forecast_total_usage_units_month
月底实际摊销  alloc     = 月费 × usage_unit / Σ(实际 usage_units_month)
无任何用量时，整笔月费记 unallocated_subscription_cost（不进任何单）
```

有硬配额的套餐用 Grok 臂的简化口径：配额内 `amortized_per_mtok = 月费 / included_tokens × 1e6`，配额外走 PAYG 溢出价；畅用包月用 `amortized_per_job = 月费 / fair_share_jobs`。`c = metered + alloc_hat`，预估配比用历史中位数、不用均值，抗单次爆量带偏。

`quota_left`（F16）供「配额耗尽可接手」：耗尽时写 `sub.usage` 并触发 `job.handoff`，源模型本段不记能力失败（见 D）。`waste`（F17）在**质量不低于该类中位数**的前提下上调订阅模型的成本优势（边际现金成本≈0），不打破禁令、不改门闩。

**被弃盲答方案（一句话理由）**：embedding/LLM 抽「任务相似度」当特征弃——违反在线零 token、贵、不可解释；上千维自动特征弃——样本太少必过拟合；只用「均价 + 成功率」两个数弃——峰谷、摊销、配额中断、归因错误全会进错账；`cache_hit_rate` 单独再加分弃——它已进成本预测，再加是重复奖励；任务类自由文本弃——类一散，所有 (m,w) 统计作废。

## C. 评分与权重

评分分三段：门闩过滤 → 层级收缩打分 → 确定性配额探索覆盖 → 输出三选项。

### C.1 层级收缩打分（小样本抗噪核心）

对每个 `(m,i,w)`：

```
q̂        = Σ 衰减正样本 / Σ 衰减总样本        # 本格原始成功率
Q_parent = (n_model·q̂_model + k·q_global) / (n_model + k)   # 模型全工种 → 全局均值
μ_shrunk = (n_eff·q̂ + k·Q_parent) / (n_eff + k)              # 本格 → 模型全工种，k = 4
```

收缩形态沿用 Claude 臂，k 取 4。样本少时向「模型全工种均值」借力，仍不足再向「全局均值」借力；`n_eff=1` 时自身只占 20%，单样本不可能把分数掀翻；约 5 单后本格数据接管主导。新工种零样本直接落在父级估计上，无需冷启动特判。

最终分（在线纯算术，每项可单独打印解释）：

```
Score(m,i,w) = μ_shrunk − λ_risk·σ_shrunk + λ_p·P − λ_c·ĉ
ĉ = c / median(c，候选集内)     # 成本归一化到 0~1 附近
默认权重（人可调）：λ_risk=1.0, λ_p=0.2, λ_c=0.15
```

**成本是选型特征（约 0.15 小权重进打分影响排序），永不做闸门**：超支只呈现不拦截；真正「通道不可用」是 F15 门闩的事实问题，不是「太贵」的评分问题。

### C.2 权重只人改

权重初值写进 `policy/weights.yml`，由人签字确认。`λ` 们**只由人改**，每次改动带 reason；离线 LLM 每月可**提议**改 `λ`（附证据），但必须走人合并才生效——在线路径始终确定、可复现、可追责。凑满「每类每模型约 30 单」之前不许自动改权重；禁令、预算、探索保底、门闩永远不在演化范围。

### C.3 确定性配额探索（替换 epsilon-greedy）

门闩通过集合里，若存在 `shortfall>0`（F8）且本单 eligible（低风险、可逆/可沙箱），本单**强制**从缺口集合选一个，不按分数：

1. 先选缺口最大的；
2. 同缺口选 `c` 最低的；
3. 仍并列用稳定哈希 `hash(job_id ‖ model_id)` 定序——**确定性、可复现，无任何随机数**。

high-risk 单、或预算只够最便宜者通过门闩时：探索让路给安全，缺口记下来，下一单低风险再补。新模型/低分模型因此永远有翻身样本，不存在饿死或死刑。

### C.4 三选项输出（对接 AskUserQuestion）

选型脚本输出三个选项供用户点选：

- **A 默认推荐**：Score 最高者，附各项得分明细与 reject 原因。
- **B 自选**：用户自己挑一个 → 记 `override` 事件，喂 F9 用户偏好 `P`。
- **C 尝鲜**：探索配额缺口最大/最饥饿者 → 记 `explore` 事件，**不进 `P`**（选择不算偏好），但其**结局**照常进 `Q`（结果仍是能力证据）。

**被弃盲答方案（一句话理由）**：Thompson 采样弃——随机抽样破坏确定性与可复现；epsilon-greedy 随机探索弃——随机、难复现，改为确定性配额（用户拍板）；在线逻辑回归/学习权重弃——每格 1–5 样本远不够且黑盒不可解释；Elo/TrueSkill 弃——任务不是两两对决、配对稀疏无法收敛；纯频率均值/点估计弃——1 样本即 0/1 或 100% 垄断该类；字典序「先最便宜」弃——忽略返工其实更贵、摊销会被账面价骗；探索做成 `S += bonus/√n` 弃——与成本项缠一起看不懂、权重一演化探索会被学没；自动演化权重直接写回弃——数据侵蚀政策。
