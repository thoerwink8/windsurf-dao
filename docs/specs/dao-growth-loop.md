## 一、诊断：为什么"好经验"落不下来

**根因是一个不对称**——今天 PR 全史复盘（237 个 PR 量化分析）实测坐实：

| | 触发器 | 结果 |
|---|---|---|
| **踩坑** | 出事了、返工了、用户骂了——**有痛感** | 会被记录：条款库 28 条几乎全是踩坑产物 |
| **做对** | 做完就过去了——**零信号** | 不会被记录，除非有人专门停下来说"这值得固化" |

**而那个"专门停下来的人"一直是用户。** 他累的不是打字，是**得先想起来该提醒**。

活证据（同日）：官们做对的三件事——拒绝编造派单令要求的错误映射（查码证其结构上不可达）、
发现 MERGEABLE 只证明无文本冲突所以合 main 后重跑整套、把测试从"断言建链"改成 before/after 全量快照
——**一条都没进 dao**，全停在项目层的 commit message 里。

同源实测：条款库 **28 条里带多例证据的只有 2 条**（93% 是 n=1 单例立法），
而最高频的两个病（漏发简报 ≥23 踩、停摆 ≥10 例）**合计只占 1-2 条**——立法密度与病灶频率完全脱钩。
根因同上：**立法有触发器（刚踩坑正在写复盘），退役与升格都没有触发器。**

## 二、闭环：三个零件

```
   项目里产出好实践  ──①收割──▶  升格进 dao  ──②备案──▶  铺回所有项目
          ▲                                                      │
          └──────────────── 新项目自动继承全部共性 ◀─────────────┘
                                    ③判据
```

### ① 收割（好实践 → dao）

**要解的问题**：好经验已经写在某处了（subagent 交付报告的"我超出要求做了 X"、帅的终审评语、PR body），
只是**没人去捞**。

**形态**：参数化 workflow `dao-harvest`（与今日固化的 PR 史复盘同款），扫这些来源，
产出**可直接粘贴的条款原文 + 该放哪层的判断**。

**触发点 ✅ 已拍板（2026-07-27，用户选「每次干完一大段活收尾时（推荐）」）**——**唯一触发点是长窗收官**：

1. **长窗收官**（既有必经仪式，唯一触发点）：收官段必跑一次收割。落地形态是
   **收官简报里的一个两态固定槽位**——`🌾 收割：已跑（候选 N / 入库 M / 落点 <文件>） | 未跑（<理由>）`，
   两态恰选其一、缺这一行视同收官未完成。判据正文：windsurf-dao `ccswitch/dao.md` 长窗节③
   （原文实查在案：「**收官段必跑一次好实践收割**……收官是长窗里唯一必经的『停下来』时刻，
   不挂在这里就只能靠谁想起来」——这句话本来就在，本次是把它立成唯一触发点并给了槽位形态）。
2. ~~**每 20 个 PR**（机器可判）~~ → **已废**。那个 20 是帅拍的、无任何实证依据（脚本头自曝在案）。
   `check-harvest-status.ps1` **不删但改语义**：从「到期判定」降级为**账实状态**——只报「上次收割在哪 /
   此后合并了哪些 PR / marker 多旧」，不给建议、无阈值，并在 `-Closing` 模式打印槽位模板与 marker 更新命令。
3. **用户纠正时**（最强信号，已在做）：用户说「你这样不对」「我希望」即触发落档，
   `docs/user-intent-log.md` 是这个机制的现役实例。

> ### ⚖️ 正面回答一个必须回答的问题：这是不是把「机器可判的坏判据」换成了「不可判的好判据」？
>
> **是，一半是——但两侧都不像这句话说的那么干净，逐条摊开：**
>
> **① 旧判据「机器可判」这一点是真的，但它判的不是这件事。** 它精确测量的是「攒够 20 个 PR」，
> 而收割要的是「刚有一批做对的事发生、还记得住」。两者之间**没有任何已验证的关系**（脚本头的调参
> 三问只答得出第①问，②③都写着「无从判断」）。**一个精确但测错对象的数字比没有数字更糟**：
> 它让人以为有护栏。所以这不是「用坏的换好的」，更像「拿掉一个装饰性的护栏」。
>
> **② 新触发点「机器不可判」也是真的**，「干完一大段活」确实是人的判断——正是本仓反复批判的
> 「无标记时刻的自由裁量」（实测携带率 9-24%）。**这个代价不打折地记在这里。**
>
> **③ 补偿：它挂在既有仪式的一个固定槽位上，不是挂在空气里。** 长窗收官不是无标记时刻——
> 它有开窗/心跳/25% 收官段/窗末简报这一整套既有动作，而收割被钉进**简报的一个槽位**。
> 本仓实测最强的两个非机检形态恰恰都是槽位：`[cc]` commit 前缀 719/719（`.git/hooks/` 一个钩子都没有）、
> subagent 身份铁律 68/68。槽位与自由裁量的区别是**「填的时刻眼前有没有一个空位」**。
>
> **④ 机器侧不撤，只降级为报事实。** 收官时 `-Closing` 跑一次就拿到素材（自上次收割以来的 PR 列表）
> 与照抄即可的 marker 更新命令；日常 verify-all 里它继续让 marker 陈旧度可见。
> **机器报事实、人判该不该做**——反过来（机器替人判「该做一件需要判断的事了」）只会逼出
> 为过闸而敷衍的执行，那正是本仓给观察线定的闸位哲学。
>
> **⑤ 未验证的部分照直说**：槽位档的携带率**本仓从未实测过**（只测过 `[cc]` 与 subagent 铁律两个
> 既有实例，那是回溯统计不是对新形态的验证）。这次改动是否真比「每 20 个 PR」更常被执行，
> **要等前几次长窗收官的实际记录**才知道。现在不得宣称它有效。

### ② 备案（dao 共性 → 每个项目）

**要解的问题**：现状是**两套并存，其中一套注定失效**——
- `dao-scaffold-check.js`（已挂 SessionStart）硬编码检查 CLAUDE.md / `.claude/rules/` / Tauri 两项 ✅ 不会失效
- `dao.md` 里两条「静默自检」文字条款要求 **AI 首次接触项目时自己想起来查** ❌ 无标记时刻的自由裁量，实测 9-24%
- 且检查项**硬编码在 347 行 JS 里**——加一条要改代码，所以没人加

**形态**：清单驱动。`scaffold-manifest.json` 列出共性 rule 及其**机器可判的适用条件**，
hook 读清单而非硬编码；dao.md 的静默自检条款全部迁进清单，只留一句指针。

**加一条共性 rule = 加一条 JSON，不改代码。**

### ③ 判据（什么算共性、什么值得升格）

**共性四分类**（回答用户的"区别于个性和共性"；`product-type` 是用户 2026-07-27 拍板加的第四类，
原为 §五 待拍板第 3 项）：

| 类 | 判据 | 例 |
|---|---|---|
| `universal` | 任何项目都该有 | `CLAUDE.md`、`.claude/rules/` 目录、`_tmp/` 进 gitignore、commit 前缀约定 |
| `conditional` | 检测到 X 则必须有 Y，**`when` 必须机器可判**（依赖名/目录/扩展名），禁写成需 AI 判断的描述 | 有 react/vue → `frontend-style.md`；有 src-tauri → `desktop-debugging.md` |
| `product-type` | 对**所有产品型项目**合理、对内部工具/基建仓不合理的中间态。**不得带 `when`**：条件由类别内建，判据是项目 `CLAUDE.md` 含「产品型项目」这一**自我声明**（opt-in、纯子串匹配、零 AI 判断） | `.claude/rules/pr-evidence.md`（PR 真机证据三态） |
| （不入清单） | 只对本项目有意义 | mousse 的「进程名固定 `mousse-app.exe`」「版本号四处一体」 |

> **为什么用「自我声明」而不是指纹推断**：「这算不算产品型项目」是语义判断，正是清单明令不收的
> 那一类。换成一句写在 `CLAUDE.md` 里的自陈之后，判据退回纯子串匹配。**失败方向刻意选漏报**
> （没写那四个字的产品型项目一律不查），与 `exempt` 的「多报」取舍相反——不适用的仓收到的是
> 纯噪音，而噪音会训练人忽略整个 hook 的输出。
>
> **「PR 必附真机截图」从个性反例升为产品型共性**，是本清单第一个「个性 → 共性」实例。
> 值得注意的是：**改判的不是判据，是那条规则本身**——原形态（必附截图）确实只对有 UI 的项目
> 成立；mousse-cli 同日把它改成「三态必填：见评论 / 豁免 / 降级挂账带真 issue 号」之后，
> 无 UI 面的产品型项目走态二即可，它才够格跨项目。**一条规则要升格，往往得先被改写成能容纳
> 差异的形态**，而不是原样搬上去。

**升格三判据**（收割时预筛用）：

1. **跨项目适用** —— 不依赖特定技术栈
2. **有实证** —— 做出来并验证过的，不是想出来的
3. **是形态不是判断** —— 能挂在某个必经动作上

> **第 3 条是硬门槛**（帅定）：今日实测形态类携带率 100%、判断类 9-24%。
> **只有形态类的好实践值得进 dao**，判断类的进了也只是笔记——
> 这也是同日给条款库加 `触发:` 字段的同一判据，两处必须一致。

**升格谁来批 ✅ 已拍板（2026-07-27，用户原话「小的我自己定，大的才问」）**：
**不再逐条送批，改按分档。**

| 档 | 分界判据（执行时要不要现场判断） | 例 | 谁定 | 标记 |
|---|---|---|---|---|
| **照做档** | 执行时**零现场判断**：跑哪个命令、填哪个字段、什么格式/前缀、写进哪个文件、按什么顺序。**可机械近似地测**——能不能写成一句「动作+对象+时机」的祈使句，且句中不含程度词与主观量词（充分/必要时/合适的/足够/尽量/酌情） | 「提交前跑 `scripts/verify-all.ps1`」「commit subject 以 `[cc]` 开头」「条款行尾带 `[n= @ 触发:]`」 | **AI 自定** | 行内必须带 `[自定@<月日>]` |
| **判断档** | 执行时**要现场取舍**：什么算够、什么时候停、要不要换方向、删什么留什么、哪个优先 | 「什么时候该停下来重新想」「这条条款该不该退役」「这个 skill 该不该删」 | **问用户** | 无 |

**两条否决项压过上面的祈使句测试**（命中即判断档，措辞多机械都不行）：
1. **它给 AI 自己定及格线**——验到什么程度算验完、几条算够、什么情况可以跳过。
   自己给自己划及格线是**结构性利益冲突**，与能力无关。
2. **它改用户可见面或不可逆**——用户会看到的产物形态（PR body 格式、交付措辞、命令表）、
   删除/发布/改配置源/退役某个入口。

**拿不准归判断档。** 用户交出这份授权时**自陈了失败方向**：「我可能把不该自主的归成自主」。
误判成「该问」只多问一次；误判成「可自定」会静默改变行为，而且没有任何时刻会把它推到他眼前。

> **⚠️ 为什么这个分界不能写成「大的/小的」**：篇幅、影响面、改几个文件——这些都要现场估，
> 而「估」本身就是判断，于是分界判据自己变成了判断档，等于没有判据。
> 「执行它的那一刻还需不需要取舍」是**对着条款正文就能答**的问题，且答案与谁在答无关。
> **它仍是近似**，两向都有反例：措辞机械但内里是取舍的（「验到足够即可」→「验到 3 组即可」，
> 仍是替用户定量，靠否决项①捞回）、措辞含糊但其实只有一种执行方式的（会被误判为判断档，
> 代价是多问一次，可接受）。

**回溯面（自定档的对价，与分档同时落地，不是后续再补）**：
- 每条自定项行内带 `[自定@<月日>]`（`docs/rules/dispatch-clauses.md` 📌 元字段节有字段说明）
- verify-all 的 `check-clauses-structure` 道（2026-08-02 起实现在 windsurf-dao
  `ccswitch/scripts/check-clauses-structure.ps1`，本仓入口 `scripts/check-clauses-gate.ps1`）
  统计段**每次运行必打印一次**：「AI 自定 N 条（条款区 X · 观察区 Y）」
  + 按日期分组的逐条行号 + 一行撤回说明。**观察线不设闸**（该不该自定是判断）
  （⚠️ 上一条里的「**本仓**」写于 mousse-cli，指的是**它**——按 `dao-officer-clauses.md`
  开头那条跨仓读法：条款/文档正文里的「本仓」指原出处的那个仓，不是你此刻所在的仓）
- 撤回方式：对帅说「**<月日> 之后你自定的全撤**」，按打印的日期分组删，**撤回不需要理由**
- **没有回溯面的自主授权等于不可撤销**——撤回的前提是知道有哪些

**这份回溯面自己的漏洞，写在这里而不是等人发现**：
- 机器只认「标记在不在」，**判不出分档判得对不对**——一条判断档条款被标成 `[自定]`，闸照样放行
- 「0 条」有两种读法（真没有 / 有人忘了打标），脚本分不开，输出里已写明
- 打标记这个动作本身仍是「无标记时刻的自由裁量」（只是它跟着写条款这个动作走，属槽位档）

**🔴 第一次量化结果（2026-07-27 夜，条款库加字段后的实测）**：

> **63 条顶层条款中 52 条是 `触发:无`（82.5%）。**
> **2026-07-24 建库后新立的 28 条里，27 条是 `触发:无`**——唯一例外是「`gh pr create` 撞 5xx 降级路径」（挂在 PR 流程）。
>
> 有触发的 11 条全部集中在四类载体：`模板首行`（subagent 身份铁律，68/68 实测）·
> `权限deny`（工具约束，读 settings.json deny 列表实证）· `verify-all` 四道机检 · `PR流程`。
>
> **这个数字就是本闭环存在的理由**：我们写的条款八成只提供判据、不提供触发点。
> 它们在事后核验与争议裁定时有价值，但**不该被指望改变行为**，也不该在有效性统计里被计入。

## 三、诚实边界

**完全自动不可能。** "这个做法值不值得固化"最终是价值判断，尤其"跨项目是否适用"这一条只有用户能拍。

能做到的是：**候选自动浮出、按判据预筛、给出可直接批准的形态**。
用户的动作从「想起来 + 判断 + 描述」缩到「看一眼 + 批/否」，且只在收割时批一次。

**本文档不承诺"以后用户再也不用提醒"**——那是笃定措辞。它承诺的是：
**用户不再需要充当"想起来"的那一环**，只需充当"拍板"的那一环。

### 裁定 A · 立「共性 rule 文件名契约」

**入清单 `_doc` 段作为原则声明**（不是又一条检查项）：

> 共性 rule 必须由**约定文件名**承载（如样式路线 → `.claude/rules/frontend-style.md`）。
> 内容可以项目化，**文件名不可**——跨项目自动核对的全部可能性都建立在文件名固定上。
> 若某项目已把该领域规范散在多个自定义命名的文件里，正确动作是**建一个约定名文件，
> 内容写成对既有文件的指针**（而非搬运，避免双份漂移）。

**理由**：不立这条，清单的每次「缺项」报告都是可争议的——被报方总能说「我有这个规范，只是文件名不同」。
而清单的价值恰恰在于**无需语义理解即可核对**。

### 裁定 B · 元仓库不再整体豁免，例外逐条显式声明

- 清单条目加可选字段 `exempt: [{repo, why}]`，`AGENT_GUIDE.md` 那条据此为 windsurf-dao 声明例外并写明理由（`dao.md:182` 引用它）
- hook 取消 `basename === "windsurf-dao"` 的整体 `done()` 早退，元仓库照跑模式 B

**理由**：**例外显式化 > 例外隐形**。现状是「检查从不跑到立法者头上，所以没人发现它自己违规」——
而一旦有了 `exempt` 字段，「哪些规则有例外、为什么」变成清单里可读的数据，
下次有人想删 `AGENT_GUIDE.md` 时会先看到理由。

### 裁定 C · rule frontmatter 共性挂账不立

**解冻条件：先验证 `paths:` 条件加载在当前宿主真的生效。**

**理由**：今天刚踩过「未验证就当兜底承诺」的坑（帅向用户宣称漂移检测器能报竞品 hook 复发，
经查其判据结构上跳过第三方 exe）。`paths:` 若实际不生效，立这条规矩等于要求所有项目
加一段无效 frontmatter——**先验证，再立法**。
