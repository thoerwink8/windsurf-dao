# dao 架构优化提案 · 202608（双路调研合成）

> 来源：2026-08-01 两路外向调研（官方生态 rules-arch-survey-official / 开源实践 rules-arch-survey-oss，均在 docs/research/）。
> 触发：用户问「dao 主线还能优化吗？模板方式走模板？参考市面最佳实践」。
> 本文件是**提案不是执行令**——逐条呈用户拍板后才动手。

## 一句话回答用户

**能优化，而且优化方向与直觉相反**：继续瘦身买不到遵守率（1650 会话实证：文件大小对遵守率无可检测影响）；真正的空白是**投递机制**——dao 只有「always-on 全量」和「用户手敲 skills」两档，中间的「由代码按路径/时刻判定注入」档完全空着，而那一档五大生态全有、Claude Code 原生支持（`.claude/rules/` 的 `paths:` glob）。「模板方式走模板」business 已部分做到且两格领先业界（scaffold 机检、条款元字段），欠的是第三格：门控类条款还写在文本里——实证遵守率 **0%**。

## 三个颠覆性发现（改变判断的）

1. **禁令写在文本里 = 不存在**（arxiv 2607.26819）：Refuse/Handoff 类规则 4 个前沿模型遵守率 **0%**，引原文、给反馈都推不动；agent 仅 3.5% 的运行打开过策略文件。**唯一有效路是 agent 外强制（hook/permissions/CI）**。dao 的 🔒 必止门控、自主边界、各种「禁止」条款全在此列。
2. **瘦身买不到遵守率**（arxiv 2605.10039，1650 会话）：文件大小/位置/架构/矛盾四变量对遵守率全部无可检测影响；**唯一显著杠杆是会话长度**（每多一个函数 -5.6%）。瘦身的正当理由是 attention budget 与信噪比，不是遵守率——已完成的 -28.8% 瘦身价值仍在，但别再往这个方向押注遵守率。⚠ 与 Anthropic 官方「大文件稀释遵守」说法存在未决张力（论文测试档位可能远小于 62KB），并置呈现不选边。
3. **「模型自己决定加载」是最脆的一环**（Vercel 四档实测）：Skill 默认触发率 44%、通过率 +0pp；8KB always-on 索引 100%。dao 的 skills 手敲机制歪打正着绕开此坑，**不该动**；该补的是「代码判定」档。

## dao 已领先业界的三格（调研确认，不动）

- **条款元字段**（`[n=][基线:][自定@][触发:]`）：生命周期字段是全行业空白，dao 领先任何公开规范
- **scaffold-manifest 跨项目机检**：业界无对应物
- **派单令首行强制 Read 条款库**：subagent 不继承 CLAUDE.md 是官方硬事实（issue #62944），这是唯一下发通道；且 Quote 条件实证把遵守率从 17-40% 推到 76-77%

## 行动方案（合并去重后 P1-P8，按实证强度×成本排序）

| # | 方案 | 实证 | 工程量 | 拍板点 |
|---|---|---|---|---|
| **P1** | **门控出文本层**：🔒 必止门控/自主边界/「禁止」类逐条改由 hook（exit 2 阻断）/ permissions deny / CI 强制，dao.md 只留一行指针 | ★★★（0%→hook 档 ~100%，双路一致） | 中（逐条写 hook；难机判的退化为宽 hook「拿不准即问」） | 哪些门控先做（清单呈审） |
| **P2** | **补作用域档**：有路径锚点的条款下沉 `.claude/rules/*.md + paths:`（PR 流程→`.github/**`、守卫→`scripts/**`、设计→`design/**`、隔离→`crates/**`、前端→`src-ui/**`） | ★★（五家生态全有+官方原生；零量化研究） | 中；**必须先造 canary 规则验机制**（#17204：paths/globs 不一致、不加引号静默失败） | 下沉清单呈审 |
| **P3** | **死闸检测**：扫 hook/permission 指向脚本存在性 + 机检档条款的检查器真跑过 | ★★（ctxlint 同构；dao 本窗刚实证 isMetaRepo 漏跑） | 极低（一个脚本） | 无（照做档可自定） |
| **P4** | **字节硬闸**：always-on 面（dao.md+无 paths 的 rules）设字符上限，超限即红——「一进一出」自动成立 | ★★（Windsurf 物理封顶先例） | 低；**必须排 P2 之后**（先有出口再设闸，否则是堵不是疏） | **闸值必须用户定**（AI 自划及格线命中否决项①） |
| **P5** | **dreaming 式离线整编**：收割扩「合并重复/标记过期/重组」半边，产出 **diff** 交用户 approve | ★★（Anthropic Dreaming 形态；Harvey 6× 系厂商自报不作依据） | 中；两护栏：产出是 diff 不是覆写、改一条必须引具体 case | 每次整编结果拍板 |
| **P6** | **条款结构化混合 + 按官种渲染**：元字段/官种归属进 YAML（机器面），叙事留 Markdown（人读面）；派单时渲染出只含该官种条款的一份 | ★★（渲染=Quote 条件 76%；JSON 比 Markdown 更少被乱改是官方实测） | 大；分两步走 | 第一步范围呈审 |
| **P7** | **会话长度治理升格**：短会话接力+HANDOVER 从「偏好」升「硬判据」（可量化：窗内产出函数/文件数超阈值即建议收窗交接） | ★★★（唯一被测出的遵守率杠杆 -5.6%/函数） | 低（判据+简报槽位） | 阈值形态 |
| **P8** | **AGENTS.md 生成式派生**：从同一真相源生成（不手写第二份），让 Codex 等其他宿主可消费 | ★（事实标准 60k+ 仓库） | 低 | 要不要做 |

**观望**：条款消融测量（需评测集，dao 没有）、skills 自动路由（误触发重仪式的风险）、账本机器面 JSON 化（可能已被 issue 中枢覆盖）。
**明确不做**：为遵守率继续瘦身（S9，强零支持）、加强措辞（AGENTIF 行业地板 <30% + 措辞微调大摆动）、全面检索式加载（Vercel 44% 反证）。
