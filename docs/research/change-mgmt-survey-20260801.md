# 四步执行验证流程 · 业界对照与改进建议（外向调研归档）

> 2026-08-01 · 触发：用户固化「拍板→逐项测试→可回退→最终全量测试」四步后问「这是不是最佳实践，帮我改进」。
> 调研官结论先行：**四步骨架与业界主流高度一致，但有一个共同的结构性偏差——四步全部是「串行的一次性动作」，而业界近十年的演化方向是把同样的四件事「挂到必经的自动闸上、并前移」。**②③是实证最强的两条，①最易被误读为反模式但可调和，④位置错了（业界前移成合并门）。
> 由帅从交付通知转录落盘（tasks/*.output 恒 0 字节）。完整出处 URL 见文末 Sources。

## 一、四步逐条对照（摘要）

### ① 拍板先行
- **支持**：Claude Code 官方 plan-first 工作流（「让 Claude 直接跳到写码会产出解决错问题的代码」）；plan-first 解的是「AI 解错问题」这个高频昂贵失败模式。
- **挑战性证据（DORA）**：「没有证据支持『更正式的外部评审流程与更低的变更失败率相关』」；有正式外部审批机构的组织 2.6 倍更可能是低绩效者。失效机理：外部审批**拖慢流程⇒批量变大⇒单次影响面更大⇒失败率更高**。
- **调和**：DORA 靶子是 CAB（审批者不承担后果/在团队外/引入排队）——单人+AI 场景拍板者=owner=唯一后果承担者，只命中「排队推大批量」一条。**危险的那一半真实存在**：①方案清单式批量审批=DORA 机理小尺度复现（判据：拍板环节让工作排了多久的队）②审批疲劳（Faros AI 遥测：高 AI 采用团队 PR 评审时长 +91%、PR 体积 +154%——用户注意力是唯一不能扩容的资源）。
- **缺口**：没按可逆性分档；审批点在方案不在 diff；拍板时不定验收判据（=执行方给自己划及格线）；审批疲劳未防。
- **处方**：ITIL 4 标准变更预授权 × Bezos 单向门/双向门——**拍板强度 ∝ 不可逆性**，不 ∝ 改动大小。dao 已有的「自定档/判断档」+`[自定@]` 可整批撤回机制就是现成实现。

### ② 逐项测试
- **业界支持最强的一条**：Fowler CI（集成地狱→非事件）、shift-left、Google small CLs（更少 bug/更快评审/更易回滚）、**DORA 直接命中**：「小批量工作是 AI 采用的安全网——AI 常导致交付不稳定性上升，小批量是这个风险的关键对冲」。
- **但有下界**：Reinertsen B11 经济批量 U 曲线——最优批量由反馈延迟与每批固定开销共同决定，不能假设「越小越好」。
- **缺口**：①「验证锚」没有判别力要求（mousse #358 活标本：断言 subject 存在的单测全绿而渲染宽度为 0）——**一个断言若在被测物被故意破坏时不变红，它就不是锚**；②「逐项」粒度未定义（业界绑原子提交/一 PR 一关注点，使②粒度与③回滚粒度自动重合）；③缺 U 曲线例外（真机/独占资源类每批固定成本高，最优批量>1——13 笔真机欠账逐条合规而整批覆盖率 0 的实证）。

### ③ 可回退
- **业界**：SRE 回滚优先于调试（detect→roll back→fix→roll forward，理由是 MTTR/错误预算）；「回退判据预先写明」的业界实现是自动化的（Argo Rollouts AnalysisTemplate/Flagger——阈值前置进 spec）；不可回退变更走 expand-contract（Fowler 陷阱警告：contract 阶段不执行会落到比开始更糟的状态）；**回滚能力要演练**（AWS REL12-BP05 game day：「恢复路径历来是系统中最少被测试的部分」）；DORA 2025：**回滚能力放大 AI 对团队绩效的正向作用**。
- **强项**：「回退判据预先写明」比业界多数团队做得好（Argo/Flagger 的人工版）。
- **缺口**：①写了回滚点≠回滚可用（缺演练）②没区分可逆/不可逆（本场景的单向门：已被叠加的改动、外部可见状态、**规则条款类——git 回滚后 AI 行为未必复原**）③没写回滚 vs 前滚的选择判据。

### ④ 最终全量测试
- **业界**：Google TAP 论文明说资源再多也做不到每变更全量（依赖图选择+里程碑全量）；经验阈值**全套 <20 分钟就全跑**，超了用影响面分析；**位置问题：业界把「最终全量」实现为合并门（merge queue/gating）——在合并前跑，不是「全部落地之后」**。
- **强项**：补了②的结构性盲区（逐项验证看不见组合效应）。
- **缺口**：①时机偏后——发现问题时已叠 N 项，**②辛苦压小的批量在④这里又被攒了回去（四步内部最大结构矛盾）**②效果对照缺基线前测（基线必须在开工前采，不是「新 vs 记忆中的旧」）③全量范围无判据（套件长起来后必然被跳过——`-Skip` 退出码不可区分的实证正是这个坡）④缺浸泡期（bake time/soak）。

## 二、缺的业界标配（按代价×成本排序）

1. **合并态门（merge gating）**——最重要。缺它⇒批量在④重攒+「两个各自合规合起来越线」只能事后发现。dao 已有同源条款（预算型护栏合并态求值），只是没挂进四步。
2. **变更前影响面分析（blast radius）**——premortem 的 prospective hindsight ≈ +30% 风险识别率（Klein, HBR 2007）。轻量版三行：反向依赖/是否触及守卫路径/是否触及不可逆面。
3. **基线前测**——必须在②开工前采。
4. **浸泡期/观察窗**——本场景对应物=合并后一窗真机 dogfood+下一窗把本批列为复审强制靶。
5. **回退演练**——每批抽一项真跑 revert→锚变红→恢复。
6. **锚判别力校验**——「先破再验」（mutation 思路最小版）。
7. **分档预授权清单**——ITIL 标准变更。
8. **流程自身的度量**——change fail rate/返工率。四步没有自我度量⇒**无法回答「这四步有没有用」**——与 dao「立法必带基线数字」完全同构。

## 三、明确不采的业界重器（过度工程）

| 重器 | 不采理由 |
|---|---|
| 金丝雀/百分比放量 | 无生产流量，统计功效不存在（arc42 明确列为 skip 场景） |
| feature flag 发布控制 | 无 deploy/release 解耦需求；flag 有 carrying cost（Fowler）。例外：真机对照两版行为时临时用，用完即删 |
| 蓝绿部署 | 其价值的本场景等价物就是 git revert，已有 |
| CAB/正式审批板 | DORA 实证反对，单人项目更无意义 |
| 变更窗口/冻结期 | 「冻结是症状不是解法」；真机排队是资源调度问题（#446 双实例思路），不是变更窗口 |
| SLO/error budget 自动回滚 | 无生产遥测。退化为轻量版：验证锚红⇒revert 该项 |
| Kayenta 式自动判定/AB 平台 | 需要流量与指标流 |
| 对所有改动 expand-contract | 只用在不可逆面；对可 revert 改动是纯开销 |

## 四、改进版流程草案（保留四步骨架）

**⓪ 前置：影响面速评+可逆性分档** `[+新增]`——三行：触及文件的反向依赖/是否触及守卫·护栏·配置源/单向门还是双向门。全流程唯一一次「还没花钱之前」能砍掉错误方向的机会。

**①' 分档拍板+双判据冻结** `[改]`——单向门逐条呈审；双向门走预授权清单（事后批量报告）。拍板同时冻结：**验收判据+回退判据**。

**②' 逐项测试（粒度绑定+锚判别力+U 曲线例外）** `[改]`——一项=一原子单元（一 PR 一关注点）；每项锚**先破再验**；U 曲线例外（验证固定成本>项本身时允许成批，批边界开工时写明不许事后追认）；「不攒批」仍是默认（DORA：AI 不稳定性对冲）。

**③' 可回退（+演练+不可逆面单独走）** `[改]`——回滚点=原子 commit/单 PR；**每批至少一次真 revert 演练**；能回滚先回滚，已叠加/不可逆副作用时前滚；不可逆面走 expand-contract 且 contract 时机写死。

**③.5 合并态门** `[+新增，最重要]`——每次合并前：fetch→核 origin/main 真的动了→merge→重跑受影响面+全部预算型闸→再合。把④的一半前移，避免批量重攒。

**④' 批末全量+基线对照（范围按风险分层）** `[改]`——套件 <20 分钟 retest-all，超了影响面选择+高风险项必跑；**基线在①'后②'前采**；退出码只有 0 叫通过。

**⑤ 浸泡+记账** `[+新增]`——一窗真机 dogfood 观察；未清项带解冻条件挂账；**记录本批返工数/回滚数作为下一批基线**（流程自身的度量）。

**一句话读法**：四步改后仍是四步——①分了档、②定了粒度和锚判别力、③加了演练、④拆成「合并前的门」和「批末对照」，末尾多一个观察窗。新增每一样都挂在已有必经动作上（拍板/开 PR/合并/收官），不新增独立文书。

## 五、未尽处（调研官自报，摘录）

- sre.google 全站 WebFetch 失败（5 次），SRE 引文来自搜索摘要未逐字校对；Google eng-practices、ITIL 4、Reinertsen 同为二手。
- DORA 2019「2.6 倍」来自摘要未定位页码；capability 页的「无证据支持外部评审」有直接对应可靠度较高。
- Faros AI 的 91%/154%/9% 全部二手，当方向性证据不当精确数字。
- **「四步缺什么」「哪些过度工程」两节整体是推断**——业界没有对「单人+AI agent+无生产流量+PR 为单位」场景的直接研究，所有映射是类比，类比合法性无实证。
- 「拍板先行会把批量推大」是从 DORA 机理外推，无本仓实测（「方案清单从呈审到拍板的平均等待时长」可测未测，应标 `[基线:未测]`）。
- 未取仓内 PR/issue 实证验证四步实际执行率——所有「缺口」是与业界的差距，不是与实际做法的差距（至少三处 dao 已有条款重叠：合并态求值、验证判别力、义务转移落台账）。
