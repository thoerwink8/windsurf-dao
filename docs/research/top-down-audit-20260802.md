# 三仓「违反自上而下」探查 · 呈拍板清单（2026-08-02）

> 用户令：「dao 体系初衷是自上而下——查出其他不满足这一点的地方」。
> Workflow 30 官：3 仓探查 → 逐条对抗核验 → 汇总。原始 26 → 核验确认 21 → 打掉误报 5 → 去重呈报 17 件。
> 拍板状态：批准后在条目行首标【批·批次】；否决标【否】。

**一段话总览**：dao 是全局规则层，项目仓该从它派生规范，而不是反过来。反复出现的病只有三种：①通用工具/规则长在某个项目里，第二个项目拿不到；②dao 已备好母版，项目侧没接线，两份各自称「唯一真相源」且已实际漂移；③最严重——dao 自己的测试和 hook 反过来把 mousse 里的文件当权威，全局层被一个项目文件治理。

---

## 第一档 · 推荐立即办（多仓复现，或母版已备好只差接线）— 7 件

**1. 派单条款库的通用半边搬回 dao**　[mousse + TraceyU 双仓复现｜工作量：大]
- 是什么：给被派出去干活的 AI 立规矩的那份 113KB 条款库（通用节 30+ 条 + 五个官种节），实测约 73% 条款与技术栈无关。
- 卡在哪：唯一真相源在 mousse；dao 的生产 hook 里写死着 mousse 的本机绝对路径、dao 元仓的测试称它为「唯一真实语料」——全局层被项目文件治理。TraceyU 有多 agent 作业痕迹却无此文件、也无处派生，只能从零重新发明。
- 去处：新建 `ccswitch/rules/dao-officer-clauses.md`（官侧，与帅侧 dao-dispatch.md 平级）承接 74 条通用条款；上移前先去重（三条已在 dao-powershell.md 等处）；同批拆掉 dao 侧 6-7 处倒置依赖；备案清单补可派生的指针存根。mousse 留 28 条项目特有条款 + 指针；TraceyU 侧派生不在本批（休眠仓，留人裁）。
- 核验官：「全局层的测试与判据被一个项目文件治理，这正是 stuck-generic 的定义式形态。」（同时订正原报告一处错误机制叙述：所谓「静默假通过」实为响亮报错后的可见降级。）

**2. 把「你是产品型项目吗」这道必答题送到存量项目面前**　[TraceyU + devin-byok 双仓复现｜小]
- 是什么：dao 有一整档只对产品型项目生效的检查（PR 真机证据 / PR 模板 / issue 模板三件），开关是项目 CLAUDE.md 里一句自我声明——但这道题只有**新建**项目会被问。
- 卡在哪：TraceyU 的 CLAUDE.md 成文于该机制之前、从没被问过；devin-byok 连 CLAUDE.md 都没有。两个真产品仓对那三件检查**结构上永不触发**，且机器上「从没答过」与「答了，不是」长得一模一样。
- 去处：先改 CLAUDE.md 模板让「不是」有机器可读形态（负向声明串），再往备案清单加一条 info 级必答题投递（顺序反了就是永久噪音）。devin 侧照模板派生 CLAUDE.md + 建 .claude/rules/ + 删冗余的 AGENT_GUIDE.md（AGENT.md 降为生成投影，不拆删——它还要服务 Devin/Codex 宿主）。算不算产品型由用户答，机器不代答。
- 核验官：「两条路都到不了（有 CLAUDE.md 就不问）实测坐实……B6 理由在此得第二个实证。」

**3. 桌面端调试处方成批翻新**　[TraceyU + devin-byok，跨 Tauri/Wails 两栈｜小-中]
- 是什么：dao 发给桌面项目的调试/隔离处方（dev:debug 脚本模板、desktop-debugging 规则、备案清单里两条桌面机检）。
- 卡在哪，三处：①dao 至今**仍在下发已被自己实证不足的旧模板**（写死 9222 端口、无独立 user-data-dir）——TraceyU 那行缺陷脚本与 dao 模板逐字节相同，是忠实照抄不是偏离；②TraceyU 的 windows-mcp 禁令副本停在 6/29 旧版（「常规场景禁」），比用户 7/25 拍板的全域一票否决弱一档；③Wails 项目不在两条机检的指纹里——同一个 WebView2 底座的第二生态整个不可见（实测加一行指纹立即命中）。
- 去处：P0 撤三处旧模板片段（desktop-debug-gate.md / stacks / dao.md WebView2 条）；补 desktop-debugging-rule 的模板（决策树指针 + 全域禁令）；指纹加 `go.mod 含 wailsapp/wails` 一路（原提议的 wails.json 对首例仓是空转，不可省）；stacks 里与框架无关的两节提级。
- 核验官：「不是契约立完没有投递面，是契约立完，旧处方的三处投递面一个都没撤，还在持续铸造缺陷件。」（另注：windows-mcp 实际误用风险近零——硬闸在拦、MCP 已卸载，真实危害是教材在教旧禁令。）

**4. mousse 接上 GitHub 开单模板**　[mousse｜极小，一条零编辑命令]
- dao 已备好缺陷/任务/欠账/待拍板四个 issue 表单母版，与 mousse §六的四标签一一对应；mousse 自陈产品型却是零消费者——姊妹件 PR 模板同日已接，这是同批漏下的另一半。核验官六路证伪全不成立；唯一未验的是远端标签名是否漂移。

**5. mousse 的 PR 真机证据规则接上母版**　[mousse｜小]
- 卡在哪：两份文件各自称「唯一真相源」（mousse 指自己的 CLAUDE.md，dao 指母版），检查器只查文件存在、结构上永远报不出这个冲突；且漂移已发生——母版的「起前查端口占用即拒启」在 mousse 版被弱化成「备用调试端口」。
- 去处：改成三级链条（母版→CLAUDE.md→约定名指针），速查副本删或标「冲突以母版为准」；附带一项需拍板：备案清单该条从「查文件在」升级为「查内容含母版指针」，否则下一个产品型项目会一字不差复现这个病。
- 核验官：「同一文件自己 43-44 行记着上一次同型漂移——它自己的立论恰好支持接上母版。」

**6. mousse 的派单中枢手册按母版重新派生**　[mousse｜中]
- 卡在哪：DISPATCH-HUB.md 是母版的**来源**却从未反向派生、零指针；标签判据已实质漂移——「待拍板」在母版是完整取舍判据，mousse 压成「等用户决策」，照它根本判不出该不该打标；仓内还自相矛盾（蓄水池两类 vs 三类）。
- 核验官：「净状态是同一套标签语义两处平行定义，弱的那份在项目侧当值。」

**7. 条款库结构检查器收敛到 dao 那份**　[mousse｜中，替换已实测可行]
- 卡在哪：同一道闸 dao 已有参数化母版，mousse 953 行先行实现仍在双写、各自演进。已在 mousse 实测母版裁决逐条一致（exit=0、76 条款、行号一致），且母版修掉了 mousse 版的中文乱码病。
- 去处：verify-all 两道改调 dao 母版，mousse 两个脚本退役；删前两侧实跑一次测试夹具（核验官声明「夹具覆盖」是读断言标题所得、非执行所得）。
- 核验官：「替换是今天就能落地的 drop-in；留着 mousse 那份不仅是冗余，是留在更差的一版上。」（订正一处路径：回归网在 tests/ 下，原报的 ccswitch/tests/ 不存在。）

## 第二档 · 建议上移但可缓（单仓，通用性核验成立，各带前置修正）— 9 件

**8. 凭据脱敏两层防线**　[devin-byok｜中｜安全向]——QA 工件落盘前脱敏过滤 + UI 渲染面「密钥不得出现」自动断言。dao 全链路无任何脱敏步，密钥会永久留进 git 历史。前置：改 fail-closed、注明只管文本不管截图、清单条目用条件档。核验官降级一处论据：仓私有，风险是「留在 git 历史」非「发出去」，仍成立。

**9. dao 体系自己的两份设计文档搬回 dao**　[mousse｜中]——生长闭环设计定稿 + 生态退役审查，被描述对象整个在 dao，dao 侧 7 处母版机件反把它们当真相源。修正：生长闭环文档混有 mousse 落地记账，拆迁——dao 级正文走，落地状态留存根。

**10. 增量三镜复审 workflow 上架**　[mousse｜小]——dao 的 workflow 货架 README 已把它当自家成员在讲，货架目录里却没有。前置：repoPath 改必填，先剥掉「版本四处一体」这句 mousse 私货（「去项目化已完成」是作者自陈非实况）。

**11. 四个流程观察线检查器上移**　[mousse｜大]——PR 正文乱码/占位符扫描（21KB 判据库实测零项目耦合）、`git add -A` 误收清单、同文件 24h 反复返工告警。最硬一条：「24h 三次返工」判据原文就在 dao 规则文件里，机检半边却只挂 mousse——判据在上、机器在下。修正：三个脚本各有一行活代码含 mousse 指纹，须参数化，成本别按零估。

**12. memory 陈旧引用扫描并轨**　[mousse｜中]——它扫全部项目的 memory（含 dao 的），却只在 mousse 跑 verify-all 时执行。核验官：「windsurf-dao 自己的 memory，目前只有在有人跑 mousse 的 verify-all 时才真的被扫过。」修正：并轨进 dao 既有 memory-truth-source.js + 挂 SessionStart，不新建第三份实现。

**13. 设计值硬编码的棘轮守卫**　[TraceyU｜中]——「禁裸 px/hex、lint 拦裸值」dao 写了五处散文零实现；TraceyU 做成了可执行守卫+CI。前置：先修「基线与规则脱节即恒红」病、补基线自动收紧；清单只上 info 级（硬性要求属判断档须用户拍板）。

**14. 「改 UI 必动 design/」的 git 提交闸**　[TraceyU｜小]——dao 的设计同步门刚做成 Stop hook 但只覆盖 Claude 主会话且未注册；这个 git 闸管所有宿主（Codex/Cascade）所有提交——互补不互替。前置：修 when 条件循环依赖；三通道分工写清防三份漂移。

**15. 交互成熟度检查清单**　[TraceyU｜小]——拖拽反馈/可调布局宽度记忆/滚动渐隐/状态过渡：dao 设计体检四维之外的第五层；且 dao 现有条款把结构区域建模成「固定宽度不可调」，与它自己引的 VS Code/Linear/Notion 蓝本相反。前置：砍与已有条款重复的 6 条；按产品类型启用的专章，不进无条件模板。

**16. TraceyU 补一个约定名指针文件**　[TraceyU｜极小]——样式路线散在五个文件，机器核对靠文件名固定。项目侧建 frontend-style.md 五行指针；dao 侧把已有正解下沉进报文（原议「补模板」被核验官打掉，违 dao 两处明文决定）。
