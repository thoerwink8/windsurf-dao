# 机制巡检：GitHub 事件桥通道已经断了 8 小时，父进程还在跳心跳，systemd 绿，唯一的闸挂在没人跑的 server-check 上

## 结论

`dao-gh-events` 设计上靠 `gh webhook forward` 把 PR 事件拉回来，立刻叫醒指挥官；自证 ping 是用来把「通道断了」和「这段时间没事」分开的。本轮现场：父进程从 09-12 开机起一直 `active / success / NRestarts=0`，心跳还在写；`gh webhook forward` 子进程不在，近几分钟每 5 秒 exit 1，累计重启 4941 次；最近一次 ping **收回来**是 503 分钟前。判据函数当场红。systemd 看不见子进程，单元不进 `--failed`。唯一接线的活体闸是 server-check ㉓——那份检查 09-06 就已经报过没人跑，本轮仍然没有 timer、没有单元。dao-check 的 ㉓ 是另一件事（盲考收卷）。指挥官盘点 0 处问这件事。测试只锁「server-check 文本里有这一格」和「兜底 timer 文件还在」，两头都绿。快路死了，看起来像一直没事。

## 建议的最小改造

删掉「父进程在 + 心跳还在写 = 事件桥还在守着」这一层。通道活着的判据已经写好了（`classifyGhEventBridge` 看 ping 收回来没有、forward 一小时崩几次），缺的是一个**会跑的人**去调它。

要么把这一问挂到已经在跑的 `commander-act` / 指挥官盘点上（ping 超时或 `recentExits` 超阈 = 这一轮报出来，不要等 server-check）；要么让单元在子进程起不来时自己非零（父进程别用心跳把死通道续成 success）。不要再给 server-check 加一格「允许没人跑」——09-06 就报过它没人跑，测试还把接线锁在那一格上。
