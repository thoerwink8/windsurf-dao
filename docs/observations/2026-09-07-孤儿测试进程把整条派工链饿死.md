# 一个挂死 11 小时的测试进程把整条派工链饿死了，而报警长得完全不像「有进程失控」

## 结论

2026-09-07 04:30 查到：

```
PID 166628  orca  98.0% CPU  16.0% MEM  已跑 10:47:15  父进程 = 1 (init)
/usr/bin/node --test --test-reporter=tap /srv/projects/windsurf-dao/tests/session-events.test.js
```

昨日 **17:43:30** 起的一次单文件测试，跑到今晨仍在满吃一个核、占 1.8G 内存。父进程是 init——**起它的会话早就没了，它是孤儿**，没有任何东西在等它的结果。连 `SIGTERM` 都不理，要 `SIGKILL` 才死。

它造成的下游后果是整条链停摆：

```
Sep 07 04:11:27  commander-act
  hub：机器余量不够，这轮不派新单（归一化负载 1.78 ≥ 阈值 0.85，机器已满，不收）
```

commander 每 20 分钟醒一次，每次都只说这一句就退出。**没有一条报警说「有进程失控」**——盘面上看到的是「机器忙」，一个完全正常、甚至像是「我们干得很满」的说法。杀掉之后 1 分钟负载从 6.99 掉到 5.01。

判例 memory `clean-exit-is-still-down` 记的是「干净退出照样是死了」；这条是它的镜像——**满负荷运转照样是死了**，而且更难看出来，因为「忙」听起来像好事。

## 三层，每层都缺一道闸

### ① 测试进程没有上限，也没人回收孤儿

`node --test` 单文件跑 11 小时无人过问。仓内没有任何东西在看「有没有跑了超过 N 分钟的测试进程」。CLAUDE.md 写着「反馈时间正比于改动，不是仓库规模；新检查/新测试默认要快」——但那是**写给人的纪律**，没有对应的执行者。

一个孤儿 node 进程能把 commander 的准入判据钉死在「机器已满」，这是单点饿死整条链。

### ② `commander` 的「机器已满」不区分「在干活」和「有东西失控」

`归一化负载 1.78 ≥ 0.85` 这句话对两种截然不同的世界给出同一个输出：
- 6 个工人在正常跑测试 → 该等
- 1 个孤儿进程满吃一核 → 该杀

按本仓「输出必须能区分『扫完查出 0 条』和『这次没扫到任何样本』」的同一条纪律，这里也该区分：**拒收时至少报出前 3 个吃 CPU 的进程是谁、跑了多久、父进程还在不在**。现在这句话只报数字，不报归因，所以连续 3 轮（03:51 / 04:11 / 04:31）都没人发现真因。

### ③ `tests/dao-mode.test.js` 的沙箱是仓内固定路径，并发跑必假红

```js
const SANDBOX = path.join(REPO, "_tmp", "mode-sandbox");
fs.rmSync(SANDBOX, { recursive: true, force: true });   // 模块加载时
```

同一个 worktree 里并发跑两次测试（例如全量套 + `dao-check` 各自那一遍），后加载的那次会把前一次正在用的沙箱删掉，**稳定刷出 11 条假红**，且全部集中在 `dao-mode.test.js`，单独重跑就 0 红。

今晚实测：并发跑 → `4423 tests / 11 fail`；独占重跑同一 HEAD → `4423 tests / 0 fail`。

危险不在于它红，在于**它红得像是真的**——11 条断言失败、堆栈齐全、指向具体行号。如果没想到去查并发，很容易被当成真回归去「修」。

## 已做的（帅位值守自拍，2026-09-07 04:31）

杀掉 PID 166628（先 TERM 无效，再 KILL）。登记依据：不在恒挂起清单；不是数据是失控进程；已核父进程 = init、无同类进程、无子进程。

## 顺带修掉的第四件：`.git` 里 280 个 root 属主文件

本次会话是以 **root** 起的（往常是 orca）。开场几条 `git fetch` / `git log` 就在 orca 属主的仓里留下了 root 属主的 `.git/config`、`packed-refs` 和 worktree 的 `logs/HEAD`，直接导致后续以 orca 身份的 `git merge` 报 `Permission denied`。

顺手查了全仓，累计有 **280 个** root 属主文件（历次 root 会话累积），其中包括：

- `objects/pack/*.pack` / `*.idx` —— orca 因此**永远重打包不了**，`.git` 已 115M、9069 个松散对象只涨不消
- `worktrees/dao-1097/index`、`worktrees/dao-1065/index` —— 正在跑的工人树，会随机写失败

已全部 `chown -R orca:orca`（只改属主不动内容，root 本身无视权限不损失任何访问）。

这正是判例 memory `root-owned-files-in-service-home` 记的形状，而它**没有配任何会报警的闸**——所以第二次撞上了。按 CLAUDE.md「出错后的制度化」，这条该配闸：`dao-check` 里加一项「仓内有没有非仓主属主的文件」是确定性的量，很便宜。

## 落点

- `tests/dao-mode.test.js:28`（固定沙箱路径）
- `scripts/commander.mjs` 的准入/负载判据（拒收时报归因）
- `dao-check`：新增「孤儿/超龄测试进程」与「`.git` 属主一致性」两项
- 判例 memory：`root-owned-files-in-service-home`、`clean-exit-is-still-down`
