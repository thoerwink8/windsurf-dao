# master 一动，全部在途 PR 同时变红——交卷闸 ① 把机械对齐变成了审官轮次

## 结论

2026-09-07 04:20 实测：**18 个开放 PR 里 17 个落后 `origin/master`**。原因只有一个——`48f941e release: v1.0.0` 合进了 master。

交卷闸 ①（`scripts/lib/handoff-check.mjs:49 judgeBaseFreshness`）要求 `origin/master` 必须是 PR HEAD 的祖先。master 每合一次，所有在途 PR 同时失去交卷资格；审官照章判红，工人/帅位去 `git merge origin/master`，推一个只含 `CHANGELOG.md` 的合并提交，再起一轮复审。**一轮完整的审官轮次，产出是一次 `git merge`。**

今晚一夜之内，#1070、#1057、#1096、#1098 四张 PR 各被这条判据判红一次，四轮复审里没有一条是代码问题：

| PR | 审官判定时刻 | 红项 | 代码本身 |
|---|---|---|---|
| #1057 | 20:11Z | P1 基底落后（唯一红项） | 同轮已跑 4421 pass / 0 fail |
| #1096 | 20:05Z | 红 1 基底落后 + 红 2 正文缺 handoff 输出 | 无代码红 |
| #1098 | 20:16Z | 交卷闸红 2 项 | `ask-gate.test.js` 56 pass / 0 fail |
| #1070 | 20:24Z | 交卷闸「2 通 / 2 红」 | 第 3 轮返工的 6 条红已逐条修完 |

四张都由帅位在 04:20–04:45 机械合了一次 master 就绿了。

## 这条闸本身没写错

`#904` 立它的病因是真的：工人自证「我写的代码对不对」，审官核「它跟仓里既成事实对不对」，中间没有闸。基底过旧确实会让「别人新增的文件」被误读成「本分支删了文件」（#902）。

问题不在判据对不对，在**谁来做这次对齐、什么时候做**。现在的落点是「审官发现 → 判红 → 人来合 → 再审一轮」，而这件事既确定又无需判断力。

## 三个可选落点（未拍板）

1. **派审官之前自动对齐**：`reviewer-create` 建审查树前，先把 `origin/master` 合进 PR 分支并推。冲突则不自动、退回判红。代价：机器会往 PR 分支写提交。
2. **合并那一刻才要求 ①**：审官照常审代码，① 从「交卷闸」降级为「合并闸」。代价：审过的树与最终合的树不同基。
3. **维持现状**，接受每次 master 移动 = 全体 PR 一轮机械返工。代价就是今晚这一夜。

体系类三问需要在拍板时回答，本页不预判。

## 附带发现：交卷闸 ⑤ 在审查树里必假红

⑤「自证基线＝审官所见」用**当前分支名**去找 `origin/<同名>`。审官树的分支名是 `dao-review-pr-<N>`，从来没有同名远端分支，所以 ⑤ 在任何审查树里都报红。

PR #1070 的审官（20:24Z）就是这么写的：

> ⑤ 当前审查树 `dao-review-pr-1070` 没有同名远端分支；因此这份树不能证明是可交付的最新 PR 树。

实际当时本地 HEAD 与 `origin/fix-escalate-noise` 完全同点，⑤ 想验的东西是成立的，只是它按分支名去找，找错了地方。同一形状也会打中任何「分支名 ≠ PR head 分支名」的工人树。

判据要么按 PR 的 `headRefName` 去比（需要传入 PR 号），要么在审查树里明确报「本形态下 ⑤ 不适用（没查成）」——**不能继续用「没有同名远端分支」冒充「树不是最新的」**，那正是本仓反复禁止的「把没查成当成查出问题」。
