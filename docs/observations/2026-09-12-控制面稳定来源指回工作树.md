# 机制巡检：#1165 的「稳定来源」在活工人树上就是那棵树自己；㊱ 只 grep 仓内文件所以绿

## 结论

今天 10:42 合进 master 的 #1165（`40e547e9` / PR #1197）要把 git pre-push 指到「正在跑的这份 dao 代码」的 `scripts/githooks`，专门防「工作树还停在合本单之前、那里没有钩子」。`stableHooksDir()` 的实现是 `import.meta.url` 旁边那份——谁加载了 `control-plane-write.mjs`，稳定来源就是谁的树。本轮活着的工人树（含合入之后新建的 `dao-1174` / `dao-1210` / `dao-review-pr-1159`）`core.hooksPath` 全部指回**自己**的 `scripts/githooks`，不是主树 `/srv/projects/windsurf-dao/scripts/githooks`。dao-check ㊱ 只读仓内文件内容、自己 spawn 一次钩子脚本，不问任何一棵活树的 `git config --worktree`，本轮绿。测试从主树模块调用 `ensureControlPlaneHooksPath`，锁的是测试进程自己的路径，从来没扫过 `~/mirasim-worktrees`。工人 `git push` 跑的是自己那棵树上的钩子——正是审官 P1 说会绕开闸的那份。
