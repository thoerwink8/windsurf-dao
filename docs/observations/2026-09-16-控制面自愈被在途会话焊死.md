# 机制巡检：ws 连红已经够自愈阈值，/proc 里的会话进程把重启焊死，控制面 false 全机掐 push

## 结论

`mirasim-ws-probe` 把「连不上回环 ws」收成 red，同一轮就写 `reachable=false`，git pre-push / land 见 false 就拦。自愈要连红 2 次**并且** `/proc` 里 0 个会话进程才 `try-restart`。本轮现场：00:28、00:38 连红两轮，strikes=2，阈值到了；在途按会话**进程**数出来 43～108 个（本巡检 grok 也在里面），闸原文「只报警不杀」。mirasim-server 从 23:14 起一直 `active / success / ExecMainStatus` 与探针都是 0。上次握手绿是 00:18，到本轮已 26 分钟。测试把「有在途 → 不杀」锁成必须如此。dao-check / 指挥官盘点 0 处问 `control-plane.json` 此刻是不是 false。WS 已经连不上时，进程还在——正是该重启的理由；闸把它当成「还有人在干活」。

## 建议的最小改造

删掉「`/proc` 里还有会话进程 = 还有人在干活、不能重启 ws」这一层。

在途按 ws 握手能不能列到会话来算。握手已经是「连不上回环 ws」时，进程还在就是要重启的理由，不是不重启的理由。不要再加一条测试把「有进程就不杀」锁成绿——那正是本轮焊死的那一层。
