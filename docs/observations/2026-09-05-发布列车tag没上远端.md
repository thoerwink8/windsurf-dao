# 机制巡检：发布列车把本地 tag 当成已发版，远端一条都没有

## 结论

发布列车在这台机器上打过 `v0.1.0` / `v0.2.0`，CHANGELOG 提交也进了 `origin/master`，但 GitHub 上既没有这两个 tag，也没有 GitHub Release。列车用**本机** `git tag --list` 当「上次发到哪了」，于是认定已经发过 v0.2.0，下一班要切 v0.3.0——两个从未出现在远端的版本就此从发布史上消失。守「发完要推」的闸只 grep 源码里有没有那串字符，活体检查（server-check）完全不碰这条单元。

## 证据

### 1. 本机有 tag，远端没有

```
$ git tag -l 'v*'
v0.1.0
v0.2.0

$ git for-each-ref --format='%(refname:short) tagger=%(taggerdate:iso) peeled=%(*objectname)' refs/tags/v0.1.0 refs/tags/v0.2.0
v0.1.0 tagger=2026-09-04 04:00:03 +0800 peeled=b98707367219a570274f251a98275b6a012726f8
v0.2.0 tagger=2026-09-05 04:00:00 +0800 peeled=27c1774675adedc453112a9c6957f48ab9b582bb

$ git ls-remote --tags origin 'refs/tags/v0*'
# （0 行）

$ git ls-remote --tags origin
2c8bf1ec80a62a8926c0bd4de190c7d11c9bf5b0	refs/tags/ci-sweep
f1276c58380b1903e985688b18ff7cc378619679	refs/tags/pre-rewrite

$ gh release list --limit 10
# （空）
```

两个 annotated tag 的 tagger 时间正好卡在 timer 的 `OnCalendar=*-*-* 04:00:00` 上（`/etc/systemd/system/release-train.timer`）。`systemctl show release-train.service` 同轮：

```
ExecMainStartTimestamp=Sat 2026-09-05 04:00:00 CST
ExecMainExitTimestamp=Sat 2026-09-05 04:00:03 CST
Result=success
ExecMainStatus=0
```

单元自己报 success。`360f727f release: v0.2.0`（2026-09-05 11:53:42 +0800）已经在 `origin/master` 上——CHANGELOG 段是跟着 master 走的；annotated tag 没有。

### 2. 「上次发到哪」读的是本机 tag 表

`scripts/release-train.mjs:42-52`：

```
export function lastReleaseTag(cwd) {
  const r = git(cwd, ['tag', '--list', 'v*']);
  ...
  return tags[tags.length - 1];
}
```

本轮实测：

```
$ node scripts/release-train.mjs should-run
到发布点：攒够 100≥5 个合并，提前发
# exit 0

$ node scripts/release-train.mjs release --dry-run
[发布列车] 拟发版 v0.3.0（自 v0.2.0 起 100 个合并，档位 minor）
...
[发布列车] [拟] git tag -a v0.3.0 ...
[发布列车] 拟发版完成（未写任何东西）
# exit 0；git status 干净
```

`git rev-list --count v0.2.0..HEAD` = 100。列车把「本机有 v0.2.0」当成「已经发过 v0.2.0」。

### 3. 「发完要推」是后补的源码 grep，补上时那两枪已经打过了

`git push --follow-tags` 是 `08f734ca`（2026-09-05 12:16:31 +0800）加的，比 v0.2.0 的 tagger 晚 8 小时。加完之后列车再没跑过（上次触发仍是 04:00）。`tests/release-train.test.js:251-266` 三条闸全文：

- 源码里有 `/'push', '--follow-tags'/`
- 那一行附近 700 字节里有「推送失败」
- dry-run 有拟态行

没有一条去问 origin 上有没有对应的 `v*`。`doRelease` 在推失败之后仍然 `return { ok: true, released: !dryRun, ... }`（`scripts/release-train.mjs:203-230`）：say 一句，退出码 0，systemd Result=success。

`scripts/server-check.mjs`、`tests/timer-armed.test.js`、`tests/unit-privilege.test.js` 全文搜 `release-train`：0 命中。活体闸不看这条单元跑没跑成、tag 上没上远端。

## 建议的最小改造

删掉「本机 `git tag --list` = 已发布版本」这一层。`lastReleaseTag` 改问 origin（`git ls-remote --tags origin 'refs/tags/v*'`），本机有、远端没有的 tag 不当作已发。推 tag / 建 GitHub Release 失败不许 `ok: true`。活体闸加一格：本机最新 `v*` 必须出现在 `git ls-remote --tags origin` 里，扫出 0 个也红。
