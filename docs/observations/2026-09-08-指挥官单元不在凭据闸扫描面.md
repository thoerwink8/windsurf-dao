# 机制巡检：#1015 卸个人 GitHub 凭据，闸扫不到每 20 分钟合并 PR 的指挥官

处置：#1167

## 结论

#1015 给自动化单元卸了个人 `GH_TOKEN` / `~/.config/gh`，静态闸只扫 `host/machine/systemd/*.service`。每 20 分钟跑、会 `gh-as marshal pr merge` 的 `commander-act`（以及 `commander-inventory`）是 `scripts/lib/commander-inventory.mjs` 现场生成的，不在那个目录；模板和机器上的活单元都没有 `UnsetEnvironment` / `GH_CONFIG_DIR=/var/empty`。闸在仓里绿，活着的指挥官以 `User=orca` 跑，读得到 `~/.config/gh/hosts.yml` 里 `user: thoerwink8` 的个人登录。

## 证据

闸的扫描面（`scripts/lib/issue-gateway-check.mjs` 267–271 行）：没给 `extraRels` 时只 `readdirSync(host/machine/systemd)` 取 `*.service`。`dao-check.mjs` 2434–2436 行直接 `checkIssueGatewayAlive({ root: ROOT })`，没有把指挥官单元塞进去。

指挥官装机模板（`scripts/lib/commander-inventory.mjs` 381–384 行）原文：

```
[Service]
Type=oneshot
User=orca
WorkingDirectory=/srv/projects/windsurf-dao
Environment=PATH=...
ExecStart=/usr/bin/node .../commander.mjs act
```

无 `UnsetEnvironment`、无 `GH_CONFIG_DIR`。同文件 409 行 `runInstall` 把这份写进 `/etc/systemd/system/commander-act.service`。注释 392–394 行自己承认：这两个单元「不在 `host/machine/systemd/`，所以 `tests/timer-armed.test.js` 和 `tests/unit-privilege.test.js` 两道静态闸都扫不到」——#1015 那道新闸同样扫不到，没人补。

机器上正在跑的单元（2026-09-08 12:24 读盘，与模板一字不差）：

```
$ cat /etc/systemd/system/commander-act.service
[Unit]
Description=指挥官 act：scan→decide→执行（#800）
[Service]
Type=oneshot
User=orca
WorkingDirectory=/srv/projects/windsurf-dao
Environment=PATH=/home/orca/.local/bin:/home/orca/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/usr/bin/node /srv/projects/windsurf-dao/scripts/commander.mjs act
```

`systemctl list-timers`：`commander-act.timer` NEXT=`Tue 2026-09-08 12:31:00 CST`，enabled。`systemctl show commander-act.service -p Environment` 只有 `PATH=...`，没有 `GH_CONFIG_DIR`。

同用户家目录个人 gh 登录还在（只核用户名，不抄 token）：

```
$ python3 -c '...'  # 读 ~/.config/gh/hosts.yml，oauth_token 已打码
github.com:
    users:
        thoerwink8:
            oauth_token: [redacted]
    user: thoerwink8
```

对照：仓里 `host/machine/systemd/dao-close-issues.service` 46–49 行已经写了 `UnsetEnvironment=GH_TOKEN GITHUB_TOKEN` 和 `Environment=GH_CONFIG_DIR=/var/empty`；`/etc/systemd/system/dao-close-issues.service` 仍是 2026-09-06 那份，这两行没有。这是「改了仓没装机器」的老形态（已报过），这里只用来对照：即便把仓内那批装上，指挥官仍然不在扫描面、装机模板也不会带上这两行。

指挥官确实写 GitHub：`scripts/commander.mjs` 701 行 `gh-as.mjs marshal -- pr merge`，1845 / 2004 行 `issue-gateway.mjs comment|create`。设计意图走 marshal App；卸个人凭据是防代码路径漏到裸 `gh` 时顶着人的号写。这道防漏在指挥官上不存在。

## 建议的最小改造

删掉「凭据闸 = 扫 `host/machine/systemd/`」这一层假设。`checkNoPersonalTokenInUnits` 把 `commander-inventory.mjs` 的 `INSTALL_FILES()` 生成结果一并扫进去（或把指挥官两个 service 收进 `host/machine/systemd/`，不再代码生成）；模板补上与关单单元相同的 `UnsetEnvironment` + `GH_CONFIG_DIR=/var/empty`。少这一处就红，装机跑 `commander.mjs install` 才会写出卸凭据的活单元。
