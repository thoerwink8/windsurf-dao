# mirasim 巡检活性盲区

观察目标：确认帅位收件箱与定时巡检能否判断 mirasim 会话是否持续推进。

证据：

- `scripts/lib/liveness.mjs` 的 `sessionFromMirasimSession` 只有在 `lastActivityAt`、`updatedAt` 或 `ts` 存在时才计算活性；拿不到时间戳会明确标为 `unscanned`。
- 当前 mirasim `list_sessions` 返回的会话摘要只有 key、标题、agent、状态等信息，未提供活动时间戳；实际读取帅位会话时只能得到 `running` 和最近几段文本，无法得到可计算的静默时长。
- 因此定时巡检即使正常运行，也只能知道会话存在，不能证明它在推进；超过阈值的 mirasim 空转会落入 `unscanned`，不会进入 `silent` 或自动升级路径。

影响：服务器端巡检无需人工盯盘的前提，在 mirasim 会话上并未闭环。系统可能报告“已采样/会话运行中”，但无法给出“多久没有进展”的证据。

建议：让 mirasim session 列表或巡检适配器提供 `lastActivityAt`（以及可选 `turnStartedAt`、`turnEndedAt`）；在缺失时保留 `unscanned` 并把计数、原因送入帅位收件箱，禁止把 `running` 当作 active。验收标准是：构造一个运行中但 45 分钟无新 turn 的 mirasim 会话，巡检能输出 `silent` 或明确的 `unscanned`，且不会报健康。


处置：已核实——该盲区由 474f95b（mirasim 字段名按实测改为 sessionKey/runState/seatAt）关闭。
服务器实测 26 个 mirasim 会话缺时间戳 0 个，运行中会话现在能按时间判 active/silent，不再一律 unscanned。
本记录对的是修复前的代码。收件箱闸本轮首次真接住东西，且正确抓出「文件没提交」。
