## 真因

issue #1152 的验收标准原文要求「测试环境必须**结构性**够不着真执行体
（fake runtime / 强制 NO_SPAWN + 断言改判执行体单元层），不是『靠拒派闸兜住』」。

- **生产侧**有真闸：`scripts/lib/mirasim-runtime.mjs:205` 的 `judgeTestExecutorIsolation`，
  在 `dao.mjs:749/846/930` 三处、真 IO 之前拦。它读三个 env 信号
  （`NODE_TEST_CONTEXT` / `DAO_DISPATCH_NO_SPAWN` / `DAO_NO_NETWORK_LOG`）。
- 但那个闸**按 env 判断**，所以它自认的洞是：子进程 env 整份换成不含这些键的对象。
- 为了兜这个洞，引入了 `test-executor-isolation-check.mjs`——**去静态分析测试源码里的 JS 语法**，
  判断「这段代码有没有可能 spawn 出真执行体」。

这就是病灶：**判据本身不可判定**。任意 JS 能否 spawn 子进程是停机问题级别的，
手搓正则 + 括号匹配永远存在「合法、真能执行、但扫描器没见过」的写法。
每补一条正则就多一条歧义，成本单调上升、收敛性证明不存在——
16 轮不是工人偷懒，是这条路没有终点。

第二个病灶：**闸读的是 env（运行时），扫描器读的是语法（源码），两者不是同一个输入。**
闸的洞只能由它自己的输入堵，用另一个输入去兜必然漏。

## 修法方向（两条，待拍板）

**A. 换机制：退役扫描器，测试改注入 fake runtime。**
调用点其实已经就位——`executor-binding.mjs:313/356`、`dao.mjs` 都走
`bind.runtime.ensureWorkspace/startSession`，测试传桩件即可，
「够不着真执行体」由**结构**保证，不再由扫描器保证。
删 `test-executor-isolation-check.mjs`（1873 行）+ 其全部 red 夹具。
洞：测试里一次手滑的真 spawn 不再被静态拦。

**B. 加固真闸：把 `judgeTestExecutorIsolation` 从 denylist 翻成 allowlist。**
现在生产默认放行、测试默认拦截（denylist 三个信号）。改成**默认拦、显式放行**：
只有生产入口（commander / dispatch-exec）设 `DAO_REAL_EXECUTOR=1` 才放。
这样「测试源码 scan 不到」不再重要——测试里任何路径起真执行体都被拦。
洞：拿不准的调用点会被误拦，派工链可能当场瘫；需要一次真机派工验证兜底。
顺带能删掉扫描器存在的主要理由。

**推荐 B 先行、A 随后**：B 是几行改动、直接堵住生产闸自己的洞、风险可用
「故意构造一次测试环境起真执行体被拦」当场验证；A 是 A 的长期形态但动测试契约面大。
两者不互斥，B 落地后 A 可以从容做，不必再卡在返工环里。
