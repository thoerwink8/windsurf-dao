# 机制巡检：#1218 合进 master 两天了，root 用量导出仍跑 09-11 那份把 grok 记成 openai 的副本

## 结论

#1218（`5b1cfa8b`，09-13 15:15）要把用量归属从「协议名当厂商」改成「认模型家族」：`openai-responses` 不是厂商，grok-4.6 不该记成 openai。修的是仓内 `scripts/lib/execution-usage.mjs`，测试对着这份绿。root 那只导出单元按设计**不许**解释仓内可写脚本，跑的是 `/usr/local/lib/dao-execution-usage/` 下 09-11 23:16 装上的副本。副本还是旧函数：`openai-responses → openai`。本轮 inbox 抽样里 grok-4.6 仍有 `provider=openai`。orca 采集器跑仓内新码，root 家目录的账经过旧副本才进 inbox。dao-sync 只给飞书 BOT_PATHS 请求重启，不问这份副本新不新。闸锁的是「ExecStart 指向 /usr/local 副本」和 timer NEXT，副本跟 HEAD 不是同一份字节，这一问 0 处在跑。装机脚本也没把 #1218 新加的 `execution-catalog.mjs` 列入拷贝——重跑 install 会把会崩的新文件拷上去。
