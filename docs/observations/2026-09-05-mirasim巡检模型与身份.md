# mirasim 巡检模型与 GitHub 身份观察

## 结论

当前 mirasim 的 `schedule_task` 接口只接受 `name`、`cron`、`prompt`，没有 `model` 或 `agent` 参数。因此现有的“三仓机制巡检与帅位回报”定时任务不能在接口层指定 `gpt-5.5-luna`，不能声称已经切换到该模型。

仓库模型路由目前登记的是 `gpt-5.6-luna`（例如 `gpt-5.6-luna@gw/orca`），没有 `gpt-5.5-luna` 的有效登记。需要先确认用户说的是不是 `gpt-5.6-luna`，再由运行时目录确认实际可用模型。

## 证据

- `mcp__mirasim__schedule_task` 的参数定义没有模型选择字段。
- `docs/model-routing.json` 命中 `gpt-5.6-luna`，未命中 `gpt-5.5-luna`。
- 现有 GitHub 身份已经有 `dao-watchdog[bot]`，其定位正是记录巡检/叫醒人的运行状态；另有 `dao-worker[bot]`、`dao-reviewer[bot]`、`dao-marshal[bot]` 三个任务闭环身份。

## 建议的最小改造

1. 给 mirasim 定时任务增加可选 `agent`、`model`、`effort` 字段，并在每次 fire 的启动回执中记录实际模型；没有实际模型回执就标记 `model_unconfirmed`。
2. 巡检默认使用已登记且额度较低的 `gpt-5.6-luna`（若用户确认确实要 `gpt-5.5-luna`，先补路由登记和可用性探针）。
3. 不新增 GitHub 机器人账号，复用 `dao-watchdog[bot]`；新增结构化事件类型 `mechanism_observation`，字段至少包括 `run_id`、`model`、`tokens_in`、`tokens_out`、`cost`、`repos`、`finding_count`、`delivery_status`、`evidence_path`。
4. GitHub issue/comment 只留摘要和证据路径，额度明细落账本；帅位盘面按 `dao-watchdog[bot]` 的事件统计每轮成本与累计成本。

## 当前状态

定时巡检仍按原模型配置运行，尚未切换模型；本记录已作为待改机制通知帅位。
