# 机制巡检：收件箱闸只认未跟踪，已提交没推的观察对本机是「在盒里」，对别的机器是「不存在」

## 结论

09-05 收件箱的病是「写了没 `git add`，别的机器看不见」。闸后来只查 `git ls-files --others`。本轮那份 21:09 的观察已经 `git add` + `commit` 进主树（`b2e6a626`），**没 push**：`ls-files --others` 0 行，盘点 `untracked=0`；`origin/master` 上这个路径不存在。对本机盘点，文件在 `docs/observations/` 里算出 6 条未处置之一；对别的机器，它等于没写。闸的前提「没提交 = 未跟踪」已经不覆盖「提交了没推」这一档——而巡检任务书把「不提交别的机器看不到」和「不许留着不推」写成两句，检查只接了前半句的未跟踪形态。

### 2. 盘点用的就是「未跟踪」这一问

`scripts/lib/inbox.mjs:56-57` 注释原文：

> untracked：git 里没跟踪的收件箱文件。它们**一定**算未处置，且要单独说——因为「写了但没提交」在别的机器上根本看不到

```

0 处 `rev-list`、0 处 `origin/master`、0 处 `ahead`。

```

`assessInbox` 的 `untracked: []`。6 条 pending 里含这份「判据」文件——因为本机工作树读得到。`untracked=0` 所以「没提交别的机器看不到」那句不会出现。

## 建议的最小改造

删掉「没提交 = `git ls-files --others`」这一层假设。问「别的机器看不看得见」就对 `origin/master` 问这个路径在不在（或主树 `docs/observations/` 是否 ahead）。未跟踪继续报；已提交没推也要报，不要把「在本机盒里」当成「已经同步出去了」。
