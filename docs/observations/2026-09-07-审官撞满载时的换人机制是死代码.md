# 审官撞满载时的换人机制是死代码，而活着的那道闸正好禁止它

## 结论

审官撞 `Selected model is at capacity` 时**该换人**——这件事仓里早就设计好、测好了：

`scripts/lib/dianjiangtai-reviewer-slot.mjs:103 planCapacitySwitch`
> 「capacity 四档续命之后：能换人就换，认不出审官卡才报帅。#679：跳过工人那一厂。」

它按审官顺位表往下找，只跳过**工人那一厂**（保住 #679 的异厂要求），其余照换。`tests/dianjiangtai.test.js:820` 的样本换的正是 `kimi-k3`。

**但它没有任何生产调用方。** 全仓引用只有三处，全不是调用：

| 位置 | 是什么 |
|---|---|
| `tests/dianjiangtai.test.js` / `tests/reviewer-vendor-gate.test.js` | 单测 |
| `scripts/lib/reviewer-vendor-gate-check.mjs:72` | 检查器，只验「这个函数还在、换人时带了 workerId」 |
| `pr-body-833.md` | 历史 PR 正文 |

它挂在 orca 的点将台上，#1115「删影响地图与 orca 派工脊」把脊梁删了，这条腿留在原地。**检查器还在验它存在，所以没有任何东西报警**——同 `migration-half-done-breaks-checks` 的形状。

## 而活着的那道闸，正好禁止这个动作

mirasim 路的 `scripts/lib/dispatch/reviewer.mjs:581 assertReviewerSeat`：

```
审官位只许同厂换顺位（当前 gpt-5.6-luna／gpt），不许换厂到 kimi-k3／kimi
```

于是现状是：**唯一的解法被唯一活着的闸挡住。**

审官顺位表里 gpt 家族只有两位：`gpt-5.6-luna`（顺位 1，正在满载）和 `gpt-5.6-sol`（顺位 2，`direct:codex@pqapi/responses` 熔断器 open 到 2026-09-07T14:41）。同厂换顺位在今天等于无处可换。

## 实测

2026-09-07 13:30–14:05，逐个复活卡死的审官（`session-stop` → 清残壳 → `reviewer-create --force` → 等 90 秒验活）：

| PR | 结果 |
|---|---|
| #1106 | 活 |
| #1104 | 活——**但它的 round 是 `failover-kimi-codex-capacity`，agent 是 `pi`，跑的是 kimi** |
| #1110 / #1102 / #1098 / #1119 / #1015 | 又死于 at capacity |

`failover-kimi` 这个字串**全仓搜不到**——是人手工换的，不是机制干的。而它是这批里唯一稳住的那个。

同一时刻 luna 上活着的审官约 **3–4 个**；再起就撞满载。这个数是量出来的，不是猜的。

## 三层病，只有第三层是新的

1. gw 的 luna 池并发容量约 3–4，超了就 `at capacity`。
2. 死了看不出来：会话报 `phase: done`，死因只写进 `error`，而 `judgeCompletion` 只读 `incomplete`、从不读 `error` ⇒ 编排当成审完了，不重派。**这与上午三个工人被 30 分钟回合看门狗掐死是同一起因**，见 `2026-09-07-回合看门狗杀掉的工人被判成完工.md`（slug `stalled-turn-reads-as-done`），不另开单。
3. **换人机制是死代码，且活着的闸禁止它**——本页记的是这一条。

## 落点

- `scripts/lib/dianjiangtai-reviewer-slot.mjs:103`（`planCapacitySwitch`，无调用方）
- `scripts/lib/dispatch/reviewer.mjs:581`（`assertReviewerSeat`，禁跨厂）
- `scripts/lib/reviewer-vendor-gate-check.mjs:72`（验死代码存在的检查器）
- `docs/model-routing.json`「审查」节（kimi/glm/grok 写着「备选登记，不顶审官位」）

## 未拍板

两条路互斥，都动到规则，值守期内不擅自决定：

1. **接线**：把 `planCapacitySwitch` 接进 mirasim 路，`assertReviewerSeat` 加一个「撞满载」的例外口。代价是审官位的同厂约束被打开一个口子，得写清什么情况下算数。
2. **删层**：`planCapacitySwitch` 连同验它的检查器一起删，承认「审官位就是同厂换顺位」，撞满载只能等或限流。代价是今天这种全线卡死会重演，除非同时给审官加并发上限（约 3）。

无论选哪条，**审官并发上限**都该单独配一道——3–4 这个数是量出来的，而现在没有任何东西在管它。
