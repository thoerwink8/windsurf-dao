# orca-serve「干净退出」不是故障，是退役进行时——动它之前先读西瓜清单

## 撞车经过

2026-09-06 17:15，`orca-serve` 干净退出（`status=0/SUCCESS`，跑了 20 分钟）。
另一个会话判为故障，提交 `afc89868` 加了 `Restart=always` 把它拉回来。

**那个判断在它自己的语境里是对的**——服务静默死掉确实该修。问题是它不知道：
同一天早些时候，派工已经切到 mirasim（`c588522b`），orca 上**只出不进**，
它跑完存量后自己退出恰恰是预期行为。

两个协调者对着干，谁都没错，缺的是共享的方向面。

## 给下一个想动 orca 的人

**先读 `docs/initiatives.json`**（西瓜清单），里面 `orca-retire` 那条写着完成判据：

> orca workspaces 下 0 棵树 且 orca-serve 已 disabled 且 dao.mjs 里标了「整段删」的那条脊已删

`dao-check` 每轮会把这条判据念出来，不需要谁记得来翻本文件。

具体到 `Restart=always` 这个改动：**现在保留它是对的**，存量清零之前 orca 还要干活。
到判据满足那天，连同 `orca-serve` 一起 disable —— 那时删的是整个单元，不是这一行。
