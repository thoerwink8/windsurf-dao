# 机制巡检：#1015 凭据闸要求 GH_CONFIG_DIR=/var/empty，把 Contabo 额度采样的 git 推送掐死
> 处置：#1172/#1173 同一起因开了两单，待并单

## 结论

#1015 给自动化单元卸个人 GitHub 登录，静态闸要求除 `dao-gh-events` 以外每个 `host/machine/systemd/*.service` 都写 `Environment=GH_CONFIG_DIR=/var/empty`。`miraquota-contabo` 的活是每 10 分钟把本机额度 **force-push** 到私仓 `miraquota-ledger` 的 `machine/contabo`；git 凭据助手是 `gh auth git-credential`，空目录下它交不出账号。机器上的单元和仓里一字不差，闸 11/11 绿。采样自己能跑（`--dry-run` 通），本地仓每次都 amend 一笔，远端停在 2026-09-06。`systemctl --failed` 里挂着，server-check / dao-check / 指挥官盘点都不扫 `--failed`。

这不是「指挥官单元不在扫描面」（#1167）：本单元**在**扫描面里，闸要求的那一行正是把它掐死的那一行。

## 证据

## 建议的最小改造

闸按**这个单元实际用哪条凭据路**分，不要一条 `GH_CONFIG_DIR=/var/empty` 套所有非 webhook 单元：

- 写 Issue 的继续卸个人 gh、走 issue-gateway / `ghAs`（marshal token 不读 `hosts.yml`）。
- 要 `git push` 私仓的，要么给它专用 deploy key / `GIT_ASKPASS` 指向仓外只读 secret，要么不要致盲 `gh auth git-credential`——现在这样闸绿、推死。
- 活体加一格：`systemctl --failed` 里出现本仓单元 = 红（⑮ 那种「只看 timer 在册」不够）。没权限读 journal 不能把这一格改成没查成然后当绿。
