# 机制巡检：关单脚本只认「署名 + 已合 + check 绿」，人手重开的单下一轮 :23 会被再关上

## 结论

`close-issues` 的关单判据是：PR 正文（或标题）署了某张单，且这张 PR 已 MERGED、check 全绿 → 关单。已经关上的就跳过；**没有「这张单被重开过、署名单号的那张 PR 并没做完」这一维**。于是一张署错号的已合 PR 会把真没做完的单反复拍死。#1065 被看门狗重开之后 38 分钟再次 CLOSED，时间对得上 `dao-close-issues.timer` 的 `:23` + `RandomizedDelaySec=60`；今早 board-gc 仍 exit 2，修它的 PR #1104 还开着。

## 证据

`scripts/lib/close-issue.mjs:36-43`（署名单号：标题 `#N` 优先，否则正文第一张「署名 issue #N」）：

```
export function attributedIssueNumber(pr) {

  const t = title.match(/#(\d+)/);
  if (t && Number(t[1]) > 0) return Number(t[1]);
  const nums = attributedIssueNumbers((pr && pr.body) || '').filter((n) => n > 0);
```

### 3. 两处规矩打架

- 看门狗 / 人：单没做完就重开（#1065 评论 2026-09-06T19:46:33Z 写了证据）。
- 关单脚本：只要历史上存在一张署了它、已合、check 绿的 PR，OPEN 就会在下一轮被关。重开没有稳定态。

已有观察 `2026-09-06-board-gc与stall仍问orca.md` 的处置是 #1065 换盘面源。本条不是那份的复述：那份管的是 board-gc 问 orca；本条管的是关单脚本把处置单拍死，让「单还开着 → 指挥官再派」这条回流断掉。#1065 评论已经记下这一次误关，但脚本没有改，本轮仍按同一条判据会再关。

## 建议的最小改造

删掉「已合的署名单永远等于单已做完」这一层。最小改法：关单前看 issue 的最后一次 `reopened` 是否晚于该 PR 的 `mergedAt`；晚于就不要再关（人/看门狗已经否决过这张 PR 配这张单）。`已顶替` 只挡 reopen、不挡误关，这一维也该对称。本轮不动手。
