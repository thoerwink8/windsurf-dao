# 机制巡检：巡检失败告警挂在 4 秒就退的启动器上，真正干活的会话挂了没有人响

## 结论

`dao-patrol.service` 配了 `OnFailure=dao-patrol-failure.service`，注释写「巡检失败必须主动送达总控群」。这个 oneshot 只负责起会话：本轮 00:23:49 起、00:23:53 退，`Result=success` `ExecMainStatus=0`。真正写观察、`git commit`、`git push` 的是它唤起来的 grok 会话（本进程），还在跑。会话超时被 `reapBrains` 强关、push 失败、写了没推、越界——systemd 都看不见，`dao-patrol-failure` 不会响。告警上次触发是 09-10 18:23，那是启动器自己没起成的时候。闸看的那一层是启动器的退出码，失败发生的那一层已经不在这个单元里。

## 证据

本轮 2026-09-14 00:24–00:31 CST，身份 `uid=999(orca)`，未用 sudo。`HEAD=d4d04d10`。

### 1. 本轮启动器 4 秒 success，会话还在

```
$ systemctl show dao-patrol.service -p ExecMainStartTimestamp,ExecMainExitTimestamp,Result,ExecMainStatus,OnFailure,SuccessExitStatus
ExecMainStartTimestamp=Mon 2026-09-14 00:23:49 CST
ExecMainExitTimestamp=Mon 2026-09-14 00:23:53 CST
Result=success
ExecMainStatus=0
OnFailure=dao-patrol-failure.service
SuccessExitStatus=0 1
```

`host/machine/systemd/dao-patrol.service:20,38-41` 与 `/etc` 同文：`OnFailure=dao-patrol-failure.service`；`TimeoutStartSec=600`；`SuccessExitStatus=0 1`（1 = 上轮越界已报帅，不算故障）。

本会话进程链（本轮 `pstree -asp $$`）：

```
systemd,1
  `-MainThread,2693348 /home/orca/mirasim-server/0.0.310/server.cjs --port 4316 …
      `-grok,2630651 agent --no-leader stdio
```

没有 `dao-patrol.service` 这一层。当前 HEAD `scripts/commander.mjs:2199` `cmdPatrol`（原文 `:2252-2271` 已落在 `wakeBrain` 段）：`wakeBrain(...)`（`:2255`）之后 `process.exit(patrolExitCode(...))`（`:2273`）。唤成了就是 0，4 秒内退。后面的读任务书、写观察、提交推送都不在这个进程里。

`scripts/commander.mjs:108`：`BRAIN_MAX_AGE_MS = 30 * 60 * 1000`。`cmdPatrol` 自己打出来的 JSON 字段 `reapBy: '每轮 act 的 reapBrains，超龄强关'`（同文件 `:2269`）。30 分钟到点是指挥官 act 去杀会话，不是 systemd 把 `dao-patrol.service` 判失败。`TimeoutStartSec=600` 罩的是已经结束了的那 4 秒。

### 2. 失败告警上次响是启动器没起成的时候

```
$ systemctl show dao-patrol-failure.service -p Result,ExecMainStatus,ExecMainStartTimestamp,InactiveEnterTimestamp
Result=success
ExecMainStatus=0
ExecMainStartTimestamp=Thu 2026-09-10 18:23:26 CST
InactiveEnterTimestamp=Thu 2026-09-10 18:23:30 CST
```

到本轮已 3.3 天。`scripts/patrol-failure.mjs:16` 只发一句「机制巡检没有跑成」。`OnFailure=` 的触发条件是 **被绑定的那个单元** 进 failed。`SuccessExitStatus=0 1` 把启动器的 0 和 1 都收成 success；只有 `cmdPatrol` 自己 `process.exit(2)`（任务书没写成 / 会话没唤成，当前 HEAD `:2247-2251`、`patrolExitCode` `:2104`；原文 `:2245-2249` / `:2102-2104`）才会让启动器进 failed。

本轮 `systemctl --failed` 里没有 `dao-patrol.service`，也没有 `dao-patrol-failure.service`。

没验证：09-10 18:23 那次启动器 stderr 原文（orca 读不了 journal，已报 `2026-09-08-orca读不了journal-探针连红闸没查成.md`）。按 `OnFailure` 语义，那一次是启动器非 0/1 退出。没验证：本轮若 push 失败或 30 分钟被 reap，failure 单元会不会被 start——按上面三处源码，不会。

## 建议的最小改造

删掉「`dao-patrol.service` 的退出码 = 这一轮巡检成没成」这一层。启动器只负责起会话，它的 0 只能表示「会话唤成了」。

失败告警问的应是**这一轮巡检会话有没有把观察推到 `origin/master`**（`git log origin/master --grep='\[patrol\]'` 在本轮 timer 触发之后有没有新提交；没有、且会话已经不在 = 红，再 `hub-say`）。挂在启动器 `OnFailure` 上，只能接到「没唤成」，接不到「唤成了但没干完」。
