# 机制巡检：#948 控制面闸合了，没人写状态，现役工人也不走挂载面

## 结论

今天合进 master 的控制面闸（#948 / PR #1109，`fc190ccfa`）要拦的是「会话还在跑、帅接管不上时仍 `git push` / 部署」。现场永远走「没查成不拦」：仓库里没有任何东西写 `~/.dao/control-plane.json`，这台机器上这个文件也不存在；测试把「文件不在 → unscanned → 放行」锁成绿。即便有人写出 `reachable=false`，挂载面只在 Claude `.claude/settings.json` 和 Cursor `.cursor/hooks.json` 的 PreToolUse——派工已经 `MIRASIM_IS_ONLY_PATH = true`，现役是 mirasim 下的 pi/codex，两边 settings 都没有 hooks。士兵书仍教工人 `git push -u origin HEAD`。闸在仓里绿，机器上等于没装。

## 证据

**没有写腿。** 全仓（不含 observation 副本）出现 `control-plane.json` 的只有两处，都是只读：

- `scripts/lib/control-plane-gate.mjs` 第 4 条（17–20 行）：「本文件是纯函数 + 只读探头。不写控制面状态文件」。第 31 行登记落点，377–410 行 `probeControlPlane` 读文件 / 读环境变量，文件不在返回 `state: 'unscanned'`。
- `host/machine/INDEX.md` 56 行：登记为「运行态，换机不拷」，没有写者。

`rg writeFile.*control-plane` 在 `scripts/`、`host/machine/`、`tests/`、`/etc/systemd/system` 0 命中。`systemctl list-timers` 没有名字带 control-plane 的单元。

**落点不在。** 2026-09-08 12:26：

```
$ ls /home/orca/.dao/control-plane.json
ls: cannot access '/home/orca/.dao/control-plane.json': No such file or directory
```

`DAO_CONTROL_PLANE` 不在 systemd 环境、不在 `/etc/environment`。于是每次探测都是 unscanned。`decideControlPlane`（464–494 行）对 unscanned + `git push` 明确 `block: false`。

**测试把缺口锁成绿。** `tests/control-plane-gate.test.js` 178–186 行「文件不在 → unscanned，不是断了」；224–232 行「unscanned + git push → 不拦」；307–310 行 `decideGate` 同判。dao-check 第 ⑬ 项（`scripts/lib/dispatch-gate-check.mjs`）只验 Claude/Cursor 入口还挂着 `dispatch-gate-hook`，不验落点有没有被写过、不验 mirasim 会不会进这条 hook。

**挂载面不在现役执行体上。** 仓内 `.claude/settings.json` PreToolUse 指向 `scripts/lib/dispatch-gate-hook.mjs`；`.cursor/hooks.json` `beforeShellExecution` 指向 `cursor-dispatch-gate-hook.mjs`。测试 422–437 行只锁这两处。

对照现役：

```
scripts/dao.mjs:2979  const MIRASIM_IS_ONLY_PATH = true;
```

`/home/orca/.mirasim/sessions/` 本机：claude 9、codex 593、pi 518、grok 1。`/home/orca/.pi/agent/settings.json` 的键是 `lastChangelogVersion / defaultProvider / defaultModel / theme / packages / defaultThinkingLevel / compaction / retry / httpIdleTimeoutMs`，没有 `hooks`。`/home/orca/.mirasim/setting.json` 同样没有 hooks 段。`host/skills/dispatch/templates/soldier-book-mirasim.md` 29 行仍是「然后 `git push -u origin HEAD`」，全文 0 处 control-plane / dispatch-gate-hook。

工人交卷那份 PR 正文（`/home/orca/mirasim-worktrees/windsurf-dao/dao-948/pr-body-948.md` 机制判定段）自己写了：「会，如果没人把控制面状态写成 `reachable=false`」「写探测的腿不在本单射程」。它没写第二句：写腿就算有了，pi/codex 也不会进 Claude/Cursor 的 PreToolUse。

这和 `docs/observations/2026-09-05-claude-resume-audit.md` 不是同一件事：那份立的是问题；本份对的是今天合进去的那道闸实际上没接到现场。

## 建议的最小改造

删掉「闸挂在 Claude/Cursor hook 上、状态文件有人写」这个前提。要么给 mirasim/pi 接同一份 `decideControlPlane`（在真 `git push` 前问，不靠 PreToolUse），要么把 #948 从「已合上闸」改标成「只有判定函数、没有生产挂载」。写腿未接时，静态闸应把「落点从未出现过」判成没查成并让人看见，而不是测试每次绿。
