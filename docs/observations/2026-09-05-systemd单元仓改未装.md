# 机制巡检：systemd 单元改了仓、没装上机器，活体闸仍绿

## 结论

仓里把 `OnCalendar` 补进了 `dao-agent-stall.timer`（用来挡住「只有单调时钟、停掉再起就进 active(elapsed) 永不再跑」那种死态），但这台机器 `/etc/systemd/system/` 里仍是两天前那份没有 `OnCalendar` 的文件；指挥官的两个 timer 也是同一形态，而且 `commander.mjs install` 的模板现在写出来的还是「只有单调时钟」。`dao-sync` 只拉代码、不装单元；`timer-armed` 静态闸只扫仓里的 `host/machine/systemd/*.timer`，活体闸把单调时钟的 `NextElapseUSecMonotonic` 也算「有下一次」——所以检查全绿，修没有生效。

## 证据

### 1. 仓里有 OnCalendar，机器上没有

仓内文件 `host/machine/systemd/dao-agent-stall.timer`（`a9d211a`，2026-09-05 14:30:11 +0800）含：

```
OnCalendar=*:2/15
OnBootSec=3min
OnUnitActiveSec=15min
```

机器上的活文件没有那一行。命令与输出（2026-09-05 17:06 CST）：

```
$ diff -u host/machine/systemd/dao-agent-stall.timer /etc/systemd/system/dao-agent-stall.timer
--- host/machine/systemd/dao-agent-stall.timer	2026-09-05 14:32:08.584503971 +0800
+++ /etc/systemd/system/dao-agent-stall.timer	2026-09-03 20:18:48.937080789 +0800
@@ -2,17 +2,11 @@
 ...
-[Timer]
-OnCalendar=*:2/15
 OnBootSec=3min
 OnUnitActiveSec=15min
```

`stat`：仓内 2026-09-05 14:32，`/etc` 仍是 2026-09-03 20:18。本轮巡检开始于 17:03，这份修在仓里躺了约 2.5 小时。

同一次核对，机器上缺 `OnCalendar` 的不止这一个：

```
$ grep -E '^(OnCalendar|OnBootSec|OnUnitActiveSec)=' /etc/systemd/system/{dao-agent-stall,dao-board-gc,dao-close-issues,dao-patrol,dao-sync,commander-act,commander-inventory}.timer
```

| 单元 | `/etc` 里实际有的触发器 |
|---|---|
| dao-agent-stall.timer | 只有 `OnBootSec` + `OnUnitActiveSec` |
| commander-act.timer | 只有 `OnBootSec` + `OnUnitActiveSec` |
| commander-inventory.timer | 只有 `OnBootSec` + `OnUnitActiveSec` |
| dao-board-gc / dao-close-issues / dao-patrol / dao-sync | 有 `OnCalendar` |

`systemctl show`（同轮）：

```
dao-agent-stall.timer     NextElapseUSecRealtime=   NextElapseUSecMonotonic=2d 18h 24min 31.015990s  SubState=waiting
commander-act.timer       NextElapseUSecRealtime=   NextElapseUSecMonotonic=2d 18h 25min 30.547323s  SubState=waiting
commander-inventory.timer NextElapseUSecRealtime=   NextElapseUSecMonotonic=2d 20h 59min 29.642704s  SubState=waiting
```

此刻它们还在跑（`list-timers` 的 NEXT 有墙钟时间，靠单调时钟推出来的），所以不是已经进了 elapsed 死态。缺的是墙钟点位：再停一次再起，就会回到今天上午已经咬过的那种「active+enabled、NEXT=n/a、无人报警」。

### 2. 指挥官的生成模板现在仍在写出这份缺 OnCalendar 的文件

`scripts/lib/commander-inventory.mjs:379-386`：

```
function timer(desc, activeSec) {
  return `[Unit]\nDescription=${desc}\n\n[Timer]\nOnBootSec=3min\nOnUnitActiveSec=${activeSec}\nPersistent=true\n\n[Install]\nWantedBy=timers.target\n`;
}
...
'/etc/systemd/system/commander-act.timer': timer('指挥官 act 每 20 分钟', '20min'),
'/etc/systemd/system/commander-inventory.timer': timer('指挥官盘点每 6 小时', '6h'),
```

这两个 timer 不在 `host/machine/systemd/`，是 `sudo node scripts/commander.mjs install` 现场写 `/etc`。`tests/timer-armed.test.js:48-57` 的静态闸只扫 `host/machine/systemd/*.timer`：

```
const dir = path.join(__dirname, '..', 'host', 'machine', 'systemd');
const units = fs.readdirSync(dir).filter((f) => f.endsWith('.timer'));
...
assert.match(s, /^OnCalendar=/m, ...);
```

所以：仓里手写的 timer 被闸盯着；指挥官这条生成路写出的、以及 `/etc` 里正在跑的，闸都看不见。再跑一次 `commander.mjs install`，会把「只有单调时钟」重新写进 `/etc`。

### 3. 拉到新码不会装单元；活体闸把单调时钟的「还有下一次」判绿

`scripts/server-sync.sh` 整份没有 `install-*.sh`、没有把 `host/machine/systemd/` 拷到 `/etc`、没有 `daemon-reload`。它只 `git merge --ff-only`、按需 `systemctl try-restart feishu-triage`、再跑 `onboard.mjs` 接线家目录。`d28ca91` 修的是「拉到新码 ≠ skill/pi 扩展生效」；systemd 单元这一层没有对应的接线。

活体闸 `scripts/server-check.mjs:651-666`（⑱）对每个 dao/commander timer 取 `NextElapseUSecRealtime` **和** `NextElapseUSecMonotonic`，「两个点位任意一个有值就算有下一次」。上面 `show` 的三个缺 `OnCalendar` 的 timer，Realtime 为空、Monotonic 有值——按这段代码会进「都有下一次」的绿。`tests/timer-armed.test.js` 的活体样本喂的是已经算好的 `next` 字段，没有喂「Realtime 空、Monotonic 有」这种机器上正在发生的组合。

对照：同一次 `a9d211a` 也给 `dao-sync.timer` 加了 `OnCalendar`，`/etc` 里那份是 2026-09-05 16:59（后来为了 `User=orca` / sudoers 重跑过 `install-dao-sync.sh`），所以 sync 装上了、stall 没装上。装没装取决于有没有人再跑一遍对应的 `install-*.sh`，不是取决于仓里改没改。

本轮没跑完整的 `server-check.mjs`（没验证它打印出来是不是绿），只核了对代码路径和 `systemctl show` 的输入。按 651-666 行，这三个 timer 会被算活。

### 4. 不是已经报过的那几条

已有观察里，`2026-09-05-dao-sync-root-checkout.md` 管的是 root 解释可写脚本（已处置：加了 `User=orca`）。本条是「仓改了单元、机器没装、检查还绿」，不是提权。落地清单把 `OnCalendar` 写成「已修」，指的是仓内文件和闸，不是这台机器 `/etc` 里的活文件。

## 建议的最小改造

删掉「仓内 `host/machine/systemd/` 即运行中单元」这个没人核验的假设。

闸只对一件事响：`/etc/systemd/system/` 里每个本仓单元（含指挥官 `install` 写出去的那两个）跟仓内真相源的 diff 非空就红；扫出 0 个单元也红。`OnCalendar` 静态闸把 `commander-inventory.mjs` 的 `timer()` 算进去，不要只扫手写目录。装的动作仍是人跑 `install-*.sh`——本条不要求 `dao-sync` 以 orca 去写 `/etc`。
