# root 名下的 Claude 会话在 /srv/projects/windsurf-dao 里跑 git

2026-09-18 03:45:03，`/srv/projects/windsurf-dao/.git/objects` 多出 6 个 root 属主对象（2 commit + 4 tree），
03:45:04 `refs/remotes/origin/master` 也变 root——这是一次 `git fetch`。同一时刻 root 名下有进程
cwd 在该目录：

```
/bin/bash -c source /root/.claude/shell-snapshots/snapshot-bash-1789312142088-qb921l.sh ...
journalctl -u commander-act -f --since now
```

即**一个以 root 起的 Claude Code 会话**把工作目录放在服务用户（orca）的主树里，顺手 fetch 了一把。

## 后果

dao-check「.git 属主」项红 → `land.mjs` 判红不推 → 主树领先远端 → `dao-sync` 静默拒绝快进（判例 memory
`main-tree-commit-freezes-deploy`）。这与 #1358 修掉的固定名沙盒是**两条独立的路**，都通向同一个「整台机器停部署」。

本次两次 `chown -R orca:orca /srv/projects/windsurf-dao/.git` 止血（03:44 一次 index、04:00 一次 7 个文件），
中间隔 15 分钟就再出现——**只要那个 root 会话还在那儿工作，就会一直回来**。

## 这是第三次

memory `root-owned-files-in-service-home` 已 strikes 2；上一条结论是「(21) 项是探测器不是闸」。第三次的新信息：
写入方不是 systemd 单元也不是 mirasim-remote，是**人手起的 root 会话**。所以修法不在检查器这边，在起会话那一步：
root 会话不该以 /srv/projects/windsurf-dao 为 cwd，要干活就 `sudo -u orca`。

## 建议处置

1. 找到那个 root 会话（`snapshot-bash-1789312142088`，起于 2026-09-14 左右），让它 cd 出去或换 orca 身份。
2. 要么给 (21) 配闸：主树 `.git` 加 `chattr`/ACL 让 root 也写不进（`setfacl` 挡不住 root），
   要么在 `/root/.claude/CLAUDE.md` 里写一行「本机 /srv/projects/* 一律 `sudo -u orca` 进」——后者便宜且对症。
