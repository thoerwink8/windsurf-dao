## 结论

今天（2026-09-06）合进 master 的四套新单元——`dao-gh-events`、`miraquota-contabo`、`dao-refiner`、`dao-progress-watch`，共 7 个文件——仓里有、`/etc/systemd/system/` 里一份都没有，`list-timers` / `list-unit-files` 0 行。专门为「改了仓 ≠ 装了机器」补的活体闸 ⑳，自己的测试把「机器上压根没装」锁成 `unknown` 而不是 `red`；server-check 在这台机器上没有心跳（已另报），所以连 unknown 都没人看。`dao-sync` 只拉代码不装单元——昨天定性过的根因，今天又发生了四次。

### 2. ⑳ 看见了「没装」，但把它判成没查成，测试把这条锁死

本轮用 ⑳ 自己的纯函数对这台机器实跑：

```
state: unknown
detail: 7 个单元没比成：dao-gh-events.service(机器上没装)、…（共 7 个）——没查成，不是「一致」
```

判据原文 `scripts/server-check.mjs:1052-1056`（`classifyUnitDrift`）：

```
const unreadable = pairs.filter((p) => p.repo == null || p.live == null);
...

  return { state: UNKNOWN, detail: `${unreadable.length} 个单元没比成：...——没查成，不是「一致」` };

```

`live == null`（文件不在 `/etc`）和 `repo == null`（仓内读不到）走同一条 unknown。测试把它锁成「不是 red」：

`tests/server-check.test.js:666-670`：

```
await t.test('机器上压根没装 → unknown，不是 red 也不是 ok', () => {
  const r = classifyUnitDrift([{ name: 'x.timer', repo: 'A', live: null }]);
  assert.equal(r.state, 'unknown');
  assert.match(r.detail, /没装|没查成/);
});
```

内容不一致才 red（同文件 656-664 行，喂的是两边都有文件、字不一样）。所以：**仓里新增一套单元、机器上完全没有，⑳ 的设计结论是「没查成」，不是「没装上」。** 昨天那份观察（`2026-09-05-systemd单元仓改未装.md`）处置加 ⑳ 时，针对的是「已装单元内容漂了」；「根本没装」被写成 unknown，测试守着不许改成 red。
