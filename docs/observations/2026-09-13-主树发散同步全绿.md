# 机制巡检：主树与远端发散时，dao-sync 故意 exit 0，dao-land 把 exit 1 标成成功；巡检任务书以为同步会每轮 Aborting

## 结论

巡检任务书和 `tests/patrol.test.js` 把「本地留一个没推的提交」写成 dao-sync `merge --ff-only` **每轮 Aborting**——靠这一下把整台机器的代码同步停掉，逼人必须推。活脚本从落地那天起就把同一事件吞成 `exit 0`：merge 失败只 echo 一行进 journal，单元 `Result=success`。dao-land 看见发散会 `exit 1`，但 `SuccessExitStatus=0 1`，systemd 同样 success。dao-check / server-check / 指挥官盘点 0 处读主树 ahead/behind。journal orca 读不了（已报，不另报）。

本轮现场就是这个形状：本地 `b2e6a626`（观察，21:09 未推）和远端 `698898f0`（#1212，21:46）各 1 个提交，主树停在旧码上。dao-sync 从 21:51 到 00:31 至少 33 次 `ExecMainStatus=0`。闸以为会红的那条腿，装了、在跑、每次都绿。

### 2. dao-sync：merge 失败 → exit 0，单元 success

`scripts/server-sync.sh:44-47`（本机 `/etc` 这份与仓内同文）：

```
if ! g merge -q --ff-only origin/master 2>"$ERRF"; then
  echo "主树无法快进（本地有未推提交或与远端发散），不动：$(head -c 200 "$ERRF")"
  relink
  exit 0
fi
```

`git log -L 44,48:scripts/server-sync.sh`：`exit 0` 从落地提交 `535edaba` 就在，不是后来改漏。`700e112a` 的注释自己写过「同步实际停摆，而单元照样 exit 0 看着一切正常」——那次修的是 `/tmp/dao-sync.err` 权限造成的**假**失败；真的无法快进，同一条 `exit 0` 一直留着。

`host/machine/systemd/dao-land.service:9,32` 与 `/etc` 同文：

## 建议的最小改造

删掉 `server-sync.sh:47` 的 `exit 0`。快进失败就让单元非零，进 `systemctl --failed`。巡检任务书那句「每轮都失败」和活脚本同一把尺——现在任务书按 Aborting 写，脚本把 Aborting 吞了。

不要另加一格「主树 ahead/behind」去补这条被吞掉的红。那是第二层，第一层还在绿。
