# 2026-08-31 方向：群聊 → triage → 派单（客户/伙伴入口设计，Phase 0 文档）

> 方向记录 + 分阶段施工图。用户 2026-08-31 拍板「按此四阶段走」。
> Phase 1 之前不写一行适配器代码；本机不跑任何 bot 常驻（守卫归零拍板仍有效）。

## 谁提的，什么场景

用户看到 Mirasim 官方 Discord 支持机器人的效果（自动判重建单 #2428/#2429、口语转结构化记录、
群内回执），想要同款：一个客户/合作伙伴都在的群，把问题告诉机器人，机器人自动查重、
语义化、落单，AI 接着把活干了；群聊自带上下文，不用重复讨论。

## 目标架构（一句话：群聊是入口，issue 是真相源，派单永远过用户）

```
客户/伙伴群消息
  → 渠道适配器（Discord Gateway / 飞书长连接，常驻在未来 orca 服务器；两者都不需要公网入站）
  → Triage Agent（Claude；gh 只读 + 经 #792 网关以 triage 身份写 issue）
      ① 判重：gh search issues/PR → 命中则回帖引用旧单、新信息追评
      ② 语义化：口语 → 结构化 issue（现象/复现/期望/来源消息链接），发回群里让说话人确认
      ③ 落单：新建 issue + 「待拍板」label，到此为止
  → 用户放行（群里 ✅ 或摘 label）= 已消歧 → orca 派单 → PR → 审官 → 合并
  → 进度回流：PR 开/合时 bot 把链接发回原 thread
```

## 三条设计红线

1. **外人消息只到 triage，派单必须过用户**——复用「已消歧门」（global-CLAUDE 值守条款），不造新门。
2. **判重用 `gh search`，不上向量库**——现有 issue 量级全文搜索够用，不够再议（为道日损）。
3. **真相源是 issue 不是聊天记录**——群里出结论 bot 追评进 issue；AI 干活只读 issue。
   「不重复讨论」靠双向链接（thread↔issue），不靠把群灌进上下文。

## 身份与权限

- 新增第四个 GitHub App 身份 `triage`（现有 marshal/worker/reviewer 不外借）——客户触发的
  写动作在 GitHub 历史上必须与内部动作分得开。
- triage 的全部 GitHub 写动作走 **#792 的写入网关**（本设计是它的第一个外部调用方；
  网关的 idempotency_key 正好防群消息重投重复建单）。适配器进程本身不持 GitHub 凭据。

## 四阶段（每阶段独立验收，可停在任何一层）

| 阶段 | 做什么 | 前置 | 验收 |
|---|---|---|---|
| 0 | 本文档 + 挂 #792（已完成） | — | 用户拍板「按此四阶段走」✅ |
| 1 | 买服务器，orca 编排回岗 | 先补审官质量标准（8-24 前置） | 一单端到端：卡→PR→判绿→自动合并 |
| 2 | 单渠道单群 bot MVP：判重+语义化+建单+回链接，**不派单** | Phase 1 服务器（适配器与编排同住） | 群里一句口语 → 一条合格 issue + 群内回执 |
| 3 | 派单闭环 + 进度回流 + 第二渠道 | Phase 2 跑顺 | 客户报障 → 用户 ✅ → PR 链接自动回群 |

2/3 刻意分开：「客户说话变成合格 issue」半环自身就有价值（客服台账），且不碰派单权限。

## 渠道机制备忘（选型时不用重新调研）

| 渠道 | 机制 | 备注 |
|---|---|---|
| Discord | Bot Token + Gateway WebSocket 长连，开 Message Content Intent | 出站连接，无需公网 IP |
| 飞书 | 企业自建应用 + 长连接模式收 `im.message.receive_v1` | 同样无需公网回调；国内客户主场 |
| 微信 | 无官方群 bot API | 客户在微信 ⇒ 引导进飞书群/企微，不硬接 |
| mirasim 自带通道 | 只绑用户个人，外人进不来 | 单人通知可用，群聊场景不适用 |

## 待用户补的三个信息（Phase 2 选型前必须有）

1. 客户/伙伴主要在哪个平台（决定首发渠道）。
2. 谁有 ✅ 放行权：仅用户本人，还是指定伙伴也可。
3. 服务器预算与采购时间表（Phase 1 的闸）。

## 明确不做什么

- 本机不跑适配器常驻（与 2026-08-31 守卫归零同一条纪律）。
- 不在 Phase 2 之前建 triage GitHub App（避免闲置凭据）。
- 不做聊天记录全量入库；上下文只以 issue 为载体。
