## 三问（体系类）

1. **谁提的，什么场景？** 用户看完下午的卡点（核绿后又因 master 领先整轮返工）、6 核上 20 工人 + 10 审官待着占内存，以及看门狗被拆成多个独立钟。连续几轮 grill 后拍下本文。
2. **删哪一层能让问题不存在？** 删「交卷后会话继续待着等叫醒」和「核绿后因 master 动了再审再派」。执行者按任务起止；状态只住在 git / PR 上。
3. **从零重做今天还会造它吗？** 会造：一个指挥官循环、短命会话、squash 合入。不会造：独立推一把钟、审官自己合、新 head 必复审、冲突再派一张新工。

## 容量：6 核能同时开几个任务？

**对。日常按 3 个任务同时进行来排。** 不是把上限写成死数字 3（那种填空上限已经退役），而是 6 核上的操作目标。

依据（仓内已有实测，不是感觉）：

- 准入：负载 ≥ 0.85×核数 就停收。6 核 ⇒ loadavg 到约 5.1 就不再起新会话。
- 2026-09-06：12 个工人把 6 核打到 loadavg 6.29（超订）。内存当时不是瓶颈（12 人约 2.2G）。
- 新方案下，一个任务在任意时刻最多 **1 个活会话**（工人在写 / 审官在审 / 短工在解冲突，三选一）。交卷、等审、等合、等下一个人，进程都杀掉。
- 所以「3 个任务同时进行」≈ 最多 3 个 LLM 进程，远低于 12 人打满的那次。
- 准入仍是天花板：偶尔 4 个都在干活、负载还低，可以再收一个；一打满就停。不要为了「还能再塞」把 20 个会话停在 `incomplete` 里。

同时 3 个任务 ≠ 同时 3 个工人 + 3 个审官。后一种是 6 个活进程，正是今天要拆掉的形状。

树（磁盘上的 worktree）可以按 PR 数量留着，便宜。贵的是进程。

## 目标闭环（改造完成后只剩这一条）

```
消歧 → 有空位才派工人（短会话）
  → 工人做完自查、交卷、立刻杀掉会话（树留着）
  → 交卷入队；指挥官按空位起审官（短会话）
  → 审官只在 PR 上批准或打回，立刻杀掉会话；不许自己合
        红：同一棵树起短会话按红项改，改完再杀、再入队
        绿：审查结束，进入合入
  → 指挥官当轮把所有「核绿 + 可合 + CI 绿」的 PR 一张接一张 squash
        没冲突：直接合（落后 ≠ 冲突）
        Git 能自动合进 master：脚本做，不起人
        真冲突：原树起短会话只解冲突，检查绿了就合，不再审
  → 关单、清树
```

卡住 / 没人 / 排队 / 超时杀掉 / 返工 / 合入，都是指挥官这一轮里的动作。新洞不准新开 timer。

合入是 squash：一张 PR 在 master 上变成一个提交。当轮能合几张就连续合几张，每张仍是各自一个提交，不捏成一个大包，也不等「凑齐几张再一起合」。

## 抽丝剥茧（顺序不可换）

先停出血，再删会拉长流程的层，最后才把正经腿接到指挥官上。先加新钟或先开五张单，就是又一层补丁。

1. **停出血（当天可做，代码很少）**  
   关掉「推一把」继续往待着的树上堆人；对已经交卷/已判定的会话执行 `session-stop`。树不删。没有这一步，后面每改一刀都在满载机器上打。
2. **冻结同因补丁**  
   `#1125` `#1122` `#1121` 各有两张竞争 PR。新方向未接线前，这些 PR 不按「再打一层」往 master 合。意图并进统领单。
3. **合入改对（删层）**  
   审官停止自己合；合并闸 ① 不再拦 squash；当轮连续合所有可合 PR。下午那种圈从这里断。
4. **会话改短命**  
   交卷、审官落判定，两条热路都 `session-stop`。返工/冲突只在原树起短会话。
5. **交卷入队 + 同一准入**  
   `#1125` 的意图在这里落地，不再让工人决定审官并发。
6. **冲突两档**  
   能自动合的归指挥官脚本；合不上的归短工。不要「叫醒」那个还占着内存的旧进程。
7. **看门狗并进指挥官**  
   `routeSilent` 从死代码变成真正的唤起（唤 = 起短会话，不是给死人发下一句）。删独立 `dao-nudge-stalled`。发现面不再叫醒另一个钟。
8. **收尾与制度**  
   任务书、NEW-MACHINE、initiatives 跟代码同基线；统领单关，观察条目写处置。

每一步必须自己可验收：合完 master 上的行为已经变了，而不是「文档先写完」。

## 验收总判据（统领单 `done_when` 用）

机器可当场算的，不要百分比：

1. `worker-done` 与审官落判定的生产路径会调 `session-stop`（测试钉调用，不是「文档写了」）。
2. `systemctl list-timers --all` 没有 `dao-nudge-stalled.timer`。
3. 审官 mirasim 任务书全文搜不到 `pr merge`。
4. 指挥官对 APPROVED+MERGEABLE+CI 绿的 PR 会 squash，且合并闸 ① 红不再挡住这次调用（测试钉）。
5. 活会话数在负载门下由准入收紧；交卷 N 张不会起 N 个审官（测试钉入队 + 空位）。
