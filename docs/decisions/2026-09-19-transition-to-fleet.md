# 2026-09-19 过渡态：新机制的活走新链路（fleet），老链路降级兜底

## 拍板

用户 2026-09-19 拍板（原话）：

> 「很多该实现的耽搁了。我觉得因为 windsurf-dao 是一个机制仓库，机制仓库实现新机制，还要走老机制，
> 本身就是很不合适的方式；想妥善方案。」

方案三条（见 #816 的方向评论）：**新机制的活走新链路（dogfood）；老链路降级为兜底并正式登记退役；
加一道闸：不许新机制的活依赖老链路。**

## 起因：老链路已停用、新链路刚被证明

| 事实 | 证据 |
|---|---|
| 老链路单元已全部停用 | 2026-09-19 `bootstrap-server.mjs --prune-legacy`：`dao-patrol`、`dao-refiner`、`dao-board-gc/watch`、`dao-close-issues`、`dao-gh-events` 全 `inactive + disabled`；在途僵尸工作流清零 |
| 新链路走通了首个全闭环 | issue #1454 → PR #1467 **MERGED**（`1b7e2cd88e`）→ issue **CLOSED** → workflow `completed`（证据全回读） |
| 老链路的过程开销是「耽搁」的机制性原因 | 每件新机制的活都要过工卡/审官席位/派工账/旧看板 |

⇒ 过渡空窗（老路已断、新路未验）**在 2026-09-19 合上**。

## 决策

1. **新机制的活 → 走新链路**：一个 issue = 一条 `fusionTaskWorkflow`（`packages/fleet` CLI 起），
   走 `prepare → lead → execute → verify → review → integrate → closeIssue`。
   **机制仓库造新机制，用的就是它自己造的新机制**（最强自验）。
2. **老链路降级为兜底，并登记退役**。保留的只有明确兜底场景：
   ① fleet 不可用（Temporal/worker 起不来）时的应急手改；② 需要人在树里直接操作且不适合派工的事。
   其余（工卡/审官席位/旧看板/旧派工账）**不再承接新活**。
3. **闸（并进 `repo-hygiene` 出口）**：
   - 旧链路单元保持 `inactive + disabled`（`bootstrap-server --prune-legacy` 可复现）；
   - 新开 issue 若其落地路径写着旧链路（工卡/审官/派工账）→ 红；
   - 新 PR 若来自旧链路的分支命名/身份 → 红。
4. **过渡期验收**：把「该实现却耽搁了」的真问题单（首版范围内，含 P1 #1420/#1447/#1353）
   **逐张派给新链路跑完**——跑完即证明过渡完成，**不靠声明**。

## 后果

- **不再**：新机制的活过旧派单/审官/看板；用旧链路的账本推断状态。
- **仍然**：本仓的协作约定（CLAUDE.md/AGENTS.md）、`dao-check`、`land.mjs`、PR-only master、
  issue 写动作走网关——这些是**跨链路通用**的规矩，不属于「老链路」。
- **风险与缓解**：新链路尚年轻（1 次全闭环）→ 缓解：首版范围**只装与新链路直接相关的活**（见 `docs/stages/v2.11.json`），
  并且出口判据里有「冒烟任务跑完 fleet 全闭环」这一条。
- **退役的登记方式**：本文件即退役声明；旧链路的脚本与单元**不删**（判例档案），只停用 + 本文件指明兜底边界。
