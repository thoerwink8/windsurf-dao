# 回流机制：好东西由 Agent 主动抽离，不靠用户口头提醒（2026-09-04 用户拍板，issue #888）

## 起因

用户第二次口头提这件事（第一次没落盘 = 没拍）。制度缺口很具体：
**「Agent 发现通用产物」这件事没有任何落账入口**，也没有任何闸会在它没发生时报警。
靠自觉已实证四次全哑（判机制不靠自觉，2026-09-04 拍板）；靠用户提醒 = 拿用户当闸，最贵的一种闸。

## 架构归属（帅位判定，用户认可「你自己考虑」）

| 侧 | 做什么 | 为什么 |
|---|---|---|
| **仓库侧（主）** | 产物落点（`scripts/lib` / `host/skills`）+ 机械闸（dao-check 回流闸） | 只有这里能「逼」——闸在仓里，绕不过 |
| **流程侧（辅）** | 发现点挂在**既有**两个动作上：士兵交卷自查、帅/收口官终审 | 不新建环节；新环节 = 新的会被忘掉的地方 |
| **机器人侧（不做）** | — | 机器人是通知面。判据放那儿会变成第二套账本（`admit-push` 同款教训） |

## 协议：一个段，贯穿两个方向

士兵交卷时若有可复用产物，PR 正文写 `## 回流` 段，三行缺一即红：

- **产物**：是什么
- **为什么通用**：≥2 个使用场景（说不出就别写——空段比没段更坏，它看着像做了）
- **落点**：上收总仓 / 下发 host/skills / 留原仓+指针

终审时收口官/帅当场接单，段内回写受理证据之一：`已回流：<sha>` / `回流单：#N` / `不回流：<原因>`。

**两个方向共用这一个段**：自下而上 = 子仓与单卡的产物经此段上收 windsurf-dao；
自上而下 = 落进 `host/skills` 即进**既有**分发面（符号链接 + `onboard.mjs`），不另造分发机制。

## 三层发现面（提示 → 动作 → 机械）

1. **提示层**：`host/skills/dispatch/templates/soldier-book.md` 交卷自查第 4 条（有通用产物 → 写段）。
2. **动作层**：`host/skills/dispatch/SKILL.md`「终审接回流段」——合并时三种落法 + 回写证据。
3. **机械层**：`scripts/lib/harvest-check.mjs` + dao-check 两项（样本三态常跑；live 在 `--full`，
   扫近 7 天 merged PR）。**孤儿回流段 = 有人发现了好东西但没人接** → 红，点名 PR 号。

零样本纪律：取到 PR 却正文全空 = 没查成（红），不是「大家都没写段」；近 7 天无合并 PR = SKIP，不是绿。

## 落点表

| 产物类型 | 去哪 | 分发方式 |
|---|---|---|
| 通用纯函数 / 判据 | windsurf-dao `scripts/lib` | 各仓 import / 抄用时写指针 |
| 通用技能 / 任务书 / 模板 | windsurf-dao `host/skills` | 既有：符号链接 + `onboard.mjs`（自上而下面已存在） |
| 项目专属 | 留原仓 | 写指针必须配会报警的检查（既有规矩），配不了就别留指针 |

## 派单方式

机制类走**快马**（`type/体系` 不进服务器自动派单队列，PR #877），但**不免审**——
用户 2026-09-04 明确：「快马做完，也让审官审审」。本单即按此走：帅位写码 → PR → 审官照审。

## 边界与取舍（grill-ai）

- 根因：口头设想无落账入口 + 无机械闸。
- 该不该做：该——它是唯一能让「一次性解法」变成资产的机制。
- 删哪层：**删掉「另建回流台账」这一层**。账本就是 GitHub（PR 段 + issue），不新建文件、不新建 label 体系（只用一个 `回流` label）。
- 已知不覆盖：士兵压根没意识到产物通用时，段不会出现——机械闸只能抓「写了没人接」，抓不到「压根没写」。
  这层交给审官必核清单（与 `admit-push` 同款取舍：不假装全覆盖）。
