# dao 体系重设计（从头版）

> 任务：为 windsurf-dao 从头设计最佳实践形态。用户三条出发点：① 不要内部黑话，注释言简意赅不当账本（过程叙事归 git 历史与 issue）；② 测试契约重型机制（断言基线、守卫测试）从头审视；③ 此前一切任务书与已拍结论都只是输入，可推翻。
> 本文只出设计，不动手改。出处纪律：线上来源带 URL（本机实取）；凭模型知识写的逐条标「模型知识·未核」。

## 1. 这个体系在解决什么问题

一句话：**让 AI 在「即将犯错的那一刻」做对的事。**

规则、闸、测试，全部用这一句话量。量出来的第一公理：

> **规则的价值 = 到达率 × 遵守率 × 判别力；厚度是三者共同的敌人。**

这不是立场，是本体系自己的实测（出处：本仓条款库/issue #301/#268 的当日记录）：

| 规则形态 | 实测携带率 |
|---|---|
| 文字禁令（写在文档里） | **0%**（外部研究同向：arxiv 2607.26819，模型知识·未核，本仓引用过该编号） |
| 无标记时刻的自由裁量条款 | **9–24%** |
| 固定模板槽位（不判断、照抄） | **68/68 = 100%** |
| PreToolUse 硬闸（机器拦截） | **100%**（当场拦、当场给替代路径） |

同一个体系、同一批作者，效力差两个数量级。结论不是「文字没用」，是：**文字只在「极短 + 在正确时刻出现在眼前」时有效；其余一切交给机制。**

第二公理：**机器能算的，不让人记，也不让人同步。** 派生物（从文本算出来的 JSON 清单/索引/台账）每存在一份，就要多一道「同步闸」守它，同步闸本身又要测试守它——这是自指税的根源。消灭派生物，整类守卫随之消失。

第三公理：**过程叙事有自己的家：git 历史、issue、档案 CSV。** 注释和规则正文只写「现在生效的为什么」。「哪天谁拍了什么板、返修了几轮」写进注释，等于让每个读者为考古付 token。

## 2. 目标形态：三层 + 一个出口

```
L1 根基层      常驻注入，≤150 行（≤8KB）——只有原则与路由
L2 规则层      按需触发，单文件 ≤200 行 ——判据句，触发点投递
L3 机制层      代码，零文字成本        ——拦截闸 + 出口机核 + CI
出口          交活单 schema            ——过程自由、出口收严
过程叙事       git log / issue / CSV   ——注释与正文里的「故事」全部搬去这里
```

### 2.1 L1 根基层（每轮都在，所以必须极短）

- 内容：诚实铁律（未验不声明/拿不到就写拿不到）· 减法优先 · 终审权属一句话（merge 只有人能按）· 路由表（「这类事去哪查」的五行指针）。
- 硬顶：**150 行 / 8KB**。依据：Claude Code 官方 memory 文档建议每文件 200 行以内、超长降低遵守率（见 §4 E1），本层取更严一档。
- 每条一行读得完；每条要能通过「不可再压」检查。
- **租约制**：一条规则连续一个评审周期（建议每月）没在任何真实决策里被引用 ⇒ 删。规则不是资产，是负债——每条的持有成本是每轮 token + 注意力稀释。
- 道德经引文保留为每层一句的层题（精神内核、品牌），不进判据正文。

### 2.2 L2 规则层（触发投递，不写进每轮）

- 单文件 ≤200 行（官方截断线）；单条 ≤3 行：判据句 + 一句为什么 + 至多一个例子。
- 投递三通道，按触发可靠性排序：paths 触发（改某类文件时自动出现在眼前）＞ 任务书注入（派单 spec 里渲入本节相关条）＞ 路由自读（L1 指路、开工自己读）。
- 条款库现状 92.6KB，其中 **43.8% 是修法史/出处故事**（2026-08-11 逐段审计，粗分口径）。剥离后判据正文 ≈44KB，再删「已有闸兜底」与「底座绑定」两格，**目标 ≤25KB**。

**注释规范**（用户判断①的落地，全体系通用）：

| 写 | 不写 |
|---|---|
| 为什么存在（约束/不变量） | 日期流水、谁拍的板、第几轮返修 |
| 不这么干会怎样（一句话） | 「2026-XX-XX 实证……」（归 git/issue） |
| 去哪看完整故事（一行指针） | 与现状无关的历史形态描述 |
| 头注 ≤10 行：是什么/谁消费/改前须知 | 头注写成本文件的编年史 |

**黑话政策**：一律换通用词——coordinator（帅）/ worker（官）/ review（验）/ gate（门）/ 档位直接叫模型名。**例外保留条件**：术语有唯一且常用的语义、通用词替代会丢判别力（如「对抗验证」），且首现括注。内部代号不留——它们对新 AI 与新人都是阅读税，实测不产出判别力。

### 2.3 L3 机制层（主力）

- **PreToolUse 拦截闸**：保留并继续是「禁令」的唯一合法形态（官方同见：文字是上下文不是强制，要拦动作用 hook——§4 E1）。新增规则先问「能不能写成闸」，能写闸的不许落成文字条款。
- **出口机核（交活单 schema / 已拍板的 exit-gate 六道门）**：这是「官侧条款」的新形态——工人怎么干活不设明文质量门，交出来的单必须机器可解析、声明必须与盘上对账。**条款从「管过程」改到「管出口」**，是本设计与已拍门阀方案的接合点。
- **SessionStart 体检**：改为离线跑（cron/CI/手动）+ 落盘，会话开场只读一行摘要（毫秒级）。凡需扫目录/读几十文件的检查一律不许挂在会话开场。

### 2.4 出口与过程叙事

交活单 schema（任务号/commit 清单/验证命令+真实退出码/改动文件清单）是 L2 条款的**结构化替身**：与其用 92KB 教工人怎么干活，不如用 1KB schema 规定交付物的形状。过程叙事（为什么改成这样、谁拍的板、哪几轮返修）全部归 git log 与 issue——它们天然带日期、可检索、不占每轮 token。

## 3. 测试守卫：从头审视（用户判断②）

### 3.1 先问「测试在守什么」

现状 50 套测试的构成：守拦截闸 ~12 · 守条款库自身一致性 ~8 · 守配置不漂移 ~7 · 守脚手架模板 ~6 · 守流程脚本 ~8 · 守测试系统自己 3 · 功能测试 1。

**≈90% 的测试在守「规则系统自己」，不是守产品质量。** 这就是自指税：体系的「代码」大部分是文本，文本没有编译器，于是每种「文本会怎么坏」都长出一道闸，闸又要测试守。

### 3.2 转向：规则即代码 ⇒ 测试回到正常形态

业界对照（§4 E5，模型知识·未核）：ESLint 这类 linter 的规则库没有「规则文本一致性闸」——规则是代码，测试只测**行为**（fixture 输入→判定输出）。dao 该照此分家：

| 现状部件 | 重设计处置 |
|---|---|
| 拦截闸（PreToolUse 等代码） | **保留行为测试**（mutation 先破再验照旧）——这是正常软件测试 |
| 条款索引/被守护文件清单等派生物 + 它们的同步闸 | **消灭派生物**：hook 运行时现算（毫秒~百毫秒级，可加 mtime 缓存）或直接取消 ⇒ 同步闸整类消失 |
| 条款台账（复发次数/首次入库/基线字段）+ 双向对账两套解析 | **删**。台账是过程叙事，归 git/issue/CSV（第三公理）；对账闸随之死 |
| 断言条数基线（--write-baseline 全量重扫） | **换形态**：每套测试自报「应跑 N 条」（写在测试文件头部常量里），聚合入口对账「实跑 < 应跑 ⇒ 红」。治同一个病（锚点漂了壳内断言整块消失），但**无中央派生物、无全量重扫、无基线漂移**——应跑数随测试文件同改同提交，不可能脱节 |
| 名册对账（新套忘登记的触发器） | **保留**：扫目录 vs 汇总行契约，秒级、不跑测试、无派生物（名单从盘上现扫） |
| 配置漂移检测（真机 settings 对账） | 保留瘦身：合并为一条「启动摘要」，由 §2.3 的落盘机制承载 |
| 脚手架守门 | 降为一次性校验脚本（`--check` 手动/CI 跑），不挂常驻闸 |
| 守测试系统自己的 3 套 | 随被守对象消亡而消亡 |

### 3.3 目标规模与判据

- 测试套数：**~50 → ≤20**；全量墙钟：**~6 分钟 → <1 分钟**。
- 每套测试必须能一句话回答：「它守的部件坏掉的概率 × 坏掉的后果是什么」。答不出 ⇒ 删。
- 「测试够不够」不再按覆盖率叙事，按**事故回放**：最近一次真实事故有没有对应的测试？有 ⇒ 体系在工作；没有 ⇒ 补那一条，而不是全面加闸。

## 4. 业界对照（出处纪律：线上带 URL，其余标注）

- **E1（线上，已取）** Claude Code 官方 memory 文档：「The more specific and concise your instructions, the more consistently Claude follows them」「target under 200 lines per CLAUDE.md file」「context, not enforced configuration——to block an action, use a PreToolUse hook」；HTML 注释注入前剥离（维护者笔记不占 token）。https://code.claude.com/docs/en/memory.md
- **E2（线上，已取）** AGENTS.md 开放标准：60k+ 项目采用；官方形态示例就是极简清单（setup 命令 + 代码风格各几行）——「agent 版 README」的定位本身是「短而可预期」的论据。https://agents.md/
- **E3（线上，已取）** Anthropic 多 agent 实践博客：按工种精细拆 agent（写码/测试/评审各一）是点名的反模式（交接丢上下文、协调 token 超执行 token，典型 3–10×）；强协调者可直接评估产出，独立验证步不预设；验证的合理形态是黑盒机核（跑测试报结果不需要实现上下文）。https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them
- **E4（线上，已取）** GitHub branch protection：required status checks（机检做门）+ required reviews（人审做门）+ merge queue（合并串行+合并后验证）——机器查的做门、人判断的做门、其余做评论。https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches
- **E5（模型知识·未核）** Linter 生态（ESLint/gofmt）的「规则即代码 + fixture 行为测试」形态；无「规则文本一致性闸」这一物种。
- **E6（模型知识·未核）** 注释「写 why 不写 what」是主流工程指南共识（Google eng-practices 评审指南、Linux kernel 文档均有同向表述，本次未逐页取回）。

## 5. 与已拍结论的关系（诚实清单）

**继承**：出口门阀六道（本设计的「出口」层正是它）· 终审不可让渡（进 L1）· issue 主账 · 诚实铁律 · 减法优先（本设计是它的体系级兑现）· 编排迁 Orca（投递通道 §2.2 已按 Orca spec 写）。

**推翻/修正**（逐条给理由，最终取舍归用户）：

1. **条款台账与双轨对账：删。** 它是过程叙事（第三公理），且「台账⇄正文对账」这套守卫本身就是自指税的最大单体。
2. **断言基线（中央记账版）：换形态为「自报应有数」。** 同一目标、消灭派生物与全量重扫——本条是对我自己 2026-08-11 当天所建机制的修正，算「可推翻任何一条」的诚意样本。
3. **派生物体系（条款索引/被守护清单）：消灭**，改运行时现算或取消。
4. **常驻文字量**：dao.md 从现状量级瘦到 L1 硬顶 150 行——「八句根基」保留精神，正文只留原则与路由。
5. **军衔四级/官种等内部代号**：改通用词（黑话政策 §2.2）。
6. **SessionStart 开场体检**：改离线落盘 + 一行摘要。

## 6. 度量（改没改成，拿这四个数说话）

| 指标 | 现状 | 目标 |
|---|---|---|
| L1+L2 常驻+触发文字总量 | ≈150KB+（92.6KB 条款 + dao.md + dispatch 细则 + 项目侧档） | **≤35KB** |
| worker 开工必读占 token 预算 | 37–49%（中位 73,934 token 的样本） | **<15%** |
| 测试全量墙钟 | ~6 分钟（50 套） | **<1 分钟（≤20 套）** |
| 派生物数量（需同步闸守的 JSON） | 3+（条款索引/台账/被守护清单） | **0** |

迁移原则：本文不动手；实施时每刀可 revert；**先消灭派生物、再删守它的闸、最后删被守的文字**——顺序反了会出现「闸还在守一个不存在的东西」的假绿。
