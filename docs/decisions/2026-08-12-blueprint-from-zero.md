# 从零做 windsurf-dao：蓝图（2026-08-12）

> 命题：假设这个项目今天还不存在，要从零做一个「定义 AI 如何思考/行动/协作」的规则系统，
> 它需要哪些件、每件长什么样、为什么非有不可。
> 唯一写死的前提：**这套体系的目的是服务用户的个性化编程体验，不是约束模型做事。**
> 契约：issue #324（`_tmp/issue-blueprint-0to1.md`）。现仓一切既有做法在本文中只是素材，不是约束。

---

## 一、识别问题本质（五步法第①步）

用户和 AI 一起写代码：有时结对，有时把活派出去让多个 AI 并行干。裸的 AI 宿主（Claude Code 等）
在四个时刻会让用户难受：

1. **每天开工的那一刻**：AI 不记得我的偏好——说什么语言、代码走什么流程、交付长什么样，
   每个新会话都要重新交代一遍。
2. **踩过的坑再踩的那一刻**：上个月付过学费的错误，这个月换个会话原样重犯。会话没有记忆，
   教训不写进文件就等于没发生。
3. **授权它通宵干活、自己去睡觉的那一刻**：AI 的推进是事件驱动的，等待链一断就永远沉默。
   这不是假想——2026-07-17 用户授权 8-10 小时夜间自主工作，AI 实际 3 小时后静默停摆一整夜
   （`docs/evolution/evolution-lessons.csv` L25）。
4. **不可挽回的那一刻**：密钥进了 git、数据被覆盖——这类伤害没有撤销键。本仓管理过含脱敏真实值的
   `config-sync/common-secrets.json`（不进 git），泄漏即不可逆。

**问题本质一句话**：把「这个用户想要的工作方式」变成一份机器能可靠承载的持久资产，
并且这份资产本身消耗的注意力（AI 的上下文 + 用户的阅读时间）越少越好。

它是一个**个性化层**，不是一个合规系统。这个定位是后面所有取舍的根。

## 二、挑战每项假设（五步法第②步）

现仓的每个大件背后都有一条隐含假设。逐条摆出来审：

### 假设 A1：「规则要被遵守，就必须配上闸门和测试」

这条假设驱动了现仓最大的一块体量：17 个 hook（`ccswitch/hooks/`）、18 套测试（`tests/`）、
条款元数据体系。

审：前半句里藏着一个真事实——文字规则确实是概率遵守的。现仓自己的记录最硬：
`ccswitch/rules/dao-officer-clauses.md` 的 `[#官通-body-file回读]` 条记着「我事前读过本条，
当天已经引用过它两次，仍然违反了」。**但结论推过头了**。「读了也可能不遵守」推不出
「所以每条规则都要机器守着」，只推得出**分级**：违反后果不可逆的，上机器；违反后果可逆的
（git 能回滚、下次对话能纠正），接受概率性遵守，靠使用中发现、发现了就地纠正。
给可逆错误修防护网，防护网的维护成本很快超过它防住的错误成本——18 套测试、六种退出码、
分层协议、几百行说明书，就是这条假设复利滚出来的账单。

**判决：推翻。改为「只有不可逆伤害配机器闸；可逆的一律停留在文字层」。**

### 假设 A2：「每条教训都值得变成一条带元数据的条款」

现仓条款库单条正文可达千余 token，行尾挂 `[n=] [基线:] [#slug]`，正文里嵌着两三层
「2026-07-27 补」「2026-08-07 订正」。围绕它长出了解析器、结构检查器、渲染器、注入 hook、
指针档协议。

审：教训的价值密度差异极大。少数教训真的改变行为（「长窗必设心跳」）；多数教训是
「某个具体形态的坑」，复发概率低、复发了也可逆。给所有教训统一套上重型形态，
等于给每粒沙子配一个保险柜。现仓 2026-08-11 已经自己删掉了台账和索引派生物
（CLAUDE.md「拷问局定案③」）——方向对了，但条款正文的重型形态还在。

**判决：推翻。教训只有两层归宿：改行为的，压成偏好档或手册里的一行；其余进追加式档案，
不加工、不挂元数据。**

### 假设 A3：「规则投递不可靠，所以要建注入管线」

现仓为「subagent 收不到规则」建了 `dao-subagent-clauses.js` 注入 hook、渲染管线、
指针档自声明协议，而注入率至今未审计（`dao-officer-clauses.md` 头注自己写着
「已证的是它响过，不是每次都响」）。

审：投递不可靠是真的，但病根是**常驻层超载**——正因为规则多到塞不进每次注入，才需要
按角色筛选、按需渲染、降级指针这一整套机器。如果常驻层小到永远塞得下（一份百行以内的偏好档），
投递问题就不存在：宿主的每消息注入机制本身就是可靠通道。

**判决：推翻。不修投递管线，缩小要投递的东西。**

### 假设 A4：「验证协议的精确性本身有价值」

现仓 `run-tests.mjs` 的六态退出码（0/1/2/3/4/5）、「默认层恒退 2 是正常的」、env 分层标记、
断言条数基线、串行环境要求——每一格都有真实事故做出处，逐格看全是对的。

审：逐格对，合起来错。用户的实感是判据：**跑一次测试要先读懂几百行说明书，这份阅读成本
已经超过了协议防住的错误**。协议的精确性服务的是「测试体系自身不出错」，而测试体系守护的
大头（见 A1）本不该存在。当被守护对象缩到只剩不可逆闸，六态协议失去存在理由。

**判决：推翻。检查结果的解释成本是一等设计约束：一条命令、过/不过两态、说明三行讲完。
三行讲不完的检查，重新设计或删除。**（此条是用户已拍方向，这里补的是它在推理链上的位置。）

### 假设 A5：「文档里保留每次订正的过程才诚实」

现仓文风：错误结论划线保留、订正注嵌套订正注、「作废的原文照录」。一条规则读下来
像在读地层剖面。

审：动机是好的（错误是证据链一环），但**付费方式错了**——让每个后来的读者为一次历史错误
反复付阅读费。git 历史天然保存每一版全文和改动原因，这正是它的本职。

**判决：推翻。文档只陈述现在为真的内容；过程史归 git 和 issue。**（用户已拍的
「砍掉的直接删、git 历史兜底」是同一个原理。）

### 假设 A6：「单一真相源 + symlink 部署」

审：经得起挑战。偏好要跨会话、跨项目、跨机器生效，就必须落文件、进版本控制、
一处编辑处处可见。symlink 让「改仓库文件」与「宿主生效」零延迟同步，消除了拷贝漂移。

**判决：保留。这是全系统的地基。**

### 假设 A7：「用哲学语言表达规则」

审：分两半。给**用户**看的层面，道德经的表达方式本身就是这个用户的个性化——第一性原理
写明体系目的是个性化体验，这一半成立。但内部黑话（官种、三才、收割……）渗进了操作文档，
让「没参与项目的人读不懂」，违反了体系自己的说人话铁律，也抬高了每个新 AI 会话的理解成本。

**判决：改形。哲学保留在面向用户的表达里；一切机器读的、协作用的文档用平实语言。**

## 四、从事实向上推理（五步法第④步）：需要哪些件

推理主线：F8 定目的 → F1 逼出「偏好落文件」 → F2 逼出「常驻层极小、其余按需」 →
F3+F4 逼出「机器层只管不可逆」 → F5 逼出「心跳」 → F6+F9 逼出「体检必须自发现、单层、二值」 →
F7 定演化方式（做减法可放心做）。

每件回答三问：**它解决用户的什么时刻？没有它会怎样？最简形态是什么？**

### 件 1 · 偏好档（常驻层，全系统唯一每消息注入的东西）

- **时刻**：每天开工，AI 从第一句话起就像共事多年的搭档——知道说中文、知道回答末尾给选项、
  知道 commit 怎么写、知道用户讨厌什么。
- **没有它**：每个会话重复交代；或偏好散落多处互相打架。
- **最简形态**：一份文件，**硬预算约 100 行**（数字由用户定，原则是「小到永远塞得进任何注入通道」），
  平实语言，内容只收「几乎每次对话都用得上」的偏好：语言与语气、回答收尾方式、commit/PR 约定、
  删优于加的口味、心跳纪律（见件 4）、按需手册的入口指针（见件 2）。哲学表达可以要（这是用户的
  个性化），但每句话删掉哲学外壳后必须还剩一条可执行的偏好。
- **溯源**：F1（要落盘）、F2（要极小）、F8（内容是偏好不是禁令）。A3 的判决在此兑现：
  常驻层塞得下，就不需要注入管线。

### 件 2 · 按需手册（少量场景文档，指针触达）

- **时刻**：开始某类特定任务的那一刻——要写 PowerShell 了、要派活给多个 AI 了、
  要设计产品功能了、要通宵自主干活了。
- **没有它**：要么这些知识挤进常驻层撑爆预算，要么教训丢失重踩。
- **最简形态**：个位数的 Markdown 文件（现仓 16 份 `ccswitch/rules/` 是它的膨胀态），
  每份对应一个「用户真的会遇到的任务类型」，由偏好档一行指针触达
  （「写 .ps1 前先读 X」）。每份只写现在为真的判据，不写订正史（A5 判决）。
  合并判据：两份手册若总在同一个时刻被读，就该是一份。
- **溯源**：F1、F2（常驻/按需分层正是注意力预算的实现）、A2 判决（教训的轻归宿）。

### 件 3 · 不可逆闸（机器层，全系统唯一必须带自测的部分）

- **时刻**：AI 正要做一件没有撤销键的事的前一秒。
- **没有它**：一次坏日子抹掉全部信任——密钥泄漏无法收回，这正是「概率遵守」不可接受的唯一场合（F3+F4）。
- **最简形态**：三样东西，合计越小越好——
  1. **密钥防线**：密钥文件永不进 git（放置约定 + `.gitignore`）+ 输出脱敏过滤
     （现仓 `dao-redact` 的职责）；
  2. **毁灭性操作拦截**：优先用宿主自带的配置（`permissions.deny` 类，零代码零维护），
     配置够不着的才写 hook，目标清单以「不可逆」为唯一准入判据——force push、递归删除、
     密钥外传；
  3. **每道闸配一条自测**：闸是「静默失效」型部件（挂了没人知道，F9），所以这是全系统
     唯一「必须有测试」的地方。
- **溯源**：F3（确定遵守只有机器给得了）、F4（只有不可逆值这个价）、F9（闸必须可自证活着）。
  A1 判决在此兑现：机器层的准入判据是不可逆，不是「有人违反过」。

### 件 4 · 长窗心跳（活性保障）

- **时刻**：用户说「接下来 8 小时交给你」然后去睡觉。
- **没有它**：2026-07-17 原样重演——等待链一断，AI 静默到天亮（F5）。
- **最简形态**：一条纪律 + 一个模式，不需要专门子系统——
  1. 偏好档一行：**进入长时间自主模式的第一动作是设定时唤醒**（20-30 分钟一次：
     盘点在途、悬挂则介入、无事推进下一批、用户接管则停）；
  2. 派活便签一行：**任何等待超 15 分钟，放弃该验证手段、欠账写明、带着已完成部分交付**——
     完美验证卡死不如降级交付。
  监督信号（时间驱动）与作业信号（事件驱动）必须是两条独立信道，这是 L25 的全部教训。
- **溯源**：F5。这笔学费的交代形态：**两行纪律，不是一套监控系统**——事故根因是
  「把整窗押在每个通知必达上」，处方是换信道，不是加机器。

### 件 5 · 一条体检命令

- **时刻**：合并前、交接前、换机后，用户或协调 AI 想知道「这套系统现在是好的吗」——
  并且**不想读任何说明书**。
- **没有它**：要么没人检（闸静默失效，F9），要么长回六态退出码和几百行协议（本单直接诱因）。
- **最简形态**：`dao check` 一条命令，**设计不变量**如下——
  1. **二值**：exit 0 = 好，exit 1 = 坏，没有第三种；
  2. **自发现**：检什么靠扫描（闸的自测、文件指针都能解析、部署链接活着），
     没有任何手维护的清单（F6）；
  3. **解释三行封顶**：每条失败的输出 ≤3 行且直接说怎么修；一个检查项若做不到三行讲清，
     这个检查项本身违宪，重设计或删除；
  4. **快**：秒级。慢的检查等于没人跑的检查；
  5. **检查面 = 件 3 的闸 + 结构完整性，不再有别的**。「环境敏感」「串行要求」这类需求
     出现时，优先删掉产生该需求的检查对象，而不是给协议加态。
- **溯源**：F6（自发现）、F9（闸要有人验活、但守卫只许一层——检查自己不再配检查）、
  F2（解释成本封顶）、用户已拍的理想形态。

### 件 6 · 部署器

- **时刻**：换新机器的那一刻；以及日常「改一处、处处生效」。
- **没有它**：手工拷贝 → 多副本漂移 → 哪份是真的都说不清。
- **最简形态**：一个安装脚本（建 symlink/Junction 到宿主目录 + 验证链接活着）+
  一页新机器说明。现仓的 symlink 机制原样保留（A6 判决），dao.bat 的菜单、状态矩阵、
  doctor 等属于可选的便利层，不是必需件。
- **溯源**：F1（真相源在仓库）、A6。

### 件 7 · 教训的两层归宿

- **时刻**：「今天我们学到了一个东西」的那一刻——付过的学费要能留下来。
- **没有它**：教训要么丢失（重踩），要么全部涌进规则层（撑爆预算，A2 的病）。
- **最简形态**：只有两层，归哪层看一个问题——**它改变日常行为吗？**
  1. 改变 ⇒ 压成一行，进偏好档（几乎每次用）或对应手册（特定场景用）。写不成一行的，
     先怀疑它是不是真的要改变行为；
  2. 不改变（一次性的坑、完整因果链、盘点快照）⇒ 追加进档案（现仓 `docs/evolution/*.csv`
     的形态即可），只追加、不加工、不挂元数据、不建索引。要用的时候全文检索。
  中间层（带元数据的条款库 + 解析渲染注入机器）从零不建（A2、A3 判决）。
- **溯源**：F1（要留下来）、F2（规则层有预算）、F7（档案层零维护成本才养得起）。

### 件 8 · 协作约定（多 AI 并行）

- **时刻**：用户把一批活派给多个 AI 并行干、自己只在决策点出现。
- **没有它**：多个 AI 写同一棵工作树互相踩；工人 AI 重复踩已付费的坑
  （evolution-lessons.csv L26：工人无视派单指令自行合并 PR）。
- **最简形态**：一份手册（属件 2 的一员）+ 一个便签模板——
  1. **隔离**：每路工人一棵独立 worktree，改动走分支 → PR → 用户或协调者验收合并；
  2. **派活便签**：写清目标、边界、验收方式，末尾附**十行以内**的工人纪律
     （覆写前先读、止步于开 PR、超时降级交付、与项目规则冲突时点名谁覆盖谁）。
     十行是硬预算：便签直接进工人的开工上下文，投递可靠性 100%，不需要注入管线（A3 判决）；
     现仓条款库里千 token 级的长条款，在这个形态下要么压成一行、要么归档案层。
- **溯源**：F1（约定落文字）、F2（十行预算）、F4（隔离让工人的一切错误可逆——
  worktree + PR 本身就是把「多 AI 并行」整体搬进可逆区的手段，这比任何行为规则都值钱）。

### 件 9 · 决策收口

- **时刻**：用户想知道「现在有什么事在等我拍板」，以及每轮对话结束时下一步往哪走。
- **没有它**：决策请求散落在长对话里被淹没；用户被迫全程盯着。
- **最简形态**：两条偏好（住在件 1 里，不是独立子系统）：
  1. 回答末尾给 2-4 个可选下一步；
  2. 等用户拍板的事项集中一处（issue 标签或置顶清单均可），拍了板立即落盘。
- **溯源**：F8（用户无为而系统推进，是「个性化体验」的核心一格）、F1（拍板落盘）。

## 六、防复发：这套系统怎么保证不长回现在的样子

现仓不是设计出来的，是**一次次事故的正常反应累积**出来的：每次事故加一条规则，规则怕不被
遵守就加一道闸，闸怕失效就加一套测试，测试怕误报就加一层协议。每步局部合理，合起来把
「服务用户」变成了「维护自己」。从零重做若不带结构性防复发，五个月后会长回同一个形状。
防复发靠**宪法级不变量**（写进偏好档，改它们需要用户明确拍板）：

1. **预算不变量**：常驻层 ≤ 约 100 行；工人纪律 ≤ 10 行；检查失败解释 ≤ 3 行。
   超预算时必须先删一条才能加一条——预算是防复发的第一道墙。
2. **准入三问**：任何新件（规则/手册/闸/检查）入册前必须答出「什么时刻用 / 没有它会怎样 /
   最简形态是什么」，答不出即拒。
3. **闸的准入判据只有一条**：它防的失败是不可逆的，或是静默的。可逆且会被使用发现的失败，
   不设闸。
4. **守卫单层**：`dao check` 检查所有闸；没有任何东西检查 `dao check`——它坏了会在使用中
   被发现（它的输出每次都有人看），这正是可逆失败的定义。
5. **事故后的第一问**：不是「加哪条规则能防住」，而是「**删掉哪一层能让这类事故不可能**」。
   加规则是最后手段，且要过准入三问。
6. **文档只写现真**：任何「订正」直接改成对的；为什么改，写在 commit message 里。
