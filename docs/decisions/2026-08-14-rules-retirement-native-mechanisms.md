# 2026-08-14 拍板：规则体系退役重构——从「规则约束 AI」改为「官方机制承重」

> 拍板记录，从 issue #425 落盘至此（#556 存量分流：拍板的家长住 docs/decisions/，issue 只装待办）。
> 完整论证、处置表明细与执行实录见 issue #425 正文。

## 为什么

用户用 /grill-me 五步法把整套规则体系从头拷问了一遍：一个简单任务 AI 光走流程 37 分钟；13 天 840 次提交近半在维护规则系统自己；每轮对话常驻注入几十 KB 规则文字，拖慢且降低质量。根因：把「AI 记得守规则」当承重墙。结论：**现行体系退役，换成官方机制承重的极简形态**。

真需求（用户确认的唯一标准）：**「我拍板，活被干对，不要让我操心过程；模型选最合适的，快、少出错、出错有兜底。」**

## 新世界（四层，全部官方槽位）

1. **用户层**：全局 CLAUDE.md 十几行精华（八句根基 + 一事一问 + 选项题收口 + 说人话判据）。
2. **项目类型层**：GitHub Template Repository——1 公共底座 + 3 薄层（Node / Expo / 文档仓）。
3. **项目层**：各项目自带 CLAUDE.md + .mcp.json + PR 模板，clone 即得。
4. **承重层**：任务 = draft PR（body 即任务书，push 即留痕，`gh pr ready` 即完工信号）；
   跨机接力 = `gh pr list --draft`；本机调度 = Orca 任务卡 + 决策门；兜底 = PR-first + revert + 一条 check 命令。

组织：一帅 + N 工，扁平；树帅不常设。

## 处置（概要）

- **拆**：config-sync 整套、dao 部署层、11 份规则文件、9 个 hooks、19/20 个旧测试、三条旧管线 skill、认领协议、教训 CSV 管线、issue 派单仪式。
- **留**：dao-check 核心三条（挂 CI）、PR-first + revert、docs/classics、docs/decisions、memory 降级为可丢缓存。
- **历史**：旧 issue/PR 一个字不改。

## 唯一新增的机制：修正案门槛

往体系里加任何东西，PR 必答三问：①谁提的、什么场景？②删哪一层能让这个问题不存在？③从零重做还会造它吗？守门人是模板和分档，不是常设机构。（2026-08-16 #531 补：适用面扩到新造长驻机制。）

第一批（仓库设置 + 模板仓雏形 + 新 CLAUDE.md/PR 模板/dao-check 挂 CI）与第二批大扫除均已执行；第三批（限流闹钟、批量拍门摘要）按「手动养一到两周再自动化」节奏另行处理。
