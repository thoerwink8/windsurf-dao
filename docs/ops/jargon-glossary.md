# 黑话词表

## 判定规则（jargon-scan 子命令照这条判）

命中下表「词」列的词，**同一次命中满足以下任一条 ⇒ 算已解释**：

1. **括注**：命中位置前后 20 字符内出现括号（`（`/`(`）——标准的「词（解释）」写法。
2. **举例语境**：命中词紧挨着另一个词表词，中间只隔一个 `/` 或 `、` 分隔符（比如「树帅/挂账/对抗审」）——
   这是在枚举术语本身，读者一眼就看得出这是举例，不是裸用。

**判定按"词"不按"次"**：同一张单里只要这个词有任意一次命中满足上面两条，这个词本身就不算违例——
不要求每次重复出现都重新括注一遍，首现讲清楚了就够。全部命中都不满足 ⇒ 这个词进违例清单。

**代码块（\`\`\` 围栏 / 行内 \`反引号\`）与 Markdown 表格单元格内的命中一律排除**——那两处的黑话是
标识符/枚举值本身（如 \`候选\` 标签名、表格里的判据说明），不是写给圈外人看的叙述性正文，误报率最高的就是这两处。

这是**近似判定，两个方向都举得出反例**：可能把「凑巧挨着另一个黑话词」误判成「举例」而放过真裸用
（假阴性）；也可能把「词后 20 字符内恰好有个无关括号」误判成「已解释」（假阳性）。所以这是**软闸**：
命中且判定未括注只进报告清单，脚本本身不拦截、不阻断 issue 创建（automation 每日跑一轮提醒，见 DISPATCH-HUB.md §二「候选 B」）。

## 无需括注的词（仅供参考，不进扫描）

这些词在样本里同样高频，但圈外工程师无需上下文即可读懂——进扫描只会制造噪音，不解决真问题。

| 词 | 可懂度 | 为什么无需改 |
|---|---|---|
| 真机 | 懂 | "真实设备"缩写，行业通用（本仓 `真机` 标签已删，见 DISPATCH-HUB.md §二，词偶尔仍出现在叙述中） |
| 自测 | 懂 | 行业通用 |
| 派单 | 懂 | "分配任务"缩写，行业通用 |
| 机检 | 懂 | "机器检查"缩写，行业通用 |
| 打回 | 懂 | "退回重做"是通用中文词，非本项目自造 |
