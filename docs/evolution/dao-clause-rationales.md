# dao.md 条款论证与订正史档

> **这个档承载什么**：`ccswitch/dao.md` 是 always-on 每轮注入面——它每多一个字，用户每一轮对话都付一次钱。
> 故 dao.md 正文的目标形态是 **判据句 + 载体/触发点 + `[元字段]` + 指针**，
> 而「**为什么这条是对的**」「**当初是怎么错的**」「**这个数字是怎么算出来的**」这三类内容
> 一律住在这里——它们只在**有人质疑某条条款**时才需要读，不需要每轮注入。
>
> **与 `incident-narratives-202607.md` 的分工**：那边是**事故叙事**（N1-N11，一次事故一条编号，
> dao.md 与 dispatch-clauses 双向引用）；这边是**条款的论证与订正史**，按 dao.md 的节组织
> （`§帅-n` / `§反-n` / `§归-n` / `§动-n` / `§Shell-n`），dao.md 正文里的指针形如「见 rationales §帅-1」。
> 两边都不是第二真相源：**判据的真相源永远是 dao.md 正文**，这里只放被搬出来的论证与经过。
>
> **本档不参与 always-on 注入，写多长都不花用户的每轮 token。** 故删减时优先删 dao.md 正文、
> 把原文搬来这里，而不是直接销毁——「为道日损」损的是注入面，不是记忆。

## §帅-1 · 档位实证调整：升档/降档两侧的实测数字

dao.md 帅节「档位实证调整」只留「任何档位变更都是试点+记质量对比」这条判据，两侧实测搬来这里：

**升档实证（2026-07-26 用户拍板尉档 Sonnet→Opus）**：同窗 7 官降档试点显示 Sonnet 整体合格且多次超出要求，唯一缺陷是目标压力下越权压缩判据；升档收益在**大上下文**（同窗三官实测单任务 380-434K token，读半仓再动刀的手术会撑爆小窗）与权衡质量。

**过载降级路径的出处**：同窗实证：Opus 档两遭 529 零落刀，降档后一次交付。

**workflow/agentType 那条的实测**：实测：dao 审计舰队用 `agentType:'Explore'` 未传 model，整队跑成 4.8 而非当前代 opus-5。

**限流类死亡重派判据的两句解释**（正文只留判据，理由在此）：每一次成功输出 = 池子可用性的实时探针。写「等 X 小时后重置再派」那是把死亡时刻的预告当成了重派时刻的实况。

## §帅-4 · 「写入面归谁」：为什么理由是实验前提而不是礼貌

原正文逐字留档（dao.md 现留「射程判据 + 两句判据一句话 + 派单令那一行」）：

> 不是所有测量都需要这一行，需要的是**结论会被「期间发生过什么」影响的那一类**……理由不是礼貌，是**实验前提**：测量类任务的结论建立在「自变量唯一」上，而**指挥官继续写文档就是往它的自变量里掺东西**——帅的写入既不在对照组也不在实验组，官只会把它归因到自己的动作上，于是产出一个**看起来有实据的假阳性**。

另一半射程（不必写的那类）：「此刻这个值是多少」——**别人写文件影响不了它**。

**本条的出处正是「事后才想起」**：帅派完真机官后又改了 3 次文档，靠自曝+发消息作废那段观测才补回来。

## §帅-7 · 「判定 subagent 越权前先 Grep 它自己那份记录」的出处（帅位重伤全过程）

原条款正文（2026-07-30 立、2026-08-01 路径订正）曾嵌在长窗节 ④.5 里，本次瘦身把判据提为帅节独立条款、经过留档于此：

🔴 **这一条还带出一次帅位重伤，一并记死（2026-07-30 同窗实犯）**：改这条 dao 的是一位 dogfood subagent，**它有用户直接授权**（用户原话末句「你也修改下 dao 吧」）。而帅**没收到那条消息**（用户是直接发给那个 subagent 的），于是帅：①判它「越权改全局规则」②判它「伪造用户原话」③**回滚了用户授权的改动**④当着用户的面公开指控它伪造。**四步全错，而错因只有一个**：把「**我的上下文里没有这条消息**」当成了「**用户没说过这句话**」。⇒ 那正是 L31 那一族最贵的一次实例——**「我没看到」诚实回答的是「我没收到」，不是「它不存在」**；而 subagent 的上下文与帅的上下文**本来就不是同一份**，用户可以直接对它说话。

原条款的处方段逐字留档（dao.md 正文现以判据形式保留同一处方）：

> **处方（挂在必经动作上）**：判定 subagent「越权」之前，**先 Grep 它自己那份记录找授权来源**——路径 `~/.claude/projects/<slug>/<session-uuid>/subagents/agent-<agentId>.jsonl`（有界小窗口 `-o` + `head_limit`；`<slug>` 推导与取数工艺见 `ccswitch/workflows/README.md` §transcript 一路的取数路径）。**用户中途插话有固定签名 `The user sent a new message while you were working`，Grep 它即可定位。** ⚠️ **别去 Grep 顶层 `<session-uuid>.jsonl`**：那里装的是 subagent 交回的**报告原文**，用报告证明报告等于没证；用户直接对它说的那句话只在子代理自己的记录里。**在找到之前不许回滚、更不许公开指控。**

**2026-08-01 路径订正**：原写 `tasks/<agentId>.output`——它不是不存在，而是**对正常结束的 agent 恒 0 字节** ⇒ Grep 恒不命中，失效方向 fail-safe 但处方恒静默。用本条自己那次事故的原话双向回测：新路径 5 命中、旧路径 1 命中。

## §归-2 · dao-first 次序的实证，与两条清单配套原则的正文

**dao-first 的实证**：本窗先在 mousse 建 PR 模板 + issue 中心，再固化 dao 原则，结果模板/标签/看板全是 mousse 专属、新项目一个都拿不到。dao-first 则让 canonical 住在共享仓、任何项目从它取。

**共性 rule 备案的两条配套原则**（真相源在 `ccswitch/scaffold-manifest.json` 的 `_doc` 段，此处是被 dao.md 正文搬出来的转述）：**①文件名契约**——共性 rule 必须由约定文件名承载，内容可项目化、文件名不可，否则每次「缺项」报告都可争议；**②例外显式化 > 例外隐形**——例外逐条写 `exempt: [{repo, why}]`，元仓库不再整体豁免（原状是检查从不跑到立法者头上，于是没人发现它自己违规）。

**STAR/折叠证据条被搬出来的两处括注**（逐字留档；dao.md 正文保留三条硬要求与判据句）：

> ③**技术证据进 `<details>` 折叠段**：精度数字一个字不删、折叠起来，**人读顶部、AI 读全部、零丢失**（AI 本就读全文，折叠不伤它；不写人话才伤人）。判据：**没参与项目的人扫一眼顶部知不知道发生了什么。** 落地：PR 用 `.github/pull_request_template.md`（分层内建），issue 模板同理；这是「说人话」原则（本就贯穿续力选项/AskUserQuestion）在**人读载体**上的延伸，不是新原则。

另一处同源表述（工作项三态归位节的 issue 中心条）：**为什么不伤 AI**：AI 本来就读全文，折叠不影响它；受益的是人不用在密文里捞。

## §Shell-1 · PR 合并链三条边界的成因

**①「事后提醒不是守卫」的机制**：PostToolUse 在命令跑完之后才触发。

**③「`--delete-branch` 的沉默不可信」的机制**：本地分支被 worktree 占用时它整体失败、错误只提本地 ⇒ 远程也没删。

## §Shell-2 · patch-id 复核：那次「疑似遗失工作」的实况

**`--is-ancestor` 为什么失明**：本例正是：孤儿 commit 与 main 上某个 commit 作者、时间戳、message 逐字相同，`--is-ancestor` 照样判「未并入」。

**为什么「开 PR 反而有害」**：本例若照令开 PR，其相对当前 main 的差异恰好是一个 release commit 的反向，等于提议回滚该版本与随行的六笔账。
