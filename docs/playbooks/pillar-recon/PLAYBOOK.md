# 支柱工作法 · 产品定位战役 Playbook

> 「品 · 产品之思」的宏观层：功能级用场景心法（dao.md 品节），产品级定位用本战役。
> 蓝本：2026-07-17 mousse-cli 支柱大侦察（52 agent，合成判读见 mousse 仓库 `docs/research/pillar-recon-20260717.md`）。
> L27 铁律：进 dao 的只有**过程**；某个产品的支柱结论（那 13 根）留在该产品仓库，绝不进 dao。

## 生命周期（七步）

1. **直觉假设**：创始人口述几根支柱（支柱=产品价值维度假设，不是 feature 清单）
2. **仓库对账**：帅逐根核实现状（已建成 / 半建成 / 仅骨架），不凭记忆断言
3. **全盲侦察挑战假设**：多路互盲侦察防创始人视野框死自己——三种模态混编：竞品痛点挖掘（竞品 issues=免费用户调研）× 第一性原理透镜 × 仓库盘点（找「已有地基没长出楼」的）→ `pillar-recon.workflow.js`
4. **聚类 + 对抗评审**：opus 聚类成候选支柱 → 每根双镜评审（A 用户价值×差异化 / B 可行性×商业），给分吝啬
5. **查漏批判 → 定向补盲**：opus 查漏官找结构性盲区；商业项目必照**三面镜子**再定路线图：**克制**（该少做什么/宿主自身开销，防功能军备竞赛）· **蒸发测试（双闸，见 §5.1）** · **变现**（免费付费边界；gate 错东西比不 gate 更伤）→ `blindspot-recon.workflow.js`

### §5.1 蒸发测试是**双闸**，不是一闸（2026-07-27 补，用户拍板）

一根支柱要判「结构性可防御」，**两道闸都要过**：

| 闸 | 问句 | 判 FAIL 的含义 |
|---|---|---|
| **厂商吞闸**（原有） | 平台厂商一个 release 会不会把它原生化吞掉？ | vendor-killable，别投 |
| **同侪闸**（新增） | **第三方竞品是不是已经占了这块？** | 位置还在，但你去了是第 N 名——不是护城河 |

**为什么必须补这一闸**：厂商吞闸问的是「会不会被杀」，答 PASS 只证明**没人会来杀你**，
不证明**这块地还空着**。蓝本战役里有一根支柱厂商吞闸 PASS 却仍无护城河，
逐层追问「到底谁做不到」才发现同侪早已发布同一套形态——**一根只值中等功能的柱子
会持续误导「哪根最短」的选题排序**，故它该降级，而原判据看不出这一点。

**怎么查（可照做）**：对每个候选支柱，取 3-6 个同侪（含长尾 GUI 壳/包装器，不只看头部），
逐个查 README/官网/`gh api` 文件树+commit message，**结论按「哪一半被占、哪一半没被占」逐条写**，
不写笼统的「已被占/未被占」。

**判决形态：拆成两半，别整根判生死**。同侪闸的常见真实答案是「**部分已占**」，
此时正确产出是 ①正面承认被占的那一半，并据此**改判该半的候选方案**（在别人已做且用户已拒绝过的形态上当第三名，是双重负分）
②逐条说清没被占的那几条**为什么**没被占（触发条件不相交 / 形态不同 / 结构上做不到），而不是笼统宣称「缺口存在」。

**这一闸的诚实边界（每次都要写）**：查的是**公开描述**（README/官网），
「没描述」≠「没有」；抽样不是穷尽；竞品在动，结论应挂进既有的增量扫节律里定期复核。

**范例（只作形态示例，产品结论按 L27 留在产品仓）**：2026-07-27 mousse-cli 的
`docs/kit/only-user-outlet/scoping.md` §5 是本闸第一次真实产出——两个同侪（其中一个 1831★）
被查出**已占「瞬时提醒」那一半**，直接改判了该批的一个候选入口形态；
同批 `docs/kit/audit-trail/scoping.md` 则是双闸皆过的写法参照。
6. **终版落地**：帅合成终版支柱图 → 落项目 `docs/POSITIONING.md`（北极星），此后选题与长窗自主排程以它为镜（问「哪根最短/最防御」，不问「竞品有没有」）
7. **重跑时机**：市场剧变 / 产品形态大转 / 厂商原生化吞掉某支柱时

## 复用脚本（换 CTX 与透镜清单即可移植）

## 军规

- 侦察兵 prompt 必带：Grep-first 军规（禁 shell grep/find/rg）+ 来源强制（无来源即废）——本次 6 个评审官违例的教训
- 查漏官必设：没有查漏的侦察 = 创始人视野的回声室
- 侦察各路必须互盲：同一 prompt 模板不同角度，禁止共享中间发现
- 原始数据必归档进产品仓库（raw.json），帅合成判读另写一份人读版
