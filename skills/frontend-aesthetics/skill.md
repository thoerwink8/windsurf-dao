# 前端审美术 · Frontend Aesthetics

> 少则得，多则惑。

## 适用场景

- VS Code 侧边栏/Webview 面板设计
- 仪表盘、监控面板、状态显示
- 任何宽度 < 400px 或注意力碎片化的界面

## 核心认知

**审美不是装饰，是信息传递效率。**

好的界面 = 用户在最短时间内获取最多有效信息。
- 1秒内看懂整体状态 → 成功
- 需要阅读文字才能判断 → 失败
- 需要滚动才能概览 → 失败

## 四步法

### 一、约（☶止·识别约束）

设计始于约束，不始于灵感。

**必须回答的问题：**
- 可用空间是多少？（VS Code 侧边栏 ~250-350px 宽）
- 用户注意力模式？（盯着看 vs 瞟一眼 vs 主动查询）
- 数据有多少？（3个账号 vs 300个？）
- 刷新频率？（实时 vs 手动？）
- 宿主环境的视觉语言？（VS Code 暗色主题、CSS 变量体系）

**约束不是限制，是设计的骨骼。** 没有约束的设计是无根的。

**产出：** 约束清单（空间·注意力·数据量·刷新·宿主）

### 二、层（☲视·信息分层）

> 万物并作，吾以观复。

人一次只能处理一层信息。三层是极限。

**通用三层架构：**

| 层 | 功能 | 视觉占比 | 交互 |
|----|------|---------|------|
| 总览层 | 一眼看到全局健康度 | 15-20% | 无（纯展示） |
| 列表层 | 扫描每个个体状态 | 60-70% | 点击/hover |
| 操作层 | 需要时才出现的操作 | 10-15% | 展开/收起 |

**列表层的一行一世界原则：**
- 每行必须自包含——不看其他行也能判断这一行的状态
- 关键指标靠右对齐——眼睛沿右侧扫描比左侧高效
- 状态用颜色/图标，不用文字——`●` 比 "正常" 快 10 倍

**产出：** 信息层次图（哪些信息在哪一层，优先级排序）

### 三、色（☵听·语义色彩）

颜色是最快的信息通道——比文字快 200ms。

**铁律：颜色必须有语义，无语义的颜色是噪音。**

**三色系统（多数场景够用）：**

| 语义 | 色值（暗色主题） | 使用场景 |
|------|----------------|---------|
| 充裕/正常 | `#4ec9b0`（翠绿） | >50% 余量、活跃、健康 |
| 注意/中等 | `#dcdcaa`（暖黄） | 15-50%、即将到期、需关注 |
| 危险/耗尽 | `#f44747`（警红） | <15%、错误、不可用 |

**进阶规则：**
- 三档跳变，不做连续渐变——清晰 > 精确
- 颜色搭配 VS Code CSS 变量（`--vscode-terminal-ansiGreen` 等）
- 面积越大颜色越淡，面积越小颜色越饱和（进度条 vs 文字）
- 灰色 = 无数据/不适用，不要用灰色表示"坏"

**产出：** 色彩方案（每个颜色的语义 + 使用位置）

### 四、密（☳触·密度与呼吸）

**信息密度的真谛：不是塞满，是精简后的紧凑。**

```
╳ 低效密度（看起来"满"，实际信息少）：
┌─────────────────────────┐
│ 邮箱: user@example.com  │
│ 状态: 正常              │
│ 日额度: 68%             │
│ 周额度: 85%             │
│ [切换] [删除]           │
└─────────────────────────┘
5行传递4个信息 = 0.8 信息/行

✓ 高效密度（看起来"简"，实际信息多）：
● user@ex..  D68% W85%  ⬆ ✕
1行传递5个信息 = 5 信息/行
```

**密度技法：**
- **缩写约定**：D=日额 W=周额 %= 剩余百分比——建立后不需要解释
- **图标替代文字**：`●○◌` = 活跃/可用/不可用，`⬆` = 切换
- **hover 展开**：常态只显示关键指标，hover 显示完整信息
- **对齐即结构**：左对齐名称、右对齐数字——不需要分隔线
- **留白是信息**：行间距 > 行内间距 = "这是不同的行"

**产出：** 单行信息模板 + 交互展开方案

## 技术选型（约的延伸）

> 朴散则为器。器的选择不是审美问题，是约束问题。

视觉设计之前，先选对工具。选型原则同"约"——从约束出发，不从偏好出发。

### 嵌入式 UI 的三个特殊约束

| 约束 | 原因 | 影响 |
|------|------|------|
| **无热更新** | iframe/sandbox 隔离，改代码必须重载宿主 | 框架的 HMR 优势归零 |
| **单视图** | 侧边栏/面板通常是一页，不是 SPA | 路由/组件复用场景极少 |
| **体积敏感** | 每增 100KB 影响安装和启动 | 运行时越小越好 |

这三个约束让框架的核心优势（热更新、路由、组件复用）全部失效。剩下的只是框架带来的构建复杂度。

### 选型决策树

```
UI 复杂度？
├─ 低（单视图，<500行）→ Vanilla JS/TS，零框架
├─ 中（多面板，500-2000行）→ Vanilla + 结构化模板函数
└─ 高（多页面，>2000行，团队协作）→ 考虑 Svelte（编译后无运行时）

后端复杂度？
├─ 低（纯 UI 展示）→ 保持 JS，无构建
├─ 中（API 调用、状态管理）→ TypeScript + esbuild
└─ 高（协议编解码、数据库操作、加密）→ TypeScript 必须

构建工具？
├─ 无构建需求 → 直接运行
├─ 仅后端 TS → esbuild（亚秒级，VS Code 官方推荐）
└─ 前后端都需构建 → esbuild 双入口 或 Vite
```

### VS Code 扩展的推荐架构

**后端 TypeScript + 前端 Vanilla + esbuild**

验证来源：wf-dialog v5.9.3（复杂度远超一般扩展，50+ CSS 类，多页面导航）选择了完全相同的架构——TypeScript + Webpack 后端，纯 Vanilla 前端。

- 后端：TS 的类型安全保护复杂逻辑（协议编解码、SQL 操作、认证流程）
- 前端：Vanilla 的零开销匹配嵌入式约束
- 构建：esbuild 比 webpack 快 100 倍，配置量 1/10
- 前端结构：模板函数 + CSS 变量体系 + `getState()/setState()` 持久化

### 反选型模式

| 病 | 典型表现 | 治 |
|----|---------|-----|
| 框架迷信 | "用 React 因为我熟" | 从约束出发，不从偏好出发 |
| 过度工程 | 为 300 行前端上 Svelte + Vite + Tailwind | 问"构建链复杂度是否 < 它节省的开发时间？" |
| 工具包依赖 | 引入已废弃的 @vscode/webview-ui-toolkit | 查生命周期状态。2025年已废弃，社区替代品稳定性待验证 |
| 一致性执念 | "前后端都要 TS" | 前端 300 行 DOM 操作的类型收益趋近于零 |

## 反模式

| 病 | 症 | 治 |
|----|----|----|
| 代码逆向UI | 试图从混淆代码中还原他人的CSS | 截图是最好的设计文档。视觉参考 > 代码分析 |
| 先码后设计 | 直接写HTML/CSS，边写边想布局 | 先画信息层次图（纸上或脑中），再码 |
| 卡片病 | 每个条目一个大卡片 | 卡片吃纵向空间。列表项一行即够 |
| 彩虹病 | 5种以上颜色各有含义 | 三色系统。更多语义用形状/图标区分 |
| 精确病 | 显示 67.3% 而不是 67% | 用户不需要小数点。整数 + 颜色已够 |
| 标签病 | "日额度: 68%" 而不是 "D68%" | 空间受限时，约定 > 说明 |

## VS Code Webview 速查

```css
/* 必用的 CSS 变量 */
--vscode-font-family          /* 字体 */
--vscode-font-size            /* 基础字号 */
--vscode-foreground           /* 前景色 */
--vscode-sideBar-background   /* 侧边栏背景 */
--vscode-list-hoverBackground /* 行 hover */
--vscode-focusBorder          /* 焦点边框 */
--vscode-input-background     /* 输入框背景 */
--vscode-badge-background     /* 徽章背景 */
--vscode-descriptionForeground /* 次要文字 */

/* 字号层次（不超过3级） */
11px — 次要信息、标签
13px — 主要内容（默认）
14px — 标题、关键数字

/* 间距节奏 */
4px — 行内元素间距
8px — 行间距
12px — 区块间距
```

## 与其他 Skill 的关系

```
逆向拆解术    →  理解他人的 UI 实现
边界探测术    →  确认宿主环境约束
前端审美术    →  在约束中创造美
```

逆向告诉你别人怎么做的，探测告诉你你能做什么，审美告诉你应该做什么。
但注意：**逆向 UI 时，截图 > 代码。** 设计意图在视觉中，不在实现里。
