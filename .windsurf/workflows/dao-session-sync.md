# Session Sync · 元会话同步

> 致虚极，守静笃。万物并作，吾以观复。

## 机制说明

**核心机制：git + 文件系统**（无需其他会话配合，无需会话ID）

- `git log + git status` — 各会话提交的代码是最可靠的工作产出记录
- `TODO.md / FUSION_PLAN.md / AGENT_GUIDE.md` — 项目状态的单一真相来源
- 文件修改时间 — 补充感知"最近谁动了什么"

**可选补充：trajectory_search**（如果用户提供了其他会话 ID，可读取对话上下文）

---

## 步骤

### 1. 读取 git 状态

```
git log --oneline --all -20 --format="%h %ad %s" --date=format:"%m-%d %H:%M"
git status --short
```

### 2. 读取项目状态文件

按优先级读取（存在则读，不存在跳过）：
- `TODO.md` — 任务完成情况
- `FUSION_PLAN.md` — 迁移/融合计划进度
- `AGENT_GUIDE.md` — 最新版本号 + 教训记录

### 3. 扫描近期文件变动（补充）

查找最近1小时内被修改的源文件：

```
git diff --name-only HEAD~5 HEAD
```

### 4. 输出全局报告

格式：

```
## 项目状态 · HH:mm

### 最近提交（来自所有会话）
- [时间] commit — [内容]

### TODO 完成度
- ✅ 已完成：...
- 🚧 进行中：...
- ❌ 未开始：...

### 工作树状态
- clean / 有 N 个未提交变更

### 📋 评估
[基于TODO.md + git log的整体完成度判断]

### 🎯 下一步建议
[基于剩余TODO项，给出优先级最高的下一个任务]
```

### 5. 可选：读取其他会话对话内容

如果用户提供了其他会话的 Conversation ID（格式：`@[会话名]`），
调用 `trajectory_search` 读取该会话的最新动态，补充到报告中。

否则跳过此步骤——git 已经是足够完整的状态来源。

---

## 注意

- **不需要其他会话做任何配合**——git 是天然的共享状态
- 会话对话内容是"过程"，git 提交是"结果"——结果比过程更可靠
- 如果某个会话有大量未提交工作，让用户切换过去先提交，再回来 sync
