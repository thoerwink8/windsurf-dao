# /thread-tree · 对话线索树

> 万物并作，吾以观复。夫物芸芸，各复归其根。

## 三种模态

| 模态 | 触发 | 行为 |
|------|------|------|
| **分析模式** | `/thread-tree` 或 "梳理一下" | 分析对话 → 输出树 → 可选沉淀 |
| **解决模式** | "处理 Open Threads" 或 "整理 TODO" | 读取 TODO.md → 逐条推进 → 实时写回 |
| **混合模式** | 分析时发现 TODO.md 有旧项 | 先输出当前树 → 合并旧项 → 一起处理 |

AI 根据上下文自动判断模态：
- 对话中有多轮交互 → 分析模式
- 用户提到 Open Threads / TODO / 未解决项 → 解决模式
- 两者都有 → 混合模式

## 作用域

| 模式 | 触发方式 | 数据源 |
|------|---------|--------|
| **L1：当前对话**（默认） | `/thread-tree` | 当前对话上下文 |
| **L2：指定历史对话** | `/thread-tree` + @某个历史对话 | `trajectory_search` 检索指定对话 |

- L1 是默认模式，AI 直接分析当前上下文
- L2 需要用户通过 @mention 引用历史对话，AI 用 `trajectory_search(ID, "")` 获取全量内容后分析
- 两种模式的分析流程完全相同，只是数据源不同

## 执行流程

### 一、扫描（观）

回溯当前对话的完整上下文，逐轮识别：

1. **用户发起的每个独立问题/需求**（不是 AI 的反问）
2. **每个问题的触发源** — 是全新问题，还是从某个回复的某一点分叉出来的追问
3. **每个问题是否得到了实质性解答**

识别规则：
- 用户中断 AI 回复并提新问题 → 新分支节点
- 用户对 AI 回复的某一点追问 → 子节点（挂在触发它的父问题下）
- 用户跳回之前的话题 → 回链到原节点
- 用户提出完全无关的新话题 → 新根节点

### 二、分类（行）

为每个问题节点标注状态：

| 状态 | 标记 | 判定标准 |
|------|------|----------|
| 已解决 | ✅ | AI 给出了实质回答，且用户未表示异议/继续追问该点 |
| 未解决 | ❓ | 问题被提出但未得到回答（被中断/遗漏/AI 跳过了） |
| 部分解决 | 🔄 | AI 回答了一部分，但用户中断导致未完成，或答案不完整 |
| 已替代 | ⏭️ | 后续问题使该问题不再需要回答（需求变更/方向调整） |
| 进行中 | 🔨 | 当前正在处理的问题 |

判定边界：
- 用户说"好的"/"明白了"/"可以" → 该节点 ✅
- 用户没回应就跳到下一个问题 → 上一个问题 **默认 🔄**（可能满意但未确认，也可能被遗忘）
- 用户明确说"不对"/"再想想" → 该节点 ❓

### 三、构建（验）

组装成树形结构输出。格式：

```
🌳 对话线索树（共 N 个问题，✅M 已解决，❓K 未解决）

📌 根问题 1：[一句话描述] ✅
   ├── 追问 1.1：[描述] ✅
   │   └── 追问 1.1.1：[描述] ❓
   └── 追问 1.2：[描述] 🔄

📌 根问题 2：[描述] ❓

📌 根问题 3：[描述] ⏭️
   └── （被根问题 2 替代）
```

原则：
- 一句话描述 = 问题的核心诉求，不是原文复制
- 层级反映逻辑关系，不是时间顺序
- 如果某个问题跨越多轮讨论，标注涉及的大致轮次范围

### 四、洞察（省）

在树之后补充：

1. **未解决清单** — 列出所有 ❓ 和 🔄 节点，按优先级排序，并标注**意图类型**：

   | 类型 | 标记 | 含义 | autopilot 权限 |
   |------|------|------|---------------|
   | 待决策 | 🔀 | 讨论了多个方案，还没选 | 🔴 红灯：不可自动执行 |
   | 待确认 | ✋ | 方案已讨论，但用户未明确认可 | 🟡 黄灯：高置信可推进，需标注假设 |
   | 待执行 | 🔨 | 已确认要做，但还没做 | 🟢 绿灯：可自动执行 |

   > 类型标记是 AI 的执行权限系统，不只是给人看的标签。

2. **断裂点** — 哪些地方用户中断导致信息丢失最严重
3. **建议** — 下一步应该先处理哪个未解决问题，为什么

### 五、沉淀（归根）

> 万物归根，归根曰静。对话是流水，文件是沉淀。

将有价值的未解决项写入 `TODO.md` 的 `## 🌳 Open Threads` 区域，使其跨对话持久存在。

#### 5.1 筛选

不是所有未解决项都值得沉淀。过滤规则：

| 沉淀 | 不沉淀 |
|------|--------|
| 影响后续工作方向的决策 | 即兴的好奇心问题 |
| 阻塞具体任务的确认项 | 已被替代（⏭️）的问题 |
| 明确要做但未执行的任务 | 纯知识性问答（答案已给出但未确认） |

#### 5.2 格式

写入 `TODO.md` 时，在 `## 🌳 Open Threads` 区域追加（若该区域不存在则创建）：

```markdown
## 🌳 Open Threads

- [ ] 🔀 **[问题标题]**：[一句话描述]
  > 来源：[日期] | [背景/选项摘要]

- [ ] ✋ **[确认项标题]**：[方案描述]
  > 来源：[日期] | [待确认的具体内容]

- [ ] 🔨 **[任务标题]**：[要做什么]
  > 来源：[日期] | [阻塞于/依赖于什么]
```

- 类型前缀（🔀/✋/🔨）= AI 执行权限标记，autopilot 据此判断自主权限
- `> 来源` 行提供上下文，使条目脱离对话仍可理解
- 已解决的条目打 `[x]` 并追加解决日期

#### 5.3 合并策略

如果 `TODO.md` 已有 Open Threads 区域：
- 检查是否有重复项（同一问题在之前的对话中已记录）→ 更新而非重复添加
- 检查是否有已在本次对话中解决的旧条目 → 标记 `[x]`

#### 5.4 半自动确认

沉淀前，用 `ask_user_question` 展示待沉淀条目列表，让用户确认：
- 哪些要写入
- 哪些不需要
- 用户确认后才执行写入

> 品味而知止（☶味）—— 不替用户决定什么重要，但替用户承担执行。

## 解决模式

> 千里之行，始于足下。一条一条来。

当用户说"处理 Open Threads"、"整理未解决项"、"逐个解决"时进入此模式。

### R1、加载

读取项目 `TODO.md` 的 `## 🌳 Open Threads` 区域，提取所有 `- [ ]` 条目。

若无 Open Threads 或全部已 `[x]` → 告知"无待处理项"，结束。

### R2、排序

按优先级排序：
1. 🔀 待决策（阻塞性最高——后续确认和执行可能依赖它）
2. ✋ 待确认（次之——方案已有，只差点头）
3. 🔨 待执行（最低——已确认，AI 可自动做）

同类型内，按依赖关系排序（被依赖的优先）。无依赖关系则按时间先后。

### R3、逐条推进

展示总览后，逐条处理：

```
📋 Open Threads 共 N 条未解决（X🔀 Y✋ Z🔨）

━━━ 第 1/N 条 ━━━
[类型标记] [标题]

背景：[从 > 来源行提取的上下文]
[针对类型的具体内容]
```

**各类型的处理方式**：

#### 🔀 待决策

1. 展示背景和可选方案
2. `ask_user_question` 提供选项（从来源上下文提取）+ "跳过" 选项
3. 用户选择后：
   - 记录决策结果
   - **立即**更新 TODO.md：`- [ ]` → `- [x]` 并追加决策内容和日期
   - 若决策产生新的执行项 → 在 Open Threads 追加 🔨 条目

#### ✋ 待确认

1. 展示待确认的方案
2. `ask_user_question`：确认 / 修改 / 拒绝 / 跳过
3. 用户确认后：
   - **立即**更新 TODO.md：`- [ ]` → `- [x]` 并追加确认日期
   - 若确认产生新的执行项 → 追加 🔨 条目
   - 若拒绝 → 标注拒绝原因，条目保持 `[ ]` 或改为新的 🔀（需要重新决策）

#### 🔨 待执行

1. 告知用户"这是执行项，我直接做"
2. AI 执行任务（编辑文件/运行命令/etc.）
3. 验证完成后：
   - **立即**更新 TODO.md：`- [ ]` → `- [x]` 并追加完成日期

### R4、汇总

全部处理完（或用户说"够了"）后，输出汇总：

```
📊 本次处理：M/N 条
🔀 X 决策已拍板
✋ Y 确认已通过/拒绝
🔨 Z 任务已执行
⏭️ W 条跳过（仍为 [ ]）

Open Threads 剩余：K 条
```

### R5、续力

`ask_user_question` 提供选项：
- 若有跳过项："继续处理跳过的项"
- 若全部完成："Open Threads 已清空" + 下一步建议
- 始终包含："结束，不再处理"

## 分析模式续力

分析模式（一～五）完成后，调用 `ask_user_question` 提供选项：
- 至少一个"继续处理最重要的未解决问题"
- 至少一个"沉淀未解决项到 TODO.md"
- 若 TODO.md 已有旧 Open Threads："一并处理历史 Open Threads"
- 至少一个"全部已了解，结束梳理"

## 注意事项

- **不遗漏** — 宁可多标记一个可疑节点，也不漏掉未解决的问题
- **简洁** — 树形图本身应该一屏能看完，详细说明放在下方
- **对话极短时**（< 3轮）— 直接告知"对话较短，无需梳理"，不强行输出
- **沉淀是可选的** — 如果用户只想看树不想写文件，尊重选择
- **解决一条写一条** — 每解决一条立即写回 TODO.md，防止对话中断导致丢失
- **可以跳过** — 任何条目都可以跳过，不强制全部解决
- **决策可产生新项** — 🔀 解决后可能产生新的 🔨，直接追加到 Open Threads
