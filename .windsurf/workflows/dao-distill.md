# 知识沉淀 · Distill

> 致虚极，守静笃。万物并作，吾以观复。

## 触发条件

- 用户显式调用 `/distill`
- 用户想综合本会话多轮任务的教训，统一写入文档

> **注**：单次任务的教训提炼已内置于 `/dao-cycle` 涅槃流程。`/distill` 用于**会话级全量扫描**——处理本会话内所有未被单次涅槃捕获的洞察。

## 流程

### 一、识（☲视·扫描全会话）

回顾**本会话从头到尾的全部内容**，识别所有可复用的洞察：

- 踩坑经验：做了无效尝试、发现外部系统行为与预期不符、推翻假设
- 新模式/反模式：发现了更优做法，或确认了某种做法不可行
- 架构/设计决策及理由
- 工具/库/API 的正确用法（与文档/预期不一致的部分尤其重要）
- 命名/约定/风格的新共识

### 二、去重（☶艮·先查再写）

读取目标文件（至少读 `AGENT_GUIDE.md §教训`），检查：

- 哪些洞察已有记录 → 跳过
- 哪些是新的 → 进入写入步骤
- 哪些与已有内容冲突 → 替换旧内容并注明原因

### 三、写（☳触·直接写入）

不需要 `ask_user_question` 确认——用户触发 `/distill` 即是授权写入。

每条新洞察按类型路由到对应文件：

| 知识类型 | 归属 |
|---------|------|
| 教训（踩坑/假设被推翻/反模式） | `AGENT_GUIDE.md §教训` |
| 架构/设计决策 | `AGENT_GUIDE.md §架构决策` |
| 开发操作指南 | `AGENT_GUIDE.md §开发指南` |
| 行为准则（怎么思考/工作） | 道德法术层规则文件 |
| 领域技能 | `skills/` |

**教训写入格式**（严格对齐 `AGENT_GUIDE.md §教训` 现有格式）：
```
| T[下一个编号] | **教训标题** | 版本 | 踩坑现象 → 根因 → 正确做法 |
```
同时在演化索引对应行的「关键教训」列追加编号。

写入时遵循：
- 不重复已有内容（已在第二步去重）
- 冲突时替换旧内容并注明
- 追加到对应章节末尾，保持文件结构不变

### 四、虚（☴巽·清理残留）

> 万物归根，归根曰静。

检查当前会话中系统检索到的 Memory 列表：
- 与本次写入内容相关且已被文件完整覆盖的 → 直接删除
- 未完整覆盖的 → 补充写入后再删除

**原则：规则文件 > 项目文档 > Skills > Memory。Memory 一旦写入文件即应清理，不留残存。**

## 跨窗口说明

> 各 Cascade 会话彼此隔离，无法实时感知其他窗口内容。

**唯一可行的跨窗口集成路径**：

1. 每个会话涅槃时 → 教训写入 `AGENT_GUIDE.md`（文件系统共享）
2. 新会话开始时 → AI 读取 `AGENT_GUIDE.md` → 自动感知已有教训
3. 用户在任意窗口触发 `/distill` → 处理当前窗口的未捕获洞察 → 追加到共享文件

本质：**`AGENT_GUIDE.md §教训` 是跨窗口的教训账本。** 只要每个会话涅槃时写入，账本自然累积。

## 反模式

- **为沉淀而沉淀**：纯执行性任务（改变量名、修 typo）无需沉淀
- **重复写入**：写入前必须检查目标文件是否已有相同内容（第二步）
- **Memory 堆积**：写入文件后忘记清理对应的 Memory
- **过度细碎**：每个小发现都写入 → 合并同类，保持文件精炼
- **等待确认**：直接写入，不打断用户——触发 /distill 即是授权
