# 知识沉淀 · Distill

> 致虚极，守静笃。万物并作，吾以观复。

## 触发条件

- 用户显式调用 `/distill`
- 任务完成后评估产生了可复用洞察（由 ask-next-step 或涅槃门触发）

## 流程

### 一、识（☲视·照见洞察）

回顾当前对话，识别所有可复用的洞察：

- 新发现的模式或反模式
- 架构/设计决策及理由
- 工具/库的踩坑经验与正确用法
- 命名/约定/风格的新共识
- 调试根因分析方法论

### 二、归（☶艮·知识归位）

每条洞察按类型路由到对应文件：

| 知识类型 | 归属 |
|---------|------|
| 不变原则 | 道层规则 |
| 行为倾向 | 德层规则 |
| 操作流程 | workflows/ |
| 具体技能 | skills/ |
| 项目知识 | 项目文档（AGENT.md 或等效） |

**项目知识的细分路由**（按项目自定义，以下为示例）：

| 洞察类型 | 目标文件 |
|---------|---------|
| 代码风格、命名、注释 | 项目规范文档 §代码规范 |
| 依赖使用、状态管理 | 项目规范文档 §工具库 |
| 模块结构、目录约定 | 项目规范文档 §项目结构 |
| 样式约定 | 项目规范文档 §样式 |
| 性能、测试、CI | 项目规范文档 §质量 |

### 三、确（☱兑·确认写入）

用 `ask_user_question` 向用户展示洞察清单和目标文件，确认后再写入。

### 四、写（☳触·执行写入）

1. **读取目标文件**，确认：
   - 内容是否已存在（避免重复）
   - 是否与已有规则冲突（如冲突则替换并说明）
   - 应插入的位置（追加到合适章节）

2. **写入规则文件**，遵循：
   - 用 Markdown 标题分层，保持文件结构清晰
   - 不重复已有内容
   - 冲突时替换旧规则并注明

// turbo
3. **验证**：用搜索工具确认写入成功，无重复/矛盾。

### 五、虚（☴巽·清理残留）

> 万物归根，归根曰静。

检查当前会话中系统检索到的 Memory 列表：
- 与本次写入内容相关且已被文件完整覆盖的 → 删除
- 未完整覆盖的 → 保留，或补充写入后再删除
- 用 `ask_user_question` 展示待删除清单，确认后执行

**原则：知识优先级 规则文件 > 项目文档 > Skills > Memory。Memory 仅为跨会话临时桥接，一旦写入文件即应清理。**

## 反模式

- **为沉淀而沉淀**：纯执行性任务（改变量名、修 typo）无需沉淀
- **重复写入**：写入前必须检查目标文件是否已有相同内容
- **Memory 堆积**：写入文件后忘记清理对应的 Memory
- **过度细碎**：每个小发现都写入规则 → 合并同类，保持规则文件精炼
