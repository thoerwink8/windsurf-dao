# 重构 · Refactor

> 为学日益，为道日损。损之又损，以至于无为。

## 触发条件

- 代码重复、过长函数、过深嵌套
- 命名不清晰、职责不单一
- 用户显式调用 `/refactor`
- `/cycle` 二转（法性·结构优化）中触发

## 流程

### 一、析（☲离 · 视 · 识别病灶）

1. **识别重构类型**：

| 类型 | 症状 | 手法 |
|------|------|------|
| 提取函数 | 函数>30行、重复代码块 | Extract Method |
| 消除重复 | 相似逻辑出现≥2处 | DRY |
| 简化条件 | 嵌套>3层、复杂布尔 | Guard Clauses |
| 重命名 | 含义模糊、缩写过度 | Rename |
| 移动方法 | 方法在错误的类/模块中 | Move Method |
| 提取接口 | 模块间耦合过紧 | Extract Interface |

2. **安全评估**：
   - 影响范围：几个文件？几个调用点？
   - 测试覆盖：有没有测试保护？
   - 风险等级：低（重命名）→ 高（提取接口）

### 二、行（☳震 · 触 · 最小变更）

- **一次一个技法**：不同时重命名+提取+移动
- 同一文件用 `multi_edit` 一次完成
- 保持代码风格与现有一致
- **Guard Clauses 示例**：

```
// Before（嵌套地狱）
if (a) {
  if (b) {
    if (c) { doWork(); }
  }
}

// After（卫语句）
if (!a) return;
if (!b) return;
if (!c) return;
doWork();
```

### 三、验（☵坎 · 听 · 确认不破）

// turbo
- 检查所有 import / 引用是否更新
- 编译/类型检查通过
- 测试通过（如有）
- 功能行为不变

### 四、省（☶艮 · 味 · 够了吗）

- 代码是否更简洁了？（为道日损）
- 是否引入了新的复杂度？
- 还有没有值得继续重构的点？（知止）
