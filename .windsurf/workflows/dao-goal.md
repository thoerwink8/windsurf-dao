# 立志 · Goal

> 知止可以不殆。
> 始制有名，名亦既有，夫亦将知止。

`/dao-goal` 是轻量目标锚定入口。它不写代码、不写 design、不拆 plan，只把当前会话要达成的目标定清楚。

## 触发条件

- 用户显式调用 `/dao-goal`
- 用户希望“锁目标”“定目标”“像 Codex /goal 一样”
- `/dao-cycle` 前需要一个目标锚点
- 长对话中需要防止目标漂移

## 运行步骤

### 一、加载目标镜头

调用 `dao-goal` skill，按其 Goal Contract 协议执行。

### 二、提取原始目标

从用户当前消息和最近上下文提取原始目标。

要求：

- 保留用户原话
- 不把目标扩写成 PRD
- 不把实现方案塞进目标

### 三、补齐成功标准

把目标转成 1-5 条可验证成功标准。

好标准：

- 能通过命令验证
- 能通过文件变更验证
- 能通过 UI 行为验证
- 能由用户明确确认

坏标准：

- “更好”
- “更优雅”
- “差不多完成”
- “应该可以”

### 四、收窄范围

同时写出：

- 本次范围：这轮会做什么
- 范围外：这轮明确不做什么

范围外是硬边界。后续 `/dao-cycle` 的行相不得越界。

### 五、处理不确定点

- 小缺失：AI 自行推断，并标注“推断”
- 大缺失：调用 `ask_user_question`，只问一个多选问题
- 无不确定：写“无”

### 六、输出 Goal Contract

输出格式固定为：

```markdown
## 🎯 Goal Contract

- 原始目标：
- 成功标准：
  - [ ]
- 本次范围：
- 范围外：
- 当前不确定点：
- 下一步建议：
```

### 七、路由下一步

根据目标状态给出下一步建议：

| 情况 | 下一步 |
| ---- | ---- |
| 目标清楚、任务小 | 直接执行 |
| 目标清楚、任务复杂 | `/dao-cycle` 或 `dao-plan` |
| 目标仍需方案探索 | `dao-brainstorm` |
| 已有 design | `dao-plan` |
| 已有 plan | `dao-execute` |

## 与 /dao-cycle 协作

如果用户随后调用 `/dao-cycle`：

1. cycle 的「观」先复述 Goal Contract。
2. cycle 的「行」只做本次范围内事项。
3. cycle 的「验」按成功标准拿 fresh evidence。
4. cycle 的「省」逐项回答成功标准是否满足。
5. 范围外被误触时，必须停止并说明。

## 默认不持久化

轻量版 `/dao-goal` 默认不创建：

- `.dao-goal/state.json`
- `docs/specs/*-goal.md`
- `TODO.md` 条目

如用户明确要求“记下来”“后面继续”“写进文档”，再按项目知识归位规则另行处理。

## 反模式

| 病 | 症状 | 治 |
| ---- | ---- | ---- |
| 目标变 PRD | `/dao-goal` 输出大段设计 | 只写 Goal Contract |
| 目标变 plan | 开始拆 Task | 交给 `dao-plan` |
| 目标变执行 | 直接改文件 | 先等目标契约确认 |
| 无反目标 | 没有范围外 | 必写范围外 |
| 无验收 | 没有成功标准 | 必写可验证标准 |

## 完成定义

`/dao-goal` 完成时只交付一份 Goal Contract，并明确下一步建议。
