# 立志 · Goal

> 知止可以不殆。
> 始制有名，名亦既有，夫亦将知止。

`/dao-goal` 是轻量目标锚定入口。它先把当前会话要达成的目标定清楚，再自动选择合适的 `dao-*` 路由推进。

## 触发条件

- 用户显式调用 `/dao-goal`
- 用户希望“锁目标”“定目标”“像 Codex /goal 一样”
- `/dao-cycle` 前需要一个目标锚点
- 长对话中需要防止目标漂移
- 用户希望持续推进，中途不需要用户决策

## 运行步骤

### 一、加载目标镜头

调用 `dao-goal` skill，按其 Goal Contract 协议执行。

### 二、提取原始目标

从用户当前消息和最近上下文提取原始目标。

要求：

- 保留用户原话
- 不把目标扩写成 PRD
- 不把实现方案塞进目标

### 三、补齐成功标准

把目标转成 1-5 条可验证成功标准。

好标准：

- 能通过命令验证
- 能通过文件变更验证
- 能通过 UI 行为验证
- 能由用户明确确认

坏标准：

- “更好”
- “更优雅”
- “差不多完成”
- “应该可以”

### 四、收窄范围

同时写出：

- 本次范围：这轮会做什么
- 范围外：这轮明确不做什么

范围外是硬边界。后续 `/dao-cycle` 的行相不得越界。

### 五、确定推进模式

根据用户原话确定推进模式：

| 用户表达 | 推进模式 | 用户决策策略 |
| ---- | ---- | ---- |
| “持续推进”“不用中途决策”“一直往最终方向靠” | 持续推进 | 默认不问，仅阻断时问 |
| “先让我看看”“每阶段确认” | 关卡确认 | 关键阶段询问 |
| 目标方向明显不清 | 等待用户决策 | 先问一个多选问题 |

**硬规则**：如果目标足够清楚，且用户表达了持续推进意图，不得在输出 Goal Contract 后再问“是否准确/要怎么推进”。直接进入自动路由选中的执行流。

### 六、自动选择 dao-* 路由

根据目标类型自动选择，不把流程选择交给用户：

| 目标形态 | 自动路由 |
| ---- | ---- |
| bug、异常、现象不符合预期 | `dao-debug` |
| 开放想法、需要方案取舍 | `dao-brainstorm` |
| 复杂任务、需要多轮校准 | `/dao-cycle` |
| 清晰方案、需要拆任务 | `dao-plan` |
| 已有 plan 或任务足够明确 | `dao-execute` / 直接执行 |
| 完成声明前 | `dao-verify` |
| 测试相关 | `dao-test` |
| 部署相关 | `dao-deploy` |

持续推进模式下，选中路由后立即执行；不要问“要不要用这个路由”。

### 七、处理不确定点

- 小缺失：AI 自行推断，并标注“推断”
- 大缺失：只有影响方向、权限、安全、不可逆操作、外部凭证缺失时，才调用 `ask_user_question`，只问一个多选问题
- 无不确定：写“无”

### 八、输出 Goal Contract

输出格式固定为：

```markdown
## 🎯 Goal Contract

- 原始目标：
- 成功标准：
  - [ ]
- 本次范围：
- 范围外：
- 推进模式：
- 用户决策策略：
- 自动路由：
- 当前不确定点：
- 下一步动作：
```

### 九、执行下一步

根据目标状态执行下一步：

| 情况 | 下一步 |
| ---- | ---- |
| 目标清楚、任务小 | 直接执行 |
| 目标清楚、任务复杂 | `/dao-cycle` 或 `dao-plan` |
| 目标清楚、用户要求持续推进 | 直接进入自动路由，不等待确认 |
| 目标仍需方案探索 | `dao-brainstorm` |
| 已有 design | `dao-plan` |
| 已有 plan | `dao-execute` |

## 与 /dao-cycle 协作

如果用户随后调用 `/dao-cycle`：

1. cycle 的「观」先复述 Goal Contract。
2. cycle 的「行」只做本次范围内事项。
3. cycle 的「验」按成功标准拿 fresh evidence。
4. cycle 的「省」逐项回答成功标准是否满足。
5. 范围外被误触时，必须停止并说明。
6. 若推进模式是“持续推进”，不得把阶段性偏好问题升级为用户决策点；AI 应自行选择最小可逆路径继续。

持续推进模式下，只有以下阻断允许询问用户：

- 需要用户凭证、权限或外部账号操作
- 涉及不可逆破坏性操作
- 存在两个以上互斥方向，且无法根据目标契约裁剪
- 安全、隐私、费用风险超出当前目标
- 用户明确中断或要求重新决策

## 默认不持久化

轻量版 `/dao-goal` 默认不创建：

- `.dao-goal/state.json`
- `docs/specs/*-goal.md`
- `TODO.md` 条目

如用户明确要求“记下来”“后面继续”“写进文档”，再按项目知识归位规则另行处理。

## 反模式

| 病 | 症状 | 治 |
| ---- | ---- | ---- |
| 目标变 PRD | `/dao-goal` 输出大段设计 | 只写 Goal Contract |
| 目标变 plan | 开始拆 Task | 交给 `dao-plan` |
| 目标变执行 | 目标未定就直接改文件 | 先输出目标契约，再按自动路由行动 |
| 默认求确认 | 输出 Goal Contract 后问“是否准确？” | 持续推进模式下直接进入下一步 |
| 转嫁路由 | 问用户“要不要用 dao-cycle/dao-plan” | AI 自动选择合适 dao-* |
| 无反目标 | 没有范围外 | 必写范围外 |
| 无验收 | 没有成功标准 | 必写可验证标准 |

## 完成定义

`/dao-goal` 完成时交付一份 Goal Contract，并立即按自动路由推进。若推进模式是“持续推进”，下一步不是询问用户确认，而是直接进入对应执行流。
