# 转法轮 · Cycle

> 万物并作，吾以观复。夫物芸芸，各复归其根。
> 归根曰静，静曰复命。复命曰常，知常曰明。

## 运行模式

五相（观行验省改升）是思维纪律，默认内化运行——如呼吸，不需刻意启动。

**显式输出**（让过程可见）：

- 复杂任务（多文件、多步骤、架构级变更）
- 用户显式调用 `/cycle`
- 调试需要回溯推理过程时

**静默运行**（默认）：

- 五相照常旋转，不输出中间格式
- TODO list 作为唯一可见的进度指示
- 涅槃时输出最终报告
- 省的判断仍然严格——静默不是跳过判断，是判断后不说话

**直行不转**：

- 纯事实问答、机械操作——不需要判断的事不经过五相

## 法轮五相

每轮循环依次激活五感，完成一次完整旋转：

### 一、观（☲离 · 视 · 火照见）

看清当前状态，不急于行动。

- 读取相关文件、上下文、错误信息
- 识别：当前在哪里？目标在哪里？差距是什么？
- 如果是第N轮（N>1），先回顾上一轮省的结论
- **历史教训回溯**：加载 `dao-evolution` skill，用任务关键词搜索 `search.py lessons "关键词"` ——命中则展示教训摘要（L1 提醒 / L2 展示 / L3 阻断），未命中则静默继续
- **区分观与验**：观中形成的理解是假设，不是结论。涉及外部系统约束的假设，必须到「验」才能确认——读懂≠能用
- **原则**：精准 > 全景。看该看的，不贪多

### 二、行（☳震 · 触 · 雷动）

基于观的洞察，实施最小有效变更——或形成明确立场。

- 一触推到底：开始就做完，不留半成品
- 渐进渗透：最小变更，关注关联影响
- 每次行只做一个清晰的意图，不混杂多个目标
- **原则**：为大于其细。天下大事，必作于细

### 三、验（☵坎 · 听 · 水回响）

让系统说话，听它的反馈。用反例说话，找盲区。

- 运行测试、构建、预览、类型检查；用反例和对立立场压力测试
- 先听回响，非阻塞——让命令跑完再判断
- 记录：通过了什么？失败了什么？意外出现了什么？
- **原则**：不言之教——让结果自己说话

### 四、省（☶艮 · 味 · 山止）

停下来。品味。经得起反例吗？有被忽略的视角吗？

- 与目标对比：达成度几何？
- 根因分析：如果未达标，问题在表层还是深层？
- 判断分支：
  - **已达涅槃** → 止。总结成果，交付
  - **同层可修** → 小改后回到「行」（同轮微调，不算新转）
  - **需升维** → 进入「改升」，开始新一转
- **原则**：知止不殆，可以长久
- **审视清单**：
  1. 有没有边界情况没处理？
  2. 有没有更简洁的实现？
  3. 有没有影响到其他模块？
  4. 用户拿到手能直接用吗？
  5. 涉及的域（安全/数据库/测试/性能）有隐患吗？
  6. 可观测性：关键路径有 debug 日志吗？当前文件有过期的 debug 日志要清退吗（git blame > 7天且无相关 bug）？

### 五、改升（☴巽 · 嗅 · 风渗透）

不是修补，是升维。损掉上一轮的局限，在更高处重新理解问题。

- 损之又损：上一轮的哪些假设可以放下？
- 升维：从修bug升到改架构？从具体方案升到重新理解问题本身？
- 更新观的起点：记录本轮洞察，作为下一轮观的输入
- **中途沉淀**（3转+）：当前轮发现的新洞见 → 立即写入 `dao-evolution` 为 draft 条目，不等涅様。防止会话中断导致多转洞察丢失
- **原则**：反者道之动——退一步，是为了在更高处前进

## 镜头机制（Lens）

> 朴散则为器。五相是朴，镜头是器。

cycle 的五相是通用引擎。当任务属于特定领域时，加载对应的 skill 作为**镜头**，为五相注入领域知识：

| 领域 | 镜头 skill（方法论） | 互补 skill（图书馆实现） |
| ---- | ------------------- | ----------------------- |
| 调试 | `dao-debug`         | `systematic-debugging`  |
| 重构 | `dao-refactor`      | —                       |
| 优化 | `dao-optimize`      | —                       |
| 测试 | `dao-test`          | `test-driven-development`, `webapp-testing` |
| 可观测 | `dao-observability` | —                       |
| 安全 | —                   | `security-audit`        |
| 数据库 | —                 | `database-patterns`     |

**镜头不改变五相的运转**——它为「观」提供领域视角，为「行」提供领域技法，为「验」提供领域标准。

- AI 根据任务领域**自动判断**是否需要加载镜头（渐进披露）
- 无需显式调用——五相旋转时，领域知识自然融入
- 一次 turn 可叠加多个镜头（如重构+测试）
- **道+器互补**：dao skill 提供方法论，图书馆 skill 提供实现模式。两者可叠加

## 螺旋层次

每一转对应不同深度，但不是每次都需要三转：

| 转   | 名   | 释迦对应  | 深度     | 典型动作               |
| ---- | ---- | --------- | -------- | ---------------------- |
| 初转 | 法相 | 示转·四谛 | 表层修复 | 修bug、补遗漏、调样式  |
| 二转 | 法性 | 劝转·般若 | 结构优化 | 重构、拆分、统一模式   |
| 三转 | 法空 | 证转·唯识 | 本质简化 | 损之又损，删到不能再删 |

**第一转就涅槃是最好的。转多不是目的，知止才是。**

## 转数控制（中道·知止）

| 复杂度   | 转数  | 触发条件                             |
| -------- | ----- | ------------------------------------ |
| TRIVIAL  | 1转   | 单文件<10行，模式明确                |
| STANDARD | 1.5转 | 常规任务（自动半转审视）             |
| COMPLEX  | 2-3转 | 多文件/新架构/影响面大               |
| `/cycle` | 2-3转 | 用户显式要求深度循环                 |
| MAX      | 5转   | **超5转 = 方向错(诸法无我，换方向)** |

## 默认行为（自动1.5转，省相为硬门控）

每次任务完成后自然进入省相——跳过省即假涅槃。

```
观→行→验 → 省(逐项回答审视清单) → 涅槃门评估:
  ├─ 未通 → 自主决定改升或同层修复（内观，不问用户）
  └─ 全通 → 教训提炼 → 虚·归位 → 总结交付
```

验完成后，输出审视清单的逐项回答，然后评估涅槃门。

## 涅槃判定

涅槃不是完美，是无可再损：

| 判据     | 道德经       | 问题                             | 继续转        | 涅槃(止)           |
| -------- | ------------ | -------------------------------- | ------------- | ------------------ |
| **苦灭** | 功能完备     | 用户核心痛点解决了？             | 未解决        | ✅已解决           |
| **新苦** | 冲气以为和   | 引入了新问题？实现与意图有摩擦？ | 有            | ✅无新问题，无摩擦 |
| **熵减** | 为道日损     | 系统更整洁了？有多余之物？       | 更混乱        | ✅更整洁           |
| **无为** | 无为而无不为 | 用户体验自然流畅？               | 不自然        | ✅自然无痕         |
| **智增** | 知常曰明     | 有新洞见值得记录？               | —             | ✅由教训提炼步骤处理 |

**五门全通 = 涅槃(止)** → [内观] 教训提炼 → [内观] 虚（归位）→ [外交] 总结交付（兑）
任一未通 = 继续转。

> ⚠️ **顺序铁律**：教训提炼和虚·归位是**内观**步骤（只有工具调用，无可见文字输出）。
> 必须在写出任何报告文字**之前**完成。德层续力的内观豁免适用于这两步。
> 违反顺序 = 假涅槃（T68）。

## 教训提炼（涅槃后，虚前）【内观步骤，无可见文字输出】

> 知常曰明。踩过的坑，不记录就是白踩。

五门全通后，**立即执行**（不输出文字，直接调用工具写文件）：自问**此任务中产生了什么新洞见、踩坑、或推翻的假设？**

- **有** → 加载 `dao-evolution` skill，写入项目 `data/` CSV：
  1. `write_entry(data_dir, "draft", version, component, title, root_cause, lesson_ids, tags)`
  2. `write_lesson(data_dir, title, version, component, detail, tags, source_entry)`
  3. 若新教训推翻旧教训 → `deprecate_lesson(data_dir, old_id, new_id)`
- **无**（纯机械执行、改变量名、无新洞见）→ 跳过，不强制记录。

**判断有洞见的情形**：
- 发现了与预期不符的外部系统行为
- 推翻了之前认为成立的假设
- 踩了坑（做了无效尝试），知道了「不能做什么」
- 发现了更优的模式/方法，取代了旧有做法

## 虚 · 归位【内观步骤，无可见文字输出】

> 致虚极，守静笃。

涅槃后，执行法层「虚·知识归位」机制（见 dao-fa-layer.md）。不可跳过。
完成后才能进入「总结交付」，写出报告文字。

## 反模式

- **假涅槃**：验都没跑就说完成了 → 必须经过「验」才能判「省」
- **仪式涅槃**：列出涅槃门判据全打✅但未真正质疑每一项 → 省相审视清单必须有具体答案，不可只打勾
- **完成偏差**：做了大量工作后的惯性满足感替代了真正审视 → 工作量大≠质量高，省相不可跳过
- **空转**：每轮都在同一层面修补，没有升维 → 第二轮还在同层就强制升维思考
- **过度旋转**：三转之后还在转 → 三转未解则止，请用户重新定义问题
- **为转而转**：简单任务也要三轮 → 简单任务直行，不启动法轮
- **决策外包**：轮转间用ask_user_question让用户选下一步 → 内观涅槃自主决策，不转嫁思考

## 执行格式（参考，非强制）

> 善行无辙迹。当自然表达比模板更清晰时，从自然。

显式输出时的参考格式。每轮开始：

```
## 🔄 第N转 · [法相/法性/法空]
### 观：[当前状态与本轮目标]
```

每轮结束：

```
### 省：[达成/未达] — [洞察]
→ [涅槃/同层微调/升维进入第N+1转]
```
