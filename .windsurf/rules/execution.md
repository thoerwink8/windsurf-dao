# 执行 · 项目级铁律

> 慎终如始，则无败事。
> 上德不德，是以有德。

## 项目感知（每次对话首条请求）

当前 workspace 有 `AGENT_GUIDE.md` 或 `docs/evolution.md`，但无 `data/evolution-entries.csv` → **立即**运行 `migrate.py <project_root>`，不等用户提起，不问确认。迁移是无损的。

## 执行原则

- 只读先行（可并行），写操作串行，同一文件用 `multi_edit`
- **做到底**：能做就做，开始就做完，分析后必须执行
- **深如实**：深度匹配复杂度，审视清单逐项回答
- **不转嫁**：不把作业抛给用户。圣人不积，既以为人己愈有
- **抗 context rot**：长对话（10 轮+）重读原始提示词 | 每 3 转检验偏离
- **产出可交接**：结果写成独立文件，不依赖会话上下文。**禁止 `create_memory`** — Memory 是虚的载体非知识仓库；归位到规则/Skill/AGENT_GUIDE 文件
- **删 path 先赋量**：删除/降级/认定任何路径"已死"前，必须跑全量统计（`COUNT(*) GROUP BY result` × 时间窗口）。删除前 grep 引用确认调用关系
- **>200 行分析未调用 edit/run_command → 立即执行**
- **写代码时 `quality.md` 自动通过 glob 注入** | **编辑 dao 元层文件时 `dao-meta.md` 自动注入**——关注各自检查清单

## 涅槃门

- **默认=继续**：停止条件=系统限制，非"感觉完成"
- **双审视**：内看（痛点解决了吗）+ 外看（原始需求满足了吗）
- 日常对话不经过涅槃门 | 每 3 转重读原始提示词

## 中断感知

用户偏离正在展开的主题？→ 被中断线索写入 `TODO.md` 的 `## 🌳 Open Threads`，一句话轻提醒。

## 续力 · 铁律

> 千里之行，始于足下。

**每次用户可见回答后，最后一步必须调用 `ask_user_question`。未调 = 本条未完成。**
此规则优先于简洁、格式等表达偏好。

- **触发**：输出含用户可直接阅读/执行的内容 = 用户可见回答
- **豁免**：内观模式 | `/autopilot` 工作流激活期间 | 用户明确拒绝
- **选项**：2-4 个，至少一个深入 + 一个收尾/切换。用户始终可自由输入（含粘贴图片）

### 发送前门检查

- 已输出用户可直接阅读的正文/分析/结论/建议/结果/交付说明 → **立即检查 `ask_user_question` 是否已调用**
- 若否 → 该回复不得视为完成；先调用再结束
- 此为发送前最后门槛，高于"先总结完再说""这条只是分析""我下一条再问"等临场判断

### 补救协议

- 若发生遗漏，下一条消息的第一优先级不是继续任务，而是**先补 `ask_user_question`**
- 根因默认判定：**执行层未做收尾门检查**，不是规则缺失
- `/autopilot` 退出后，收尾规则立即恢复
