# 续力 · Ask Next Step

> 千里之行，始于足下。每一步都指向下一步。

## 约束

Windsurf 采用 **quota 制**（2026年3月起）：每日+每周 token 配额，按模型消耗量计，配额耗尽后需等下一周期刷新。
每轮对话消耗 token，重型任务/大上下文消耗更多——每轮都是稀缺资源，用户不应浪费在"接下来做什么"上。

## 规则

**每次产生用户可见回答后，最后一步调用 `ask_user_question`**。

### 执行守卫（硬约束）

- **触发**：只要本轮输出包含任何对用户“可直接阅读/执行”的内容（解释、结论、建议、步骤、修复方案、结果汇总等），就视为“用户可见回答”。
- **要求**：该条回答的最后一个动作必须是一次 `ask_user_question` 工具调用。
- **豁免**：
  - **内观模式**（Agent 自主连续执行）：不调用，节省轮次
  - **自动驾驶模式**（/autopilot 激活期间）：不调用，进度只写文件；仅在激活/中断/完成时调用一次
  - **用户明确拒绝**：停止直到用户重新要求
- **补救**：如果发现上一条用户可见回答未以 `ask_user_question` 收尾，下一条消息必须先补发一次 `ask_user_question`（不夹带新内容），再继续推进。

### 选项设计

- 2-4 个选项，来自当前上下文的自然延伸
- 至少一个**深入**方向 + 一个**收尾/切换**方向
- 描述一句话，用户一眼能选
- 用户始终可以自由输入——选项是加速器，不是牢笼

### 与法轮的融合

ask-next-step 是法轮省相的**呈现层**——把思维结论转化为可选行动。

```
法轮：观→行→验→省→(涅槃门)
                      ↓
呈现：        省的结论 → ask_user_question(选项)
                      ↓
续力：      用户选择 → 下一轮「观」的起点
```

| 法轮阶段 | 选项模板 |
|---------|---------|
| 省·涅槃通过 | 验收结果 / 深度优化 / 开始新任务 |
| 省·未通过 | 继续当前方向 / 换方向重来 / 暂停回头再来 |
| 日常回答 | 相关深入 / 延伸话题 / 实操执行 |

### 断点恢复

选项同时是**上下文压缩**——用户冷却 60 分钟后回来，选项即是最快的上下文恢复路径。
不需要重读对话历史，点一个选项就能续上。
