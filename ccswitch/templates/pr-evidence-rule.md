## 三态，恰选其一，没有第四态

PR body 必含下面这一行：

```
📸 真机验证：见评论 <证据链接列表>  |  豁免：<一句理由>  |  降级挂账：#<issue 编号>
```

- **态一 · 见评论**（有 UI 可见改动的正路）
  真机走查产出的截图落在一个**独立的证据分支**（如 `qa-assets` 孤儿分支的 `pr-<n>/` 目录），
  评论里贴**文件页面链接**加一句"看哪里"导读，每张一行。
  目的：翻 PR 列表点链接就能秒懂每个改动长什么样，不用拉代码跑。
  ⚠ **私有仓库禁用 raw 图床内嵌**（`raw.githubusercontent.com` 一类）——评论内嵌图会经
  GitHub 的匿名图片代理抓取，私有仓必 404。贴**页面链接**，不贴内嵌图。

- **态二 · 豁免**（本 PR 无 UI 可见面：纯后端 / 重构 / 文档 / 脚本）
  一句话说明理由，另附验证输出摘要（命令 + 真退出码）。

- **态三 · 降级挂账**（环境确实起不了隔离实例）
  **先建 issue 拿到真实编号**再填进这一行。**「待补」「TBD」「随后补」都不成立。**

## 为什么第三态非要一个真编号

被删掉的第四态是「随帅 dogfood 补」—— 它是唯一一个**既满足格式又不产生任何证据**的选项。
转移方写下那句话的瞬间就获得了心理结算，而接收方的责任面上从来没有这一项，
于是义务在转移那一刻消失。**带编号的账目是转移的唯一合法形态**：可查、可回溯、下一窗扫得出来。

> 出处：某产品型项目 2026-07-27 实测 —— 同窗四个 UI 可见 PR 连续 **0/4** 未附图，
> 走的全是这条第四态。

## 🔴 态三对「真实交互面」不适用

改动落在下面这些面时，**没跑过真机不许合**，哪怕要排队等设备/实例名额：

- 真实按键路径（键盘事件、快捷键、焦点）
- 底层输入/输出通道的写入（终端 PTY、串口、驱动、外设）
- 弹层层叠与关闭
- **布局与尺寸**

**为什么单独立这一条**：三态本身没问题，问题是**态三对这一类会系统性地空转**——
每笔欠账都有真编号、**形式全合规**，而**一笔都不被清** ⇒ **逐条合规掩盖了整批覆盖率在跌**。

**压死这条判断的形态**（跨项目复现率高，值得原样记）：某一列的**渲染宽度为 0**，
而文字在 DOM 里、在元素 `title` 里 ⇒ **「断言文本存在」的单测全绿**；
更毒的是常见的 DOM 测试环境里 `getBoundingClientRect()` **恒返回 0**
——**0 是它的默认值，不是测量结果** ⇒ 这一类缺陷只有真机量得出来。

**不适用于**纯后端 / 纯测试面 / 文档配置 —— 那些照旧走三态，态二态三都成立。

## 怎样让它可做（不然 0/4 会复现）

0/4 的根因通常不是懒，是**用户的实例正在跑，而常见的"起 dev server"路径会 kill 掉它**。
项目侧要提供一个**隔离启动脚本**，四条硬要求：

1. **全程不杀任何现有进程**（只 `Start-Process` 一类的启动动作）；
2. **独立的浏览器/WebView 用户数据目录**——**光换端口号不够**，调试端口是按用户数据目录
   绑定的，共用目录时换端口照样静默失败；
3. **起前查端口占用**，占用即 fail-closed 拒绝启动（不带着"可能连到别人实例上"往下走）；
4. **起完自验「端口真绑在自己身上」**——绑定失败是**静默**的，不自验就会连到别人的实例上。
   最强的那一关是**祖先链判据**：端口 Listen 者的进程祖先链里必须含自己刚起的那个 PID。

收尾只杀自己登记的 PID，**从不按进程名批杀**。
另建议把「本实例的数据落在哪」也隔离掉（数据库 / 凭据命名空间 / 用户数据读写根），
否则走查里的删除、清理、改设置动作会打到用户真身上。

> 🔴 **别把"已隔离"读成"随便点什么都安全了"**：隔离面要**逐个动作**列表说明，
> 而不是按"类别"承诺。经验：按目录枚举共用面**结构上看不见**那些不走路径 API 的面
> （OS 凭据库、由 home 目录拼出来的路径）；下次扩清单时按**写入动作**枚举，
> 再补一问：**哪些面我此刻根本没办法验？**

## 为什么必须是这个文件名

共性 rule 的**文件名契约**：跨项目自动核对的全部可能性都建立在文件名固定上。
内容可以项目化，**文件名不可**——否则被报「缺项」的项目总能说「我有这个规范，只是文件名不同」，
而清单的价值恰恰在于**无需语义理解即可核对**。
本文件对应 `ccswitch/scaffold-manifest.json` 条目 `pr-evidence-rule`（`class: product-type`，
只对在 `CLAUDE.md` 里**自我声明**为「产品型项目」的仓库生效，判据是纯子串匹配、不引入 AI 判断）。
