# 代码注释怎么写 · 细则正文（dao.md 知识归位节存根的展开面）

> **必经动作**：**你正要写或改一条代码注释之前 = Read 本文件**。触发时刻很具体——
> 你打开一份 `.js` / `.mjs` / `.ps1` 准备动手的那一刻。作用域档
> `ccswitch/rules/scoped/dao-scope-comment.md` 把「去读本文件」送到眼前，
> dao.md 知识归位节只留一行存根 + 判据一句，细则住在这里；现场 Read 拿到的永远是最新版。

- **注释里不许写「关于别处的事实」，只准写「去哪查」**（用户 2026-08-10 拍板，第 1 件）：另一份文件里写着什么、某次实测是几秒、某个清单有几项、某个函数有几个调用点——这类**值**一律不进注释，注释里只留它的**坐标**（哪份文件 / 哪个函数 / 跑哪条命令），让读的人自己去取当下那一版。**一句可执行判据：这句话会不会因为我这次没碰的那个文件改了而变假？会 ⇒ 只写去哪查。** 后半句同属拍板原文：**写了指针就必须配一道会红的闸**（那个落点被挪走 / 删掉 / 改名 ⇒ 有东西报警），**配不了就别留**——「留一个指向空气的指针比没有指针更糟」，读者会以为有兜底而不再自己去核。**误伤反例（这一类照留，别拿本条去删它们）**：「本函数的不变量」「这段改坏了会怎样」「为什么不那样做」「此路实测不通别再走」——它们是**此处的事实**，随这份文件一起改、一起被 review，不会因为别处变了而变假；08-09 那次拍板的反面裁定点名保它们。**射程只到代码注释**：条款正文的 `[基线:]` 数字不受本条约束（那是 `dao-legislation.md`「立法必带基线数字」明令要求的，两条各管一面）。 [n=27 @08-10 触发:paths作用域] [基线:2026-08-10 全量分类扫描（87 份文件 / 14,727 注释行，非抽样）实测——全仓自陈假话 52 条（代码注释 27 + Markdown 25），「把盘上的话改真」的提交 57 个（占 994 个 commit 的 5.7%）；已实现的伤害 3 起：㈠一个错 7 倍的耗时数字（真值 8-9s 被写成 55-81s）被当作「端到端整跑负担不起」的论据用掉，**据此砍掉了端到端测试**（PR #252）㈡一条 A 类判断句撒谎，让 G2 硬闸少拦 4 格真拦截 ㈢一条错误提醒连续误导三名 subagent 照抄进交付报告（`ccswitch/hooks/dao-glob-gate.js`）。**救命侧代码注释可核实实证 = 0 条，这个数有观测偏斜**（救命是一次没发生的事故，天然不留痕），照直标，别读成「注释从不救命」] [#注-别处事实]
- **用户拍板的「刻意不做」不许只活在一行注释里**（用户 2026-08-10 拍板，第 3 件）：凡注释里写着「用户某日拍板：不做 / 不收 / 不升格 / 保留现状」这一类**否决**的，同一动作内落进项目侧台账（本仓是 `docs/ops/nogo-ledger.json`），一条一个 **编号 + owner + 解冻条件**；注释处只留一行 `[NOGO:<编号>]` 指针。**一句可执行判据：删掉这行注释，会不会有东西红？答否 ⇒ 它此刻靠的是「没人删它」，不是靠机制。** 台账与注释之间必须是**双向孤儿检测**（台账有条目而落点文件里找不到标记 ⇒ 红；代码里有标记而台账无条目 ⇒ 红），形态照 `ccswitch/clause-ledger.json` 与条款正文那一对。**解冻条件不是用户原话时，台账里必须标成「AI 拟定待确认」并送用户拍板**——「什么情况下可以重开」是判断档，AI 自己定等于给自己划及格线。 [n=3 @08-10 触发:run-tests/nogo-ledger] [基线:2026-08-10 全仓扫描，符合「用户拍板 + 否决 + 零机检」三条的注释 3 处：`ccswitch/hooks/dao-probe-gate.js`（deadman 兜底轮不做，08-08）· `ccswitch/hooks/dao-hard-gates.js`（rename 族 4 格漏报长期保留，08-07 · issue #132 关单裁决）· `tests/link-codex.tests.ps1`（9 个手放 junction 不当漂移，07-27）。三块注释**整块删掉后默认层测试红集一条不变**（本批实测，即无人在看着它们）。同批另见 2 处「留给用户拍板」的**待决**项指向 issue #112，不在本条射程内（它们是待拍板不是已拍板），挂在 issue #274 的未尽处里] [#注-拍板不做入账]

## 反面裁定（08-09 拍板里最容易被读丢的半句）

**部分叙事型注释本身带防呆实证**（「此路实测不通别再走」「这一格实测会误伤」），
**这半边该留、不进清空范围**。处置是**拆开搬**：防呆判据句留原地，
「谁发现的 / 哪天 / 第几轮复核」那半搬进档案层（`docs/evolution/` 或对应 issue），
**不整段清空**。

⚠️ 这句话是用户原话的压缩，不是 AI 的补充判断。谁要拿「注释该少写」去删一段带防呆实证的注释，
先回答 2026-08-10 拍板给的那把尺子：**删掉它，下一个不知道历史的人会不会做出一个已被验证是错的动作？**
会 ⇒ 留。

## 射程边界（照直写，别读成全包）

1. **本条管的是「写的时候」，不管「已经写下的」**。存量注释的清理是另一件事
   （用户 2026-08-10 拍板第 2 件，判据是那把「删掉它，下一个不知道历史的人会不会做出一个
   已被验证是错的动作」的尺子），本文件不重复它的判据。
2. **作用域档挂在 `**/*.js` / `**/*.mjs` / `**/*.ps1` 上，精度是粗的**：写注释必然要先 Read
   那份代码文件（宿主对「覆写既有文件」有硬规则），触发时刻天然存在且机器可判；但
   **Read 一份代码文件 ≠ 这一轮要写注释**，噪音比例未测。觉得吵就删那个作用域档再跑一次
   `node ccswitch/scripts/dao-rules-deploy.mjs`——本文件的判据半不受影响。
3. **`paths:` 的 glob 按当前项目根解析，跨项目会话未实测**（同
   `ccswitch/rules/dao-legislation.md` §射程边界第 1 条的已知缺口）。在别的项目的会话里改
   windsurf-dao 的代码时，这个触发器会不会响——**没测过，别按「已覆盖」宣称**。
4. **没有任何程序核「读到了就照做」**：闸只管 `[NOGO:*]` 那一格，
   「这条注释里有没有藏一个关于别处的值」机器判不了（判它要先判「什么算别处」，
   两个方向都构造得出反例），这一半靠人照本文件复核。
