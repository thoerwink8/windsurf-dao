- **编辑准则**：违例后修条款，只准改形态（进模板/进载荷/进 hook），不准只加叙事——叙事归账本（fortify-20260726）。
- **谁来定这条规矩：按「执行时要不要现场判断」分档，不按大小**（用户 2026-07-27 拍板，原话「小的我自己定，大的才问」，配套原话「我不希望每次我强制提醒，太累了」）。**分界判据不是条款的篇幅或影响面，是执行它的那一刻还需不需要取舍**：
  - **照做档 ⇒ AI 自定**：执行时零现场判断——跑哪个命令、填哪个字段、用什么格式/前缀、写进哪个文件、按什么顺序。**可机械近似的测法**：这条能不能写成一句「动作+对象+时机」的祈使句，且句中不出现程度词与主观量词（充分 / 必要时 / 合适的 / 足够 / 重要的 / 尽量 / 酌情）。出现即不算照做档。**这是近似，两向都有反例**（两向反例各一：见 rationales §反-1）。
  - **判断档 ⇒ 必须问用户**：执行时要现场取舍——什么算够 / 什么时候停 / 要不要换方向 / 删什么留什么 / 哪个优先。
  - **两条否决项优先于上面的祈使句测试**，命中即归判断档，措辞多机械都不行：①**它给 AI 自己定及格线**（验到什么程度算验完、几条算够、什么情况可以跳过）——自己给自己划及格线是结构性利益冲突，与能力无关；②**它改用户可见面或不可逆**（用户会看到的产物形态、删除/发布/改配置源/退役某个入口）。
  - **回溯面是自定档的对价——没有回溯面的自主授权等于不可撤销**：AI 自定的每一条必须①行内带 `[自定@<月日>]` 标记②被某个「每次都会打印一次」的地方汇总（落点示例：条款库统计段，见本仓 `ccswitch/scripts/check-clauses-structure.ps1`——原指 mousse 那份副本，PR #535 收敛后它已删除，mousse 侧只剩转调适配器）③窗末简报报一个数。用户凭标记随时抽验、凭日期整批撤回（「07-27 之后你自定的全撤」），撤回不需要理由。
  - **刻意偏保守**，因为用户自陈的失败方向就是这一侧（他的原话：「我可能把不该自主的归成自主」）：拿不准归判断档。误判成「该问」只多问一次；误判成「可自定」会静默改变行为且无人知道发生过。 [n=2 @07-27 触发:元字段] [基线:首轮收割 10 条 100% 逐条送用户拍板（dao-growth-loop §四）；按本档回溯分类未做，故「其中本可自定的占比」未测。同类诉求另一次出处：2026-06-16 用户要求 `/dao-distill` 自动化「不需要人为去干预」] [#法-偏保守]
- **立法必带基线数字**：条款括注不能只写「（某日某批实证）」，必须写「入库时基线：该类问题近 N 次同类动作中 M 例」。**没有基线数字的条款，此后不得被引用为「有效」**；写「基线:未测」是允许且诚实的——它让「哪些条款的有效性根本无从判定」一眼可见，而现在这个数字是隐形的。要防的是**归因陷阱**：行为先改好、规则才追认，然后该行为的持续被当成规则的功劳（是「防住了 vs 没机会发生」的镜像错误，更隐蔽；出处：叙事 N9-③）。 [n=1 @07-27 触发:元字段] [基线:「秒级自合」100%→13.5% 的拐点落在 PR #58，治它的条款晚 5 天入库 ⇒ 那 86.5 个百分点与条款无关；同型污染面=出处日期晚于实际拐点的全部条款] [#法-基线数字]

## 📌 条款元字段 `[n= @ 触发:]` —— 语法与分类判据

> **本节是元字段判据的真相源**（2026-08-02 搬进 dao；此前只住在某个项目的条款库里，于是
> 第二个项目拿不到、只能从零重新发明同一套词汇）。**本节整段被条款解析器跳过**
> （`^##\s*📌` 判定，JS 与 PS 两侧同判据）——里面的样例长得和条款一样，不跳过会被当成条款。
> **搬进来的是判据，不是某个仓的实况**：具体条数、占比、盘点快照留在各仓自己的条款库里，
> 那些数字随该仓的条款增删变化，搬到 dao 会立刻变成一份没人更新的旧快照。

条款行尾带一个机器可读字段：`[n=<复发次数|?> @<首次入库月日> 触发:<触发点>]`。三格各答一件事：

- **`n=`** —— 该条款要防的那类问题**已知发生过几次**，取**下界**（只数得出出处标注里明写的次数，
  不宣称穷尽）。`n=?` 表示入库时未标出处次数、无从推断，**不等于零次**。
  ⚠ `n` 是人手填的、没有任何东西校验它，也**没有任何机制在事故复发时真的去 +1** ⇒
  `n>=2` 只证明有人写下了一个 ≥2 的字符，别拿它当「有复发证据」用。
- **`@`** —— 该条首次进条款库的月日，由 `git log` 实算得出（条款库搬过家的仓要跨两条路径实算
  才不漏早期条目），不是凭印象填的。
- **`触发:`** —— 这条条款**挂在哪个必经动作上**，即是否存在一个「不需要自由裁量就必然到达」
  的时刻使它被执行。取值见下。

### `触发:` 的已用取值

**跨项目通用的**（换个仓照样成立）：

- `模板首行` —— 跟着派单令必带首行走（官读到通用节+自己那一节即生效）。**填它有额外判据，见下节**。
- `PR流程` —— 挂在 `gh pr create` 或合并这个必经动作上。
- `派单契约门` / `完成流水线③` / `元字段` / `守卫头注` —— 指该条是某个**必然被生产的产出物**里的
  一个槽位（派单 prompt / 未尽处段 / 条款括注 / 守卫脚本头注）。
- `权限deny` —— 宿主 settings 的 `permissions.deny` 有对应拦截（覆盖面以那份列表实际内容为准，
  不是全覆盖）。
- `分类器拦截` —— 由宿主的 auto 分类器在派单那一刻给出反馈。
- `workflow-schema` —— 只在 workflow 编排内由输出 schema 的 required 字段强制。
- `hook硬闸` —— 已由 `ccswitch/hooks/dao-hard-gates.js` 的 PreToolUse 硬闸强制（违例动作
  `exit 2` 当场拦截），文本条款只是指针。**生效前提是该 hook 已在 live settings 注册**——
  没注册时它退回判据层，而「没注册」与「注册了没触发」在日志上长得一样。
- `paths作用域` —— 由作用域档（`ccswitch/rules/scoped/*.md` 的 `paths:`）在宿主 Read 到匹配文件时
  自动送达。射程是**送到**，不是**做到**。
- **`无`** —— 答不出「跟着什么走」。填 `无` 的条款同行另标 `[仅判据·无触发]`。
  **`无` 不是「这条没价值」**：判据层在事后核验与争议裁定里独立有用，它的含义是**不该指望这一条
  自己改变行为**。故 `触发:无` 的条款不计入「条款有效性」；要它真生效得另找形态。

**仓特有的**（值本身没错，但**换个项目读到它时按 `无` 读**——那个仓没有那道闸，就没有那个触发点）：

- `verify-all` / `verify-all/<check 名>` —— 该仓的验证入口里有对应机检道。
- `IsGate槽位` —— 挂在该仓 `verify-all` 脚本的检查数组上：新增一道检查时 `IsGate = $true/$false`
  是必填且二选一的字段，填它的那一刻就是该条款被执行的时刻。属**槽位档**——没有程序在判「你选得对不对」。
- `start-isolated-dev` 之类**具名脚本** —— 挂在该仓某个 fail-closed 的脚本上（属机检档），
  但**射程仅限"走这个脚本"这条路**：绕开它手起，关卡一个都不生效。

### 两档强度：机检档 vs 槽位档（读统计时别混为一谈）

- **机检档**（`verify-all/*` · `权限deny` · `workflow-schema` · `hook硬闸` · 具名 fail-closed 脚本）
  —— **有程序在判**，条款没被执行会以红/告警形式现形。
- **槽位档**（`模板首行` · `PR流程` · `派单契约门` · `完成流水线③` · `元字段` · `守卫头注` ·
  `IsGate槽位` · `paths作用域`）—— 靠「产出物有个位置在等着填」生效，**无程序兜底**。

**槽位档不是自欺**：已知最强的实测正例恰是槽位档——某仓 commit 前缀 719/719 = 100% 且
`.git/hooks/` 里一个钩子都没有。**它与 `触发:无` 的真实区别是「填的时刻有没有标记」**：写 commit
subject 时那个前缀位置就在眼前，而「这条条款还有用吗」没有任何时刻会把它推到眼前。
**但槽位档确实弱于机检档**：槽位可以被跳过而无人知晓（写交付时不写未尽处段、写守卫时不写头注），
两个方向都构造得出反例，故这一档条款的携带率**未经实测**，不得按 100% 宣称。

### 填 `模板首行` 的四条判据

**投递是普遍的，执行时刻不是**——那句派单必带首行让每个官读完通用节 + 自己那一节，所以
「读没读到」对这两节的**每一条**都成立，它区分不出任何东西。真正的区分变量是**执行时刻在不在**。
故填 `模板首行` 须同时满足前三条，缺一即退回 `无`：

1. **无条件** —— 该动作是那个官种的定义性内容（复审官必有 range、对抗验证官必做 mutation、
   dogfood 官必起实例），不是「碰上某种情况才用得着」。
2. **有确定时刻** —— 存在一个具体的点（进 worktree 时 / 写报告时 / 起实例前），不是弥散在全程的态度。
3. **结果可指认** —— 做没做产出一个能贴出来的东西（一个 commit 串、一行"零增量"、一个退出码）。
4. **禁令类的处置**（原三条判不了禁令）：禁令没有"填它的那一刻"，照上面三条会被一律判 `无`——
   但同档最强实测正例「subagent 身份铁律」本身就是禁令。**两者的真实差别不是「禁令 vs 动作」，
   而是射程边界与产出物是否重合**：身份铁律的射程恰好等于「那一次回答」这**一个**产出物
   （回答一交出去，它要么被遵守了要么没有，当场可指认）；「只读红线」的射程是**整段工期**，
   跨无数个动作、没有任何单一产出物与它对齐。⇒ **射程与某个单一产出物重合 ⇒ 可填对应槽位；
   射程弥散在整段工期 ⇒ 要么在产出物里加一句自陈把它收敛成"有位置在等"，要么如实填 `无`。**

### 这套分类的四个已知弱点（照直写，别把「分类完了」读成「分对了」）

1. **「定义性」是人判的**，同一条换个人可能判反——实证：某条被作者判为满足、由对抗验证官判为挂错
   并退回 `无`（作者把一条自带豁免分支的规则读成了无条件）。
2. **`模板首行` 条数变多 ≠ 遵守变好**——它只表示"这条有个必然到达的执行时刻"，不表示"到了那一刻
   就一定会做"。这一档的携带率至今**未实测**，谁要引用这批数字先读本段。
3. **上面三条判据隐含一个从未写下的前提：读到条款的人有能力执行它。** 实证：一条标着 `模板首行`
   的 mutation 类条款，三条判据全部满足，而那位官的 agent type 只有只读工具 ⇒ mutation 一环
   **零执行**，且**台账上看不出来**——「没跑的闸」与「过了的闸」长得一样。⇒ **`模板首行` 的射程是
   「必然被读到」，不是「必然被执行」**；这一档的条数只能读作「有执行时刻的条款数」的**上界**。
4. **「条款自带判定命令」不等于「条款有触发点」**，前者极易被读成后者。实证：某条给了一条纯机械、
   零歧义的判定命令，标的却是 `触发:无`——而这是对的，因为验证入口里**没有任何一道跑它**。
   **一条带命令的条款看起来比别的条款硬，正因为看起来硬，没人会去想「那么谁来跑它」。**
   ⇒ 凡条款自带一条纯机械的判定命令，就该当场问「把它接进已有机检入口要多少行」；不接的理由要
   写下来，不接而不说等于把它留在 `触发:无` 却让读者以为它是机检档。

**⚠️ 还有一个弱点在机器侧，且结构上无解**：结构守卫**对 `触发:` 的取值真伪完全盲**——mutation
实证：编一个 `触发:纯属胡编的载体` 写进条款行，闸照样 `EXIT=0`，那个不存在的载体还会在
「触发点分布」里**自成一桶**。**所以「挂错」在机器侧不可能被发现，只能靠人照本节复核。**

### 另两个独立方括号：`[基线:…]` 与 `[自定@<月日>]`

两者的**判据正文在本文件上半部分**（「立法必带基线数字」「谁来定这条规矩」两条），这里只写
与元字段格式有关的那一面：

- **刻意写成独立方括号，禁混进 `[n= @ 触发:]` 里**：`触发:` 的正则捕获到 `]` 为止，混写会把基线
  文本吞进 `触发` 取值、污染分类统计。**已实测的失效形态（未设闸，故意）**：混写成
  `[n=1 @07-27 触发:PR流程 基线:…]` 时闸照样放行，而统计里会多出一个名叫「PR流程 基线:…」的
  **假桶**、该条同时被计入「未标基线」。写明形态是让下一个撞上假桶的人能立刻归因，
  而不是去怀疑统计代码。
- **两者都只进统计、恒不参与退出码**：该不该补基线、这条该不该自定，都是人的判断；
  硬闸会让人为过闸而编一个数字，比不填更糟。
- **机器判不了的那一半照直说**：闸只认标记在不在，**判不出这条该不该自定**——把一条判断档条款
  标成 `[自定]`，脚本照样放行。这一面没有护栏，靠的是那份每次都会打印的清单被人扫一眼。
- **`[自定@]` 回溯面的射程是「条款条目」，不是「AI 对规则集的写入」**（第一人称实测）：统计段只在
  **被解析成条款记录的行**上解析该标记，而散文段、`## 📌` 元文档段整段在扫描面之外 ⇒ 打在那里的
  标记**一条都数不到**。危害具体：分类判据本身住在元文档段里，**改它比改任何单条条款影响都大**，
  而「某月某日之后你自定的全撤」抓不到它。**零条有三种读法**：真没有 / 有人忘了打标 /
  **打了标但打在扫描面之外**。

### 判断类候选不直接进条款库

判断类的好实践直接写进正式条款节，只会变成又一条 `触发:无`。它们进条款库末尾的
**「观察区（判断类候选 · 复发即升格）」**，第二次复发（`n` 升到 2）时再升格进正式节，
**升格那一刻强制回答「这次能挂在哪个必经动作上」**。观察区条目带 `[观察中]` 标记，
不计入条款统计，派单时也不摘。
