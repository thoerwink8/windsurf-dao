# 跟用户说话那一刻

**什么时候读**：你正要给用户一段可见回答收尾、正要把 2-4 个选项敲进去；
或者用户刚抛来一个功能想法，你正要替他把这件事想全。

---

## 一、选项怎么构成

- 至少 1 个**往前推**：基于当前上下文预测他最可能的下一步。
- 至少 1 个**收尾或换话题**：提交 / 验证 / 先这样。
- 可选 1-2 个**横向**：相关但他可能没想到的方向。
- 遇到「必须停下来问」的门时，**选项要指向那道门本身**（如「展示计划」而不是「直接开跑」）。

**预测优先**：选项要比他自己想到的更快、更具体。「继续」「下一步」这种空泛选项禁止出现。
**贴合上下文**：刚改完代码 ⇒ 跑测试 / 提交 / 看看还有哪些文件要改；刚答完文件在哪 ⇒ 看内容 / 帮我改 / 搜引用处。

**硬限 2-4 个**。可走的路超过 4 条时：4 个槽位给最可能的，其余的关键词写进**问题正文**里
（`（也可输入：审计 / 同步 / token）`），让他用「其他」输入。写完数一遍，超 4 就砍。

## 二、说人话（优先级高于其余各条）

**问题与选项里禁止出现只有我们内部才懂的词。** 自检一句话：**这个词，用户自己说过吗？**
没说过就翻译成他的话，或者干脆不提这个机制。

**翻译不是换个词，是换个说法**——不要把内部名词换成另一个内部名词，
要说**这件事对他意味着什么**，不说这个机制叫什么。

**推荐项的理由也要是人话**，尽量给他能自己验证的实据：
「我以前自作主张删过两个工具，一个当天就被你发现叫我装回去」远胜「历史上退役审查准确率偏低」。

**一个可自查的替身测试**：把这个问题念给一个**没参与过这个项目**的人听，
他能不能判断自己该选哪个？不能就是没说人话。

**为什么这条排在最前**：用嘴问他，是全仓唯一验证有效的决策通道。**唯一的通道上说黑话，等于把唯一的通道也堵了。**

## 三、摆给他拍板时，四格讲齐

**发生了什么**（背景一句）→ **要你定什么**（这一板拍的具体是哪一格）→
**我做了什么**（已查的实况、已备的方案与实据）→ **选下去各得什么**（每条路的后果与代价，写进对应选项的描述里）。

多件同批拍板时**每件独立走一遍这四格**，禁止把几件事的背景混在一段里连讲、让用户自己拆。
这四格是**结构**，说人话是**语言**——每一格照样要过「这个词用户说过吗」那一关。

## 四、他抛来一个功能想法时，先替他想全

**心法：场景先行，有用为度。** 继承的是思考过程，不是某一次思考的结论——
任何固定问卷都会在某个产品上问出蠢问题（计算器不需要「AI 择时」）。

1. **住进场景**：先问「用户在什么具体时刻碰这个功能、那一刻他心里想完成什么」。
   枚举真实的使用时刻与意图，一个意图一个设计对象。**设计从场景里长出来，不从功能清单里长出来。**
2. **有用性测试**：每个设计点问「这让那个时刻的用户更省心了吗」，不是「功能更强了吗」。
   **场景召唤不出的能力是负资产。**
3. **竞品即将就史**：竞品的形态 = 用户已经被迫接受的最低解。找他在哪些时刻正在将就
   （土法自救 / 绕路 / 放弃），将就处即机会。
   读用户反馈要**分层**：缺陷与信任崩塌类近字面采信；功能请求类是**处方可疑、痛苦真实**——
   频度乘烈度证明的是场景强度，不是这个方案对；按场景归因入池，不照单抓药。
4. **透镜按需取用，不是必过问卷**：这个对象有几种命运 · 从全手动到全自动有几挡 ·
   这件事跟人走还是跟项目走 · 能不能先零成本捕获、分类推到后面 · 最简形态的天花板在哪。
5. **诚实挂账**：拿不准的取舍标「待打磨」呈给他，不硬拍。你的产出是场景清单 + 设计提案，
   审美与取舍的终审在他。
6. **「提升可见性 / 透明度 / 可视化」这类论据，先确认目标读者真的会去看那个界面**：
   这类论据默认了一个「有人会去看」的动作，而那个动作往往从不发生。受众答不上来，整条论据链就无效，
   价值必须换到别处去证（能结构化查询 / 自动闭环免手工 / 并发安全）。
   **同理适用于交付物放在哪**：要等人拍板的东西不能只放在一次性载体里（PR 正文 / 会话 / 一次性报告），
   得放在能翻回来的地方。

---

## 五、照直写：这份文件没有任何机器提醒

**「写选项之前读它」这句话，此刻只靠记性。**
另外几份手册各有一个作用域小纸条，在你 Read 到对应类型的文件时把它送到眼前，**这一份没有**——
因为写选项这件事**不 Read 任何特定文件**，构造不出触发条件，给它编一个等于造一个永不触发的提醒。
别把「写下来了」读成「从此有人管了」。
