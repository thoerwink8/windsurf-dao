# 用户拍板了一批事，正要开工

**什么时候读**：用户刚拍板了一个多项方案的执行批，你正要动第一下。

一句话读法：**用户拍的是「做哪些」，下面这张单管的是「怎么做都一样稳」。**

## 开工前（每项三行，写进拍板材料）

- 这一项会碰到哪些文件的**反向依赖**？
- 它触不触及**守卫 / 护栏 / 配置源**？
- 它是**单向门**（拍下去难反悔）还是**双向门**（一次 `git revert` 就能完全恢复）？

这是全流程唯一一次「还没花钱之前」能砍掉错误方向的机会。

## 拍板这一下同时冻结两样

- **单向门的项逐条呈审**：不可逆的 / 用户看得见的 / 改 AI 自身行为的规则 / 对外发布 / 删数据。
- **双向门的项走预授权**：能被一次 `git revert` 完全恢复、且没有外部可见副作用的，
  预授权一类动作，事后批量报告，不事前逐条问。
- **拍板动作同时冻结**：**什么算做完**（不冻结 = 执行方给自己划及格线）+ **什么信号出现就回退**。

## 逐项做（粒度 + 断言要真的能红）

- **一项 = 一个原子单元（一个 PR 一个关注点）**——让这一步的粒度与回滚粒度天然重合。
- **每项的断言必须「先破再验」**：临时把被测行为反转，确认断言变红，再复原。
  **一条断言若在被测物被故意破坏时不变红，它就不是断言。**
- **例外**：单项验证的固定成本高于该项本身时（真机 / 独占资源类）允许成批，
  但**批的边界必须在开工时写明，不许事后追认**。
- 「不攒批」仍是默认——小批量是对 AI 不稳定性的关键对冲。

## 能回滚就先回滚

- 回滚点 = 一个原子 commit / 一个 PR；回退判据已经在拍板时冻结了。
- **每批至少做一次真的 revert 演练**：抽一项 → revert → 重跑该项的断言确认变红 → 恢复。
  恢复路径历来是系统中最少被测试的部分。
- 选择判据：**能回滚先回滚**；已被后续叠加、或含不可逆副作用时才前滚。
- **不可逆的面走「新旧并行一窗」**：旧的标为将退役，**并且把退役时机写死**——
  不写死会落到一个比开始更糟的中间态。

## 每次合并前（不等批末）

`git fetch` → **核 `origin/main` 真的动了**（fetch 会静默失败）→ `merge origin/main` →
重跑受影响面 + **全部预算型的闸** → 再合。

**预算型的闸必须在合并后的树上求值**：它们对「和」设限，而 PR 是按「增量」审的——
两边各自都没越线，合起来越线。`MERGEABLE` 只是语法绿。

## 批末

- 全量范围判据：**套件跑得完 20 分钟就全跑**；超了就按依赖 / 影响面选，高风险项无条件必跑。
- **效果对照的基线在拍板之后、开工之前采**——不是「新的 vs 记忆中的旧的」。
- 退出码语义严格：**只有 0 叫通过**（「跳过了几道」与「全绿」在退出码上必须可区分）。
- 合并后一窗真机试用观察；下一窗把本批列为复审的强制靶。
- 未清项**带解冻条件挂账**，不许「随后补」。
- **记录本批的返工数与回滚数，作为下一批的基线**——没有它，永远无法回答「这套做法有没有用」。

## 收 PR 时另外两条（只对做产品的项目成立，内部工具仓不适用）

- **合并前构建并本机安装试用一轮**，体验发现写进项目 `TODO.md`（发现不阻塞本 PR，下轮择优吸收）；
  在 `PROGRESS.md` 一行记账：版本 / 变更 / 试用发现 / 回滚点——让用户读一个文件就总览全部战况。
  产品未发布期，AI 既是开发者也是第一个用户。
- **待办池三级准入**：用户点名的直进里程碑；AI 确信的（有证据：可复现 / 竞品高频痛点 / 阻塞既有验收）
  自主转正并记账；AI 怀疑或用户未确认的留候选池并标来源（用户 / 试用 / AI 推测 / 竞品）待定夺。
  竞品的 issue 区是免费的用户调研。

## 明确不采的几件业界重器（防止将来有人重新提起）

金丝雀放量（没有生产流量，统计上无效）· 功能开关做发布控制（没有部署与发布解耦的需求，
开关本身有维护成本；例外：真机对照两版行为时临时用、用完即删）· 蓝绿部署（等价物就是 `git revert`）·
变更审批委员会（业界实证反对）· 变更冻结窗口（冻结是症状不是解法）·
按服务水平目标自动回滚（没有生产遥测，退化为「断言红 ⇒ revert 该项」）·
对所有改动都做新旧并行（只用于不可逆的面）。
