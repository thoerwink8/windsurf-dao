# 拍板执行批八步铁序（细则正文）

> dao.md 「拍板执行批」条款的存根指向这里。**触发时刻：用户拍板了一个多项方案执行批、正要开工的那一刻**——开工第一动作 Read 本文全文。
> 出处：用户四步基线（拍板/逐项测试/可回退/最终全量测试，2026-08-01 点名固化）+ 业界对照升级（同日用户拍板采纳；调研归档 `docs/research/change-mgmt-survey-20260801.md`，每处增删带出处）。
> 一句话读法：**用户拍的是「做哪些」，八步管的是「怎么做都一样稳」**——四步骨架未变，①分了档、②定了粒度与锚判别力、③加了演练、④拆成「合并前的门」与「批末对照」，首尾各多一步。

## ⓪ 影响面速评 + 可逆性分档（开工前，三行）

每项写三行进拍板材料：**触及哪些文件的反向依赖 / 是否触及守卫·护栏·配置源 / 单向门还是双向门**。
（出处：premortem 的 prospective hindsight ≈ +30% 风险识别率，Klein HBR 2007；Bezos 可逆性分档。这是全流程唯一一次「还没花钱之前」能砍掉错误方向的机会。）

## ①' 分档拍板 + 双判据冻结

- **单向门项逐条呈审**：不可逆 / 用户可见面 / 改 AI 自身行为的规则 / 对外发布 / 删数据——逐条拍。
- **双向门项走预授权**：能被一次 `git revert` 完全恢复且无外部可见副作用的——预授权一类动作，事后批量报告不事前逐条问（与 dao「照做档/判断档」+`[自定@]` 回溯面同构，引用即可不重造）。
- **拍板动作同时冻结两样**：**验收判据**（什么算做完——不冻结=执行方给自己划及格线）+ **回退判据**（什么信号出现就回退）。
（出处：ITIL 4 标准变更预授权；DORA——外部审批的失效机理是「排队推大批量」，拍板强度 ∝ 不可逆性而非改动大小；Argo/Flagger 把回退阈值前置进 spec。）

## ②' 逐项测试（粒度 + 锚判别力 + U 曲线例外）

- **一项 = 一个原子单元（一 PR 一关注点）**——使本步粒度与 ③' 回滚粒度天然重合。
- **每项的锚必须「先破再验」**：临时反转被测行为，确认锚变红，再复原——**一个断言若在被测物被故意破坏时不变红，它就不是锚**（mousse #358 血案：断言 subject 存在的单测全绿而渲染宽度 0）。
- **U 曲线例外**：单项验证固定成本高于该项本身时（真机/独占资源类）允许成批，但**批边界必须在开工时写明**，不许事后追认。
- 「不攒批」仍是默认（DORA：小批量是 AI 不稳定性的关键对冲）。

## ③' 可回退（+ 演练 + 不可逆面单独走）

- 回滚点 = 原子 commit / 单 PR；回退判据已在 ①' 冻结。
- **每批至少一次真 revert 演练**：抽一项 → revert → 重跑该项的锚确认变红 → 恢复（「恢复路径历来是系统中最少被测试的部分」——AWS REL12-BP05）。
- 选择判据：**能回滚先回滚**（SRE：detect→roll back→fix→roll forward）；已被后续叠加或含不可逆副作用时前滚。
- **不可逆面走 expand-contract**（新旧并行一窗、旧的标 deprecated、**contract 时机写死**——不写死会落到比开始更糟的中间态，Fowler ParallelChange 陷阱）。

## ③.5 合并态门（每次合并前，不等批末）

`git fetch` → **核 `origin/main` 真的动了**（fetch 会静默失败）→ `merge origin/main` → 重跑受影响面 + **全部预算型闸** → 再合。
（与 dao 既有「预算型护栏必须在合并态求值」同源；把批末全量的一半前移，防「②压小的批量在④重新攒大」——四步基线版最大的内部矛盾。`MERGEABLE` 只是语法绿。）

## ④' 批末全量 + 基线对照

- 全量范围判据：**套件 <20 分钟就 retest-all**；超了用依赖/影响面选择 + 高风险项无条件必跑（Google TAP：资源再多也做不到每变更全量）。
- **效果对照的基线在 ①' 之后、②' 开工之前采**——不是「新 vs 记忆中的旧」。
- 退出码语义严格：只有 0 叫通过（`-Skip` 与全绿在退出码上必须可区分）。

## ⑤ 浸泡 + 记账

- 合并后一窗真机 dogfood 观察（bake time 的本场景对应物）；下一窗把本批列为复审强制靶。
- 未清项**带解冻条件挂账**，不许「随后补」。
- **记录本批的返工数/回滚数，作为下一批的基线**——流程自身的度量；没有它永远无法回答「这八步有没有用」（与 dao「立法必带基线数字」同构）。

## 明确不采的业界重器（有出处的过度工程判定，防未来有人重新提起）

金丝雀放量（无生产流量无统计功效）· feature flag 发布控制（无 deploy/release 解耦需求，flag 有 carrying cost；例外：真机对照两版行为临时用完即删）· 蓝绿部署（等价物就是 git revert）· CAB 审批板（DORA 实证反对）· 变更冻结窗口（冻结是症状不是解法；真机排队是资源调度问题不是窗口问题）· SLO 自动回滚（无生产遥测；退化为「锚红 ⇒ revert 该项」）· 对所有改动 expand-contract（只用于不可逆面）。
