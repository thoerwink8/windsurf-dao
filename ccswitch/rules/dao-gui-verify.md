# 看界面那一刻

**什么时候读**：你正要对一个跑着的界面做一次观察——截图、点一下、读 DOM、走一遍流程。

> 绝利一源，用师十倍。三器不争，各归其位。

## 一、选工具走这棵树，不凭习惯选

```
应用有 WebView 层吗？（Tauri / Electron / CEF / WebView2）
├─ 是 → 远程调试端口开了吗？
│   ├─ 是 → chrome-devtools MCP（直连 WebView，DOM 级精度）      ← 首选
│   └─ 否 → 先开端口（各框架怎么开、为什么禁止写死 9222、起完怎么验端口归属：
│           见 `ccswitch/stacks/desktop-webview.md`），再用 chrome-devtools
├─ 否（纯 Web 应用 / dev server）
│   └─ playwright MCP（自管浏览器，端到端流程最佳）              ← Web 首选
└─ 否（原生 Win32 / WPF / 没有 Web 层）
    └─ 没有 MCP 工具可用 → PowerShell + .NET 截图脚本（`System.Drawing` 的
       `CopyFromScreen`，落 `_tmp/qa/`）；脚本也不可行时诚实挂账「需用户目视」，
       不得为此复活 windows-mcp
```

**windows-mcp 一律不得用**（这条现在只剩文字层，见末节）。
工具能力细节矩阵在 `ccswitch/stacks/desktop-tauri.md`，选型只走上面这棵树；
直连原理与端口归属判据在 `ccswitch/stacks/desktop-webview.md`（那两节与框架无关——
调试端口是 WebView2 运行时读的环境变量）。

## 二、防断路三条

- **同一个会话内只用一个浏览器工具，不中途换**——换工具 = 端口/锁冲突 = 排障循环 = 烧上下文。
- **进程管理**（启动 dev server、开调试端口）在会话最开头做一次，不在中途反复杀了重启。
- **MCP 连接失败 2 次就停下来查端口与进程状态**，不盲目重试。全盲时反向思考，别做第三次同样的尝试。

## 三、截图落哪

截图一律落 `_tmp/qa/` 之类的临时目录，别落进仓根。两支 MCP 的参数名不同
（chrome-devtools 是 `filePath`，playwright 是 `filename`），
**playwright 省掉 `filename` 不是「内联返回」，是落进仓根的 `.playwright-mcp/`**——那就是往仓里扔垃圾。

## 四、照直写：这一份此刻没有任何机器兜底

这份手册以前有两道机器支撑：一个「第一次调浏览器 MCP 时把它送到眼前」的提醒钩子，
和一道拦截截图落盘路径的硬闸。**2026-08-12 钩子精简后两者都已退役。**

⇒ 现在「选对工具」「截图落对地方」「不碰 windows-mcp」三件事，**全部只是文字**。
读不读、读完照不照做，没有任何东西在核。

**还有一半是结构性的缺口，就算钩子还在也补不上**：那类提醒挂在「你已经调了浏览器 MCP」这个动作上，
所以它覆盖**第二次及以后**的选型，**覆盖不了第一次那个选择本身**——
你可能一上来就选错了工具，而它只会在你选完之后才出声。
