# 密钥放哪、程序怎么拿到它

**什么时候读**：你正要给某个项目接一条「程序怎么拿到密钥」的路——
在写加载 `.env` 的代码、在改一条取环境变量的链、或者在给一个新项目决定密钥放哪。

## 要治的是什么

**只要密钥和代码住在一起，「哪些文件是密钥」就只能靠猜**——而这个猜必然两头出错：
猜多了改坏在用的配置，猜少了漏掉真凭据。**密钥集中之后，位置本身就是标识，不需要猜。**

这是业界标准不是临时想法：SSH → `~/.ssh/` · AWS → `~/.aws/credentials` ·
Docker → `~/.docker/config.json` · gcloud → `~/.config/gcloud/`。**没有一个放在项目目录里。**

## 存放形态

```
%USERPROFILE%\.dao-secrets\        ← 凭据根：只有密文，没有钥匙
  ├── .sops.yaml          加密规则（只含公钥 —— 公钥泄露无害，它只能加密）
  ├── _shared.env         跨项目共享的那几把
  ├── _backup\<时间戳>\    迁移时的明文备份（回滚材料，确认无恙后自己删）
  └── <项目 slug>.env     各项目的加密凭据：键名明文可见、值加密

%AppData%\sops\age\keys.txt        ← 私钥，住在凭据根之外（sops 在 Windows 上的默认位置）
```

建它跑 `ccswitch/scripts/dao-secrets-init.ps1`，搬凭据跑 `dao-secrets-migrate.ps1`。
**两个脚本都由用户跑，不由 AI 跑**——凭据的事交用户经手。
`init` 的退出码是分档的（`0` 全成 · `2` 主体成功但权限没收紧 · `1` 真失败），
唯一真相源是那个脚本 `.NOTES` 里的「退出码分档」节；`migrate` 那侧仍是两态 `0/1`，别把这一档套过去。

**为什么选 SOPS + age**：因为「加密存放」和「能带走」这两件事，Windows 的原生方案一条都满足不了——
凭据管理器 / DPAPI / keyring **没有一条支持跨机迁移**，而「换机器不用逐个找密钥」正是要解的问题之一。
SOPS + age 完全本地、免费、不需账号不需联网。

**为什么一个项目一个文件，而不是一个大文件加前缀**：一个项目一个文件时，**文件名就是命名空间**
⇒ 各项目的键名一个字都不用改 ⇒ 消费方代码零改动。合成一个大文件才需要前缀，
而那个前缀**反过来要求每个消费方都改读法**——用一次改造成本换一个根本不存在的问题。

## 程序怎么拿到值：两条路

### 路 A · 注进环境变量（绝大多数程序走这条）

```powershell
# PowerShell 写法。cmd 里把 $env:USERPROFILE 换成 %USERPROFILE%——
# 第一个参数是由你敲命令的那个 shell 展开的，不是由 sops 展开的，写错就找不到文件。
sops exec-env "$env:USERPROFILE\.dao-secrets\<slug>.env" "<你的启动命令>"
```

解密后的值只进子进程的环境，不落盘。适用于读环境变量的程序。

🔴 **值不要用引号包起来，也别留首尾空格**：`sops exec-env` 把值**原样**注入——
源文件里写 `K="abc"`，子进程拿到的就是**带引号的** `"abc"`。
而搬走之前，消费方读的是它自己那个会 trim、会去引号的解析器
⇒ **恰恰是这条被推荐的路把消费方自己的解析器整个绕过去了**，两边不等价。
**失败长得像「密码错了」**，极难归因。

### 路 B · 解密到一个临时文件（只认文件、又肯接受路径的程序）

```powershell
sops exec-file --no-fifo "$env:USERPROFILE\.dao-secrets\<slug>.env" "<命令，用 {} 代表临时文件路径>"
```

代价：明文在进程活着的这段时间**确实落在磁盘上**，进程被强杀时可能残留。

🔴 **临时目录路径里有空格时，`{}` 会给出一个不存在的路径，而退出码仍然是 0**——
它对 `{}` 做的是纯文本替换、零转义，加引号也没用。用路 B 前先确认 `TMP`/`TEMP` 不含空格。

### 怎么选（要问两句，不是一句）

1. **入口是环境变量还是文件？** 答环境变量 ⇒ 走 A。
2. 答文件的，**还要再问「它接受别人告诉它路径吗」** ⇒ 接受才走 B。
   **不接受的**（路径写死、或按固定文件名从当前目录往上找）**两条都不适用**，
   得另找出路（系统 keyring / 改那个程序 / 挂账）。

答不上来就去读它的取值链，别猜。

## 三个会咬人的地方

1. 🔴 **sops 找 `.sops.yaml` 是从「你当前所在的目录」往上找，不是从被加密文件所在的目录往上找。**
   文件放在凭据根里也救不了——这不是路径没写对，是发现机制本身。
   报错长这样、看不出跟当前目录有关系：`config file not found, or has no creation rules, …`
   ⇒ **凡是脚本里调 sops，一律显式钉 `--config <凭据根>\.sops.yaml`**，
   且它是全局位标志，**必须放在 `encrypt` / `decrypt` 前面**，放后面直接报「未定义的 flag」。
2. **搬东西的次序是「加密 → 复核 → 备份 → 删原件」**，不是「先备份再加密」——
   后者的每一次失败迁移都会在磁盘上多留一份明文口令，而用户只看到一行红字。
   **搬不成功就一个字节都不多写。**
3. **共享那几把用两层注入**：外层 `_shared.env`、内层项目自己那份。
   **直接嵌套写不通**——外层 `exec-env` 只收两个参数（文件 + 命令串），
   内层要成为**一个**参数就得加引号，而**含引号的命令串本身就过不了外层那一关**。
   可行形态是把内层那条命令住进一个 `.cmd` 包装脚本，外层只喂一个不含引号的路径。
   实测到的语义是**内层覆盖外层**（项目专有值压过共享默认值），方向是对的，
   但那是跑出来的、不是文档承诺的。

## Windows 上的三条硬事实（别按 Linux 经验推）

1. **age 私钥的默认位置是 `%AppData%\sops\age\keys.txt`**，不是 Linux 的 `~/.config/sops/age/`。
   走默认路的人一个环境变量都不用设。
2. **`--no-fifo` 是「显式但无害」，不是「必须」**——调用方在 Windows 上会自动降级，
   加它只是少一行警告、语义明确。（`--same-process` 与 `--user` 才是真的不可用。）
3. **`exec-env` 在 Windows 上走的是 `cmd.exe /C`，不是 PowerShell**——
   你传进去的命令串按 cmd 的引号规则解析，照 PowerShell 的写法写会得到难归因的失败。

## 明确不覆盖的面（别读成全包）

- **前端构建期的变量在 build 时被编译进产物**——把 `.env` 挪到项目外一寸都解决不了「密钥进包」。
  那是判据不是迁移任务，不属本方案射程。
- **主目录里那十来处**（`~/.ssh/`、`~/.aws/`、`gh`、各 AI 工具的配置）**结构上就不该搬**——
  它们是各工具按业界标准写死的落点。**改它们不是合规化，是把工具弄坏。**
- **不是「键=值」形态的凭据本方案不管**：成批账号清单、浏览器登录态目录、证书文件。
- **本方案不提供「谁在读我的密钥」的审计，也不提供轮换。**

## 照直写

这份手册没有机器提醒——「我正要接一条取密钥的路」那一刻不 Read 任何特定文件，构造不出触发条件。
**真正有机器兜底的只有一件事**：密钥不进 git（`node scripts/dao-check.mjs` 扫 git 追踪面，
密钥形态的文件名一个都不许有）。那是整个体系里唯一真正不可逆的伤害——
**密钥一旦进 git，删不掉、改不回，只能换密钥。**
