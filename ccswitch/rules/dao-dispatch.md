# 派活手册

**什么时候读**：你正要把一件事交给别人干，或者正在等别人把活交回来。
从「这件事该记在哪」一直管到「他交回来的东西凭什么算数」，以及一个长时间无人值守的窗口怎么不停摆。

不管的事：这活为什么要做（那是 issue 里写的）、干活的人怎么想（那在 `dao-officer-clauses.md`）。

---

## 一、先给这件事安个家

**一句话判据：说得出「什么算做完 + 谁负责」⇒ 开一张 issue；是把很多张单聚成一个全景 ⇒ 看板；
是流水账 / 叙事 / 策略 ⇒ 仓库里的一个文件。** 同一件事只许有一个真相源，两处写必漂移。

- **issue = 分配中心**：有独立生死的一件事（缺陷 / 任务 / 欠账 / 等用户拍板的）。
  没把握的想法挂 `候选` 标签同池，**转正是改标签，不是重开一张**。
- **看板 = 观测中心**：所有单的聚合全景。**别用常驻 issue 凑观测面，那是看板的活**
  （issue 手维护的全景必然过期，而过期的那份在撒谎）。
- **常设 issue = 交互面**：看板卡片没有评论区，用户在看板上回不了话。
  凡是「**用户回一句就让事情动起来**」的入口，归常设 issue。数量不设硬上限，
  但**与「谁该动」轴的 label 一一对应**——多一张常设单必须先多一个收件箱 label，
  而 label 要过「消费方 + 消费时刻」那一关。
- **仓内文件 = 叙事层**：流水账、CHANGELOG、定位策略、流程说明——它们没有「一件一生死」这个属性，
  硬塞进 issue 反而散掉。反过来，一个「问题树面板」型文件在 issue + 看板建成之后多半是冗余，
  归档掉、活账交回 issue。

**挂账往哪放，看接下来谁处置、什么时候处置**：本窗立刻要用 ⇒ 新开一张单；
要等外部条件才能动 ⇒ 就在原处评论挂账，不新开单；纯用户判断题、没有技术后续 ⇒ 进待拍板池。
三态互斥，同一条信息别同时挂两处。

**开单三件套**（缺一格这单以后就找不回来）：
① **类型标签三选一必贴**：`缺陷` / `任务` / `欠账`。「改动性质」轴（feature / chore /
refactor / docs / perf 那一类）不设——说不出谁会在什么时刻按它筛，没有消费方的标签只是装饰。
② **标题写人话**：内部术语进正文不进标题；写完自问一句——**没参与这个项目的人读标题，
知道这是干什么的吗**。精度留正文，标题只担一件事：让人一眼看懂。
③ **关联用结构化字段**，别只写在正文里：子单挂父子（`gh issue edit <子> --parent <父>`），
前置条件用 `--add-blocked-by`。⚠ blocked_by 的目标**只能是 issue，不能是 PR**——
「等某个 PR 先合并」这类前置条件目前只能写在正文散文里。

**issue / PR / 评论是给人看的，无条件按这三条写**（与上面那道「这个项目要不要接看板」的开关无关）：
① **STAR 结构**：为什么改 → 改了什么 → 怎么验的（关单则是：原来什么问题 → 怎么解的 → 验证结果）。
② **人话领先**：术语第一次出现时括注一次，不删精度，是把人话加在精度之上。
③ **技术证据折叠进 `<details>`**：数字一个不删，只是收起来——人读顶部、AI 读全部。

**全仓缺省项不进单正文**：每张单都适用的要求（验收命令 / 提交前缀 / 流程约定）写进正文只是噪音，
不写即默认生效，正文只写这单特有的。哪些算缺省，各项目自己列清单——dao 只立这条原则（写指针不写副本）。

**两台机器 / 两个 AI 同时盯一个队列时，领单之前先看这单被认领没有**：认领只有评论租约这一层
（谁 / 哪台机 / 何时，**而且必须自己会过期**——不会过期的认领只是把撞车病换成锁死病，
而锁死病更隐蔽：撞车会在 PR 冲突那一刻响，锁死是一张单静静地永远没人领）。
不另设「在途」类标签：标签没有过期语义，只会长成租约的影子，两份必漂移。
协议全文、解析与判定都在 `ccswitch/scripts/dao-claim.ps1`（跑 `-Action selftest` 可原地验它没坏）。
**一台机器一个会话的项目连租约也不需要**——没有第二个领单人，就没有要抢的单。

**上面「看板 + 标签 + 认领」这套只对 GitHub 托管、且持续多窗口 / 多 agent 派活的项目生效。**
本地仓、一次性小脚本不需要，一个文件面板兜底就够。

## 二、这一批谁来干（先定形态，再探测，再提案，再拍板）

**编排形态的规划权归总帅**（用户 2026-08-13 拍板，#350）：接单先定结构形态，三档菜单——
**轻装单兵**（单关注点 / 模板化 / 错了代价小 ⇒ 一树一工兵，总帅直收）·
**树帅制**（多件耦合 / 护栏类 / 预期返工循环 ⇒ 树帅＋树内可见终端工兵，见 §三½）·
**多树并行**（多单互不相交 ⇒ 上两档并发，文件面开工前划死、热点文件指定独占）。
判据两句：**返工概率 × 返工成本，定配不配树帅；文件面相交与否，定串还是并。**
菜单只定结构、**不绑模型**——树内谁上哪档，每单照本节动态编排提案、用户决策；
形态与模型分配同批呈拍板，定稿后并成一行编排声明进「⚔️ 已派」通报槽位（形态＋模型＋并行度）。

**没有固定的「谁配哪个模型」表。** 谁干什么由三样东西现算：任务性质 × 本机现在有什么 × 成本。
提案前扫一眼 dao 仓 `docs/ops/model-profiles.md`（模型画像**活档案**：定位倾向 / 红线 / 实战记录，
随收活复盘更新，用户体感裁定最高）——它省掉从零提案，不豁免探测与拍板。

```powershell
node scripts/dao-roster.mjs    # 一行 JSON：编排工具活不活 + 各家 CLI 在不在
```

探测面刻意包含**编排工具本身**：它挂了，方案里自然只剩本地 subagent 这条路。
**断供预案就是探测本身**，不另写一份双轨文档。

接到一批活，按「任务性质 × 探测结果 × 成本」拟一个分配方案，用 AskUserQuestion 呈给用户拍板再开派。
任务性质常用三档：查资料 / 盘点类（便宜模型够用）· 写代码类（要强模型）· 挑错类（要换一个模型当外人）。

提问形态照这个来，**第三个选项是防打扰的关键**：

```
本批 3 单拟分配（探测：orca✓ claude✓ codex✓ pi✗）：
❶ 规则库盘点（查资料）→ 便宜模型
❷ 出口检查实现（写代码）→ 中档模型
❸ 合并链挑错     → 换一家的模型当外人

A. 照此派   B. 调整（说明哪单换谁）   C. 照此派，且本窗口同类活照此办 ← 问一次管一窗
```

**只在派活类任务上弹这个问题**（批量 / 并行 / 要交 PR 的）；自己顺手一次编辑的小活与纯问答不弹。
拍板时可以同批授予「本窗按推荐自动走」——此后只有真分歧才弹，其余以「已按推荐选 X」留一行痕迹，随时可叫停。
**永不自动的四类**：不可逆的决定、密钥与权限、删留判决、用户体感偏好题。

🔴 **回退红线（无条件生效）**：出口检查连续放过 2 个后来才被抓的真缺陷，
或者单个窗口里折腾编排的时间超过干活的时间 ⇒ **停新单、回头评架构**，不许硬扛。

**难回退的决定可以先拷问一轮**：删库、退役一套机制、换部署形态这类拍下去难反悔的，
拍板前可以跑一轮 `/grill-me`（查事实归 AI，做决定归用户）。这是可选项不是仪式，
问题已经想清楚的直接拍。

## 三、怎么派（Orca 推荐模式 · 用户 2026-08-12 拍板全体系遵守）

**命令与参数的唯一真相源是版本匹配指南**：动手前跑 `orca skills get orchestration` 现查——
它由将要执行你命令的那个程序自己吐出，永不过期。本文件刻意不背参数表，只固化**模式本身**：

**建树前先追平**：开派单流程先跑 `node scripts/dao-pre-dispatch.mjs`——本地 `master` 追平 `origin/master` 才算齐，红了（落后 / 领先 / 分叉 / fetch 失败）先追平再建树，三态与退出码契约全在脚本头注，不抄进本文。

1. **一次绑定 Run**（`run-create --objective`），**先建全部独立 Task**（`task-create --spec`），再起工兵。
2. **树的谱系跟随工作独立性**：独立关注点 / 独立修复 ⇒ 各开 `new-top-level` 树，一分支＝一关注点＝一 PR；
   概念上叠在当前工作之上、依赖它的 ⇒ `new-child`；**同一交付物拆给多工兵且文件面不相交** ⇒
   同一棵树里 `worker-start --worktree <该树>` 加终端；单被总帅规划为**树帅制**时，
   树内编制与纪律见 §三½。Orca 明说**不替你推断冲突**——
   同树多工兵先把「谁写哪些文件」划死，写同一份文件必互踩。
   **批开工即冻结其文件面，对协调者同样生效**：批在途时协调者对该批范围内文件的增量，
   要么发编排消息让工兵合入，要么排队批后由合并者亲手移植——两头写必造冲突
   （2026-08-12 实咬：B 批重写 rules 期间协调者仍在 master 上给同一文件立法，
   合并时 modify/delete 冲突，解铃人只能是自己）。
3. **工兵一律 `worker-start` 起可见终端**（工作树 + 终端 + 就绪 + 派单一步到位）——外族工兵尤其如此：
   可见标签页，不起无头后台。模型 / 思考档随 `--model`/`--effort` 传——**只对 Claude/Codex/Cursor 的
   新起终端生效**（别家不吃这两个参数，指定 provider/model 走低层配方），`--effort` 必须搭配 `--model`，
   两者都不能与 `--terminal` 复用同传。**读回执**（`launch.effective`、setup 状态）再继续，
   失败看 `stage`/`effects` 不盲重试。
   **Claude 族工兵出生即 auto mode**（用户 2026-08-12 拍板）：机制是**用户级** `~/.claude/settings.json`
   的 `defaultMode: "auto"`，由进 git 的幂等工具 `scripts/dao-auto-mode.mjs` 三层改齐
   （live 设置 + cc-switch DB + config-sync 快照），换机配完 provider 后由用户重跑一次即带。
   就绪后读屏核对一次屏底「⏵⏵ auto mode on」作兜底验证。见「manual mode on」⇒ 用户级设置没生效：
   查 `~/.claude/settings.json` 的 defaultMode、该仓有没有 `.claude/settings.local.json` 锁回 manual——
   **AI 不能隔空替工兵按审批或切模式（权限分类器拦死），只能报用户处置**。别家终端无此芯片，跳过。
   > 历史脚注：AI 代写 settings / 带 `--permission-mode` 起进程两路被分类器拦死的实测不变；
   > 项目级 `.claude/settings.json` 的 auto 自 Claude Code v2.1.142 被设计性忽略（官方明文：
   > 仓库不能给自己授 auto），随仓携带方案证伪。正解＝用户级、用户亲手跑工具（拍板见 issue #324）。
4. **收活循环**：`check --wait --types worker_done,escalation,question` → 逐条处理 → 同一工兵有接续任务
   用 `worker-start --terminal <handle>` 转交，否则 `worker-release`（成败都释放，用户明说留才
   `worker-retain`）→ 全处理完才 `--ack`。超时 / 终端空闲 / 心跳 / status / question / escalation /
   被拒或过期的 worker_done——这七样都不是释放理由。
   **合并链的 -RepoPath 禁手抄，从 PR 反查**（两棵树只差一个词，语境切换时手打必抄串）：
   `gh pr view <N> --json headRefName` → `orca worktree show --worktree "branch:<head>"` 取
   `.result.worktree.path` 传给脚本（`worktreePath` 是 terminal show 的字段名，两者不同）——
   凡是能从真相源推导的值都推导，不转写。
5. **恢复条件化**：`worker-show` 判 ready（继续等）/ failed·stopped（`--retry-of` 重起，位置显式重选
   不默继承）/ outcome_unknown（stop 后再查或显式 abandon），同一 task 连败 3 次自动熔断。
6. **禁替代**：说了走编排就必须有 task/dispatch 出处（`task-list`/`dispatch-show` 查得到）；
   用别的途径起的工兵不许事后描述成「已编排」。`worker-start` 表达不了的自定义命令行走低层配方：
   worktree create → terminal create 自定义命令 → dispatch --inject。

派单书四段式骨架（写进 `task-create --spec`）：

```
背景：一段说清来龙去脉。
范围（改这几处）：文件级清单。
约束（不许碰）：禁项 + 边界 + commit 前缀（按宿主：[cc]/[pi]/[codex]）。
验收：跑哪条命令、exit 0 才算过；完工交 exit-gate 交活单。
```

**四段合计默认短档（≤6 行），护栏类 / 判据类改动才升详细档**；派单书自身同受说人话铁律——
体系词首现括注，禁括号套括号一行塞三层（用户 2026-08-13 拍板；基线：#390 批 3 份 spec
约 40 行满篇体系词，5 行短档修红单 1 例实测即接单开工）。

铁律（每条背后都有一次尸检）：

1. **派单只走编排通道**，禁手建工作树 + 终端的散装路（低层配方也要挂上 dispatch）。
2. **派单书一次给全**（背景 / 范围 / 约束 / 验收四段），缺一段就是下一轮往返。
3. **派单书之外的上下文工兵拿不到**——交回的东西必须落盘成文件，完工消息只报路径。
4. 完工消息**恰好发一次**、带成败结论（失败禁只写在散文里）与改过的文件清单。
5. orca 命令只信 `--json` 出口。
6. **工兵体内没有 AskUserQuestion**（会挂死）；要问走 `orca orchestration ask`，协调者 `reply` 答。
7. **底座缺省 = Orca 编排**：要审要追踪的走 `orchestration`（task-create + worker-start）；
   完全撒手不管的走 `orca-cli`（仅剩「用户显式说派完不用管」一个合法场景）；
   本地 subagent 降为没有 Orca 时的备选。
8. **陌生执行者名先查环境再问，禁静默替换成最像的那个**：「用哪个执行者」是只有环境知道的事。
   用户点名一个你不认识的执行者时，次序固定：①先查环境（orca 可用面 / 已装 skill / `dao-roster.mjs`）
   ②仍不认识再问用户 ③**无论如何轮不到静默替换**。
9. **给 orca 传多行 / 含反引号等特殊字符的文本，先落文件再 `--spec "$(cat 文件)"`，禁双引号裸拼**
   （基线：反引号裸拼致命令替换吞字符 2 例）。[自定@0813]
10. **依赖未合并产物的后续动作（配 automation / 挂 cron）排进合并后收官链直接做**，
    不造「命令清单文件」中间交接（用户 2026-08-13 拍板；基线：#390 批 automation
    命令落盘再照单配，多一跳 1 例）。

## 三½、树帅制（结构形态之一 · 用户 2026-08-13 拍板，#350）

单选定树帅制时两层分形：**总帅**只派树帅、收成品、终审合并；**树帅**在树内派官、跑返工循环、
自审全绿才发 `worker_done`，模型档按 §二 每单提案。

- **树帅出生即无写工具（结构约束替代纪律 · 2026-08-13 三犯定形）**：起树帅走低层配方，命令自带工具面裁剪——
  `terminal create --command "claude --model <档> --autocompact 350k --disallowedTools \"Edit,Write,NotebookEdit,Task\"" → dispatch --inject`。
  压缩阈值双档（用户 2026-08-13 拍板，任何项目任何机器沿用）：帅位 500k（≈1M 的 50%，settings
  `autoCompactWindow` 经 config-sync 全局兜底，不用手动带）；树帅与 Claude Code 工兵终端 300~400k 档，
  起终端的命令行**必带 `--autocompact 350k`**——省着点上下文，压缩宜早不宜满。
  「树帅不亲手干制作活」从此不是纪律是结构：写不了文件、派不了 subagent，只剩读＋终端编排；
  只读勘察用自带 Read/Grep/Glob。教训：散文禁令对模型天性必输（v1 拿 subagent 干活、
  v2 令写明白了仍亲手改码）——**违例动作要从「被禁止」做成「不存在」**。Bash 旁路写文件仍存在，
  由验收硬项兜底：**树内终端数 ≥2（总帅 `terminal list` 机器可查）＋ `worker_done` 带派官记录，孤军完工不收**。
- **开工第一动作＝报编排计划**：树帅规划完先发一条 status（几路工兵 / 各派什么 / 文件面怎么分）再开派，
  把总帅的形态核对从完工提前到开工。

- **树内工兵 = 可见终端**（`orca terminal create --worktree <本树> --command <CLI>`），
  树帅用 `terminal send/read` 轻管理（首战形态；嵌套编排跑通后再评估升级）。
  **subagent 仅限只读小勘察**（一分钟内的查证）——制作性 / 审查性的活必须可见终端：
  可观测、烧对家的额度、与「工兵层归谁」的拍板不冲突（2026-08-13 实咬：树帅拿 subagent
  干实现，烧的是树帅自己的高档额度且 Orca 侧栏全程不可见）。
- **低层配方标准链固定四步，一步不少**（基线：未测，单次实证——为带 `--autocompact` 等旗标跳过建树步，
  工兵落在主仓，用户当场抓）：`worker-start` 表达不了的旗标（如 `--autocompact`）一律走低层配方——
  pre-dispatch 追平闸 → `worktree create --no-parent --issue N --comment "<形态·棒次·等什么>"` →
  `terminal create --command "reclaude --model <档> --autocompact 350k [--disallowedTools ...]"` →
  `dispatch --inject` → 回读验证任务书落屏（见下「启动序」）。[自定@0813]
- **完工前必有一路换家对抗审**：树内起异家模型终端审全部 diff（先破再验），红的树内修完才许交。
  开审前先照 `ccswitch/rules/dao-attack-surfaces.md` 破点清单过一遍，表内五类列全不靠现场想
  （基线：#340 四轮对抗审实打，来源即表内容）。[自定@0813]
- **审官选派不写死执行者名，只锁家族约束**：派单令只需保证「审官家族≠实现者家族」，具体派谁派前跑
  `node scripts/dao-roster.mjs` 探测可用面自选，不停摆、不上报。换人按**依赖通道**降级，不只按家族——
  中转站是共享依赖，网关挂了后面全家一起挂（本机三通道：new-api 中转 / deepseek 直连 / Claude 订阅）；
  降级到同家必须在交付里显式标注「审官同家、判别力打折」，禁静默。
  （基线：2026-08-13 夜 codex 网关 503 近 3 例中 2 例按此序零往返自愈）[自定@0813]
- **验证密度按失效代价×静默程度分三档，不是一律拉满**：不可逆档（失效即删/改不可撤销之物）
  ⇒ 正负控 + 边界穷举 + 逐判据 mutation；静默档（失效不可见但可逆）⇒ 正负控 + 零样本闸 + 关键 mutation；
  fail-loud 档（失效当场可见）⇒ 正负控 + 零样本闸即止，不穷举不逐 mutation。
  **对抗审强度同表取档**：软闸（失效只出错报告、不拦任何动作）⇒ 独立复跑 + 关键 mutation 一处即止；
  硬闸 / 不可逆才全套（逐 mutation + 反向验证 + 语料夹击）。
  （基线：未测，单次实证：#340 对 fail-loud 部件误拉满密度多烧两轮；对抗审档：#391 对软闸
  误拉满全套审 1 例，用户 2026-08-13 拍板）[自定@0813]
- **树帅令用四格短模板**（替代长派单书）：【任务（含一句树帅纪律：派官干活、完工前换家对抗审）】
  【边界（不许碰）】【验收】【审计锚（争议以 issue #N 拍板评论为准）】。瘦身三则：
  机器闸已拦的**删字留闸**（配了闸就别再写指针）；触发器会自动送达的不重复写；
  只手写这单特有的地形情报。契约给操作规格、不布置「全读」考古；
  officer-clauses 由官种机制随 agent_type 送达，树帅不代下级预习。
- **启动序＝先证就绪再回读，不做无条件盲发**（基线：未测，单次实证——treelord-360 首发任务书被吞
  5 分钟零执行，旧序「`worker-start` 返回→等数秒→无条件补一发回车」对抢跑是空的）：
  注入前先证就绪（读屏见输入框 / 底栏）→ `dispatch --inject` → **回读验证任务书落屏**
  （不落屏 = 未注入成功，`task-update ready` 后重投，盲等秒数不是证据）→ 补一发回车。
  注记：`reclaude` 启动比裸 `claude` 多一段配置同步，抢跑必吞令。见 manual 态仍走兜底：
  **先切 auto 再回车**——弹窗挂着时一切按键喂给弹窗，答掉弹窗再切。[自定@0813]
- **看门狗分形**：总帅盯树帅、树帅盯树内工兵，判据同一条——读屏指纹连续两次相同（≥10 分钟）
  即走接手流程，最多救一发回车；树帅常驻本身就是树内的活看门狗。
- **收活哨兵必须四格齐，缺一格那一格就变静默**：①产物出现 ②屏上失败信号 ③屏文本剔数字后连续
  10 分钟静止 ④兜底超时——「什么都没写」与「还在思考」在观测面上逐字节相同，缺哪一格就在哪一格里
  分不清。两条实证坑：失败信号片段必须短到被 TUI 字符级重绘切碎后仍存活（写 `econnect` 不写
  `Reconnecting`）；指纹必须先剔数字再比对（屏底计时器每秒变，不剔就永远判不了静止）。配哨兵必跑
  两面：真挂终端负控必须响 + 活终端正控不误报——没跑过负控的哨兵只是装饰。
  （基线：本夜 3 单实战中命中该类静默坑 2 类）[自定@0813]
- **清树前先把 `_tmp/` 搬去主仓，再 `worktree rm`**：树内 `_tmp/` 下的报告与提案随清树一起消失，
  只剩消息摘要留档。（基线：340v2 两份提案原文随清树消失）[自定@0813]

## 四、派单书里写什么

### 必带首行，原样复制，不要现场判断该不该带

```
开工第一步：Read `<dao 仓根>/ccswitch/rules/dao-officer-clauses.md`（跨项目通用）+ 本仓 `<项目条款库路径>`（本仓特有），两份都通读「通用节」+ 你这一类工人那一节，逐条遵守。有冲突以盘上文件为准，不以本 prompt 的转述为准。
开工第二步：全套验证入口去 `<目标仓根>/CLAUDE.md` 自己查——**本令刻意不给验证命令**。那份文件没写、或它列的清单与盘上对不上时，以盘上为准，并把差异写进交付（别只在自己这一路悄悄改对）。
开工第三步：起了后台/异步验证任务后**别停手等通知**——收不到通知就自己读输出文件或前台重跑拿真退出码；本轮你只需跑相关套 + 默认层，全量层归合并链在串行环境统一跑；**禁止把「等不到通知」静默当「已通过」**。
```

**为什么固定写、不许现场判断**：同一份文件里，跟着模板走的那句携带率是 100%，
而要求每次重新判断该带哪几条的只有个位数到两成。**区分变量不是措辞强弱，是「有固定形态」还是「要现场判断」。**

**为什么第二步是「不给命令」而不是「给对的命令」**：验证入口是**只有盘上那份文件知道**的字段，
你写下的任何值都只能来自记忆。**把这一格从派单书里删掉，比把它填对更彻底**——填对是一次性的，
删掉是结构性的。第二步给的是**路径**不是命令，正因为 `<目标仓根>/CLAUDE.md` 这个路径不看仓也说得出。

⚠ 两格照直写：㈠**它不指定节名**——不同的仓落点根本不同名，写死节名会让它在第二个仓上静默落空。
㈡**那份文件本身会过期**——所以第二步末句「以盘上为准 + 把差异写进交付」是必填不是客套；
**收到差异后该改的是那份 `CLAUDE.md`，不是下一个派单书的措辞**。

### 两道门

- **契约门**：派单书必须引用契约文档路径（spec / 验收标准 / 对齐矩阵 / UX 定稿），
  并列**本批覆盖 vs 显式不覆盖**两栏。**禁止凭会话记忆拼需求**——上下文一压缩，记忆必丢细节。
- **成本门**：多 agent 大约是十几倍的开销，任务价值不够不开。六项自评
  （模板化？/ 需不同档？/ 主上下文臃肿？/ 真独立？/ 值这个价？/ 能真并行？）满足 3 项以上才派。
- **写禁项前先答「验证禁令反噬」**：这条要禁的动作，是不是某条验收标准的必经路——
  禁令禁掉唯一执行路径时，验证退化成零执行还全绿。
  （基线：未测，单次实证：树帅令禁 DryRun 致被测代码零执行，单测全绿）[自定@0813]

### 派之前最后过一遍的六格

1. **工具面**：把任务要求的动作逐条对一遍那个 agent 的工具清单。凡出现「独立复跑」「换靶」
   「字节级复原」「真机截图」「起服务」，就都需要能跑命令、能写文件；**只读型 agent 结构上做不到**。
   一句话：**这个工人被要求做的事，它手上有那个工具吗**。危险不在会失败，在于**它一路跑到最后才失败**。
2. **身份**：派写代码 / 挑错 / 查资料 / 试用类工人时，选对应的 agent 类型
   （`dao-implementer` / `dao-adversary` / `dao-scout` / `dao-dogfood`，复审用 `dao-reviewer`），
   别一律拿通用底座。那几份 profile 刻意很薄，**它们的全部职责就是让 agent 类型带上工人类型**。
   ⚠ 没有程序在核你选对没有；且 profile 不在 `~/.claude/agents/` 里就选不着（那是部署的事）。
3. **模型档**：**显式传模型**，不传 = 落到宿主默认档，不是继承你这一档。
   连续 2 次 API 错误（限流 / 过载）⇒ 降一档重派，不做第三次同档盲试。
   **省没省钱按「每件活的总成本」记，不按单价推**——存在「单价更便宜、每件活更贵」的形态。
   **降档的第一收益往往不是钱，是并发**——撞到的常常不是账单是账号级限流，
   所以成本门之外再加一问：**这一批同时在跑几路，池子扛得住吗**。
   **工人死于「额度用完 / N 小时后重置」时**：报错里的时间是死亡那一刻的状态，不是现在的状态——
   **你此刻还在推理，就是限流已结束的活证据**。醒着即刻重派，禁写「等 X 小时后再派」。
4. **写入面**：结论依赖「这段时间只有我在动」的任务（对照实验 / 偶发复现 / 某段时间内有没有发生 X），
   派单书里必须有一行说清**这段时间谁能往这个仓写、谁不能**。读一个瞬时值、拍一张截图不必写。
   一句话：**这段时间里仓里的每一次写入，我说得出是谁干的吗**。
5. **字段来源**：**只有盘上那份文件知道的字段一律不写值**（验证入口 / 构建命令 / 包管理器 /
   主干分支名 / 版本号落点 / 账本文件名），改成一句「去 `<目标仓根>/CLAUDE.md` 自己查」；
   **不看那个仓也说得出的才准写值**（工作树开在哪 / 止步 `gh pr create` / 文件路径）。
   ⚠ 跨仓派活时**你手上那份别的项目的验证入口，比手上什么都没有更危险**——它让这一格产生「我知道」的手感。
6. **近似手段的语料从哪来**：改动涉及正则 / 启发式 / 关键词表时，派单书须指定**外部语料来源**
   （真实命令历史 / 线上日志 / 竞品规则库 / 历史事故样本），**禁止「用本轮发现的形态构造正反例」**——
   内生语料只能证明「上一轮那些洞已补」，证不了「还有没有第 N+1 类」，结构上必然产出补漏—再漏循环。
   配一个停手信号：**同一文件 24 小时内第 3 次返工即转设计评审**（`git log --since=24h -- <file>`）。

### 两类特殊派单

- **接手令必带接手点，接手不是重来**：重派一个死掉的工人时，派单书固定四格——
  ①工作树 / 分支 / 基点 ②前任已提交的 commit ③前任未提交的改动清单
  ④**前任死前最后一句原话，标「待坐实或推翻」**。并令工人开工先 `git status` + `git log -5` 对核、以盘上为准。
- **前提可疑的修复单按「先核再修」派**：修复对象的前提存疑（疑似假阳性 / 来源不明）时，
  派单书先考古后修，并预写三态——干净 ⇒ 照原修法；真错 ⇒ 先修错处（单独 commit 写明结论）再修；
  **判不出 ⇒ 停手不修，材料上报定夺**。「判不出」禁静默降级为「按干净处理」。
  考古结论同时决定修法形态：清白 ⇒ 只做归一化消噪；不清白 ⇒ 才写真正的阻断逻辑。
- **修红类派单书另加一格自答**：派修复红色判据 / 护栏的单，骨架「约束」段后追加一格
  「你这个修法可能引入什么、你验了没有」，工兵自己先答一遍再交，把发现提前一轮。
  （基线：未测，单次实证：#340 N2 围栏误红即第 2 轮修法自己引入；正向对照：要求修前绿/修后红
  对照后工兵自抓 fixture 失真。）[自定@0813]

### 一句话提醒（写进派单书比让每个工人各撞一次便宜）

**覆写一个已存在的文件之前先用 Read 工具读它**——没读过宿主直接判失败。新建文件不受此限。

### 什么时候拆成多路

并行只在**横向按模块切**时赢，三条判据全过才拆：①各路要改的文件几乎不相交
（共享的那几份指定唯一负责人）②接口能在派单前**冻结进契约文档** ③单路预估超过 40 分钟
（拆分的固定成本约 10 分钟：冻结契约 + 多轮验收）。**纵向按功能切片不拆。**
已经开工的领地被占时中途重切是负收益，改用「加速令」（要一个预计完成时间 + 砍掉非核心）。

**批量同构 / 需要挑错 / 编排要可复现** ⇒ 用 Workflow 脚本（重器，须用户明示授权）。
用户说出「高性能自主任务」这一档信号，本身即构成对 Workflow 的显式授权，不必再逐次征询；
但形态判据不变（批量同构才开），开前一句通报规模量级。

## 五、派出去之后：看着它真的跑起来

- 🔴 **派完看一眼首回合真的烧起来了**：任务书卡在输入框、回车被吞，是真发生过的形态。
  判据：终端预览里计费 / API 时长在动才算开跑；躺着的补一发 `terminal send --enter` 即活。
  **「送到了」不等于「跑起来了」。**
- 🔴 **卡住这件事不靠人眼发现**：卡住的形态很多（回车被吞 / 限流 / 分类器拦截 / 审批弹窗等），
  都不产生编排消息，收活等待对它们是瞎的——在跑的工兵除 `check --wait` 外必须配一个看门狗
  （周期读屏，异常即上报）。**发现卡住第一动作是读屏底那行模式**：见「manual mode on」⇒
  用户级 auto 没生效，查 `~/.claude/settings.json` 与该仓 local 锁（见上 §三.3）；
  AI 无法替工兵按审批或切模式，弹窗挂着只能报用户。
- 日常观测只看三样：`worker-show`（状态 + 终端预览）+ 心跳 + 提交流，不翻别的。
  直接翻工兵的会话文件只作事故取证的最后手段。
- **「Setup failed」通报点名的是 setup 终端，不是工兵**——先看 agent 终端在不在烧再处置
  （2026-08-12 实况：仓库级 setup 脚本每建一树必败一次，工兵全程正常；根治是在 Orca 仓库
  设置里清掉那条 setup 命令，CLI 无写口）。
- 给已有终端挂新任务必须显式 `--worktree`（默认瞄协调者所在的树，会报不匹配）。
- 打回用 `orchestration send --to dispatch:<id>` 或 `terminal send`，**都排在 `worker-release` 之前**
  （release 会关掉终端标签页）。

## 六、收活

**完工消息不是验收，只是铃响。** 验收 = `scripts/dao-exit-gate.mjs` 五道秒级门
（格式 / 凭证边界 / 卫生 / 限时重放），契约见该脚本头注。**人工最终审核不退役**——
门只抬门槛，判断仍是人的。合并链的验证步 = `dao check` 一条命令，exit 0 才合。

**验的深度按「错了代价多大 × 反转多难」分级**：
① 写代码的**全验**（复跑构建测试 + 逐条对验收标准 + 真机验证，全过才合）；
② 查资料的低风险件**抽验**（亲自核 1-2 条最承重的论断）；
③ 查资料的高风险件**对抗验**（论断带出处 + 抽验最承重的两三条，或两路独立调研只对分歧深挖）——
调研出错不炸 CI，反转成本却高于代码缺陷，该验得更狠。
**验证可以委派，终审不可让渡**：定标准 / 读结论 / 按合并那三下必须自己来。
**给判官的输入不许静默截断**：发现清单、出处这类承重字段被截断，制造的是「无从核验」型误裁。

🔴 **验证资源独占时，「每条都合规地挂了账」会掩盖「整批的覆盖率在跌」**：
某类验证依赖一个同时刻只能有一个人用的资源（真机 / 设备 / 生产账号 / 独占端口）时，
批内各路会各自合规地走「降级挂账」——**单看每个 PR 都无可指摘，合起来看这一批几乎没被验过**。
缺的不是纪律，是**聚合视角**。⇒ 派批前先数「这一批里有几路要抢同一个资源」，
超过 1 就**指定谁真的用它**、其余在派单书里写明本路不验；窗末**按批**报一次真实覆盖率，不是按条报合规率。

🔴 **一边跑着监听重编译的进程、一边还有人写那棵树，验证就是假的**：
验证方式是「从工作树跑一个 watch 编译的进程」（dev / vite / webpack --watch / 任何热重载）时，
那棵树的任何写入都会触发重载、打断验证。**正解不是更努力地冻结主干，是让验证进程从一棵专用工作树起**——
主仓怎么改都不进它的监听面。判据一句话：**我的验证进程盯的是哪棵树？那棵树此刻只有它一个人写吗？**
答主仓＝错。

🔴 **判一个工人「越权」之前，先去读它自己那份记录**：
subagent 的上下文与你的**本来就不是同一份**，用户可以直接对它说话。
**「我的上下文里没有这条消息」不等于「用户没说过这句话」。**
去 `~/.claude/projects/<slug>/<session-uuid>/subagents/agent-<id>.jsonl` 里用有界小窗口读，
用户中途插话有个固定签名 `The user sent a new message while you were working`，搜它即可。
⚠ **别去搜顶层那份会话文件**——那里装的是工人交回的报告原文，用报告证明报告等于没证。
🔴 **在找到之前不许回滚，更不许公开指控。**
盘上多出来路不明的 commit 同理：先读 `Claude-Session` 尾注定出处再处置。

## 六½、协调者这个位子本身

**三件事**：
- **谋**——把相互独立的子任务拆出来；**强耦合的不拆**（拆了要付冻结契约 + 多轮验收的固定成本）。
- **派**——按档派人，**独立任务一条消息并行同发**，不排队。
- **合**——验证、去重、把各路摘要综合起来，**不让原始输出灌爆主上下文**。
  **自己下场干活会烧上下文 ⇒ 加速压缩 ⇒ 记忆流失**，「协调者下场」与「协调者忘事」是同一个病。

**转向权铁律**：与用户共处的会话里，协调者**只谈方向、不亲手做批量实现**——
实现件一律派出去，**派完立即回对话席保持可讨论**。用户中途改方向 ⇒ **当场**转向在跑的那几路
（下新指令 / 掐掉重派 / 续跑），**不等它们跑完再纠**。

**亲历上限**：制作性交付物（代码 / 原型 / 测试 / 文档 / 截图）算产出就派；
亲手只做读码定案、一次编辑级的微调、验收合成。
**新建超过 50 行、或同一交付物超过 3 轮工具循环，必须派出去。**

## 七、长时间无人值守的窗口

### 开窗那一刻

① **设心跳**（`ScheduleWakeup`）+ 登记在途任务台账 + 输出开窗报告（现状 → 拆解 → 时长预算）。
台账里的时刻以心跳返回的实时为唯一锚，**禁凭批次进度推算**。
接力 / 恢复的会话不经过开窗仪式，要续用自主排程就补跑一遍这一步。

② **选题是问题树，不是时间表**：先判健康期还是病期（体检 / CI 红着 ⇒ 先修；干净 ⇒ 建设）。
🔴 **禁止给方向或任务预分小时数**——伪精确，且到点就切换会让挖到一半的问题被搁置。
正解：**列大方向 → 每个方向钻到底 → 子问题拆到能解决为止 → 过程中的新发现挂回同一棵树**；
完成判据是「这个方向的树清空了」，不是「到点了」。**没有承接物，「不搁置」就是空话**——
承接物就是 §一 那三个家。

③ **外部输入是常态不是偶发**，四个来源：业界最佳实践（做技术 / 交互决策前先查别人怎么做，
不闭门发明）· 自己端到端跑一遍记「卡在哪」· 竞品做得好的地方（学形态与信息架构；
读源码不禁，但读完写自然语言笔记、基于笔记实现，不对着源码写，绝不复制代码片段 / 注释 / 独特命名 /
文件结构）· 竞品评论区与社媒里的真实痛点。**再配两个反向来源**：
⑤**减法自问**——「这批之后有什么该删 / 该合并 / 该默认关掉」；
⑥**无声失败扫描**——无障碍、边界数据量、极端环境的受害者不发声直接走人，
而端到端由熟练者跑，**跑不出新手会卡的地方**。
落地靠挂在必经动作上：用户面功能批的派单书须附「外部参照三问」各一句话 + 出处，查了没有就显式写「无先例」。

### 每次心跳醒来

🔴 **第一个工具段就是「在途几路 × 队列有活吗」，补派到水位，排在任何合并 / 裁决 / 抽验之前。**
合并期是水位最容易漏的时刻。**默认态是多路满载，单路在途是需要理由的例外。**
每个「不派」都要答得出「这一路为什么不能现在跑」，答不出就是水位缺口。
两个已实证的滑落形态都不是「忘了派」而是「有理由地不派、而理由是错的」：
①连环死亡后只重派了死的那路，没恢复其余并发；②「冻结主干推送」被读成「少开工」。

**水位是上限不是配额**：目标 = `min(档位水位, 并行安全的队列深度)`。
队列被**串行独占资源**主导时，少于水位是对的，硬凑等于造无用功。
把待办拆「纯代码可并行 / 抢独占资源 / 待拍板 / 受阻」四堆看，只有第一堆能填并行水位。
**抬吞吐的钥匙是解开那个串行约束，不是再多派一个人**——问「现在什么资源在串行化整条队列」。

**档位水位随限流实况三态取值**（判据读限流哨兵落盘的标记与死亡记录，不新造判据源）：
- **健康**（最近 30 分钟零限流死亡）⇒ 满载 6-8 路。
- **受创**（最近 30 分钟发生过一波死亡）⇒ 水位减半，且补派**错峰**（不同时起两路）。
- **限流**（标记文件仍在）⇒ 收到 1 路探路，其余排队，不批量重派。
- **恢复**：标记解除后，首批重派的工人存活满 10 分钟起，每 15 分钟 +1 路爬回满载，不是一解除就拉满。

### 一轮怎么收尾

**简报先于心跳、作为独立完整消息发出**；心跳的 prompt 里只准写未来动作，**不准预记「已发」**。
**`ScheduleWakeup` 是本轮刻意的最后一个动作**——它一返回，这一轮立刻被宿主终结，其后不可能再有任何调用。
所以调它之前，简报与全部实质动作必须已经做完。
**一轮的收尾只有两种合法形态：殿后心跳，或显式 `{stop:true}` / 交还用户。**
不存在「纯文本收尾且没设心跳」这一态，误入即零在途 + 零待触发 = 循环饿死。
心跳一返回就无法回头证明「刚才那条简报真的独立发出去了」，所以**每次唤醒仍要核查上一轮简报是否真发**
（含「只写进了心跳 prompt 里」这种未发形态），未发则先补。

心跳的 prompt 末尾固定携带这两句，原样复制：

```
醒来第一动作：Read `ccswitch/rules/dao-dispatch.md` §七「每次心跳醒来」，按节内次序逐条对账。
铁序自提醒：简报先于心跳且独立成条发出；ScheduleWakeup 是本轮刻意的最后动作，调用前简报与全部实质动作须已完成。
```

**监督信号必须独立于作业信道**——只靠任务完成通知驱动，任何一路沉默就饿死整窗。
所以除心跳外还要有一路常驻兜底（`[dao-heartbeat]` 定时任务，只在本会话内有效，每次开窗重建）：
殿后心跳若因限流 / API 错 / 用户打断而没调成，简报已发但零心跳待触发，兜底是把这种窗口唤回来的那一路。

窗末简报里三行固定槽位，**每行两态恰选其一，没有第三态；缺任一行视同收官未完成**：

```
🌾 收割：已跑（候选 N 条 / 入库 M 条 / 落点 <文件>） | 未跑（<一句理由>）
♻️ 整编：已跑（建议 N 条 / 采纳 M 条） | 未跑（<一句理由>）
🔄 会话接力：建议收窗交接（本窗已合 PR <n> 个 / 已开窗 <h> 小时，达阈值） | 可续窗（<n> 个 / <h> 小时，未达阈值）
```

**接力阈值：合并 PR ≥ 25 个，或开窗 ≥ 24 小时，任一先到即取「建议收窗交接」态。**
达阈不等于必须停——它强制的是**把这句话说出来**，给用户一次接管机会；续窗要在同一行后面补一句为什么。
（会话越长遵守率越低，这是外部实证里唯一显著的杠杆，量级高于本文件里绝大多数条目——
所以它必须是一个槽位，不能是一句提醒。⚠ 阈值取值仍待用户拍板。）
**坏经验有天然触发器（出事了 / 返工了），好经验没有**——收官是长窗里唯一必经的「停下来」时刻，
那是收割的唯一触发点。

### 到点那一刻

**授权的是时长不是批次**：每批收完核对剩余时长——够一批就回去再排，不够但还有半小时就填充短活，
接近零才真收窗。**禁止「计划完成 = 窗口完成」的单方面提前收窗。**

**「到点」管的是「不再开新的」，不管「已经在跑的」**：一个已派出去的工人正在烧真机 / 编译 / 额度，
到点掐掉它等于把已付出的成本全额作废，而它往往只差最后一步。三段：
① **软截止 = 你报出去的那个结束时刻本身**——报出去的数是「开工到几点」，不是「几点关灯」；
收官段在那之后继续，不占用报出去的时长。到点这一刻做一次显式盘点写进台账，
每一路的**预期交付物**与**兜底方案**各一行（凭印象对账实测失败多次）。
② **收官段与「收在跑的工人」并行，不排在它后面**——收官大部分是文档动作，不抢编译与真机资源；
串行是收官段整段消失的直接原因。
③ **硬截止：两边都收完才停。** 超时未交付的走失联流程：**先查环境终态再判死，判死后盘它已产出的部分接手**。
⚠ **唯一不容协商的硬边界是「不再开新的」**，否则「把手头干完」会退化成无限延窗。
**判据一句话：到点之后，允许收尾，不允许开工。**

**窗界还有另一个维度**：授权语含「X 小时」⇒ 时长窗，上面三段原样生效；
含「直到完成 / 改无可改 / 你认为完成为止」⇒ **目标窗**——边界不是时刻，是目标闭包。
目标窗三则：㈠收窗判据 = 问题树清空，或剩余项全部挂账且每笔带解冻条件
（「证明此路不可达 + 写明何时可达」也算达成），或触及下面的自主边界；**没有「到点」这回事**。
㈡遇阻**先绕**（换手段），绕不通**回退**（撤当前支线走另一支，撤销留痕），全支不通**挂账**——
**停摆不是这四个动作之一**。㈢树外不开新方向，否则目标闭包被新发现无限撑大。

### 自主边界（永不进自主窗）

不可逆决策（架构定死 / 对外发布 / 删用户数据）、需用户在场的（凭据 / 审美拍板 / 真钥匙）、
用户没点头的新疆域——只做「沿既定方向推进 + 健康维护」，转向权归用户。
其中「对外发布」已经有机器拦截（`ccswitch/hooks/dao-hard-gates.js` 的 G3），
**其余各格机器判不了，仍然只是判据**。

**几周级的任务，正确形态是短会话接力 + 交接文档，不是一个不死的长会话**——上下文压缩有损，消不掉。

## 八、已知边界（照直写）

- 探测是「跑一下 `--version`」那个级别的：CLI 在 PATH 才算在，装在别处的探测不到（标缺席，不猜）。
- 「本窗口同类活照此办」只在这个窗口内有效，没有跨窗持久机制（刻意——持久化会再长出一本配置账）。
- Orca 的静默失败面没有被治愈：完工消息发送失败仍可能无声，出口检查的「凭证边界」那道门只能事后兜底。
- 本节里绝大多数判据**没有任何程序在核**：你派错档、漏了一格、跳过一步，
  在台账上与做对了长得一样。现场唯一的判据是派单通报里那几个槽位。
- 心跳这条通道有一段未验证：**上下文压缩之后心跳还在不在，至今不知道**。
  在实测出来之前，别把「设了心跳」读成「一定醒得来」——常驻兜底那一路就是为此存在的，
  而它自己同样是会话级的。
