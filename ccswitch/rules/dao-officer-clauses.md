# 工人开工便签

派单书第一行让你读的就是这份。**先读「所有人」那十条，再读你这一类那几行。**
有冲突以盘上文件为准，不以派单书里的转述为准。项目特有的（跑哪条命令、账本文件、专有脚本）
在那个仓自己的 `docs/rules/dispatch-clauses.md` 里，两份都要读。

## 所有人（十条）

1. **你是被派来的，回答对象是派你来的那个人，不是用户**——不要调 AskUserQuestion（会挂死），
   要问就走派你来的那条通道。
2. **覆写一个已存在的文件之前，先用 Read 工具读它**。「读过」按路径算（在别的树里读过同名文件不算），
   用命令把文件打印出来也不算。新建文件不受此限。
3. **起了后台或异步任务，就得亲手读到终态才准停手**。挂上监听、装个轮询器都不算「已主动轮询」——
   停手就是停摆。**等待类超过 15 分钟仍不就绪 ⇒ 放弃这个验证手段，把欠账写进交付，带着已完成部分交，
   不无限期卡等。**
4. **止步 `gh pr create`**：不合并、不删分支。终审与合并归派你来的人。
5. **PR 正文 / issue 评论永不经过 shell 字符串**：先落文件，再 `--body-file`；
   发出后回读一次（`gh pr view <n> --json body -q .body > 文件`，再用 Grep 扫乱码签名字），零命中才算发完。
   理由不是礼貌——正文过任何 shell 字符串都可能被静默改写，**而退出码是干净的**。
6. **禁笃定措辞**：「已补全 / 全覆盖 / 无遗漏 / 零行为改动 / 已修好」这类，把近似说成了判定。
   用正则、字符类、启发式做的事必须标注为近似，并写明两个方向都举得出反例。
   「已修好」和「已补全」是同一类措辞，区别只在被断言的对象是你上一轮的修。
7. **改、迁、删任何被别处引用的东西，同一批把引用面 Grep 一遍**：被引用方一改，引用方静默失效，
   失效形态是「照着旧内容做会得到假结论」。两格容易漏：**它可能被另一个仓引用**（有名字就会被别人写下来），
   以及**那个对象自己的头注也在描述它自己**，而头注比文档更少被人回头看。
   **留一个指向空气的指针比没有指针更糟**——读者会以为有兜底。
8. **交付必带未尽处**，「没有未尽处」也要给理由。零发现也是合格交付——沉默会被读成「这一路没扫」。
   任何结论带可复核的出处（文件+行号，或命令+真退出码）。
9. **验证要跑得对**：搜索用 Grep / 找路径用 Glob / 读文件用 Read；切目录跑验证前先加目录守卫
   （特征文件不在就退出）并打印当前目录标记，复验先核那一行——否则会静默跑在错的仓上而退出码正常。
   收账一律 `git add <具体路径>`，**禁 `-A` / `.`**：多路并行时工作树是共享的，别人的半成品会被你一起收走。
10. **接手不是重来**：做任何有副作用的动作前先查它是不是前任已经做过了（`git log` / `gh pr list`）。
    **前任死前最后一句是死亡瞬间的意图宣告，不是进度报告，两个方向都会失真**——
    说「正要做 X」的可能已经做完了，下了结论的可能根本没证据。**两个方向都只认盘上。**

> **Windows 上还有一条编码铁律**：`Get-Content` 的**任何形态**（含 `-Raw`、含只读不写）
> 读无 BOM 的 UTF-8 文件时，中文内容当场就毁了，写侧再规范也救不回来；
> 而且字符串毁掉之后，后续 `-replace '<含中文的模式>'` 一律不命中、不报错、退出码照样 0。
> 用 `[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)` 读。全套坑见 `ccswitch/rules/dao-shell.md`。

## 按你这一类，再看这几行

| 你是来干什么的 | 开工与交付各多一件事 |
|---|---|
| **写代码** | 进工作树先核基点（`merge-base HEAD main` 等于 main 顶端才算齐，落后先 merge 再开工）；**交付前再核一次**——`MERGEABLE` 只证明没有文本冲突，它看不见语义冲突，更看不见**预算型的闸对「和」设限而 PR 是按「增量」审的**（两边各自都没越线，合起来越线）。冲突解按「两侧都留」走时附纯增量证明；生成物一个字不手解，在合并态重跑生成器。 |
| **挑错 / 对抗验证** | 不重跑对方已经跑过的那套构建测试——改成核对他贴出来的原始输出是不是真的（时间戳 / 退出码 / 标记对不对得上，有没有转述痕迹）。**换靶要看到红绿两态**，且「改坏」至少试三个方向：①整段删掉 ②保留字面但让它不执行（注释掉 / 提前 return）③保留调用与副作用但结果不被消费。**读红集之前先确认变异体还活着**——一个把靶弄死的变异会让每条断言都红，那正是「判别力满分」的表象。**红集超过 2 条就逐条归因**，并答一句「换一棵树、换一台机器，这个红集还一样吗」。报告里报**调用点覆盖率**（生产调用点总数 vs 本批真跑到的数，分母为 0 就照直写 0，不报百分比）。**负控也要从真实语料采样**——自造的诱饵只证明「我的诱饵不会被误伤」。验完**字节级复原**（`git diff` 空）；复原前先确认基线是哪一态（`git checkout --` 复原到的是 HEAD，会连你这批未提交的实现一起冲掉）。 |
| **复审** | range 必须实算（`git merge-base` / 逐个 merge commit 取父），**禁目测「最近几个提交」**——发布或收账提交落在合并点之后时，估出来的起点会把整批 PR 排除在外。 |
| **查资料 / 侦察** | **只读红线**：全程不写不改，不新建文件、不 commit、不动配置；发现异常只记录不擅自修。收工在报告里写一行「本轮零写入（`git status` 空）」。与基线比无变化时**显式写「零增量」**。能实测的不停留在「应该是」。 |
| **试用 / 走查** | **走查期间不动那棵树**——不只是 git 操作，直接编辑源码同样算：监听重编译的进程盯的是文件，它不管你是用什么改的。要改就等走查做完，或者用第二棵树。抽验要问「数据对不对」，不满足于「有数据 / 有响应」。 |

## 两条容易读错的

- **「本仓」「全库」这类词，指的是写下这条判据时那个仓，不是你此刻所在的仓。**
  同理，判据里写死的脚本名 / 账本文件 / 进程名，你这个仓可能根本没有那个东西。
  读到这类词先问「它说的是哪个仓」，再问「我这个仓里对应的是什么、有没有」。
- **加一个词进拦截清单 / 关键词表之前，先实测它在别处是什么意思**（同名可执行文件、常见参数、日常词汇）。
  有歧义就显式挂账说明为什么不补，不硬塞。同时**每补一类命中形态，必须配一条「形似但不该拦」的反例**——
  只证明「能拦住」不算完成。
