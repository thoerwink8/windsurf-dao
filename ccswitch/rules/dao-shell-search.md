# 搜索与读文件：谁在拦什么（Grep-first 的落地面）

> **触发时刻**：你想知道「`X` 这个命令能不能跑 / 是谁拦的 / 为什么拦」的那一刻。
> 平时不用读——**被拦下的那一刻，闸的 stderr 会当场把该改用什么打给你**，那是主投递通道，
> 本文件只是它的背面：闸只说得出**它自己**拦了什么，说不出另一层拦了什么。

## 判据一句话

搜索内容用 **Grep**、找路径用 **Glob**、读文件用 **Read 的 `offset`/`limit`**；
不用 Bash/PowerShell 的 `grep` / `find` / `rg` / `sed` / `cat` / `head` / `tail` / `Select-String`。
理由：Grep 底层就是 ripgrep，跨平台、快、内存友好，且不吃 Windows 引号/转义/编码的亏。

**具体该换成哪个工具、参数怎么对应，不在本文件**——真相源是
`ccswitch/hooks/dao-hard-gates.js` 里的 `SEARCH_TOOL_ALT` 对象（Grep 那个符号即见），
它同时就是闸打给你的那段文字。**副本必漂移，故此处不抄。**

---

## 两层拦截，不是一层

它们**机制不同、清单不同、判据不同、改法也不同**。把两层混成一句「已经有硬闸了」，
正是 issue #110 那句假话的成因。

| 层 | 是什么 | 判据模型 | 改它要动哪 |
|---|---|---|---|
| **`permissions.deny`** | 宿主的权限规则 | **逐字前缀匹配**，看不懂管道、看不懂重定向 | cc-switch DB 的 `providers.settings_config`（**用户动作**，AI 侧被权限分类器拦）。`~/.claude/settings.json` 只是**投影**，改它下次下发即被覆盖 |
| **G7-shell-search** | `dao-hard-gates.js` 的 PreToolUse 闸，命中 `exit 2` | **段首 + 前一个分隔符**，管道位/落文件/`-c` 字节/`-f` 流式一律豁免 | 那个 hook 文件 |

🔴 **别把它们读成「一强一弱」或「后者取代前者」**——**各自都拦得住对方放行的东西**。
两向各一个实证：**管道位的 `Select-String`** G7 豁免而 deny 照拦；**段首的 `grep`** deny 里已没有、只剩 G7 拦。

## 覆盖面（2026-08-04 实测，口径见下）

| 命令 | 谁拦它 |
|---|---|
| `grep` | **只有 G7**（deny 里**没有**——2026-08-02 G7 上线时被显式摘掉，摘得对：deny 看不懂管道） |
| `find` · `rg` · `ag` · `ack` | **两层都有** |
| `Select-String` | **两层都有**（且分歧：管道位只有 deny 拦得住） |
| `sed` · `cat` · `head` · `tail` | **只有 G7**（deny 里没有） |
| **`awk`** | 🔴 **两层都不拦**——见下面「一格照直写」 |
| `ls` · `wc` · `Get-Content` · `gc` | **两层都不拦，而且是刻意的**，不是漏了。理由在 hook 头注 G7 ㈢（`ls`/`wc`：内置工具给不出时间戳/权限位/字节计数，收进来是凭空造 4298 次必然误伤）与 ㈦（`Get-Content`：显式的范围决定，另有一条更该先生效的编码规则） |

## 🔴 怎么自己验一遍（**别相信上面那张表，去问机器**）

上表是**跨文件事实断言**——而 issue #110 记的病就是这种断言会静默过期。
所以它配了三条复核路，**每条都在 30 秒内跑得完**：

1. **G7 那一半 —— 跑探针**（判据直接取自闸的退出码，中间不插任何自写正则）：
   ```
   node ccswitch/scripts/probe-shell-search.mjs
   ```
   它逐条打印「拦下 / 放行」+ 闸 id，末行给一句机器可读汇总，并**自检**（全拦或全放行即报可疑）。

2. **deny 那一半 —— 读 live 清单**（用 Read/Grep 工具读，别用 shell）：
   `~/.claude/settings.json` → `permissions.deny`。上面那个探针也会顺带把它打出来。

3. 🔴 **最快、最硬的一验 —— 真去撞一次，而且撞两次**。
   两条命令，**分别验两层**，因为它们**回你的话不一样**：

   | 撞什么 | 预期是谁答话 | 答话长什么样 |
   |---|---|---|
   | **管道位**的 `Select-String`（`… \| Select-String -SimpleMatch 'x'`） | **deny** —— G7 对管道位豁免，能拦它的只剩 deny | 宿主的权限拒绝：`Permission to use PowerShell with command … has been denied.` |
   | **段首**的 `grep`（`grep -n "x" somefile`） | **G7** —— deny 里已没有 grep | 闸的 stderr：`🔒 [dao-hard-gates G7-shell-search] 这一步被拦下了。` + 当场给替代写法 |

   **看「谁答的话」比看「拦没拦」信息量大得多**：
   - 管道位 `Select-String` **跑通了** ⇒ deny 那一层此刻不在了，护栏悄悄回退，去查 provider 是不是被切过。
   - 段首 `grep` 收到的是**权限拒绝**而不是 G7 的 stderr ⇒ `Bash(grep:*)` 被重新加回 deny 了。

   **这两行不是想出来的，是撞出来的**：2026-08-04 写这份文档的官，在查证过程中先后**自己撞了两次**——
   ①用管道位 `Select-String` 去读 settings.json，收到权限拒绝；②用段首 `grep` 查 `.gitignore`，收到 G7 的 stderr。
   **写「谁在拦」的人，被他正在写的那两层拦截各拦了一次，且两次收到的是不同的消息**——
   这比任何转述都硬，而且它恰好就是本节要教的那个判据本身。

## 口径与失效条件（这张表什么时候会开始说谎）

- **实测时间 2026-08-04**，方法即上面三条路。
- **真相源不是本文件**：G7 收词以 `SEARCH_TOOL_ALT` 为准，deny 以 live `permissions.deny` 为准。
  **本表与它们不符时，一律以它们为准，并把本表当成一个已经过期的断言来修。**
- **deny 那一半随时会变且不吭声**：live 是投影，源是 cc-switch DB，**切一次 provider 就整体覆盖一次**。
  `ccswitch/lib/settings-drift.js` 的头注（写于 2026-08-02）记着两个 `app_type=claude` 的 provider
  各带一份 **6 条**的 deny（含 `Bash(grep:*)`），而 live 此刻是 **5 条**——
  ⚠️ **两个数字对不上，本批未查明 DB 侧实况**（写 DB 属用户动作）。
  ⇒ 若某天 `grep` 又被 deny 拦了，不是本表写错，是 provider 被切过。

## 一格照直写：`awk` 两层都不拦

issue #110 的方案 body 里那张覆盖面表写着「`sed` / `awk` / `cat` / `head` / `tail` → G7」。
**`awk` 那一格是错的**：`SEARCH_TOOL_ALT` 里根本没有 `awk` 这个键，探针实测 `awk '{print $1}' f.txt`
**exit 0 放行**。hook 头注 G7 ㈥ 恰恰把 `awk` 当成**下游聚合器**（「被拦那一段的下游是
`awk`/`wc`/`sort`/`jq` 之类」），即它是**被豁免那一侧**的东西，从来就不在收词里。

**这一格自己就是本文件存在的理由**：一张**转述来的**覆盖面表，在被转述的那一次就已经错了一格，
而错的方式与 issue #110 记的病**完全同型**——文件 A 断言文件 B 的状态，没人回去问 B。
**要不要把 `awk` 收进 G7 是判断档（扩范围 + 已知约 4% 硬误伤 + 逃生阀只有用户设得了），
归用户拍板，本批不动——挂在 issue #123。** 那张单里照直写了一格：这个缺口**没有任何已知事故出处**，
按「不为假想敌立判据」的既定政策，**维持现状可能才是对的**。

## 已知误伤一例：heredoc 正文里行首的搜索词

hook 头注 G7 ㈥ 量过「约 4% 是硬误伤」。**下面这一例是本文件作者当场撞到的第三次拦截，
而它是个误报**，记在这里省得下一个人以为自己写错了命令：

```
git commit -F- <<'EOF'
…（正文某一行以 `grep` 两个字开头）…
EOF
```
⇒ 被 G7 判为「`grep` 被当成主命令跑」。**正文只是一段文本，从不会被执行。**

**正路不是去绕它，是本来就该走的那条**：提交信息/PR body **落文件再 `-F <文件>` / `--body-file <文件>`**
（dao-officer-clauses「PR body 永不经过 shell 字符串」讲的是同一件事，理由也一样——
**正文过任何 shell 字符串都会被静默改写**）。换成 `-F _tmp/commit-msg.txt` 即一次通过。

⚠️ **这一格没修，挂在 issue #124**（`dao-hard-gates.js` 本批禁碰，另一路官占着；且改切分器属
护栏改动、要走对抗验证）。**那张单自己倾向「不修代码」**——正路已存在且更好，改判据只为让一条
本来就不该走的路也能走。
