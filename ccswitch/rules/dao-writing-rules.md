# 你正要往盘上写一条会约束未来的东西

三件事同一个时刻：**往规则集里加一条或改一条**、**写一个检查器或一道闸**、**写一条代码注释**。
它们是同一件事的三种写法——一条写给 AI，一条写给机器，一条写给下一个读这段代码的人。

作用域小纸条会在你 Read 到规则文件、`check-*` / `verify-*` 类文件、或任何代码文件时把这份送到眼前。
⚠ 触发条件是「Read 到了那类文件」，**不是「你正在立一条规矩」**——从零新建一份规则集时没有可 Read 的旧文件，
那一半只靠记性。

---

## 一、这条规矩该我自己定，还是该问用户

> **本节是候选：整节压缩后并入常驻层（下一批落地）。** 在那之前它住在这里。

**分界不是这条规矩有多大，是执行它的那一刻还需不需要取舍。**

- **不需要取舍 ⇒ 我自己定**：跑哪个命令、填哪个字段、用什么格式或前缀、写进哪个文件、按什么顺序。
  **可机械近似的测法**：这条能不能写成一句「动作 + 对象 + 时机」的祈使句，
  且句中不出现程度词（充分 / 必要时 / 合适的 / 足够 / 尽量 / 酌情）。出现即不算。
  ⚠ 这是近似，两个方向都举得出反例。
- **需要现场取舍 ⇒ 必须问用户**：什么算够 / 什么时候停 / 要不要换方向 / 删什么留什么 / 哪个优先。
- **两条否决项优先于上面那个祈使句测试，命中即归「问用户」**，措辞多机械都不行：
  ①**它给 AI 自己定及格线**（验到什么程度算验完、几条算够、什么情况可以跳过）——
  自己给自己划及格线是结构性的利益冲突，与能力无关；
  ②**它改用户看得见的东西或者不可逆**（产物形态、删除、发布、改配置源、退役某个入口）。
- **自己定的对价是可撤回**：每一条自己定的规矩要①行内带 `[自定@<月日>]` 标记
  ②被某个「每次都会打印一次」的地方汇总 ③窗末简报报一个数。
  用户凭标记随时抽验、凭日期整批撤回（「某月某日之后你自定的全撤」），**撤回不需要理由**。
  **没有回溯面的自主授权等于不可撤销。**
- **刻意偏保守**：拿不准归「问用户」。误判成「该问」只多问一次；
  误判成「可自定」会静默改变行为**且无人知道发生过**。

**立一条新规矩必须带基线数字**：不能只写「（某日某批实证）」，要写「入库时基线：该类问题近 N 次同类动作中 M 例」。
**没有基线数字的规矩，此后不得被引用为「有效」**；写「基线：未测」是允许且诚实的——
它让「哪些规矩的有效性根本无从判定」一眼可见，而现在这个数字是隐形的。
要防的是**归因陷阱**：行为先改好、规矩才追认，然后该行为的持续被当成规矩的功劳。

**违例之后修规矩，只准改形态**（进模板 / 进产出物的槽位 / 进机器闸），**不准只加一段叙事**——
叙事归账本。同理，判断类的好实践直接写进正式条款只会变成又一条「没有触发时刻」的规矩；
它们该先进观察区，**第二次复发时再升格，升格那一刻强制回答「这次能挂在哪个必经动作上」**。
（例外：经逐条实证复核**且**用户整批拍板的，可以直入——整批拍板本身即比「有人第二次踩到」更强的门。）

## 二、写一个检查器或一道闸

- **建护栏前先摸一遍全域分布**：新增任何阈值型守卫（行数 / 复杂度 / 依赖数 / 体积）时先跑一次全仓摸底，
  把前几名与「它们在不在本护栏覆盖内」记进守卫自己的头注或输出。
  判据：**答得出「当前体量或频率最高的前 5 个对象是谁、在不在覆盖内」才算建完**——
  否则护栏会精确地守住上次出事的位置，而风险已经长到别处。
- 🔴 **守卫里「我是不是瞎了」那一半，绝不能复用被守对象的解析逻辑**：
  一个检查器若同时负责「找出违例」与「确认自己真的看到了样本」，这两半**必须走两套独立实现**。
  复用同一个解析器看似省事，实则让两半**一起错**：解析漏掉一整段时，违例数与样本数同时归零，
  二者的差恒为 0 ⇒ 自检永远为真，退化成一句废话。
  **判据一句话：自检那一半，要能在主逻辑瞎掉时仍然看得见。**
  已知最难发现的失效形态是**结论碰巧一样**——复用了被守对象的解析去做历史核验，
  结论恰好正确，但理由是假的。
- **检查器的输出，不能落在它自己的扫描面内**：否则报告成为下一轮的输入 ⇒ 每跑一次命中更多，
  而那个增长看起来像「问题在恶化」。
  **判据一句话：答得出「我的报告写在哪、那个位置在不在我扫的范围里」才算建完。**
- **规则集只增不减是结构必然，必须专门给退役造触发器**：立规矩有天然触发器（刚踩坑、正在写复盘），
  **退役没有**——「这条还有用吗」要在无标记的时刻主动问，而那正是最容易被跳过的一类动作。
  ⇒ 任何规则集（条款库 / 检查清单 / lint 规则）必须自带①**复发计数**
  （新事故命中已有条款时给它加一，而不是新写一条——把查重变成立规矩流程的必经步骤）
  ②**候选退役区的周期性打印**（入库超过 N 天的每次都输出一次，不自动删但强制可见）。
  ⚠ 覆盖面要按「计数已知 / 计数未知」分两栏——**只扫计数为 1 的，会让「计数未知」那批无论多老都永不进候选**。
  **排除「计数未知」等于默认它「已复发多次」，与直接判它退役是同一个错的两面：都在替未知下结论。**
  两栏问的是不同的问题：计数为 1 问「这条还有用吗」；计数未知问「它到底踩过几次」，处置是**先回填，不是删**。
  另外要防一个反常激励：若允许「两条合并」，合并会让计数变大 ⇒ 永久免于退役审查。
- **被守护对象的清单必须是实况的派生物，不手写**：手工维护的清单会**结构性滞后**。
  正路不是「再补一次清单」，是让它指向一个自己会更新的东西——
  新守卫一进网自动进清单，某个守卫的验证被删则自动掉出清单并触发「是刻意退役还是被顺手删掉」的追问。
- 🔴 **宿主对命令型钩子的失效态是「放行」**：你的闸崩了或超时了，动作照常发生。
  任何非 0 非 2 的退出码都是非阻断错误（官方文档原话是「The action proceeds」），
  超时同样是「取消 + 输出丢弃 + 动作继续」，**只有 `exit 2` 才拦得住**。
  ⇒ 三条推论：㈠**宿主不替你兜底**——「守卫崩了」与「守卫判放行」在它眼里逐字节相同，
  所以守卫必须自己保证不崩不超时；㈡**`exit 1` 与 `exit 0` 对宿主同类**（都不是 2、都放行），
  把 `exit 1` 改成 `exit 0` 不改变拦截行为，**只是把失败静默化**；
  ㈢一次同步 I/O 就能把同一挂载点上的所有闸拖到超时。
  ⚠ 这是文档证据不是本机实测（要实测得改钩子注册，那属用户动作）。
- **验证一道守卫时，「改坏」的那一下要真的改到**：靠在源码里找一段锚点再替换掉的做法，
  锚点没命中时替换会原样返回 ⇒ 变异体等于原文 ⇒ **被测守卫照常绿**，
  而那与「守卫真的没塌陷」逐字节相同。三件事：
  ①**跨行的锚点才有风险**（单行锚点里没有换行，行尾差异咬不到它）；跨行就用正则、换行位写 `\r?\n`，
  **别改用「读进来先归一化行尾」**——那会改变副本内容，可能撞上被测守卫自己的指纹检测。
  ②**「锚点仍在」的断言，断的必须是你真正喂给替换函数的那个表达式**，不是它的前缀或近似——
  断言前缀串而替换用正则是两个不同的锚，锚落空时断言照常通过，
  于是「锚落空」与「判据真坏了」再次不可区分。**一条守着近似物的断言，提供的是虚假的安心。**
  ③**读红集之前先确认变异体还活着**——一个把靶弄死的变异会让每条断言都红，那正是「判别力满分」的表象。
- 🔴 **判据类 / 护栏类的改动不许先合后审**：改动落在以拦截 / 守卫 / 扫描 / 判定为职责的文件上时
  （可按路径机械判定），`gh pr create` 之后**必须先过一轮对抗验证再合并**。
  写代码的那一路跑构建与单测，挑错的那一路跑变异与双向语料夹击，
  **后者能发现的东西前者结构上发现不了**——把它排在合并之后，等于把本可在合并前拦下的缺陷
  系统性地转化成「必然产生的后续 PR」。
- 🔴 **闸红了，先审红得对不对，再动环境**：判据错与环境错是两种病，治错方向比不治更贵。
  「让红变绿」的每一步动作在升级（改环境 → 要授权 → 绕拦截）而你一次都没回头问判据，
  就是在用越来越大的代价满足一个设错的判据（2026-08-13 实咬：新闸把「合并前分支必然未部署」
  误判为部署漂移，反应链一路升到申请绕权限分类器才被拷问停下）。
  判据一句话：**动作在变大而红因没被重审过，先停手审红因。** [#反-闸红先审红因]

## 三、写一条代码注释

- **注释里不许写「关于别处的事实」，只准写「去哪查」**：另一份文件里写着什么、某次实测是几秒、
  某个清单有几项、某个函数有几个调用点——这类**值**一律不进注释，注释里只留它的**坐标**
  （哪份文件 / 哪个函数 / 跑哪条命令），让读的人自己去取当下那一版。
  **一句可执行判据：这句话会不会因为我这次没碰的那个文件改了而变假？会 ⇒ 只写去哪查。**
- **写了指针就必须配一道会红的闸**（那个落点被挪走 / 删掉 / 改名 ⇒ 有东西报警），**配不了就别留**——
  **留一个指向空气的指针比没有指针更糟**，读者会以为有兜底而不再自己去核。
- **别拿上面两条去删这一类**：「本函数的不变量」「这段改坏了会怎样」「为什么不那样做」
  「此路实测不通别再走」——它们是**此处的事实**，随这份文件一起改、一起被审，不会因为别处变了而变假。
  **删掉它，下一个不知道历史的人会不会做出一个已被验证是错的动作？会 ⇒ 留。**
- **用户拍板的「刻意不做」不许只活在一行注释里**：凡注释里写着「用户某日拍板：不做 / 不收 / 保留现状」
  这一类**否决**的，同一个动作里落进项目侧台账，一条一个**编号 + 负责人 + 解冻条件**，
  注释处只留一行指针。**一句可执行判据：删掉这行注释，会不会有东西红？答否 ⇒ 它此刻靠的是「没人删它」，不是靠机制。**
  **解冻条件不是用户原话时，台账里必须标成「待确认」并送用户拍板**——「什么情况下可以重开」是判断题。
- **订正一条已经写错的结论时，形态按载体分**：**判据文件**里用 `~~划线~~` 保留原句、紧接着写现在为真的陈述
  （错误结论本身是后来者理解「为什么现在长这样」的证据链一环）；
  **代码注释里直接改正、不留划线**，过程性溯源（谁订正的 / 哪天 / 第几轮）归 git 历史与对应 issue。
  同一批凡引用那条结论的地方一并改真，不留只改了一处的半吊子订正。

## 四、照直写：这三节各有多少是机器管着的

| 这一条 | 谁在管 |
|---|---|
| 规矩该谁定 / 要不要带基线数字 | **没有任何程序在管**。把一条判断题标成「我自己定」，脚本照样放行 |
| 守卫的那几条 | **没有程序在管**。它们是写守卫时自问的清单，不是闸 |
| 注释只写去哪查 | **机器判不了**（判它要先判「什么算别处」，两个方向都构造得出反例） |
| 指针指向的文件还在不在 | **当前无对账闸**（原先那几道随文字一致性检查一起退役了），靠 review 维持 |

**这不是失败，是照直说。** 别把「已经写进手册了」读成「这条现在有人管了」——
作用域小纸条改的是**送不送得到**，不是「送到了就会做」。
