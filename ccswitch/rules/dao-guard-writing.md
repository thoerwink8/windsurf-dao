- **判据类 / 护栏类改动的对抗验证前置到合并之前**：改动落在以**拦截 / 守卫 / 扫描 / 判定**为职责的文件时（可按路径白名单机械判定），实现官 `gh pr create` 后**必须先过对抗验证官再合并，不得先合后审**——实现官跑构建 + 单测，对抗验证官跑 mutation + 双向语料夹击，**后者能发现的东西前者结构上发现不了**，而它被排在 merge 之后 ⇒ 本可在合并前拦下的缺陷被系统性转化为「必然产生的后续 PR」（出处：叙事 N9-⑦）。入库时基线：某仓修复间隔呈双峰，24% 的返工发生在合并后 4 小时内。**本条的台账（复发次数 / 首次入库 / 触发点）在 `ccswitch/clause-ledger.json` 的 `帅-对抗前置` 条目下**，判据句仍留 dao.md 帅节。


- **建护栏前先摸全域分布，别只护住刚出事的那一层**：新增任何阈值型守卫（LOC/复杂度/依赖数/体积）时先跑一次**全仓分布摸底**，把 Top N 与「它们在不在本护栏覆盖内」记进守卫自身的头注或输出。判据：答得出「当前体量或频率最高的前 5 个对象是谁、在不在覆盖内」才算建完——否则护栏会精确地守住上次出事的位置，而风险已经长到别处（出处：叙事 N9-⑤）。 [n=1 @07-27 触发:守卫头注] [基线:某仓 LOC 治理网只覆盖 Rust 侧，而全仓体量与改动频率前三全在零覆盖的前端层（2339行/52次、2125行/35次、1924行/22次）] [#守-全域分布]
- **守卫里「我是不是瞎了」那一半，绝不能复用被守对象的解析逻辑**：一个检查器若同时负责「找出违例」与「确认自己真的看到了样本」，这两半**必须走两套独立实现**。复用同一个解析器/状态机看似 DRY，实则让两半**一起错**：解析漏掉一整段时，违例数与样本数同时归零，二者的差恒为 0 ⇒ 自检永远为真，退化成一句废话。判据一句话：**自检那一半，要能在主逻辑瞎掉时仍然看得见**。这与「零检出 ≠ 零存在」是同一件事的实现层——后者说要区分两种 0，这条说**怎么才区分得开**（出处：某仓扫描面塌陷下限断言，分母由独立普查函数产出、刻意不共享节状态机）。 [n=1 @07-28 触发:守卫头注] [基线:未测——该守卫上线当轮真实数据零触发，判别力只由合成夹具验证] [#守-自检独立]
- **检查器的输出，不能落在它自己的扫描面内**：否则报告成为下一轮的输入 ⇒ **每跑一次命中更多**，而那个增长看起来像「问题在恶化」。实测一轮：3 文件 16 处 → 9 文件 34 处；且当流程要求「把正文回读留档」时，正文与回读记录逐字节相同 ⇒ **同一处天然被计两遍**。判据一句话：**答得出「我的报告写在哪、那个位置在不在我扫的范围里」才算建完**。与上一条同为守卫的自指问题：上一条防「自检瞎了」，这一条防「自检把自己数了进去」。 [n=1 @07-29 触发:守卫头注] [自定@07-29] [基线:某仓乱码扫描器上线首轮即自我放大，由对抗验证官测出、实现官未察觉；收敛性未验] [#守-输出面外]
- **规则集只增不减是结构必然，须专门给退役造触发器**：立法有天然触发器（刚踩坑、正在写复盘），**退役没有**——「这条还有用吗」要在无标记时刻主动问，正是实测携带率约 9% 的那一类动作。故任何规则集（条款库/检查清单/lint 规则）必须自带**①复发计数字段**（新事故命中已有条款时 n+1 而非新写一条，把查重变成立法流程的必经步骤）**②候选退役区的周期性打印**（入库超 N 天者每次验证输出一次，不自动删但强制可见）。缺这两样，规则集会单向膨胀直到无人通读（出处：叙事 N9-⑥）。
  **⚠️ ②的覆盖面必须按「计数已知 / 计数未知」分栏，别只扫计数=1 的**（2026-07-27 实证补）：只扫 `n=1` 会让「**计数未知**」那批无论多老都永不进候选——本仓实测那批占 30%，且恰好集中在最早入库的那一天。**排除「计数未知」等于默认它「已复发多次」，与直接判它退役是同一个错的两面：都在替未知下结论。** 两栏要问不同的问题：计数=1 问「这条还有用吗」（处置＝退役或留着）· 计数未知问「它到底踩过几次」（处置＝**先回填计数，不是删**）。
  **另一处同型**：若规则集允许「两条合并」，要防**合并 ⇒ 计数变大 ⇒ 永久免于退役审查**这个反常激励。 [n=1 @07-27 触发:verify-all/check-clauses-structure] [基线:某仓条款库 18 次提交净删除 3 行（唯一那次是修自伤非退役）；63 条里 n≥2 仅 11 条，而最高频两个病（≥23 踩、≥10 例）合计只占 1-2 条] [#守-退役触发]
- **mutation 的锚点必须扛得住行尾差异，且「锚点仍在」的断言要断言你真正用的那个表达式**：mutation 靠在被测源码里找一段锚点再替换掉。锚点若写死 `\n` 而盘上检出是 CRLF，**恒不命中** ⇒ `replace` 原样返回 ⇒ 变异体 == 原文 ⇒ 被测守卫**照常绿**——**而那与「守卫真的没塌陷」逐字节相同**（本条是「零检出 ≠ 零存在」在 mutation 这一层的形态：那条说绿信号会答错问题，这条说**你以为在做的那个实验根本没做**）。最阴的一格：它**跟着检出走**，同一份代码在 LF 的 worktree 上全绿、合到 CRLF 的主仓就红（例2 实证）⇒「我这儿是绿的」不构成证据。
  **①风险面只有跨行锚点，单行锚点结构上免疫**——锚点里没有换行，行尾差异就咬不到它。本仓 25 处 mutation 站点实测，跨行锚点**只有 1 处**。⇒ 别把这条读成「所有锚点都要改写」，那是无谓返工。
  **②改法用正则、换行位写 `\r?\n`，不要「读进来先归一化行尾」**：归一化会改变副本内容，PR #99 第一版即因此触发被测守卫**自身的规则指纹检测**（exit 4 `rules-drift`）——修一个坑撞进另一个。正则锚点保持原文件逐字节不变，是更干净的那条。
  **③锚点断言必须与 mutation 用的是同一个表达式对象，不是它的前缀或近似**（2026-08-02 实测订正，本条最值钱的一格）：`glob-gate.tests.js` 的靶点③断言的是前缀串 `"const isSettingsJson ="`，而 MUT3 真正喂给 `replace()` 的是正则 `/const isSettingsJson = .*;/`——**两个不同的锚**。实测把那个正则改成永不命中：**断言照常 PASS**，只有行为断言 FAIL，而它的报文说「settings.json 掉成零输出」⇒ 指向被测 hook 的判定逻辑，**不指向「你的锚没命中」**。于是「锚落空」与「判据真坏了」再次不可区分——**一条守着近似物的锚点断言，提供的是虚假的安心**。⇒ 锚点定义一次、断言与 mutation 共用同一个对象，锚一改两处同时改。
  **④能机检的只有一半，照直写**：**「锚点里有跨行裸 `\n`」可以机检**，已做成 `ccswitch/scripts/check-mutation-anchor.mjs`（回归网 `tests/mutation-anchor.tests.js`，含**例2 修复前的逐字原文**作正控——它是本闸唯一的真实语料）。**「每组 mutation 有没有锚点断言」实测做不到**：在本仓 25 处站点上量了四档窗口，误报率 **84.6%（±3 行）→ 100%（±40 行）**，而窗口必须放大到 ±40 才盖得住 helper 间接（6/25 处的断言在 helper 内部或调用点十几行外）——**两头堵死，没有可用窗口**。根因是 `.replace(` 本身几乎不携带信息（全仓 75 处里绝大多数是路径归一化与注释剥离），且锚点断言有**至少 5 种写法**（`includes` / `split().length===2` / 正则命中计数 / 后置 `applied===1` / 后置 `body !== SRC`）分布在两种语言里。⇒ 那一半留作判据，不造检查器。**顺带一件事本身就是证据**：本条作者的首轮人工普查把 `glob-gate:210` 误判为「无保护」，正因为它的断言在 31 行之外且写法不同——**人读都会错判的东西，别指望窗口扫描**。
