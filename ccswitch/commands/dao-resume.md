# 会话接力 · Resume

> 各复归其根。知识归文件不归会话，结果可交接。

**这个命令替代的是「用户复制一段手写的长提示词」**——手写提示词是快照，写完那一刻就开始漂移，
且质量取决于写它的那个 AI 当时的状态。本命令**当场查实况**，没有快照。

## 四步

1. **查实况**（只读，可并行）：`git status -sb` · `git worktree list` · `gh pr list --state open`
   · `gh issue list --label 在途 --state open`
2. **找接力单**：`gh issue list --label 接力 --state open` —— **一个仓应当恰好一个**
3. **读它**：`gh issue view <n> --comments`，重点看「最近拍板」与「下一步」两节
4. **报告**：上次干到哪 / 用户拍过什么板 / 下一步建议。**报完停下等点头，不自动开工**

## 三条判据

🔴 **实况与接力单冲突时以实况为准，且冲突本身要报出来** —— 单里的 commit hash、PR 状态、
在途路数都是写下那一刻的快照。对不上不是小事：它说明上次收窗之后有别的东西动过。

🔴 **`gh` 跑不成 ≠ 没有待办** —— 命令失败必须**明说查不到**，绝不静默当成「零待办」交付。
判据：**数到 0 和没看到样本，输出一模一样**。

**找不到接力单不许拿别的单顶替** —— 报「本仓没有 `接力` 标签的单」，问用户要不要现在建。

## 接力单里装什么

三样：**最近拍板**（用户定过什么 + 日期 + 一句为什么）· **下一步**（可动手的活）·
**卡住的**（等用户的事，含每笔在等什么）。

**不装实况快照**（分支名 / commit hash / PR 开关状态）—— 那是第 1 步现查的活，
写进去只会漂移，而漂移的快照比没有快照更坏：它看起来是可信的。

## 对偶纪律在收窗侧

`dao.md`「续力」节：**用户拍板后当场评论进对应 issue，不落盘等于没拍**。
本命令读得到什么，完全取决于那一条有没有被执行——**它是这个命令的唯一数据来源**。
