# 会话接力 · Resume

> 各复归其根。知识归文件不归会话，结果可交接。

**这个命令替代的是「用户复制一段手写的长提示词」**——手写提示词是快照，写完那一刻就开始漂移，
且质量取决于写它的那个 AI 当时的状态。本命令**当场查实况**，没有快照。

## 四步

1. **查实况**（只读，可并行）：`git status -sb` · `git worktree list` · `gh pr list --state open`
   · 在途路数看 Orca：`orca worktree list --json`（托管树即在途路数，树备注答「这棵树在干嘛」）。
   ⚠ `在途` label 已随 issue #360（2026-08-13 拍板 2-B）退役，**不要再跑 `gh issue list --label 在途`**——
   label 删掉后这条命令**恒返回空且不报错**，「找不到标签」和「零在途」在输出里逐字节相同，
   接力报告会谎报「零在途」。没有 Orca 的机器改看认领评论：
   `gh issue list --state open --search "dao-claim in:comments"` 初筛，逐单回读精算（工具即下一条）。
   🔴 **多机/多 AI 并行时，准备接手的单要逐单看认领评论里的机器名**（独立成行的
   `dao-claim:`，不要求是评论第一行——2026-08-09 issue #198 订正：本节原写「首行
   `dao-claim:`」，`ccswitch/scripts/dao-claim.ps1` 把判据定为「独立成行、
   不限位置」，对齐对抗 FAIL-1；判据没有实质变化，回读仍然是找那一行独立的机器面，只是
   不再要求它是评论的第一行）：**别人机器的单只报不接**，自己这台机的过期单按接管流程
   处理——判据与实操在 `ccswitch/scripts/dao-claim.ps1`。**一台机一个
   会话的仓不必看这一格。**
   🔴 **「自己这台机」要连宿主一起看，机器名相同还不够**（2026-08-09 issue #250）：本仓是
   双栈仓（cc 与 Codex 同机共存），同机另一个宿主的认领**是别人的单**，同样只报不接。
   认领的单位从一开始就是「机器 + 宿主」两格（协议节 §二），此前 `Get-EffectiveClaim`
   只按机器名分组，于是 cc 会把同机 codex 的认领读成"这是我的"并替它续命——判据现在按
   `<机器名>/<宿主>` 组合键查，两格都对上才是自己的单。
   🔴 **认领评论若带第三格会话短 id（同机同宿主开了多个并发会话时必填，见认领协议节
   §二/㈩），先比对它与当前会话是否一致再判「是不是自己的单」**（2026-08-09 issue #198，
   对抗 FAIL-6）：hostname 相同**不再**默认就是自己的会话——会话 id 不同时按「别人的单」读
   （只报不接），避免同机的两个并发会话互相把对方的单当成自己的、都接着干。没带会话 id 的
   认领（单会话场景）行为不变。
2. **找接力单**：`gh issue list --label 接力 --state open` —— **一个仓应当恰好一个**
3. **读它**：`gh issue view <n> --comments`，重点看「最近拍板」与「下一步」两节
4. **报告**：上次干到哪 / 用户拍过什么板 / 下一步建议。**报完停下等点头，不自动开工**

## 三条判据

🔴 **实况与接力单冲突时以实况为准，且冲突本身要报出来** —— 单里的 commit hash、PR 状态、
在途路数（Orca 板上的）都是写下那一刻的快照。对不上不是小事：它说明上次收窗之后有别的东西动过。

🔴 **`gh` 跑不成 ≠ 没有待办** —— 命令失败必须**明说查不到**，绝不静默当成「零待办」交付。
判据：**数到 0 和没看到样本，输出一模一样**。

**找不到接力单不许拿别的单顶替** —— 报「本仓没有 `接力` 标签的单」，问用户要不要现在建。

## 接力单里装什么

三样：**最近拍板**（用户定过什么 + 日期 + 一句为什么）· **下一步**（可动手的活）·
**卡住的**（等用户的事，含每笔在等什么）。

**多机场景多装一格：上一窗收在哪台机上**（机器名，`$env:COMPUTERNAME` 取）——它让接力方一眼看出
接的是不是自己这台机的活。**接力单本身不参与认领**：它是每仓恰一个的常设单、没有关闭条件，
认领它没有对象（见 `ccswitch/scripts/dao-claim.ps1` 头注）。

**不装实况快照**（分支名 / commit hash / PR 开关状态）—— 那是第 1 步现查的活，
写进去只会漂移，而漂移的快照比没有快照更坏：它看起来是可信的。

## 对偶纪律在收窗侧

`dao.md`「续力」节：**用户拍板后当场评论进对应 issue，不落盘等于没拍**。
本命令读得到什么，完全取决于那一条有没有被执行——**它是这个命令的唯一数据来源**。
