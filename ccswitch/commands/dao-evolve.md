# 进化 · Evolve

> 致虚极，守静笃。万物并作，吾以观复。
> 夫物芸芸，各复归其根。归根曰静，静曰复命。
> 复命曰常，知常曰明。不知常，妄作凶。

## 铁律

```
进化是减法，不是加法。
为学日益，为道日损。
系统越进化应该越简洁，而非越臃肿。
```

## 触发条件

- 定期审查（感觉系统需要升级时）
- 发现规则/技能/命令与实际行为不一致
- 新工具/MCP引入后需要整合
- 多次遇到同类问题但缺少对应命令/技能
- 用户显式调用 `/dao-evolve`
- 用户说 `/health-check` → 直接跳到§快速体检

## 审查域 · 四脏与虚

系统由四个实体结构和一个流通机制组成：

五脏：**心** Rules（`ccswitch/dao.md` + 项目 `CLAUDE.md`/`AGENT.md`，行为准则）· **肺** Commands（`ccswitch/commands/`，标准流程）· **肝** Skills（`ccswitch/skills/`，能力封装）· **肾** MCP（`settings.json` MCP 配置，外部工具连接）· **骨** Stacks（`ccswitch/stacks/`，技术选型）。**虚**（Memory `~/.claude/.../memory/`）是层间流通的气，涅槃时归位清空，不在此审查。

## 流程 · 观复

每次进化是一轮深度迭代（/dao-dev §2.5），但对象是系统自身：

### 一、观 · 审查现状（☲离 · 视）

> 知人者智，自知者明。

逐一审视四脏，记录现状。

**心 · Rules 审查：**

1. 读 `ccswitch/dao.md`（道德经元规则场域）+ 项目根 `CLAUDE.md`/`AGENT.md`（项目级铁律）
2. 检查：
   - 哪些规则在实际中经常生效？（活规则）
   - 哪些规则从未被触发？（死规则 → 考虑删除）
   - 哪些行为没有被规则覆盖但应该被覆盖？（缺口）
   - 规则之间有矛盾吗？
   - 四层一致性：法不违德，德不违道

**肺 · Commands 审查：**

1. 列出所有 slash command（`ccswitch/commands/*.md`）
2. 检查：
   - 哪些命令经常被使用？效果如何？
   - 哪些从未使用？（考虑删除或合并）
   - 命令之间的协作关系是否清晰？
   - 有没有缺失的命令？（反复出现的模式但没有对应流程）
   - 步骤是否与实际执行一致？

**肝 · Skills 审查：**

1. 列出所有技能（`ccswitch/skills/dao-*/`）
2. 检查：
   - 技能 description 是否准确触发？（该触发时触发，不该触发时不触发——渐进披露靠 description 命中）
   - 技能内容是否与当前最佳实践一致？
   - 有没有应该提取为技能的重复行为？

**肾 · MCP 审查：**

1. 列出已配置的 MCP 服务器（`settings.json`）
2. 检查：
   - 每个MCP是否正常工作？
   - 使用频率如何？低频的是否还需要？
   - 有没有新的MCP可以增强能力？
   - 配置是否最优？

**追踪日志清退**：`git blame` 扫描 `logger.debug`，超 7 天且无相关 bug → 删除。

**教训新鲜度**：`search.py stale --data-dir <project>/data` → 距最新版 ≥5 major 的 active 教训标 `review`，用户确认保留/废弃。

**Git 考古**：`git log -n 20` 按前缀分类（fix/refactor/feat），检测同模块多次 fix 等模式，深挖最多 5 commit，与已有教训对照只写 gap。

**产出**：四脏审查报告 + 清退清单 + 新鲜度报告 + Git 考古洞察

### 二、辨 · 识别改进点（☶艮 · 味 · 止而辨）

> 曲则全，枉则直，洼则盈，敝则新。

从审查报告中提取改进点，**按减法优先排序**：

1. **删**（最高优先）
   - 死规则、无用技能 → 删除
   - 重复的 → 合并
   - 这是为道日损的核心

2. **修**（次优先）
   - 不准确的 → 更正
   - 过时的 → 更新
   - 矛盾的 → 统一

3. **增**（最低优先）
   - 确认缺失的 → 补充
   - 但每增一项，问：真的需要吗？
   - 能不增就不增

**产出**：改进清单（删 → 修 → 增 排序）

### 三、行 · 实施改进（☳震 · 触）

> 为大于其细。天下大事，必作于细。

逐项实施改进，每项都是一个最小变更。

- **Rules变更**：编辑 `ccswitch/dao.md` 或项目 `CLAUDE.md`/`AGENT.md`
- **Command变更**：编辑对应 `ccswitch/commands/*.md` 文件
- **Skill变更**：编辑技能文件 `ccswitch/skills/dao-*/SKILL.md`
- **MCP变更**：编辑 `settings.json`（涉及凭证或本地环境时记录建议，由用户确认）

**原则**：一次改一处，改完确认，再改下一处。

### 四、验 · 验证一致性（☵坎 · 听）

> 名与身孰亲？

确保改动后系统内部一致：

1. Rules ↔ Commands：规则变了，命令是否需要跟着变？
2. Rules ↔ Skills：规则变了，技能 description 是否一致？
3. Commands之间：协作关系是否仍然正确？
4. 四层一致性：法不违德，德不违道，道法自然

### 五、省 · 进化评估（☶艮 · 味 · 归根）

> 归根曰静，静曰复命。复命曰常，知常曰明。

回到根本问：

- 系统是否因这次进化变得**更简洁**了？（信息熵减少了吗？）
- 道·本源 是否仍然是一切的根？
- 人+AI=AGI 的冲气是否更和了？

如果系统变复杂了 → 反思：是否在妄作？回到"删"。

## 快速体检（/health-check 模式）

> 知人者智，自知者明。胜人者有力，自胜者强。

轻量触发（感觉行为异常 / 用户说 `/health-check`）时，只跑以下 4 项，不进入完整五步：

```
# 1. 元规则注入链路
#    确认 ~/.claude/CLAUDE.md 经 @import 注入了 ccswitch/dao.md（dao 场域常驻）
#    🟢 已 @import 且 dao.md 存在 → 正常 | 🔴 缺失 → 用 dao.ps1 link-claude 修复

# 2. Command / Skill frontmatter 校验
#    遍历 ccswitch/commands/*.md 与 ccswitch/skills/dao-*/SKILL.md：
#    - commands 必须有 description（吃参数的应有 argument-hint）
#    - skills 必须有 name + description（缺失 = 技能不被渐进披露调度，等于隐身）
#    🔴 列出缺 frontmatter 字段的文件

# 3. 文件式 memory 检查
#    扫描 ~/.claude/.../memory/ 残留——属于项目文件的应已归位，仅跨会话私有知识可留

# 4. 教训统计
py search.py stats --data-dir <project>/data
```

报告格式：`| 元规则注入 🟢/🔴 | frontmatter 校验 🟢/🔴 | memory 🟢/🟡 | 教训 N条 |`

## 进化节律

不是每次都需要全面审查：

行为异常 → 快速体检 4 项（1 分钟）· 感觉某处不对 → 单一脏器快速修正 · 新能力引入 → 相关脏器整合 · 定期审查 → 全四脏完整进化 · 重大理念变化 → 心（Rules）深层重构。

## 与其他命令的关系

元工作流：审查并改进所有 commands + skills + stacks（含自身），含 /health-check 快速体检 + Git 考古跨会话教训挖掘。道的自指性——自然包括道自身。

## 反模式

只加不删（删优先于增）| 频繁进化（有感觉才进化，不定闹钟）| 改了不验（必查四脏一致性）| 规则越改越多（规则多=系统病了）| 为改而改（没问题就不改）

## 执行格式

启动时报：触发原因 + 审查范围（全四脏 / 指定脏器）。
审查报告：四脏表格（脏 | 状态 | 发现）。
完成时报：删了什么 / 修了什么 / 增了什么（希望增最短）/ 熵变（变简洁了还是复杂了）。
