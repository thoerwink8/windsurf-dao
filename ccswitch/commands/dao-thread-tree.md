# /dao-thread-tree · 线索追踪

> 万物并作，吾以观复。夫物芸芸，各复归其根。

## 与项目铁律的协作

对话中的「中断感知」机制（实时检测对话偏离，自动把被中断线索写入 `TODO.md` 的 `## 🌳 Open Threads`）已在对话中实时记录。
本工作流负责**回顾和处理**已积累的线索——不做事后全量分析，因为线索已被实时记录。

## Open Threads 格式

```markdown
## 🌳 Open Threads

- [ ] 🔀 **[问题标题]**：[一句话描述]
  > 来源：[日期] | [背景/选项摘要]

- [ ] ✋ **[确认项标题]**：[方案描述]
  > 来源：[日期] | [待确认的具体内容]

- [ ] 🔨 **[任务标题]**：[要做什么]
  > 来源：[日期] | [阻塞于/依赖于什么]
```

类型前缀 = AI 执行权限：🔀 红灯（不可自动）| ✋ 黄灯（需标注假设）| 🔨 绿灯（可自动执行）

## 处理流程

### 1. 加载

读取 `TODO.md` 的 `## 🌳 Open Threads`，提取所有 `- [ ]` 条目。
无待处理项 → 告知"Open Threads 已清空"，结束。

### 2. 排序

1. 🔀 待决策（阻塞性最高）
2. ✋ 待确认（方案已有，只差点头）
3. 🔨 待执行（AI 可自动做）

同类型内按依赖关系 > 时间先后排序。

### 3. 逐条推进

**🔀 待决策**：展示背景 + 用 AskUserQuestion 工具提供选项（这是真正的路歧/不可逆决策，路歧则问）→ 更新 TODO.md `[x]`
**✋ 待确认**：展示方案 + 用 AskUserQuestion 工具确认/拒绝（方案待用户拍板）→ 更新 TODO.md `[x]`
**🔨 待执行**：AI 直接执行 → 验证 → 更新 TODO.md `[x]`

**铁律**：解决一条写一条，立即更新 TODO.md，防止对话中断导致丢失。

### 4. 汇总

```
📊 本次处理：M/N 条
🔀 X 决策已拍板 | ✋ Y 确认通过 | 🔨 Z 任务已执行 | ⏭️ W 跳过
Open Threads 剩余：K 条
```

## 注意事项

- 任何条目都可以跳过
- 🔀 解决后可能产生新的 🔨，直接追加
- 合并策略：重复项更新而非重复添加，已解决的旧条目标记 `[x]`
