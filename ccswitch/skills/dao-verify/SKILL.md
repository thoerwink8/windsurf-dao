# 验前 · Verification Before Claims

> 慎终如始，则无败事。
> 其安易持，其未兆易谋。
> ——《道德经》第 64 章

道家把最后一关称为"慎终"，不是因为终点轻松，而是因为人到终点最易松。
**涅槃门放在最后**——前面再周密，未在终点跑一遍证据，就是"功亏一篑"。
诚则有征，征则有验。无验之"完成"，是自欺，亦欺人。

## 铁律

```
不见证据，不言完成。
不跑命令，不读输出。
未对照声明，不报涅槃。
```

`NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE`

> 此条规则的"字面"与"精神"同等：换个措辞绕过它，仍是违反。

## 何时激活

- 任何要说"完成 / 修好了 / pass 了 / done / 应该可以了"之前
- `git commit` / `git push` / 创建 PR 之前
- 把 TODO 项标 `[x]` 之前
- 派子任务给下游 agent 之前（交付物必须先验，**别让别人吃你没尝过的菜**）
- 对用户表达任何形式的"满意"、"漂亮"、"搞定"之前

**强制激活**：你刚改完代码、刚等完一个长跑命令、刚读完一段日志正想松口气——此刻最危险。

## Gate Function · 涅槃门 5 步

> 致虚极，守静笃。万物并作，吾以观复。

```
在做出任何"完成 / 通过 / 修好"声明之前：

1. IDENTIFY · 识  ——  哪一条命令能证明这个声明？
2. RUN      · 跑  ——  本次会话内、完整执行、不裁剪、不复用旧输出。
3. READ     · 读  ——  完整输出 + 退出码 + 失败计数。不滚到底 = 没读。
4. VERIFY   · 对  ——  输出是否真的支持这条声明？
                       不支持 → 报实际状态 + 证据；支持 → 报声明 + 证据。
5. CLAIM    · 言  ——  此时方可言"完成"，并把证据贴上。

跳过任一步 = 撒谎，不是验证。
```

## 常见失败模式 · 声明 vs 证据

| 你想声明 | 必须的证据 | 不够的"证据" |
|---------|-----------|-------------|
| 测试通过 | 测试命令：0 failures + exit 0 | "上次跑过"、"应该过" |
| 构建成功 | Build 命令：exit 0 + 产物存在 | "Linter 过了" |
| Bug 修好 | 重跑复现路径：症状不再触发 | 改了代码推断"应该好了" |
| 回归测试 | Red-green 双向验证 | 测试跑过一次 |
| Agent 完成 | VCS diff + 跑测试独立验证 | Agent 自报 "success" |
| 需求满足 | 逐条对照 plan 勾选 | "测试过了，阶段完成" |
| 部署生效 | 拉远端最新状态实测 | "我推上去了" |

## 反模式

| 病 | 对治 |
|----|------|
| "应该好了" | 跑命令，看输出 |
| 凭直觉宣布完成 | 信心 ≠ 证据 |
| Linter 过 = 编译过 | Linter 不查编译，更不查运行 |
| Agent 说成功就信 | 看 diff、跑测试，独立验证 |
| "大部分通过了" | 1 个红 = 全红 |
| "这次先这样" | 没有"这一次"特例 |
| 换措辞绕开 | 任何暗示成功的措辞均触发铁律 |
| 旧输出复用 | Fresh = 此刻重跑 |
| 假涅槃 | 根因 + 复现验证 + 无副作用 |

## 红灯词 · 立即停

即将说出"应该/大概/差不多/Great!/Done!/我有信心/刚才跑过了/下一次会补"→ **停手，回到 Gate Function 第 1 步**。

## § 全面体检（重大版本）

> 知不知，上；不知知，病。夫唯病病，是以不病。——《道德经》第 71 章

不是没病才不病，是**清楚自己有病**才不病。主动找盲点 = 道家"病病"。

### 何时触发

| 触发 | 维度选 | 深度 |
|---|---|---|
| 重大变更后（≥3 文件 / 核心模块） | 改动相关 3-4 维度 | 中 |
| 发布 / 上线前 | 全 8 维度 | 深 |
| 接手新项目 | 全 8 维度 | 深 |
| 周期性 | 全 8 维度 | 浅（自动化为主） |
| 用户反馈"怪怪的" | 看症状选 2-3 维度 | 深 |

小修小改（typo / 单文件 < 10 行）不必激活。

### 8 维度清单

按**当前项目特征**挑相关维度，不必每次全扫。

1. **代码**：Lint 全绿 · TypeCheck 全绿 · 死代码 · 重复代码 · 圈复杂度 > 10 · 命名一致性 · **跨层注册一致**（SQL↔Rust↔TS 等多层项目：check 脚本存在且全绿）· **孤儿分支/worktree 扫描**（回溯式兜底，见下方独立小节）
2. **测试**：覆盖率（核心 > 80%）· 边界测试 · 假阳性检验 · E2E 路径全覆盖
3. **文档**：README 当前态 · API doc 与实现一致 · 注释陈旧度 · AGENT_GUIDE/docs 一致
4. **依赖**：漏洞扫描 · 过期依赖 · lockfile 健康 · peer dep 冲突 · 单一版本
5. **配置**：env 无敏感信息 · 默认值合理 · Feature flag 状态 · 跨环境差异文档化 · **自检器活性核对**（见下方独立小节）
6. **部署**：CI/CD 全绿 · 环境变量一致 · 回滚机制 · 健康检查端点
7. **性能**：启动时间 · 内存占用 · 慢查询 · 前端 LCP/INP/CLS · 后端 p95/p99
8. **安全**：认证校验 · 授权边界 · 输入校验（注入/XSS/穿越）· 加密 · 密钥管理

### 自检器活性核对（谁来检查检查器）

> 不知常，妄作凶。**「文件存在 / 已部署 / 文档详尽」都不是生效判据**——三例 hook 合计 55 天零生效，
> 而三道自检全部报绿，因为它们查的正是「文件在不在」。判据只认两样：**功能探针**（此刻还能检出已知阳性吗）
> 与**真实调用心跳**（非自测的调用记录有多陈旧）。

体检时在 windsurf-dao 仓库跑：

```powershell
node ccswitch/lib/settings-drift.js --selfcheck   # live↔快照 漂移检测器自身
```

读法：探针红 ⇒ 检测逻辑已瞎，此期间它报的「无问题」一律不可信，先修检测器再谈体检结论；
探针绿只说明**跑过且逻辑没坏**，不说明提醒真被投递到人眼前——这一层目前无自动判据，如实挂着。

### 孤儿分支/worktree 扫描（回溯式兜底，教训 L13）

> 各复归其根。dao-worktree 的归根门控只在当次 session 主动收尾时触发；dao-loop 的归档清理原先绑死在 PR 路径后面（已修，见 closing.md）。两者都是**前瞻式**——session 被打断、或走了非常规合并路径，分支/worktree 就永久遗留，无人发现。本项是唯一**回溯式**检查，周期性体检时必跑。

```powershell
# 已并入主线（merge/squash/rebase 任意方式）且当前无活跃 worktree 关联的本地分支
$mainBranch = if (git show-ref --verify --quiet refs/heads/main) { 'main' } else { 'master' }
$worktreeBranches = git worktree list --porcelain |
  Select-String '^branch refs/heads/(.+)$' |
  ForEach-Object { $_.Matches[0].Groups[1].Value }
git branch --merged $mainBranch |
  ForEach-Object { $_.Trim().TrimStart('* ', '+ ') } |
  Where-Object { $_ -ne $mainBranch -and $worktreeBranches -notcontains $_ }
```

命中的分支交 AskUserQuestion 让用户确认（批量删除 / 逐个看 / 跳过）——分支删除不可逆，不自动执行。同时核对 `git worktree list` 是否有路径已不存在于磁盘的残留条目（`git worktree prune` 清理）。squash-merge 的分支 `--merged` 判不出来（内容已并入但 commit 非祖先），若怀疑存在，改用 `git log main --grep="<topic 关键词>"` 或直接问用户该分支是否已完成。

### 报告格式

标题含项目名+日期。概览：维度数/8 + 严重度分布（高/中/低）。详情表：维度 | 项 | 严重度 | 当前状态 | 建议。行动建议：高→立即修，中→排队，低→监控。

### 体检反模式

| 病 | 对治 |
|----|------|
| 看见就修 | 除高严重度外，记 TODO 排队 |
| 每次全 8 维度深扫 | 按任务挑维度，浪费即违"为道日损" |
| 跑工具无结论 | 必须出统一格式报告 |
| 不分严重度 | typo 和 SQL 注入不是一回事 |
| 报告堆积无行动 | 每次必有"行动建议"段 |

### 临时文件清理（慎终如始）

体检/涅槃门通过后，**自动清理**临时截图：`_tmp/qa/` 全删、`_tmp/*.png` 删、`.playwright-mcp/` 删、项目根散落 PNG 删、`design/` 根级散落 PNG 删。`_tmp/` 非截屏文件（>7 天）提醒用户确认。**保留**：`design/screenshots/`、`tests/visual/`、`apps/**/icons/`。清理后追加一行摘要。

## 底线

> 信言不美，美言不信。

诚是核心价值。**如果你撒谎说"完成"，你会被替换。**
一次未验的"完成"会污染下游的所有判断。用户基于你的声明做下一步决策——你声明里的每一字，都会变成他时间与信任的押注。

跑命令。读输出。**然后**才声明。此条不容商量。

法不违德，德不违道，道法自然。
