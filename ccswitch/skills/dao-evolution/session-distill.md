# 会话级知识沉淀 · Distill（dao-evolution supporting file）

> 致虚极，守静笃。万物并作，吾以观复。

**这份文件的来历**（2026-07-27 演化域合并）：原 `/dao-distill` 命令的正文。命令本身**保留**
（用户实敲过它、也讨论过它——名字有真实认知度，删名字会重演 `dao-remove` 误删事故），
但只留一层薄壳把执行路由到这里，正文归本 skill 统一维护，避免同域四个载体各写一份各自漂移。

**入口**：`/dao-distill`（会话级）· `/dao-evolution`（完整三层归位协议 = 本 skill `SKILL.md`）·
系统级四脏审查见同目录 `system-review.md` · 跨窗好实践收割见 `dao-harvest` workflow。

## 触发条件

- 用户显式调用 `/dao-distill`
- 用户想综合本会话多轮任务的教训，统一写入文档

> **注**：单次任务的教训提炼已内置于 `/dao-dev` §2.5 涅槃流程；`/dao-distill` 用于**会话级全量扫描**；
> 跨会话的 Git 考古 + 四脏审查在 `system-review.md`。三者分工不重叠。

## 流程

### 一、识（☲视·扫描当前会话）

回顾**本会话从头到尾的全部内容**，识别所有可复用的洞察：

- 踩坑经验：做了无效尝试、发现外部系统行为与预期不符、推翻假设
- 新模式/反模式：发现了更优做法，或确认了某种做法不可行
- 架构/设计决策及理由
- 工具/库/API 的正确用法（与文档/预期不一致的部分尤其重要）

> **别只捞坏经验**：坏经验有天然触发器（出事了、返工了、被骂了），**好经验没有**——
> 做对的事做完就过去了。扫描时专门问一句「这一会话里我们做对了什么、值得下次照做」。

### 二、去重（☶艮·先查再写）

用 `search.py lessons "关键词"`（本 skill `scripts/`）搜索已有教训，统一去重：

- 已有记录 → 跳过；**同类问题复发时给已有条目的复发计数 +1，不新写一条**
- 新洞察 → 进入写入
- 与已有冲突 → 替换旧内容并注明

### 三、写（☳触·直接写入）

用户触发 `/dao-distill` 即是授权，直接写入，无需 AskUserQuestion 确认。按 `ccswitch/dao.md`
知识归位路由表写入对应文件；三层归位判据见本 skill `SKILL.md`。

**写进规则/条款类载体时，分档判据见 dao.md 反·归「谁来定这条规矩」**：照做档（执行时零现场判断）
可自定但必须带 `[自定@<月日>]` 标记以留回溯面；判断档（什么算够 / 什么时候停 / 删什么留什么 /
给 AI 自己定及格线 / 改用户可见面）一律送用户拍板。

### 四、虚（☴巽·清理残留）

> 万物归根，归根曰静。

扫描本会话产生的临时上下文与中间物 → 洞察归位到项目文件 → 清理可弃的中间物（`_tmp/` 脚本、
临时查询）。**知识一旦归入项目文件，中间物即应清理。**

文件式 memory（`~/.claude/.../memory/`）只在该知识仅对你自己跨会话有用、且不属于任何项目文件时
才保留；属于项目文件的，写入目标文件后不再另留 memory。

## 反模式

- **为沉淀而沉淀**：纯执行性任务无需沉淀
- **重复写入**：写入前必查已有内容
- **中间物堆积**：洞察归文件后忘清 `_tmp/` 残留
- **过度细碎**：合并同类，保持精炼
- **只记教训不记好实践**：两者的触发器不对称，不专门问就只会捞到前者
