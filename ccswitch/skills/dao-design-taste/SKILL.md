# 设计品味 · Design Taste(基石)

> 少则得,多则惑。读而后行,最小变更。

本 skill 是所有设计任务的**总闸**。它不直接产代码,它决定:这次该走多重的流程、读懂需求、定下基调、给出判据。具体的形态探索交给 `dao-ui-mockup`,资产落地交给 `dao-design-assets`。

**适用范围**:product UI(桌面/Web 应用、工具、仪表盘、多步骤流程、数据密集界面)为主。营销落地页/作品集的专属版式规则见 §A 附录,默认不启用。

## §0 · 分诊门(Triage Gate)★ 入口

> 治之于未乱。动手前先问:这次引入了多少未知?

**核心判据:流程的重量由「未知量」决定,不由「改动大小」决定。**

不要用"改页面 / 新功能"分级——会失灵。标准 CRUD 新功能形态早已知(无需原型),而给老页面加一种没做过的交互反而需要原型。HTML 原型的唯一使命是**消除"形态/交互的未知"**:形态已知,原型是浪费;形态未知,原型才有价值。

### 三档分诊

```
这次任务引入了多少未知?
│
├─ 重定整个产品的形态或风格(项目启动 / 换肤 / 大重构)
│   → 【FULL】  风格定调(产 tokens)→ 全量 HTML 原型 → 实现
│      昂贵。一个项目通常只发生 1-2 次。走 dao-ui-mockup 完整流程。
│
├─ 加一块「形态未知」的东西(新交互范式 / 信息架构不清 / 你自己也说不清长啥样)
│   → 【SCOPED】 tokens 不动 → 只对这一块做「局部」HTML 原型 → 实现 → 补进 gallery
│      中等。只画这一个功能,绝不重走全量。走 dao-ui-mockup 但范围锁定单功能。
│
└─ 在「已知形态」里做事(改样式 / 调间距 / 复用现成组件 / 标准 CRUD / 修 bug)
    → 【DIRECT】 跳过原型 → 查 gallery 找现成 → 写代码 → 过 §6 taste checklist
       最轻。绝大多数日常改动都在这档。
```

### 默认 DIRECT,升档要有明确信号

> 为道日损。不主动加流程。

**DIRECT 是默认。SCOPED / FULL 是例外,只有出现明确"未知信号"才升档。**

| 信号 | 落档 |
|---|---|
| gallery 里能拼出这个界面 / 项目有先例 / 你能一句话说清交互 | **DIRECT**(不升) |
| 一种没做过的交互 / 信息架构要重新想 / "我不知道长啥样" | **SCOPED**(只画这块) |
| 需求文档进来定义整个产品 / 要换整套视觉 | **FULL** |

### gallery 兼任分诊裁判

组件画廊(`dao-design-assets` 的 reflect 真相源)不只是展示窗,还是分诊裁判:**"形态是否已知"打开 gallery 一看就有答案**——有现成组件能拼 = 已知 = DIRECT;拼不出 = 未知 = 升档。

### 无感原则

> 太上不知有之。最好的门让人感觉不到。

AI 自己分诊,默认 DIRECT。只有在真碰到形态未知、且无法自行判断时,才问用户**一句**:"这个功能你心里有大概的样子吗,还是需要我先画个 HTML 原型探一下?"——不甩"请选择走哪档"的面板。大部分时候用户不会察觉有这道门,它只在该拦时拦一下。

## §1 · Design Read(读懂再动)

> 知人者智。多数 AI 设计差,是因为跳过"读懂"直接套了个默认审美。

动手前先推断用户真正想要什么。读这些信号:

1. **界面类型** — 工具型 product / 仪表盘 / 数据密集工作面 / 表单流程 / 外围展示页(设置/空态/引导)
2. **氛围词** — 用户用过的词:"克制""Linear 风""Notion 风""极简""专业""高级感"
3. **参考信号** — 链接的 URL、贴的截图、点名的产品
4. **受众** — 谁在用、在什么场景用(盯着看 vs 瞟一眼 vs 主动查询)
5. **已有资产** — 现有 tokens、组件、配色。改造任务里这些是起点,不是可选项
6. **隐性约束** — a11y 要求、宿主环境(桌面壳 / 内嵌 webview / 浏览器等)。这些**覆盖**审美偏好

### 动手前先声明一行 Design Read

任何代码之前,一句话声明:**"我把这读作:<界面类型> 给 <受众>,<氛围> 语言,倾向 <设计系统或审美家族>。"**

例:*"读作:桌面工具的数据密集工作面,给重度使用者,克制·低动效语言,倾向现成组件库 + 高密度布局。"*

> 注:示例中的"现成组件库"等具体技术,以项目实际技术栈为准。本基石只定**准则**,不规定用哪个库——具体技术选型属项目层(见 §4 判据与 §A 附录的"可替换"标注)。

### 歧义时只问一个问题

若 Design Read 真有分歧,只问**一个**澄清问题,绝不甩问题清单。能从上下文自信推断就**不问**,直接声明 Design Read 往下走。

## §2 · 三旋钮(定调)

> 一生二,二生三。三个维度,定下整个界面的气质。

Design Read 之后,设下三个旋钮。后面所有布局、动效、密度决策都受它们约束。

| 旋钮 | 1 端 | 10 端 |
|---|---|---|
| **VARIANCE** 版式变化度 | 完全对称、规整 | 艺术化、打破网格 |
| **MOTION** 动效强度 | 静止 | 电影级、物理弹性 |
| **DENSITY** 信息密度 | 画廊、空气感 | 驾驶舱、密集数据 |

### product UI 的基线

工具型 product UI 与营销页的基线**相反**,别套错:

| 场景 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| 数据密集工作面(列表/看板/triage) | 2-3 | 2-3 | **8-10** → 见 §5 |
| 表单 / 设置 / 配置流程 | 2-4 | 3-4 | 4-6 |
| 外围展示(空态/引导/欢迎页) | 4-6 | 4-5 | 3-4 |
| 营销落地页(如有) | 7-9 | 6-8 | 3-5 → 见 §A |

**要点:旋钮按界面分区转档,不是全 app 一个值。** 同一个应用,核心工作面 DENSITY 拉到 8(§5 高密度档),空态页降到 3(呼吸)。这正是"高密度"与"呼吸感"看似矛盾、实则同一旋钮两端的真相——按区域选档即可,不存在冲突。

### 覆盖规则

基线只是起点。Design Read 里的明确信号覆盖基线(用户说"我要很克制"→ VARIANCE/MOTION 压到 2-3)。改造任务默认 match 现状,别擅自加码。

## §3 · 设计系统映射(别重造轮子)

> 朴散则为器。先选对器,再谈美。

定调后,选实现基础。两条铁律:

1. **一个项目一套系统** — 不在同一棵树里混用两个组件库/设计系统。
2. **不重造官方 CSS** — 若项目已采用某成熟设计系统/组件库,用它的 token 和组件,别手搓一份它的副本,也别导入它的 token 却覆盖 90%。

### 选型准则(具体库名以项目为准)

本基石不规定用哪个库(那是项目层决策,且库会更替)。只给准则:

- **有官方设计系统的生态**(企业级 B 端、特定平台 app 等)→ 用该生态的官方包,a11y 和 token 已就绪。
- **自己拥有组件代码的现代栈**(copy-in 式组件库)→ 拥有即真相源,**但绝不直接用其默认样式出货**,必须经 token 收口(见 `dao-design-assets`)。
- **纯审美方向**(玻璃拟态/Bento/编辑风/暗黑技术风等)→ 无单一官方包,用原生 CSS + 维护良好的库实现,代码注释里诚实标注哪些是"借鉴"哪些是"官方"。

> 项目实际选了哪个库、哪个版本,记在项目的 `AGENT.md` / 设计基础文档里,不写进本全局基石。

## §4 · 通用判据(核心体检表)

> 反者道之动。AI 默认会滑向套路,这一节是反套路的体检表。每条都是**准则**,具体字体/库/色值见 §A 附录(可按项目替换)。

### 4.1 字体

- **不把"中性默认体"当默认就完事** — 系统默认无衬线(那个最常见的 UI 字体)不是不能用,而是别**不假思索**地用它。有性格的字体能瞬间拉开辨识度。除非 Design Read 明确要"中性/标准/克制",或受 a11y/平台约束。
- **衬线要克制** — "感觉有创意/高级" 不是用衬线的理由(这是被测最多的 AI 痕迹)。只有品牌明确要、或确属编辑/出版/复古气质且能说清为什么,才用衬线。
- **同族强调** — 强调标题里的某个词,用同字体的斜体或粗体,别塞一个异族字体进去。混族强调是业余做法。
- **层级靠对比** — display/标题用大字重负间距,正文克制行宽(中文约 30-40 字/行,西文约 65ch),用字重(500/600)而非只有 400/700 拉层级。

### 4.2 颜色

- **THE LILA RULE(禁 AI 紫蓝)** — "AI 紫/蓝光晕"渐变是最典型的 AI 痕迹,默认禁用。用中性灰基底 + 单一高对比强调色。除非品牌明确要紫,且执行得克制有意图(不是泛滥渐变)。
- **最多一个强调色** — 整页/整 app 锁定一个强调色,饱和度默认 < 80%。第 7 屏不许突然冒出另一个 CTA 色,footer 不许换个状态色。选定→锁死→出货前逐组件审。
- **一个项目一套灰** — 不在同项目里冷灰暖灰来回横跳。
- **颜色必须有语义** — 无语义的颜色是噪音。状态色(成功/警告/危险/中性)各司其义,别拿强调色当状态色。

### 4.3 阴影 / 形状

- **阴影染背景色** — 用阴影时,染上背景的色相,别在浅底上糊纯黑阴影。
- **卡片只在表达层级时用** — 否则用 `border-t` / `divide-y` / 留白分组。高密度区(§5)更要少用卡片容器。
- **形状半径锁** — 全页定一套圆角刻度并贯彻。要混用必须有成文规则(如"按钮全圆角 / 卡片 12px / 输入框 8px")且处处遵守。方形布局里冒圆按钮、圆角页面里冒方卡 = 破相。

### 4.4 交互状态(全周期)

> 大成若缺。只做"成功态"的界面是残缺的。

AI 默认只画"静态成功态"。每个交互元素都要覆盖完整周期:

- **加载态** — 骨架屏匹配最终布局形状,别用通用转圈。
- **空态** — 精心设计,告诉用户如何填充(引导 + CTA),不是一片空白。
- **错误态** — 表单内联、瞬时操作用 toast;文案直接("连接失败,请重试"),不用"哎呀!"。
- **触觉反馈** — `:active` 时 `scale(0.98)` 或 `translateY(1px)` 模拟物理按压。
- **过渡** — 交互元素 200-300ms 过渡;动画只动 `transform`/`opacity`(GPU 友好),不动 `top/left/width/height`。
- **焦点环** — 键盘可见焦点指示是 a11y 底线,不是可选项。

**按钮对比度(a11y 强制)** — 出货前验每个按钮:文字对背景可读,WCAG AA(正文 4.5:1,大字 3:1)。白底白字、透明按钮贴页面无边框、幽灵按钮压在图片上无衬底 → 全禁。

### 4.5 表单

- label 在输入框**上方**,错误文字在**下方**,帮助文字在标记里常驻。
- **禁 placeholder 当 label**,任何时候。
- 表单的 placeholder/焦点环/帮助文字/错误文字,全部过 WCAG AA 对比度。

### 4.6 文案自审(出货前强制)

声明任务完成前,重读页面每一处可见字符串(标题/副标题/按钮/正文/说明/alt/错误信息),标记并改写:

- 语法不通、指代不清的
- 像 AI 幻觉的(生硬双关、不成立的比喻)
- 装深刻的 LLM 腔(假谦卑、伪工匠标签、故作诗意的微文案)
- 假精确数字(`92%`、`4.1×` 这类)— 除非来自真实数据或明确标注为示例

**em-dash(破折号 —)全禁作设计点缀** — 长停顿、动感破折号、破折号当项目符号,全部禁用。不确定某句是否成立,就换成一句平实功能句。AI 生成的"可爱文案"比无聊文案更糟。

### 4.7 主题锁

整个页面**一个主题**。section 不许中途反色——暗色页里不夹一段亮色暖纸 section(反之亦然),用户不该感觉走进了另一个网站。同主题家族内的背景微调(相邻深浅)可以;中途跳到对立色 = 破相。用内置主题系统时,主题在根节点设一次,别让单个 section 覆盖。

## §5 · 高密度档(DENSITY 8-10 专章)

> 万物并作,吾以观复。当 §2 把 DENSITY 拨到 8-10(数据密集工作面),本节接管。

**高密度的真谛:不是塞满,是精简后的紧凑。** 好的高密度界面 = 用户在最短时间内获取最多有效信息。1 秒看懂整体 = 成功;要读文字才能判断 / 要滚动才能概览 = 失败。

### 信息三层架构

人一次只能处理一层。三层是极限:

| 层 | 功能 | 视觉占比 | 交互 |
|---|---|---|---|
| 总览层 | 一眼看到全局健康度 | 15-20% | 纯展示 |
| 列表层 | 扫描每个个体状态 | 60-70% | 点击/hover |
| 操作层 | 需要时才出现的操作 | 10-15% | 展开/收起 |

### 一行一世界

- 每行自包含 — 不看其他行也能判断这一行的状态
- 关键指标靠右对齐 — 眼睛沿右侧扫描比左侧高效
- 状态用颜色/图标,不用文字 — 一个状态点比"正常"二字快一个数量级

### 三色语义系统(高密度场景够用)

- 充裕/正常 · 注意/中等 · 危险/耗尽 — 三档跳变,不做连续渐变(清晰 > 精确)
- 面积越大颜色越淡,面积越小越饱和(进度条 vs 文字)
- 灰 = 无数据/不适用,别用灰表示"坏"
- 具体色值跟随项目语义色 token,不在此写死

### 密度技法

- **缩写约定** — 建立后不需解释(如 D=日额 W=周额)
- **图标替代文字** — 用形状/图标表达活跃/可用/不可用
- **hover 展开** — 常态只显示关键指标,hover 显示完整
- **对齐即结构** — 左对齐名称、右对齐数字,不需分隔线
- **留白是信息** — 行间距 > 行内间距 = "这是不同的行"

### 高密度反模式

| 病 | 症 | 治 |
|---|---|---|
| 卡片病 | 每个条目一个大卡片 | 卡片吃纵向空间,列表项一行即够 |
| 彩虹病 | 5 种以上颜色各有含义 | 三色系统,更多语义用形状/图标 |
| 精确病 | 显示 67.3% 而非 67% | 用户不需要小数点,整数 + 颜色已够 |
| 标签病 | "日额度: 68%" 而非 "D68%" | 空间受限时,约定 > 说明 |

> 注意:§5 的高密度只在 DENSITY 8-10 区生效。外围展示页(空态/引导/设置,DENSITY 3-4)反而要呼吸感,别把高密度技法套到那里——那是把工具界面做成了仪表盘的过度反应。

## §6 · 验收(taste checklist + preview)

> 慎终如始。验证不靠像素比对,靠体检表 + 真实渲染。

**不再做 mockup-vs-代码的像素 diff**(那是把设计稿当真相、逼代码对齐的旧契约模式,已废)。新验收两步:

1. **过 §4 体检表** — 逐条肉眼过:字体/禁 AI 紫/单一强调色/阴影染色/形状锁/交互状态全周期/按钮对比度/表单/文案自审/主题锁。高密度区另过 §5 反模式表。
2. **preview 真实渲染** — 跑起来截图,所见即所得。判断"实际像素/对比度/视觉密度"时**量真实渲染**,不靠 `rem×16` 心算。

**a11y 红线(硬性)**:正文字号别低于可读下限(约 12px),焦点环可见,对比度过 WCAG AA。无论设计给什么,红线不破。

通过 = 进收尾;任一不过 = 改代码或改 token。**验收对象是代码的真实渲染,不是某张稿子。**

## §7 · 与其他 skill 的关系

```
dao-design-taste(本 skill · 基石)
  ├─ §0 分诊门 → 决定走 FULL / SCOPED / DIRECT
  │
  ├─【FULL / SCOPED】→ dao-ui-mockup(HTML 形态探索工具)
  │     产 HTML 思考脚手架(throwaway)+ 导出 design tokens
  │     tokens 是唯一长期真相,HTML 用完归档
  │
  ├─【全档】→ dao-design-assets(资产落地)
  │     代码即真相 + tokens 收口 + 组件画廊(gallery)+ lint 禁硬编码
  │     gallery 兼任 §0 分诊裁判
  │
  └─ §6 验收 → 过本 skill 体检表 + preview,不做像素 diff

上游输入:
  dao-empathy        → 用户期待的氛围(喂给 §1 Design Read)
  dao-research       → 行业视觉参考(喂给 dao-ui-mockup「援」)
下游消费:
  dao-plan / dao-execute → 拿 tokens 实现
  dao-review         → 对照 §4 体检表验收(不再对照 mockup 像素)
```

**职责切分**:本 skill 是 WHAT(品味判据 + 流程分诊),dao-ui-mockup 是形态探索的 HOW,dao-design-assets 是资产落地的 HOW。

## §A · 附录(默认不启用)

### A.1 营销落地页 / 作品集专属版式

以下规则**仅**用于营销落地页、作品集这类"首屏即一切"的展示页,**product UI 默认不启用**(它们会把工具界面带偏成落地页):

- hero 必须首屏内放下(标题≤2行、副文≤20词、CTA 不滚动可见)、hero 顶 padding 上限、hero 文本元素≤4
- 导航单行、高度上限;"Trusted by"logo 墙在 hero 之下而非之内
- bento 网格有节奏不单边重复、cell 数=内容数不留空格
- eyebrow 克制(每 3 个 section 最多 1 个)、禁 split-header 默认、版式家族不重复、zigzag 连用上限 2
- 证言≤3 行、配图策略(真图优先,禁 div 假截图)、内容密度(每 section 短标题+短副文+1 视觉/CTA)

需要做营销页时,再来本附录取这些规则。日常 product UI 忽略本节。

### A.2 可替换的具体清单(示例性,按项目技术栈替换)

本基石正文只写**准则**(dao-meta 边界:全局元层禁技术选型)。下面是 taste-skill 提供的**具体落地示例**,会随生态更替而过时,**请在项目层(`AGENT.md`/设计基础文档)固化项目实际选择,不要把项目专属清单回写本文件**:

- **字体方向示例**:有性格的几何无衬线优于中性默认体;需衬线时用编辑/出版气质的;等宽用于数据/代码/元信息。具体字体名以项目为准。
- **图标方向示例**:统一一套图标库、统一描边粗细;别手搓 SVG icon path;一个项目一个图标家族。
- **强调色方向示例**:中性灰基底(zinc/slate/stone 一类)+ 单一高对比强调(emerald/electric blue/deep rose/burnt orange 一类),避开 AI 紫蓝渐变。
- **被点名禁用的默认**:别无脑用最常见的那个 UI 无衬线体当默认;别把两个 LLM 最爱的展示衬线当默认;别给所有东西套玻璃拟态。

> 这些是"换皮会变"的层。准则(§1-§6)是"换项目不变"的层。两层分开,正是 dao-meta 通用性要求。

## 反原则(保留 dao 风格)

- **简则简** — DIRECT 档别强行走流程,改个间距就是改个间距
- **不为流程而流程** — 形态已知就别画原型,tokens 够用就别重定调
- **判据是准则不是清单** — 字体名会过时,"别无脑用默认体"不会。守准则,清单按项目替换
- **真相在代码** — 不维护代码之外的设计真相源,不写像素契约

法不违德,德不违道,道法自然。
