# 交互成熟度（第五层）· 按产品形态启用的专章

> 由 `standards.md §I` 引用。**默认不启用** —— 启用条件在下面第一节，先过那一关再往下读。
> 2026-08-02 自 TraceyU `.claude/rules/interaction-maturity.md` 上移（三仓自上而下审计第 15 件）。

## 为什么它是「第五层」而不是又一份检查清单

dao 既有的设计验证是四层：**L1 token 合规 → L1.5 结构快照 → L2 层级/间距 → L3 截图 diff → L4/L5 四态与双主题**
（见 `fidelity.md`）。这四层验的是**某一帧长什么样**。
本章验的是**两帧之间发生了什么**：拖起来跟不跟手、拖到哪儿会不会告诉你、面板能不能拉宽、
拉完下次还记不记得、列表滚到底有没有边界感、状态从 A 变到 B 是切过去还是跳过去。

**它们全部逃得过前四层**：截图 diff 拍不到「没有过渡」，token 合规查不出「侧栏拉不动」，
四态覆盖的是 hover/active/disabled 这些**静态态**，不是态与态之间的那段路。
⇒ 这不是把已有清单再抄一遍，是补一个前四层结构上看不见的维度。

## 一、启用条件（不满足就别打开，否则是纯噪音）

**启用**：常驻使用的**工作台型 product UI** —— 多面板同屏、有长列表/树、有拖拽或排序、
用户一天开着它好几个小时。典型：IDE / 项目管理 / 数据面板 / 设计工具 / 本类桌面应用。

**不启用**（打开即错）：营销落地页 · 表单为主的后台 · 内容展示站 · 一次性活动页 ·
纯 CLI 的配套文档站。这类产品的用户**没有「长期驻留、反复操作同一块界面」这个场景**，
「面板宽度记忆」「拖拽 ghost」对它们是永远勾不上的框，而一份永远勾不满的清单会训练人整份忽略它。

**判据一句话**：问「用户会不会在同一块界面上待够久、久到开始嫌它不顺手」——
答「不会」就不启用。这与 §A（营销落地页专章）是同一个形态：**按产品形态分叉，不做无条件模板。**

⚠ **这条判据是人判的，机器判不了**，也刻意没做成 scaffold 清单条目：
「这算不算工作台型产品」正是备案清单明令不收的那类语义判断。

## 二、清单（17 条）

> 用法同 §4 体检表：**判据是准则不是清单**，项目可替换具体项，但替换要说得出理由。
> 未达标项**不阻塞归档**，但必须记成 known debt（谁记、记在哪，见第四节）。

### 2.1 动效体系

- [ ] 新增 `@keyframes` 有 `prefers-reduced-motion` guard（全局覆盖优先于逐处写）
- [ ] 列表项进入有入场动画（fade-in / slide-in），不是「刷一下就在那了」

### 2.2 可调布局

- [ ] 结构区域（侧栏/详情面板）**可拖拽调宽**，有 resize handle、有 min/max 约束
- [ ] 调整后的宽度**被记住**（localStorage / 配置持久化），下次打开还是那个宽度
- [ ] 双击 handle 还原默认宽度（给一条「我拉坏了」的退路）
- [ ] 调整过程中主内容区不塌不抖（拖拽期间的中间态也要看，不只看终态）

> 🔴 **这一组与 `standards.md §L.1 Multi-column` 的「结构区域用固定宽度 + shrink-0」
> 曾经互相矛盾，2026-08-02 已在那边订正**：那句话说的是「**不随内容/窗口自动伸缩**」，
> **不是「用户不能调」**。矛盾是真的存在过 —— 那一节引的三个蓝本（VS Code / Linear / Notion）
> 侧栏**全都可拖拽且宽度持久化**，即判据与它自己的举证相反。别再照旧读法实现。

### 2.3 拖拽交互（DnD）

- [ ] Ghost/Preview 与静止态有视觉区分（阴影提升 / 微旋转 / 缩放，任一）
- [ ] 拖拽**源**有占位指示（虚线框 / 降低不透明度）—— 让人看得见「它原来在哪」
- [ ] Drop target 有悬停反馈（背景变化 / ring 高亮）—— 让人看得见「松手会掉在哪」
- [ ] Drop 落位有回弹/弹性感（spring 缓动），不是瞬移

> 四条是一个整体：**拿起 / 原位 / 落点 / 落下**四个信息缺一个，用户就得靠猜。

### 2.4 滚动体验

- [ ] 长列表有边缘渐隐指示器（`mask-image` 或等效），让「上面还有」可见
- [ ] 程序触发的滚动用 `smooth` behavior，不是瞬间跳

### 2.5 状态过渡

- [ ] 页面/视图切换有 cross-fade（opacity 过渡），不是白闪一下换内容
- [ ] Loading → Content 有淡入，不是骨架屏「啪」地换成真内容
- [ ] 进度条/环的数值变化有平滑过渡，不是逐帧跳数字

### 2.6 键盘 & 焦点

- [ ] 键盘快捷键有视觉提示（Kbd 组件 / 菜单右侧标注），不靠用户记
- [ ] Tab 顺序符合视觉顺序（不是 DOM 顺序碰巧对）

## 三、上移时砍掉的 6 条（照直列，免得下次有人当缺失又加回来）

原清单 23 条（**不是 24 条** —— 派单契约与审计报告写的是 24，实算 23，此处以实算为准，
差异记在这里不回填）。砍掉的 6 条**都不是「不重要」，是 dao 别处已经在管**，
留着就变成同一条规矩两份措辞、各自漂移：

| 砍掉的条目 | 已归属 | 说明 |
|---|---|---|
| 所有过渡使用 motion token，零硬编码 `duration-*` | `standards.md §2 动效命名系统`（禁匿名 `transition: all`）+ `open.md` 关卡表「硬编码 cubic-bezier」 | 属 token 合规（L1），不属交互行为 |
| 缓动函数使用 token（`ease-*`） | 同上（§2 表的「参考实现」列已规定） | 同上 |
| 折叠/展开有平滑过渡 | `standards.md §L.4 常见问题检查清单`第 4 条 | 逐字同义，那边先有 |
| Dialog 打开/关闭有动画 | `standards.md §2` Spring 行「典型用途：模态弹入」 | 且原文括注「已由 Base UI 管理」是项目私货，跨项目不成立 |
| 所有可交互元素有 focus-visible ring | `standards.md §8.3 a11y 红线`「焦点环可见」 | 那边是**红线**，比 checklist 强一档，降级重复反而弱化它 |
| 自定义滚动条样式（thin scrollbar） | 项目实现细节，归 `component-health.md` / 项目 token 层 | 原文括注「已有全局覆盖」同为项目私货；**滚动渐隐那条保留** —— 那条是行为，这条是皮肤 |

**判据**（下次再有人想往这里加条目，先过这一问）：**这条验的是「某一帧长什么样」还是
「两帧之间发生了什么」？** 前者归前四层，后者才归本章。

## 四、合规门控

清单在 UI Loop 造线 Phase 验收时逐项过。**未达标不阻塞归档**，但：

- 未达标项写成 known debt，落**项目侧**账本（有 issue 中枢的项目开单，无则进 `TODO.md`），
  **不留在会话里** —— 会话结束它就没了，而那正是「义务转移即义务蒸发」的形态。
- 交付里写「交互成熟度已过」时必须说清**过了几条 / 共几条 / 差哪几条**，
  不写「基本满足」（程度词在这里等于没说）。
