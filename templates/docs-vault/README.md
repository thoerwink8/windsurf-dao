# 文档/知识库薄层

给「文档/知识库」类项目（Obsidian vault、团队 wiki、资料库）的起点。与 `base/` 拼装，见文末。

## 这层给什么

- **目录组织建议**：参考 `ObsidianVault` 实盘结构——一个 00 开头的「系统」区放配置说明，一个「收集箱」接临时想法，主体按主题分区。
- 同步与保密注意点：哪些文件该进 git、哪些不该。

## 怎么和 base 拼出新项目

1. 拷 `base/` 全部 + 本目录全部到新仓库根目录。
2. 按下面的「目录组织建议」建目录。
3. 把 `base/README-骨架.md` 改成 `README.md`，写清「这是什么库、怎么往里面放东西、放哪」。
4. 想用 Obsidian 打开：装 Obsidian，把仓库文件夹作为 vault 打开。`base/CLAUDE.md` 和 `.mcp.json` 对 Obsidian 无影响，可以留着（以后接 AI 知识问答用得上）。
5. 首次提交前先读「同步注意点」，把该忽略的配好，再开第一个 draft PR。

## 目录组织建议

```
知识库根/
  00-系统/          ← 系统配置说明：怎么同步的、装了什么插件、换设备先看这里
  00-收集箱/        ← 临时想法、随手笔记，定期整理进主题区或删除
  附件/             ← 图片、PDF 等二进制附件（或按主题拆附件子目录）
  <主题一>/         ← 按主题分区，名字用人话，别用编号体系（编号体系养着养着就烂了）
  <主题二>/
  README.md         ← 库的使用说明（这库是什么、东西放哪）
```

三条原则：

1. **「00-系统」是换设备/排障的第一入口**：把「这个库为什么这样配置、怎么同步的、依赖什么」写进去，别让配置知识只存在某个人脑子里。
2. **收集箱定期清**：临时笔记超过一个月没动，要么整理进主题区，要么删。收集箱不是仓库。
3. **目录名字用人话**：`项目-A/`、`读书笔记/` 比 `001/`、`002/` 好——编号体系没人维护，三个月就烂。

## 同步注意点

- **Obsidian 的 `workspace.json` / `workspace-mobile.json` 不进 git**（`.obsidian/` 下的这些文件记录窗口布局，各设备乱变，进 git 全是冲突）。具体忽略规则见 `base/gitignore-base.txt`，Obsidian 用户追加：

```gitignore
# Obsidian workspace 状态（各设备不同，不进 git）
.obsidian/workspace.json
.obsidian/workspace-mobile.json
```

- **`.obsidian/` 目录里除了上面两个文件，其它可以进 git**（插件清单、主题、快捷键配置——团队共享这些能让所有人打开体验一致）。
- 库里可能有日记、截图、账号线索：仓库设 **Private**，别手滑公开。
- 大文件（视频、超大 PDF）别进 git，用附件外部存储或 DVC，git 只放文本。
