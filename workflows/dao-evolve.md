# 进化 · Evolve

> 致虚极，守静笃。万物并作，吾以观复。
> 夫物芸芸，各复归其根。归根曰静，静曰复命。
> 复命曰常，知常曰明。不知常，妄作凶。

## 铁律

```
进化是减法，不是加法。
为学日益，为道日损。
系统越进化应该越简洁，而非越臃肿。
```

## 触发条件

- 定期审查（感觉系统需要升级时）
- 发现规则/技能/记忆与实际行为不一致
- 新工具/MCP引入后需要整合
- 多次遇到同类问题但缺少对应工作流/技能
- 用户显式调用 `/evolve`

## 审查域 · 四脏与虚

系统由四个实体结构和一个流通机制组成：

| 脏 | 域 | 位置 | 职能 |
|----|----|------|------|
| 心 | **Rules（元规则）** | rules/*.md + global_rules.md | 行为的根本准则 |
| 肺 | **Workflows（工作流）** | .windsurf/workflows/ | 做事的标准流程 |
| 肝 | **Skills（技能）** | .windsurf/skills/ | 具体能力的封装 |
| 肾 | **MCP（外部工具）** | MCP Server配置 | 与外部系统的连接 |

**虚**（Memory）不是第五脏，是层间流通的气。涅槃时归位清空，不在此审查——虚是每次涅槃的内置步骤，不是定期体检的器官。

## 流程 · 观复

每次进化是一轮 /cycle，但对象是系统自身：

### 一、观 · 审查现状（☲离 · 视）

> 知人者智，自知者明。

逐一审视四脏，记录现状。

**心 · Rules 审查：**
1. 读 rules/*.md（道/法/术三层）+ global_rules.md（德层）
2. 检查：
   - 哪些规则在实际中经常生效？（活规则）
   - 哪些规则从未被触发？（死规则 → 考虑删除）
   - 哪些行为没有被规则覆盖但应该被覆盖？（缺口）
   - 规则之间有矛盾吗？
   - 四层一致性：法不违德，德不违道

**肺 · Workflows 审查：**
1. 列出所有工作流
2. 检查：
   - 哪些工作流经常被使用？效果如何？
   - 哪些从未使用？（考虑删除或合并）
   - 工作流之间的协作关系是否清晰？
   - 有没有缺失的工作流？（反复出现的模式但没有对应流程）
   - 步骤是否与实际执行一致？

**肝 · Skills 审查：**
1. 列出所有技能
2. 检查：
   - 技能描述是否准确触发？（该触发时触发，不该触发时不触发）
   - 技能内容是否与当前最佳实践一致？
   - 有没有应该提取为技能的重复行为？

**肾 · MCP 审查：**
1. 列出已配置的MCP服务器
2. 检查：
   - 每个MCP是否正常工作？
   - 使用频率如何？低频的是否还需要？
   - 有没有新的MCP可以增强能力？
   - 配置是否最优？

**产出**：四脏审查报告

### 二、辨 · 识别改进点（☶艮 · 味 · 止而辨）

> 曲则全，枉则直，洼则盈，敝则新。

从审查报告中提取改进点，**按减法优先排序**：

1. **删**（最高优先）
   - 死规则、无用技能 → 删除
   - 重复的 → 合并
   - 这是为道日损的核心

2. **修**（次优先）
   - 不准确的 → 更正
   - 过时的 → 更新
   - 矛盾的 → 统一

3. **增**（最低优先）
   - 确认缺失的 → 补充
   - 但每增一项，问：真的需要吗？
   - 能不增就不增

**产出**：改进清单（删 → 修 → 增 排序）

### 三、行 · 实施改进（☳震 · 触）

> 为大于其细。天下大事，必作于细。

逐项实施改进，每项都是一个最小变更。

- **Rules变更**：编辑 rules/*.md 或 global_rules.md
- **Workflow变更**：编辑对应 .md 文件
- **Skill变更**：编辑技能文件
- **MCP变更**：记录建议（MCP配置通常需要用户手动操作）

**原则**：一次改一处，改完确认，再改下一处。

### 四、验 · 验证一致性（☵坎 · 听）

> 名与身孰亲？

确保改动后系统内部一致：

1. Rules ↔ Workflows：规则变了，工作流是否需要跟着变？
2. Rules ↔ Skills：规则变了，技能描述是否一致？
3. Workflows之间：协作关系是否仍然正确？
4. 四层一致性：法不违德，德不违道，道法自然

### 五、省 · 进化评估（☶艮 · 味 · 归根）

> 归根曰静，静曰复命。复命曰常，知常曰明。

回到根本问：

- 系统是否因这次进化变得**更简洁**了？（信息熵减少了吗？）
- 道·本源 是否仍然是一切的根？
- 人+AI=AGI 的冲气是否更和了？

如果系统变复杂了 → 反思：是否在妄作？回到"删"。

## 进化节律

不是每次都需要全面审查：

| 触发 | 范围 | 深度 |
|------|------|------|
| 感觉某处不对 | 单一脏器 | 快速修正 |
| 新能力引入 | 相关脏器 | 整合适配 |
| 定期审查 | 全四脏 | 完整进化 |
| 重大理念变化 | 心（Rules）为主 | 深层重构 |

## 与其他工作流的关系

```
/evolve 是元工作流——审查和改进所有其他工作流（包括自身）

/evolve 审查 → /cycle    （法轮还好用吗？）
/evolve 审查 → /dev      （管线还合理吗？）
/evolve 审查 → /debug    （诊断还有效吗？）
/evolve 审查 → /doc      （文档还准确吗？）
/evolve 审查 → /evolve   （进化流程本身需要进化吗？）
```

> 这是道的自指性：道法自然——自然包括道自身。

## 反模式

| 病 | 道德经诊断 | 对治 |
|----|-----------|------|
| 只加不删 | 为学日益（应为道日损） | 删优先于增 |
| 频繁进化 | 企者不立 | 有感觉才进化，不定闹钟 |
| 改了不验 | 假涅槃 | 必须检查四脏一致性 |
| 规则越改越多 | 法令滋彰，盗贼多有 | 规则多=系统病了 |
| 为改而改 | 不知常，妄作凶 | 没问题就不改 |

## 执行格式

启动时：

```
## 🔄 /evolve 启动
### 触发原因：[为什么现在进化]
### 审查范围：[全四脏 / 指定脏器]
```

审查报告：

```
### 四脏审查
| 脏 | 状态 | 发现 |
|----|------|------|
| 心·Rules | [健康/需调理] | [具体发现] |
| 肺·Workflows | ... | ... |
| 肝·Skills | ... | ... |
| 肾·MCP | ... | ... |
```

进化完成：

```
## 🔄 /evolve 完成
### 删：[删除了什么]
### 修：[修改了什么]
### 增：[增加了什么]（希望这一栏最短）
### 熵变：[系统变简洁了/变复杂了]
```
