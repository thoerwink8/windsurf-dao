# 代码审查 · Review

> 知不知，上；不知知，病。夫唯病病，是以不病。

## 触发条件

- 用户请求 review 代码变更
- PR / commit 需要审查
- 用户显式调用 `/review`

## 流程

### 一、理解（☲离 · 视 · 照见意图）

1. 读变更的完整上下文（不只看 diff）
2. 理解变更的**意图**：解决什么问题？
3. 确认影响范围：哪些模块/文件受影响？

### 二、审查（☶艮 · 味 · 止而辨）

**逻辑层：**
- 逻辑错误、边界情况、空引用
- 竞态条件、死锁风险
- 错误处理是否完备

**安全层：**
- 输入验证、注入风险
- 敏感数据暴露
- 权限检查

**质量层：**
- 资源泄漏（未关闭的连接/流）
- API 契约违反
- 命名一致性、代码风格

### 三、报告（☴巽 · 嗅 · 传递洞见）

```
## 📋 审查报告
### 变更意图：[一句话总结]
### 发现：
- 🔴 [必须修复]
- 🟡 [建议改进]
- 🟢 [亮点]
### 整体评价：[通过/需修改/需重构]
```

**原则：**
- 区分 pre-existing 问题和新引入问题
- 可并行读取多个文件加速审查
- 提出问题时附带建议修复方案
