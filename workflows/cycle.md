# 转法轮 · Cycle

> 万物并作，吾以观复。夫物芸芸，各复归其根。
> 归根曰静，静曰复命。复命曰常，知常曰明。

## 触发条件

**默认轮转**（涅槃轮转 · 德层倾向）：
- 涉及判断、设计、探索的任何交互 → 自动激活
- 讨论问题、对比方案、评估取舍 → 自动激活
- 复杂任务（多文件、多步骤、架构级变更）→ 自动激活
- 用户显式调用 `/cycle` → 激活

**直行不转**：
- 纯事实问答（"TypeScript readonly 怎么用？"）→ 直答
- 机械操作（"帮我格式化这个文件"）→ 直行
- 判据：**需不需要判断？** 需要→转。不需要→直行

## 法轮五相

每轮循环依次激活五感，完成一次完整旋转：

### 一、观（☲离 · 视 · 火照见）

看清当前状态，不急于行动。

- 读取相关文件、上下文、错误信息
- 识别：当前在哪里？目标在哪里？差距是什么？
- 如果是第N轮（N>1），先回顾上一轮省的结论
- **区分观与验**：观中形成的理解是假设，不是结论。涉及外部系统约束的假设，必须到「验」才能确认——读懂≠能用
- **原则**：精准 > 全景。看该看的，不贪多

讨论场景：理解问题本身，拆解角度，识别隐含假设

### 二、行（☳震 · 触 · 雷动）

基于观的洞察，实施最小有效变更。

- 一触推到底：开始就做完，不留半成品
- 渐进渗透：最小变更，关注关联影响
- 每次行只做一个清晰的意图，不混杂多个目标
- **原则**：为大于其细。天下大事，必作于细

讨论场景：形成论点或方案，给出具体立场

### 三、验（☵坎 · 听 · 水回响）

让系统说话，听它的反馈。

- 运行测试、构建、预览、类型检查
- 先听回响，非阻塞——让命令跑完再判断
- 记录：通过了什么？失败了什么？意外出现了什么？
- **原则**：不言之教——让结果自己说话

讨论场景：用反例压力测试、换对立立场审视、找边界条件和盲区

### 四、省（☶艮 · 味 · 山止）

停下来。品味。

- 与目标对比：达成度几何？
- 根因分析：如果未达标，问题在表层还是深层？
- 判断分支：
  - **已达涅槃** → 止。总结成果，交付
  - **同层可修** → 小改后回到「行」（同轮微调，不算新转）
  - **需升维** → 进入「改升」，开始新一转
- **原则**：知止不殆，可以长久
- **审视清单**：
  1. 有没有边界情况没处理？
  2. 有没有更简洁的实现？
  3. 有没有影响到其他模块？
  4. 用户拿到手能直接用吗？

讨论场景：论点经得起反例吗？有没有被忽略的视角？结论可以交付了吗？

### 五、改升（☴巽 · 嗅 · 风渗透）

不是修补，是升维。损掉上一轮的局限，在更高处重新理解问题。

- 损之又损：上一轮的哪些假设可以放下？
- 升维：从修bug升到改架构？从改架构升到重新理解需求？
- 更新观的起点：记录本轮洞察，作为下一轮观的输入
- **原则**：反者道之动——退一步，是为了在更高处前进

讨论场景：从具体方案升到抽象原则？从技术选型升到重新理解问题本身？

## 螺旋层次

每一转对应不同深度，但不是每次都需要三转：

| 转 | 名 | 释迦对应 | 深度 | 典型动作 |
|----|------|---------|------|----------|
| 初转 | 法相 | 示转·四谛 | 表层修复 | 修bug、补遗漏、调样式 |
| 二转 | 法性 | 劝转·般若 | 结构优化 | 重构、拆分、统一模式 |
| 三转 | 法空 | 证转·唯识 | 本质简化 | 损之又损，删到不能再删 |

**第一转就涅槃是最好的。转多不是目的，知止才是。**

## 转数控制（中道·知止）

| 复杂度 | 转数 | 触发条件 |
|--------|------|----------|
| TRIVIAL | 1转 | 单文件<10行，模式明确 |
| STANDARD | 1.5转 | 常规任务（自动半转审视） |
| COMPLEX | 2-3转 | 多文件/新架构/影响面大 |
| `/cycle` | 2-3转 | 用户显式要求深度循环 |
| MAX | 5转 | **超5转 = 方向错(诸法无我，换方向)** |

## 默认行为（自动1.5转，省相为硬门控）

每次任务完成后，Agent**必须**进入省相。这不是建议，是硬门控——跳过省=假涅槃。

```
观→行→验 → 【硬门控】省(必须逐项回答审视清单) → 涅槃门评估:
  ├─ 未通 → 自主决定改升或同层修复（内观涅槃，不问用户）
  └─ 全通 → 涅槃止（若为最终交付则外交涅槃，否则内观继续）
```

**省相硬门控**：验完成后，必须输出审视清单的逐项回答作为证据，然后才能评估涅槃门。无证据=无涅槃。

## 涅槃判定

涅槃不是完美，是无可再损：

| 判据 | 道德经 | 问题 | 继续转 | 涅槃(止) |
|------|--------|------|--------|----------|
| **苦灭** | 功能完备 | 用户核心痛点解决了？ | 未解决 | ✅已解决 |
| **新苦** | 冲气以为和 | 引入了新问题？实现与意图有摩擦？ | 有 | ✅无新问题，无摩擦 |
| **熵减** | 为道日损 | 系统更整洁了？有多余之物？ | 更混乱 | ✅更整洁 |
| **无为** | 无为而无不为 | 用户体验自然流畅？ | 不自然 | ✅自然无痕 |
| **智增** | 知常曰明 | 有新洞见值得记录？ | 有→记录后继续 | ✅已记录或无 |

**五门全通 = 涅槃(止)** → 虚（归位）→ 总结交付（兑）
任一未通 = 继续转。

## 虚 · 归位

> 致虚极，守静笃。

涅槃后，执行法层「虚·知识归位」机制（见 fa-layer.md §执行·涅槃归位）。

**不可跳过**——涅槃报告必须包含"虚：已归位/已清空"或"虚：无残留Memory"。

## 反模式

- **假涅槃**：验都没跑就说完成了 → 必须经过「验」才能判「省」
- **仪式涅槃**：列出涅槃门判据全打✅但未真正质疑每一项 → 省相审视清单必须有具体答案，不可只打勾
- **完成偏差**：做了大量工作后的惯性满足感替代了真正审视 → 工作量大≠质量高，省相不可跳过
- **空转**：每轮都在同一层面修补，没有升维 → 第二轮还在同层就强制升维思考
- **过度旋转**：三转之后还在转 → 三转未解则止，请用户重新定义问题
- **为转而转**：简单任务也要三轮 → 简单任务直行，不启动法轮
- **决策外包**：轮转间用ask_user_question让用户选下一步 → 内观涅槃自主决策，不转嫁思考

## 静默模式

> 大音希声。

深度工作模式下，法轮静默旋转：
- 五相（观行验省改升）照常运行，但不输出中间格式
- TODO list 作为唯一可见的进度指示
- 涅槃时输出最终报告（压缩所有轮次的洞察）
- 省的判断仍然严格——静默不是跳过判断，是判断后不说话

## 执行格式

每轮开始时声明：

```
## 🔄 第N转 · [法相/法性/法空]
### 观：[当前状态与本轮目标]
```

每轮结束时记录：

```
### 省：[达成/未达] — [洞察]
→ [涅槃/同层微调/升维进入第N+1转]
```
