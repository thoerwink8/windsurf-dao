# 优化 · Optimize Lens

> 少则得，多则惑。

## 铁律

不猜，先量。没有数据的优化是妄作。

## 瓶颈定位

1. **建立基线**：当前性能指标（时间 / 内存 / CPU）
2. **定位热点**：
   - 时间复杂度：O(n²) 循环？不必要的遍历？
   - I/O 阻塞：同步文件/网络操作？
   - 内存：大对象未释放？重复创建？
   - 热函数：哪个函数消耗最多时间？

## 工具

| 平台 | 工具 |
|------|------|
| 前端 | Chrome DevTools Performance |
| Node.js | `--prof`, clinic.js |
| Python | cProfile, py-spy |
| Android/JVM | Android Profiler, JMH |

## 策略选择

| 瓶颈类型 | 策略 |
|---------|------|
| 算法 | 换更优算法/数据结构 |
| I/O | 异步化 / 批处理 / 缓存 |
| 内存 | 池化 / 懒加载 / 流式处理 |
| 热函数 | 内联 / 减少分配 / 预计算 |

## 原则

- 先改算法，后改常数
- 80/20：优化消耗 80% 时间的 20% 代码
- 不优化不是瓶颈的地方（知止）
- 每次只改一个优化点，改前改后对比数据
- 不牺牲可读性换取微小性能提升
