# 设计品味 · Design Taste(总闸)

> 少则得,多则惑。读而后行,最小变更。

本 skill 是所有设计任务的**总闸**——品味判据、流程分诊、资产管理、形态探索,一站式覆盖。

**适用范围**:product UI(桌面/Web 应用、工具、仪表盘、多步骤流程、数据密集界面)为主。营销落地页专属规则见 §A 附录,默认不启用。

---

## §0 · 分诊门(Triage Gate)★ 入口

> 治之于未乱。动手前先问:这次引入了多少未知?

**核心判据:流程的重量由「未知量」决定,不由「改动大小」决定。** HTML 原型的唯一使命是消除"形态/交互的未知":形态已知,原型是浪费;形态未知,原型才有价值。

### 三档分诊

```
这次任务引入了多少未知?
│
├─ 重定整个产品的形态或风格(项目启动 / 换肤 / 大重构)
│   → 【FULL】  风格定调(产 tokens)→ 全量 HTML 原型 → 实现
│
├─ 加一块「形态未知」的东西(新交互范式 / 信息架构不清)
│   → 【SCOPED】 tokens 不动 → 局部 HTML 原型 → 实现 → 补进 gallery
│
└─ 在「已知形态」里做事(改样式 / 调间距 / 复用现成组件 / 标准 CRUD)
    → 【DIRECT】 跳过原型 → 查 gallery 找现成 → 写代码 → 过 §6 验收
```

**默认 DIRECT,升档要有明确信号。** gallery 兼任分诊裁判:有现成组件能拼 = 已知 = DIRECT;拼不出 = 未知 = 升档。

AI 自己分诊,默认 DIRECT。只有真碰到形态未知且无法自行判断时,才问用户**一句**:"这个功能你心里有大概的样子吗,还是需要我先画个 HTML 原型探一下?"——大部分时候用户不会察觉有这道门。

## §1 · Design Read(读懂再动)

> 知人者智。多数 AI 设计差,是因为跳过"读懂"直接套了个默认审美。

动手前先推断用户真正想要什么。读这些信号:

1. **界面类型** — 工具型 product / 仪表盘 / 数据密集工作面 / 表单流程 / 外围展示页
2. **氛围词** — "克制""Linear 风""Notion 风""极简""专业""高级感"
3. **参考信号** — 链接的 URL、贴的截图、点名的产品
4. **受众** — 谁在用、在什么场景用
5. **已有资产** — 现有 tokens、组件、配色。改造任务里这些是起点
6. **隐性约束** — a11y 要求、宿主环境。**覆盖**审美偏好

任何代码之前,一句话声明:**"我把这读作:<界面类型> 给 <受众>,<氛围> 语言,倾向 <设计系统或审美家族>。"**

歧义时只问**一个**澄清问题,绝不甩问题清单。能从上下文推断就不问。

## §2 · 三旋钮(定调)

> 一生二,二生三。三个维度,定下整个界面的气质。

| 旋钮 | 1 端 | 10 端 |
|---|---|---|
| **VARIANCE** 版式变化度 | 完全对称、规整 | 艺术化、打破网格 |
| **MOTION** 动效强度 | 静止 | 电影级、物理弹性 |
| **DENSITY** 信息密度 | 画廊、空气感 | 驾驶舱、密集数据 |

### product UI 的基线

| 场景 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| 数据密集工作面(列表/看板/triage) | 2-3 | 2-3 | **8-10** → 见 §5 |
| 表单 / 设置 / 配置流程 | 2-4 | 3-4 | 4-6 |
| 外围展示(空态/引导/欢迎页) | 4-6 | 4-5 | 3-4 |
| 营销落地页(如有) | 7-9 | 6-8 | 3-5 → 见 §A |

**旋钮按界面分区转档,不是全 app 一个值。** 基线只是起点,Design Read 里的明确信号覆盖基线。

## §3 · 设计系统映射(别重造轮子)

> 朴散则为器。先选对器,再谈美。

1. **一个项目一套系统** — 不在同一棵树里混用两个组件库/设计系统。
2. **不重造官方 CSS** — 若项目已采用成熟设计系统,用它的 token 和组件,别手搓副本。

选型准则(具体库名以项目为准):
- 有官方设计系统的生态 → 用官方包
- copy-in 式组件库 → 拥有即真相源,**但必须经 token 收口**(见 §7)
- 纯审美方向 → 原生 CSS + 维护良好的库,注释标注来源

## §4 · 通用判据(核心体检表)

> 反者道之动。AI 默认会滑向套路,这一节是反套路的体检表。

### 4.1 字体

- **不把"中性默认体"当默认就完事** — 有性格的字体能拉开辨识度。除非 Design Read 明确要"中性/标准/克制"
- **衬线要克制** — 只有品牌明确要、或确属编辑/出版/复古气质才用
- **同族强调** — 用同字体的斜体或粗体,别塞异族字体
- **层级靠对比** — display 用大字重负间距,正文克制行宽(中文约 30-40 字/行),用字重拉层级

### 4.2 颜色

- **THE LILA RULE(禁 AI 紫蓝)** — 默认禁用。用中性灰基底 + 单一高对比强调色
- **最多一个强调色** — 饱和度默认 < 80%,选定→锁死→出货前逐组件审
- **一个项目一套灰** — 不冷灰暖灰来回横跳
- **颜色必须有语义** — 状态色各司其义,别拿强调色当状态色

### 4.3 阴影 / 形状

- **阴影染背景色** — 别在浅底上糊纯黑阴影
- **卡片只在表达层级时用** — 否则用 `border-t` / `divide-y` / 留白分组
- **形状半径锁** — 全页定一套圆角刻度并贯彻

### 4.4 交互状态(全周期)

> 大成若缺。只做"成功态"的界面是残缺的。

每个交互元素覆盖完整周期:加载态(骨架屏)、空态(引导+CTA)、错误态(内联提示)、触觉反馈(`:active` scale)、过渡(200-300ms,只动 `transform`/`opacity`)、焦点环(a11y 底线)。

**按钮对比度(a11y 强制)** — WCAG AA(正文 4.5:1,大字 3:1)。白底白字、透明无边框、幽灵按钮压图片无衬底 → 全禁。

### 4.5 表单

- label 在输入框**上方**,错误文字在**下方**
- **禁 placeholder 当 label**
- 全部过 WCAG AA 对比度

### 4.6 文案自审(出货前强制)

重读页面每一处可见字符串,标记并改写:语法不通 / AI 幻觉 / LLM 腔 / 假精确数字。**em-dash 全禁作设计点缀。**

### 4.7 主题锁

整个页面**一个主题**。section 不许中途反色。同主题家族内的背景微调可以;跳到对立色 = 破相。

## §5 · 高密度档(DENSITY 8-10 专章)

> 万物并作,吾以观复。当 §2 把 DENSITY 拨到 8-10,本节接管。

**高密度的真谛:不是塞满,是精简后的紧凑。** 1 秒看懂整体 = 成功;要读文字/要滚动才能概览 = 失败。

### 信息三层架构

| 层 | 功能 | 视觉占比 | 交互 |
|---|---|---|---|
| 总览层 | 全局健康度 | 15-20% | 纯展示 |
| 列表层 | 每个个体状态 | 60-70% | 点击/hover |
| 操作层 | 需要时才出现 | 10-15% | 展开/收起 |

### 密度技法

- 每行自包含,关键指标靠右对齐
- 状态用颜色/图标不用文字 — 三色语义系统(充裕/注意/危险),面积越大越淡
- 缩写约定(D=日额 W=周额)、图标替代文字、hover 展开、对齐即结构、留白是信息
- 灰 = 无数据/不适用,别用灰表示"坏"

### 高密度反模式

| 病 | 治 |
|---|---|
| 卡片病 — 每条目大卡片 | 列表项一行即够 |
| 彩虹病 — 5+ 种颜色 | 三色系统,更多语义用形状 |
| 精确病 — 67.3% | 整数 + 颜色已够 |
| 标签病 — "日额度: 68%" | 约定 > 说明:"D68%" |

## §6 · 验收(taste checklist + preview)

> 慎终如始。验证不靠像素比对,靠体检表 + 真实渲染。

1. **过 §4 体检表** — 逐条肉眼过。高密度区另过 §5 反模式表
2. **preview 真实渲染** — 跑起来截图,量真实像素/对比度/视觉密度

**a11y 红线**:正文 ≥ 12px,焦点环可见,对比度 WCAG AA。红线不破。

通过 = 进收尾;不过 = 改代码或改 token。**验收对象是代码的真实渲染,不是稿子。不做 mockup-vs-代码的像素 diff。**

## §7 · 设计资产(代码即真相)

> 道生一(tokens),一生二(基础件),二生三(业务件),三生万物(页面)。

### 范式:reflect,不是 push

设计资产的真相**在代码里**,不在代码之外的任何稿子里。

```
✗ push 模型(已废弃):外部设计稿 = 真相 → 推代码逼近 → 永远有 gap → 加契约锁像素
✓ reflect 模型(现行):代码 = 真相 → gallery 渲染真组件 → 永不漂移 → 零同步
```

统一性靠"约束输入"(只准用 token),不靠"事后比对"。

### 三层真相源

| 层 | 真相 | 统一性保证 | 维护成本 |
|---|---|---|---|
| **① Design Tokens** | token 定义(色/字/间距/圆角/阴影) | 所有组件只引用 token,**禁硬编码** | O(1):改一处全局生效 |
| **② 基础组件** | 项目基础件 | variant 一次定制,只引用 token | 趋近 0 |
| **③ 业务组件** | 真实业务代码 | 组合①②,不引入新样式 | 随业务走 |

### 组件画廊(gallery)

一个展示页,**直接引用项目真实组件**,把所有 variant、所有状态(default/hover/loading/empty/error/disabled)摆出来一屏看全。

- gallery 引用真组件,绝不复制代码进去;改组件 gallery 自动更新
- 用开发态开关隔离,生产构建排除
- 兼任 §0 分诊裁判:能拼出 = DIRECT;拼不出 = 升档
- 小项目一页即可;组件多到管不过来再考虑专业工具(默认不上重工具)

### lint 守护统一性

**禁止硬编码颜色/间距/圆角等设计值,只准引用 token。** 用项目 lint 体系机器化,出货前自动拦截。一条 lint 规则替掉旧体系里成百上千行像素契约测试。

## §8 · HTML 形态探索(用完即弃)

> 无状之状,无物之象,是谓惚恍。大象无形,转其形而显之。

让无形的设计语言显形,让用户在浏览器里**看见**之后再决策。

### 定位:思考脚手架,不是真相源

```
HTML 原型 = 一次性思考脚手架(throwaway)
  ├─ 使命:帮用户/AI 想清楚形态与交互
  ├─ 完成即归档(_tmp/ 或 docs/design/_archive/)
  └─ 唯一长期产物 = design tokens → 交给 §7 收口
```

**HARD-GATE**:FULL/SCOPED 档,用户未看过 HTML 并拍板前,不写实施 plan、不动样式代码。
**反向 HARD-GATE**:DIRECT 档不画 HTML——形态已知还画 = 浪费。

### 五步法(察 → 援 → 拟 → 显 → 择)

**一、察**(项目上下文):扫描产品定位、当前阶段、技术栈、现有视觉、关键场景,产出**项目画像**(一段话)。SCOPED 档只扫相关上下文。

**二、援**(借鉴已验证的视觉哲学):配色/字体/风格不凭空发明。供给源优先级:
1. ui-ux-pro-max(主供给源,若已注入)— 按项目画像检索取 3-5 套候选
2. 用户提供的参考
3. 基石 §4 准则直接定克制方向

> ui-ux-pro-max 是外部可选 skill,未注入则跳过走 2/3。

给用户 3-5 个候选拍板后进「拟」。

**三、拟**(设计方向):基于拍板方向 + 项目画像,合成 N 套设计方向,每套含结构化 tokens。方向间必须显著不同(明/暗、衬线/无衬线、密/疏),所有方向须过 §2 三旋钮 + §4 判据。

**四、显**(生成 HTML):读模板 `templates/mockup.html`,注入 tokens + 真实场景,生成单 HTML。输出 `_tmp/ui-mockup-<topic>-<时间戳>.html`。必含:方向切换 + 暗色切换 + Foundations + 关键组件 + 真实场景。技术约束:单文件零 CDN、真实文案、可实现性自检。

**五、择**(用户选定 + 导出 tokens):用户在浏览器审视后显式选定。导出 `_tmp/design-tokens-<topic>.json`(唯一长期真相),可选附 CSS 变量草稿。HTML 归档不维护。

### 双模式

| 模式 | 触发 | 产出 |
|---|---|---|
| **Style Tile** | 先看大方向 / SCOPED | 简化 HTML(Foundations + 1 场景) |
| **Style Guide** | 细化看组件库 / FULL | 完整 HTML(组件库 + 多场景) |

## §A · 附录(默认不启用)

### A.1 营销落地页 / 作品集专属版式

**仅**用于营销落地页、作品集,product UI 默认不启用:

- hero 首屏内(标题≤2行、副文≤20词、CTA 不滚动可见)、hero 文本元素≤4
- 导航单行;bento 有节奏不单边重复
- eyebrow 克制(每 3 section 最多 1 个)、版式家族不重复、zigzag ≤ 2
- 证言≤3 行、真图优先(禁 div 假截图)

### A.2 可替换的具体清单(示例性)

本基石正文只写准则。以下是具体落地示例,会随生态更替而过时,**在项目层固化实际选择,不回写本文件**:

- 字体:有性格的几何无衬线优于中性默认体;等宽用于数据/代码
- 图标:统一一套库、统一描边粗细;一个项目一个图标家族
- 强调色:中性灰基底 + 单一高对比强调,避开 AI 紫蓝渐变
- 禁用默认:别无脑用最常见 UI 无衬线体;别给所有东西套玻璃拟态

## 反原则

- **简则简** — DIRECT 档别强行走流程,改个间距就是改个间距
- **代码即真相** — 不维护代码之外的设计真相源,不写像素契约
- **HTML 是脚手架不是真相** — 用完归档,绝不写测试、不逼代码还原
- **token 先行** — 任何设计值走 token,裸值是 lint 错误
- **gallery 引用不复制** — 它渲染真组件,绝不 copy 代码进去
- **不为流程而流程** — 形态已知就别画原型,tokens 够用就别重定调
- **判据是准则不是清单** — 守准则,清单按项目替换

法不违德,德不违道,道法自然。
